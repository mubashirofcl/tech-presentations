React Week 1 › Introduction › Why React?
02 • Motivation

Why React? Imperative vs Declarative

How React solves the "spaghetti code" and performance bottlenecks of manual DOM manipulation.

Before React: Imperative DOM Manipulation (Vanilla JS)

You must step-by-step instruct the browser HOW to update every DOM node:

// Imperative: Manual query & mutation
const titleEl = document.getElementById("title");
titleEl.innerText = "Hello Mubashir";
titleEl.classList.add("active");

const btn = document.getElementById("btn");
btn.addEventListener("click", () => {
  let count = parseInt(titleEl.dataset.count);
  titleEl.dataset.count = count + 1;
  titleEl.innerText = `Count: ${count + 1}`;
});
⚠ Difficult to maintain as apps grow, error-prone, hard to keep state in sync across elements.
With React: Declarative State-Driven UI

You describe WHAT the UI should look like for a given state:

// Declarative: UI is a function of state
function Counter() {
  const [count, setCount] = useState(0);

  return (
    <div>
      <h1 className="active">Count: {count}</h1>
      <button onClick={() => setCount(count + 1)}>
        Increment
      </button>
    </div>
  );
}
✓ React automatically computes and applies the exact DOM mutations needed.
1. Component-Based

Encapsulate structure, style, and logic into self-contained blocks.

2. Declarative UI

Predictable code that is dramatically easier to debug and reason about.

3. Efficient Updates

Virtual DOM diffing guarantees only modified elements touch the real DOM.

4. Huge Ecosystem

Vast package catalog, massive community, and the highest job market demand.

03 • Architecture

React: Library vs Framework

Understanding the technical distinction and why React gives developers architectural freedom.

React is a Library

A library is a collection of helper functions and tools that focuses on one specific job. For React, that job is building user interfaces.

  • You are in control: Your code calls React when needed.
  • Freedom of choice: You decide which router, HTTP client, or state manager to plug in.
React Ecosystem Assembly
React (UI Core) + React Router + Axios + TanStack Query
A Framework (e.g. Next.js, Angular)

A framework provides a complete, opinionated application structure, enforcing specific conventions for routing, data fetching, and build pipelines.

  • Inversion of Control: The framework dictates the architecture and calls your code.
  • Full-battery included: Built-in file-based routing, server rendering, optimization.

What is a Package?

A package is reusable code written, tested, and published by open-source developers so others don't have to reinvent the wheel.

React Week 1 › Vite Build Tool › What is Vite?
08 • Tooling

What is Vite?

The next-generation frontend tooling that provides an ultra-fast development experience.

Simple Explanation for Students

Vite (pronounced "veet", French for "quick") is a modern frontend build tool and local development server.

Created by Evan You (the creator of Vue.js), Vite provides all the tooling required to develop, run, test, and build modern React applications with near-instantaneous startup and update times.

What Vite Handles For Us: Local dev server, native ES module serving, Hot Module Replacement (HMR), asset processing (images, CSS), and production bundling.
Why Was Vite Created?

Older bundlers (like Webpack in Create React App) had to crawl and bundle your entire codebase into one giant file before the dev server could even turn on!

⚡ Vite's Breakthrough: Modern browsers natively support ES modules (import / export). Vite serves modules on-demand as requested by the browser. Server boot is instant!

Understanding the purpose of every file and folder in a newly created Vite application.

Stands for "source". This is where 99% of your development takes place. Components, styles, hooks, and data live here.

public/ vs src/assets/

• public/: Assets placed here are served directly without processing (e.g. favicon.ico, robots.txt).
• src/assets/: Assets imported in JavaScript (processed, hashed, and optimized by Vite during production build).

src/components/ Convention

Neither React nor Vite enforces a specific component folder. Creating src/components/ is a universal community convention to keep reusable UI blocks clean and organized.

What is a React Component?

The fundamental architectural building block of every React application.

Core Definition

A component is an independent, self-contained, and reusable piece of user interface.

• In modern React, a component is simply a JavaScript function that returns UI (JSX).
• Components encapsulate their own structure (JSX), presentation styling, and interactive behavior.
• Can accept inputs (called props) and manage internal dynamic data (called state).
Welcome.jsx 
// A complete, valid React functional component!
function Welcome() {
  return <h1>Welcome to Web Development</h1>;
}

export default Welcome;
Two Ways to Write Functional Components
Both syntax forms are 100% valid and equivalent:
1. Function Declaration
function Greeting() {
  return <h1>Hello</h1>;
}
2. Arrow Function (ES6)
const Greeting = () => {
  return <h1>Hello</h1>;
};
React Week 1 › Components › Naming Rules
21 • Syntax Rule

Component Naming: Always Use PascalCase

Why React strictly distinguishes uppercase component names from lowercase HTML elements.

CORRECT: PascalCase (First Letter Capitalized) 
// Starts with uppercase 'H'
function Header() {
  return <header>Site Header</header>;
}

// React treats this as a custom COMPONENT
function App() {
  return <Header />;
}
✓ React executes the Header() function and renders its output.
INCORRECT: lowercase (Starts with small letter) 
// Starts with lowercase 'h'
function header() {
  return <div>Site Header</div>;
}

// React treats this as a standard HTML tag!
function App() {
  return <header />;
}
✗ React renders a blank HTML5 <header></header> tag. Your function is never called!
Why Does React Do This?

In JSX, the compiler checks the first letter:
• If it starts with lowercase (<div>, <h1>, <header>, <button>), React compiles it as a built-in browser DOM element.
• If it starts with uppercase (<Navbar>, <ProductCard>, <Header>), React compiles it as a user-defined component and invokes your function!

React Week 1 › Components › Reusability & DRY
23 • Reusability

Component Reusability & Architecture

Eliminating repetitive code through the Don't Repeat Yourself (DRY) principle.

Scenario: 10 Product Cards on an E-Commerce Page

In traditional HTML, you would have to copy and paste 200 lines of identical markup. If a designer asks to change a button style, you must edit 10 different places!

ProductCard.jsx
function ProductCard() {
  return (
    <div className="card">
      <h3>Product Item</h3>
      <button>Add to Cart</button>
    </div>
  );
}
The React Solution: Reuse as Many Times as Needed!

Call the component like an HTML tag. Later, we will pass dynamic data into each card using props.

ProductList.jsx
function ProductList() {
  return (
    <div className="catalog">
      <ProductCard />
      <ProductCard />
      <ProductCard />
    </div>
  );
}
Reusability

Write once, render anywhere across your entire app.

Maintainability

Fix a bug in ProductCard.jsx and all 10 cards update.

Separation of Concerns

Each file has one clear, isolated responsibility.

Easier Debugging

Errors are localized to specific component files.

What is JSX? (JavaScript XML)

A syntax extension for JavaScript that allows you to write HTML-like markup directly inside your code.

Core Definition

JSX stands for JavaScript XML. It lets us write HTML-like structure directly inside JavaScript files.

Here is how Vite transforms your JSX into pure JavaScript objects:

↓ Compiles to ↓
Compiled Pure JavaScript

  'h1',
  { className: 'title' },
  'Hello'
);

JSX vs HTML: Essential Differences

Because JSX is JavaScript, certain reserved words and attributes are adapted.

Feature Standard HTML React JSX Why the Difference?
CSS Class Attribute <div class="box"> <div className="box"> class is a reserved keyword in JavaScript (e.g. class Car {}).
Label Target Attribute <label for="email"> <label htmlFor="email"> for is a reserved keyword in JavaScript (e.g. for (let i...)).
Event Handlers onclick="handleClick()" onClick={handleClick} JSX uses camelCase attribute names and passes function references, not string scripts.
Void / Self-Closing Tags <img src="pic.jpg">
<input type="text">		 <img src="pic.jpg" />
<input type="text" />		 JSX follows XML rules: ALL tags must be explicitly closed with a slash (/>).

React Week 1 › JSX › 5 Golden Rules
26 • Rules

The 5 Golden Rules of JSX & Fragments

Strict grammatical rules required for JSX to compile cleanly without parser errors.

The 5 Strict Rules
  • Rule 1: Return a Single Parent Structure: A component cannot return two sibling elements directly.
  • Rule 2: Close All Tags: Tags with no children must be self-closing (<img />, <br />).
  • Rule 3: Use className: Never write class on JSX elements.
  • Rule 4: Use Curly Braces for JS Expressions: Embed variables, math, and logic with { }.
  • Rule 5: camelCase Attributes: tabIndex, autoFocus, aria-label, onClick.
Why One Parent? & React Fragments

In JavaScript, a function can only return one value. You cannot write return x, y;. Similarly, JSX compiles to function calls:

Syntax Error: 2 Roots
// INVALID!
return (
  <h1>Title</h1>
  <p>Text</p>
);
Valid: React Fragment
// VALID! Empty <> tag
return (
  <>
    <h1>Title</h1>
    <p>Text</p>
  </>
);
✓ Fragments (<>...</>) group elements without creating unwanted extra <div> tags in your HTML DOM!

JavaScript Expressions in JSX: The Curly Braces

Using { } to interpolate dynamic values, arithmetic, and object properties.

What CAN Be Embedded Inside { }?

Any valid JavaScript expression (something that resolves to a single value):

React Week 1 › Rendering › Re-rendering
30 • Re-renders

What is Re-rendering & What Causes It?

Why React components run again and how React avoids wasteful DOM rebuilds.

What is a Re-render?

A re-render means React runs your component function again to find out what its JSX output should look like now that data has changed.

CRITICAL DISTINCTION: A re-render does NOT mean React destroys and rebuilds the real browser DOM from scratch! React only modifies the specific text or attribute that changed.
What Triggers a Component to Re-render?
1. State Update (Most Common)

Calling a state setter (e.g. setCount(count + 1)) schedules an immediate re-render.

2. Parent Component Re-rendered

When a parent renders, by default React re-evaluates all children inside that parent.

3. Changed Props / Inputs

When new data arrives from the parent, the child renders with the updated inputs.

React Week 1 › Virtual DOM › Reconciliation
31 • Core Architecture

The Virtual DOM & Reconciliation Algorithm

How React's in-memory UI representation calculates surgical, high-speed DOM updates.

What is the Virtual DOM?

The Virtual DOM (VDOM) is a lightweight in-memory JavaScript representation of the real browser DOM elements.

Correct Definition: Do NOT say "React updates the Virtual DOM instead of the real DOM". Better: "React uses an internal representation of the UI to calculate the minimal necessary updates to the browser DOM."
What is Reconciliation (Diffing)?

Reconciliation is React's "diffing" algorithm that compares the previous Virtual DOM snapshot with the newly calculated Virtual DOM snapshot.

  • Identifies the exact delta (what changed).
  • Batches DOM operations to prevent layout thrashing.
  • Applies only surgical updates to the real browser DOM.
Step-by-Step Update Flowchart
1. Action State Changes setCount(1)
→
2. Execute Component Runs Returns new JSX
→
3. New VDOM New Virtual DOM Snapshot in memory
→
4. Diffing Reconciliation Compares Old vs New
→
5. Commit Surgical Patch Only modified DOM node
React Week 1 › SPA › Definition & Architecture
33 • Architecture

What is a Single Page Application (SPA)?

The modern web architecture where one document is loaded and JavaScript handles navigation.

Definition

A Single Page Application (SPA) is a web application where the browser loads a single HTML file initially, and JavaScript dynamically updates the UI and manages navigation without requesting a full document reload from the server.

Traditional Multi-Page Application (MPA)
1. User requests /about.
2. Full request sent to server.
3. Server prepares brand new HTML file.
4. Browser destroys current page (white flash).
5. Complete document reloaded and repainted.
⚠ Noticeable white blink on every navigation, slower transitions, high server bandwidth.
Single Page Application (React SPA)
1. Initial visit: downloads index.html + React bundle.
2. User clicks /about.
3. JavaScript intercepts URL change.
4. React unmounts <Home /> and mounts <About />.
5. NO full page reload! Instant component swap.
✓ Seamless, app-like transitions with zero white flash. Navigation feels instant!
React Week 1 › CSR › Client-Side Rendering
34 • Rendering Model

What is Client-Side Rendering (CSR)?

When the browser's JavaScript engine builds the UI on the client device.

Definition & Execution Flow

Client-Side Rendering (CSR) means the web server delivers an almost empty HTML container with a JavaScript script tag. The browser executes that JavaScript to construct and render the UI on the client machine.

1. Fetch Empty HTML <div id="root">
→
2. Download JS Bundle React code arrives
→
3. Execute React Runs Builds Virtual DOM
→
4. Visible DOM Populated User sees full app
Benefits of CSR
  • Rich User Experience: Fluid animations, micro-interactions, and instant updates.
  • Reduced Server Load: Server only serves static files or JSON data; user's CPU builds the UI.
  • App-like Feel: Perfect for dashboards, portals, and authenticated SaaS web applications.
Challenges of Pure CSR
  • Initial Load Time: Large JS bundles can cause a brief blank screen on slow mobile networks.
  • SEO Considerations: Search crawlers that don't execute JavaScript see an empty <div id="root">.
  • Ecosystem Solution: Frameworks like Next.js add Server-Side Rendering (SSR) to solve this when SEO is critical.
React Week 1 › Props › Definition & Passing
37 • Data Inputs

What are Props? (Properties)

How parent components pass custom data downward to configure child components.

Core Definition

Props (short for "properties") are read-only inputs passed from a parent component down to a child component, just like arguments passed into a JavaScript function.

Passing Props: Parent → Child
// 1. Parent passes prop 'name'
function App() {
  return (
    <div>
      <User name="Mubashir" />
      <User name="John" />
    </div>
  );
}

// 2. Child receives props object
function User(props) {
  return <h1>Hello, {props.name}!</h1>;
}
Modern Clean Syntax: Destructuring

Instead of repeating props.name everywhere, modern React developers destructure directly in the function parameter:

Destructured Child Component
// Destructure { name } from props
function User({ name, role = "Student" }) {
  return (
    <div>
      <h2>{name}</h2>

React Week 1 › State › Definition & Use Cases
41 • Component Memory

What is State? (Component Memory)

Data that belongs to a component, changes over time, and triggers UI updates.

Core Definition

State is data that is owned and managed internally by a component. When state changes, React automatically re-renders the component to reflect the new data in the browser UI.

Why Not Just Regular Local Variables? If you declare let count = 0 inside a component and do count++, React has no idea the variable changed and will never update the screen! State tells React: "Hey, my data changed, please re-render!"

43 • Comparison Matrix

Props vs State: The Ultimate Comparison

Mastering the clear distinction between external inputs and internal component memory.

Dimension Props (Properties) State
Origin / Source Passed from the parent component downward Created and managed inside the component itself
Mutability Read-Only (Immutable) from child's perspective Mutable via Setter Function (setState)

Yes! A component can receive props from its parent (e.g. maxCount={10}) and simultaneously hold its own state (e.g. count).

State Updates & The Immutability Rule

Why direct mutation breaks React and how to properly update objects and arrays with the spread operator.

What Happens When You Call setCount(1)?
1. Trigger setCount(1) Event handler executes
→
2. Schedule React Schedules Queues re-render
→
3. Re-run Component Runs Calculates new JSX
→
4. Reconcile Diffing Old vs New VDOM
→
5. Commit DOM Updated Only <h1> changes
BAD: Direct State Mutation (Breaks React!) 
// Direct mutation for numbers:

// Direct mutation for objects:
user.name = "John"; // ❌ Same object memory reference!
setUser(user);      // ❌ React thinks nothing changed!
CORRECT: Create a New Object via Spread (...) 
// Use the state setter:
setCount(count + 1); // ✓ Schedules re-render

// Spread operator creates brand new object copy:
setUser({
  ...user,           // Copy all existing fields
  name: "John"       // Override specific field
});
React Week 1 › Lifting State › The Sibling Problem
46 • Problem & Solution

The Shared State Problem

What happens when two sibling components need to share the exact same data?

The Dilemma

Suppose you have an <Input /> component where the user types their name, and a sibling <Display /> component that must show: "Hello, [Name]!" in real time.

In React, sibling components CANNOT talk directly to each other!
Data cannot flow sideways across branches. If state lives inside <Input />, <Display /> cannot read it.
The Stuck State Diagram
App (Parent)
↙               ↘
Input Component
(State trapped here!)
✗ ? ✗
Display Component
(Needs data!)
The Solution: "Lifting State Up"

When two or more components need to share or synchronize state, lift the state up to their nearest common ancestor (in this case, App).
• The common parent holds the single source of truth in its state.
• The parent passes the current value down to <Display /> via props.
• The parent passes an updater callback function down to <Input /> via props.

React Week 1 › Architecture › Unidirectional Flow
48 • Data Architecture

One-Way (Unidirectional) Data Flow

Data moves strictly down via Props; actions and events move strictly up via Callbacks.

The Unidirectional Data Loop
Parent Component
Owns State & Callbacks
Data Flows DOWN ↓ (via Props)
↑ Events Flow UP (via Callbacks)
Child Component
Receives Props & Fires Events
1. Highly Predictable

Because data only moves in one direction, finding where a bug originated is straightforward: trace upwards to find the state owner.

2. Controlled Communication

A child cannot accidentally overwrite parent data. It can only request changes through parent-approved callback functions.

3. Modular Testing

Child components can be tested in complete isolation simply by mocking the props passed to them.

React Week 1 › Optimization › Rendering Hygiene
50 • Best Practices

Preventing Unnecessary Re-renders

Basic architectural habits beginner students should adopt early to keep applications fast.

4 Beginner Best Practices (Week 1 Focus)
  • 1. Keep State as Local as Possible:
    Don't hoist state to the top-level App if only one tiny dropdown needs it. When state is local, only that dropdown re-renders.
  • 2. Split Large Monoliths into Small Components:
    Break a 300-line component into smaller children to limit the re-rendering radius.
  • 3. Avoid Redundant Derived State:
    Never store something in state that can be calculated from existing props/state (e.g. calculate fullName = firstName + ' ' + lastName on the fly!).
  • 4. Component Purity:
    Never modify global variables or execute side effects during the render calculation.
Roadmap Note: Advanced Tools Belong Later!
Do Not Introduce in Week 1:
• React.memo() (Memoizing components)
• useMemo() (Memoizing expensive calculations)
• useCallback() (Memoizing function references)
Students must first master clean component architecture and natural re-renders before prematurely optimizing!

Model Answer: React is an open-source JavaScript library developed by Meta for building user interfaces with reusable components. It is a library (not a framework) because it focuses strictly on the View layer of the application. Developers have total freedom to choose their own routing, state management, and HTTP fetching libraries.
Model Answer: Vite is a modern frontend build tool and dev server. Unlike CRA (which bundled the entire application with Webpack before serving), Vite serves native ES modules on demand using esbuild. This gives near-instant server boot (<200ms) and lightning-fast Hot Module Replacement (HMR). CRA is officially deprecated.
Model Answer: JSX stands for JavaScript XML. It is a syntax extension that allows writing HTML-like markup inside JavaScript. It is NOT HTML; build tools compile JSX into React.createElement(...) JavaScript objects. We use className because class is a reserved keyword in JavaScript.
Model Answer: Props are read-only inputs passed from a parent component down to a child component (unidirectional). State is internal dynamic data owned and managed by the component that changes over time via setter functions. Memory Rule: Props = Inputs from parent; State = Internal changing memory.
Model Answer: The Virtual DOM is a lightweight in-memory JavaScript tree representing the UI. React does NOT rebuild the real DOM! React uses reconciliation (diffing) to compare the old and new Virtual DOMs, and applies surgical, minimal patches to only the exact DOM nodes that changed.
Model Answer: Sibling components cannot communicate sideways. When two or more siblings need the same data, we lift the state up to their nearest common parent. The parent becomes the single source of truth, passing the state down to one child via props, and passing an update callback down to the other child via props.

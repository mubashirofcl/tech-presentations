Section 3: Components › Definition
Fundamental Concept

What is a Component?

"A component is a self-contained, reusable piece of User Interface (UI)."

Core Characteristics of Components
  • Self-Contained: Encapsulates its own markup (JSX), styling, and optional state logic.
  • Reusable: Write once, render a dozen times with different data inputs (props).
  • Composable: Components can be nested inside other components to create complex interfaces.
  • Predictable: Given the same props, a pure component always outputs the same UI markup.

Section 3: Components › Why Components?
Architecture Comparison

Why Divide UI into Components?

Compare a messy monolithic file against modular component separation of responsibilities.

WITHOUT Components: Monolithic Mess 
// ❌ App.jsx — 800 Lines of Unmanageable Code
function App() {
  // 100 lines: Header state & nav code
  // 150 lines: Complex form validation logic
  // 300 lines: Todo list rendering & drag/drop
  // 100 lines: Modal popup handlers
  // 150 lines: Footer & filter buttons
  return (
    <div>...Massive wall of nested HTML tags...</div>
  )
}
  • Impossible to reuse buttons, cards, or inputs across pages.
  • Touching line 400 accidentally breaks line 50.
  • Terrible team collaboration — merge conflicts constantly.
WITH Components: Clean Modular Design 
// ✅ App.jsx — Clean, Declarative & Readable
function App() {
  return (
    <div className="app-container">
      <Header />
      <TodoForm />
      <TodoList />
      <Footer />
    </div>
  )
}
  • Reusability: Use TodoItem 100 times without duplicating code.
  • Maintainability: Edit TodoForm.jsx without worrying about Header.jsx.
  • Separation of Concerns: Each file has one single responsibility.
Key Question to Ask Students

"If the company logo changes tomorrow, in which file would you expect to find the code? Exactly: Header.jsx! That is the power of separation of concerns."

Section 4: Functional Components › Function Declaration
Modern React Syntax

What is a Functional Component?

A functional component is simply a JavaScript function that returns JSX markup.

src/Welcome.jsx
JSX 
// 1. Standard Function Declaration
function Welcome() {
  return <h1>Hello React</h1>;
}

// 2. Export so other files can import and use it
export default Welcome;
Line-by-Line Anatomy
  • function Welcome(): Declares a standard JavaScript function. Notice the capital 'W' (PascalCase).
  • return <h1>...</h1>: Returns JSX markup. This tells React what to render onto the screen.
  • export default Welcome: Makes the component available to be imported by App.jsx or any other component.
Pro-Tip: Functional components are pure JavaScript functions. There are no mysterious frameworks under the hood—if you know JS functions, you know React components!
Teacher Script

Emphasize to students: "Do you see anything fancy here? It's literally just a regular JavaScript function. The only difference is that instead of returning a number or a string, it returns HTML-like JSX."

Section 4: Functional Components › Arrow Syntax
ES6 Arrow Syntax

Arrow Function Components

Modern JavaScript developers frequently use ES6 arrow functions. Both syntaxes are 100% equivalent in React.

src/Welcome.jsx (Arrow Function)
ES6 JSX 
// Arrow function syntax with explicit return
const Welcome = () => {
  return <h1>Hello React</h1>;
};

export default Welcome;

// Or concise implicit return:
// const Welcome = () => <h1>Hello React</h1>;
Which One Should You Use?
  • Function Declaration: function Welcome() { ... } (Hoisted, very beginner-friendly).
  • Arrow Function: const Welcome = () => { ... } (Concise, very popular in modern corporate codebases).
  • Verdict: Both are functional components. Choose one style and stay consistent throughout your team project.
In this course, we use function Welcome() for clarity, but you will encounter both in real jobs.
Teacher Script

Reassure students: "If you see an arrow function in a YouTube video or tutorial, don't panic. It is doing the exact same thing."

Section 4: Functional Components › Import & Render
Component Composition

Using Your Component in App.jsx

Import the component like a module, then invoke it using JSX tag syntax.

src/App.jsx
JSX 
// 1. Import the child component
import Welcome from "./Welcome";

// 2. Render it inside the parent App component
function App() {
  return (
    <div>
      <Welcome />
    </div>
  );
}

export default App;
The 4-Step Lifecycle
1Import: Pull the component into the file via import Welcome from "./Welcome".
2JSX Tag: Write <Welcome /> inside the return block.
3Evaluation: React invokes Welcome() and obtains <h1>Hello React</h1>.
4Render: React injects the resulting DOM elements into the browser.
Self-Closing Tag Note

Remind students that components without inner children can be self-closing: `` instead of ``.

Section 4: Functional Components › Naming Convention
Strict Syntax Rule

Component Naming Rules (PascalCase)

React components MUST always start with an uppercase capital letter. Why?

Correct: Uppercase (PascalCase) 
function Header() {}    // ✅ Correct
function TodoList() {}  // ✅ Correct
function UserCard() {}  // ✅ Correct

// Used in JSX:
<Header />
<TodoList />
<UserCard />

React recognizes uppercase tags as user-defined custom React components.

Incorrect: Lowercase 
function header() {}    // ❌ Bad!
function todolist() {}  // ❌ Bad!
function userCard() {}  // ❌ Bad!

// What happens in JSX:
<header></header>  // React treats this as normal HTML!
<todolist></todolist> // Treated as unknown HTML tag!

Lowercase tags are reserved for standard HTML elements (div, span, button, header).

Common Student Bug

"Students frequently write `function todoItem()`. When they put `` in JSX, nothing renders and no error appears because React literally sends `` into the DOM as an unrecognized HTML tag! Always uppercase."

Section 5: JSX › Introduction
Syntax Extension

Understanding JSX (JavaScript XML)

JSX is a syntax extension that allows us to write HTML-like markup directly inside JavaScript files.

src/User.jsx
JSX 
function User() {
  const name = "Mubashir";
  const role = "MERN Developer";

  // JSX: Looks like HTML, but inside JavaScript!
  return (
    <div className="user-card">
      <h2>{name}</h2>
      <p>{role}</p>
    </div>
  );
}

export default User;
Key Rules of JSX
  • Not a String: JSX is not a string (`"

    "`). It compiles to React.createElement().

  • Single Parent Element: Every component must return a single top-level parent wrapper (or a React Fragment <>...</>).
  • Attribute Differences: Use className instead of class, and htmlFor instead of for.
  • Always Close Tags: Even void elements must be closed: <img />, <input />, <br />.
Why className?

Explain that because JSX is compiled to JavaScript, `class` is already a reserved keyword in JS. Therefore, React chose `className`.

Section 5: JSX › Curly Braces {}
Dynamic Markup

Embedding JavaScript Inside JSX

Use curly braces {} as a portal to execute any valid JavaScript expression right inside your markup.

src/Product.jsx
JSX 
function Product() {
  const name = "Wireless Headphones";
  const price = 1999;
  const discount = 200;

  return (
    <div>
      {/* Outputting strings */}
      <h2>{name}</h2>

      {/* Outputting calculations */}
      <p>Price: ₹{price - discount}</p>

      {/* Calling JS methods */}
      <p>Brand: {name.toUpperCase()}</p>
    </div>
  );
}
What Can Go Inside {}?
  • Variables: {name}, {age}
  • Math & Expressions: {price * 0.18}, {count + 1}
  • Ternary Operators: {isLoggedIn ? "Welcome" : "Please Login"}
  • String Methods: {user.toUpperCase()}
Cannot Go Inside {}: Full statements like if/else, for loops, or variable declarations (const x = 10). Expressions only!
Quick Memory Hook

"Tell students: Think of curly braces in JSX as an open window. Whenever you want to step out of HTML and run pure JavaScript, open the window with `{}`!"

Section 6: Class Components › Class Syntax
Legacy & Enterprise React

What is a Class Component?

Before React Hooks were introduced in 2019, React components were authored using ES6 Classes extending React.Component.

src/WelcomeClass.jsx
CLASS JSX 
import React, { Component } from "react";

// Extends base React.Component class
class Welcome extends Component {
  
  // Mandatory render() lifecycle method
  render() {
    return (
      <h1>Hello from Class Component</h1>
    );
  }

}

export default Welcome;
Core Elements of Class Components
  • class Welcome extends Component: Inherits React's built-in component capabilities like state and lifecycle hooks.
  • render(): The only required method. React calls render() whenever the component needs to generate JSX.
  • Object-Oriented: Relies on the JavaScript this keyword.
Pedagogical Framing

Do NOT tell students that class components are "dead" or "garbage". Frame them as: "Still fully supported, very common in legacy projects and interview questions, but functional components are the modern default."

Section 6: Class Components › this.props
Class Data Access

Accessing Props in Class Components

In class components, props are accessed through the instance property: this.props.

src/UserClass.jsx
JSX 
import React from "react";

class User extends React.Component {
  render() {
    // In class components, use this.props
    return (
      <div>
        <h2>{this.props.name}</h2>
      </div>
    );
  }
}

export default User;
Side-by-Side Mental Comparison
Functional function User(props) { return <h2>{props.name}</h2>; }
Class class User extends React.Component { render() { return <h2>{this.props.name}</h2>; } }

Notice how functional components do not require binding or thinking about the tricky JavaScript this context!

Why People Love Functions

"Ask students: What is the most confusing keyword in JavaScript? Exactly: `this`! Functional components completely remove `this` from your daily React work."

Section 7: Comparison › Real-World Context
Industry Reality

When Will You See Class Components?

Even though we write functional components today, understanding class components is essential for real-world employment.

Real-World Scenarios
  • Existing Company Codebases: Large enterprise companies (fintech, healthcare, e-commerce) have thousands of class components written between 2015 and 2019 that work reliably.
  • Error Boundaries: In modern React, Error Boundaries still require class components (componentDidCatch).

Section 8: Props › Definition & Analogy
Properties & Inputs

What Are Props?

Props (short for Properties) are used to pass data from a parent component down to a child component.

The ID Card Analogy

Imagine an office printing customized employee ID cards.

  • The Component is the blank plastic card design template (has avatar placeholder, name heading, and role badge).
  • The Props are the specific details you feed into that template: Name, Age, Role, and Photo.
<UserCard name="Rahul" role="Developer" />
<UserCard name="Anu"   role="Designer" />
<UserCard name="Arjun" role="Manager" />
Same Component. Different Data. That is component reusability!
Unidirectional Data Flow
Parent
App.jsx
props →
Child
UserCard.jsx
Data in React strictly flows in one direction: from parent to child. Children never alter the parent's data directly.

            Section 8: Props › Destructuring
          


          

            Modern React Idiom
            
Destructuring Props

            
Instead of constantly typing props.name and props.age, unpack props directly in the function parameters.

          


          

            

              

                
                Without Destructuring (Repetitive)
              

              

                
function User(props) {
  return (
    <div>
      <h2>{props.name}</h2>
      <p>{props.age}</p>
      <p>{props.role}</p>
    </div>
  );
}

              

              
Repetitive typing of props. cluttering the JSX.

            


            

              

                
                With Destructuring (Clean & Modern)
              

              

                
// Unpack properties directly in the parameter list
function User({ name, age, role }) {
  return (
    <div>
      <h2>{name}</h2>
      <p>{age}</p>
      <p>{role}</p>
    </div>
  );
}

              

              
Self-documenting: you immediately see what inputs the component requires.

            

          

        


        

          

            JavaScript Refresher

            Section 8: Props › Data Types
          


          

            Syntax Rules
            
Passing Different Prop Data Types

            
Strings use quotes; all other JavaScript types (numbers, booleans, arrays, objects) MUST use curly braces.

          


          

            

              

                
                Parent Passing Different Prop Types
              

              

                
<User
  // 1. String: uses plain quotes
  name="Rahul"

  // 2. Number: MUST use curly braces!
  age={22}

  // 3. Boolean: curly braces or standalone attribute
  active={true}  /* or simply: active */

  // 4. Array: JavaScript array inside {}
  skills={["React", "Node.js", "MongoDB"]}

  // 5. Object: JavaScript object inside {}
  address={{ city: "Bangalore", zip: 560001 }}
/>

              

            


            

              

                
                The Most Common Beginner Mistake: Numbers
              

              

                
// ❌ WRONG: Passes the string "22"
<User age="22" />
// Later: props.age + 1 becomes "221" (String concatenation!)

// ✅ CORRECT: Passes the actual number 22
<User age={22} />
// Later: props.age + 1 becomes 23 (Math addition!)

              

              

                Double Curly Braces {{ }} for Objects: The outer pair is the JSX expression window; the inner pair creates the JavaScript object literal.
              

            

          

        


        

          

            Why double curly braces?
            
"Students always ask: Why are there two curly braces in `style={{ color: 'red' }}`? Explain: Outer `{}` means 'Hey JSX, evaluate JavaScript!' Inner `{}` is the JS object literal."

          

        

      


      
      

        

          

            Section 8: Props › Immutability
          


          

            Cardinal React Rule
            
Props Are Strictly Read-Only

            
A child component must NEVER mutate or reassign the props it receives.

          


          

            

              

                
                NEVER Do This: Mutating Props
              

              

                
function User({ name }) {

  // ❌ FATAL ERROR: Never reassign props!
  name = "Arjun";

  // ❌ NEVER DO THIS: Mutating prop objects
  // props.user.name = "Arjun";

  return <h2>{name}</h2>;
}

              

              
Directly modifying props violates React's unidirectional data contract and causes subtle, hard-to-find state bugs.

            


            

              

                
                The Mental Model
              

              

                

                  1
                  Parent Owns the Data: State lives at the top.
                

                
↓

                

                  2
                  Child Receives Data as Props: Read-only view.
                

                
↓

                

                  3
                  To Change Data: Child notifies parent via callback function!
                

              

            

          

        


        

          

            Teacher Analogy
            
"When your boss gives you a task assignment document, you don't take a marker and change the client's name on the contract. If you need a change, you ask your boss. In React, Parent is the boss."

          

        

      


      

      
      

        

          

            Section 9: Function Props › Callback Props
          


          

            Child-to-Parent Communication
            
Passing Functions as Props

            
How does a child component notify its parent or pass data back up? By invoking a callback function prop!

          


          

            

              

                

                  src/App.jsx (Parent)
                

                

                  PARENT
                  
                

              

              
import Child from "./Child";

function App() {
  // 1. Parent defines the handler function
  function handleMessage(text) {
    console.log("Message from child:", text);
  }

  // 2. Parent passes the function reference as a prop
  return (
    <Child onMessage={handleMessage} />
  );
}

            


            

              

                

                  src/Child.jsx (Child)
                

                

                  CHILD
                  
                

              

              
// 3. Child receives onMessage through props
function Child({ onMessage }) {
  return (
    <button onClick={() => onMessage("Hello Parent")}>
      Send Message
    </button>
  );
}

export default Child;

            

          

        


        

          

            Teacher Script
            
"Notice carefully: We do not pass `handleMessage()`. We pass the function's name `handleMessage` without parentheses. The child will call it later when the button is clicked!"

          

        

      


      
      

        

          

            Section 9: Function Props › Communication Loop
          


          

            Core Mental Model
            
The Parent ↔ Child Communication Loop

            
Mastering this loop is the single most important milestone before building the Todo application.

          


          

            

              

                
Parent (App)

                
Owns State & Logic

                
Defines handleAction()

              


              

                

                  1. Passes function as prop: onAction={handleAction} →
                  

                


                

                  

                  ← 2. Child calls onAction("data") on user click
                

              


              

                
Child Component

                
Renders UI & Buttons

                
Fires callback on event

              

            

          


          

            

              

                
                Why Does React Do This?
              

              

                Because single source of truth! If 5 different child components could directly mutate the parent's data at will, debugging state changes would become a nightmare. Passing callback functions keeps the parent in absolute control.
              

            


            

              

                
                Naming Convention Tip
              

              

                By convention, function props are prefixed with on (e.g. onAddTodo, onDelete), while the actual handler function in the parent is named with handle (e.g. handleAddTodo).

            Section 11: State › addTodo Function
          


          

            State Immutability
            
Adding a Todo with Array Spread (...)

            
Never use todos.push()! In React, always create a brand-new array using the spread operator.

          


          

            

              

                

                  src/App.jsx (addTodo)
                

                

                  IMMUTABLE
                  
                

              

              
function addTodo(title) {
  // 1. Create new todo object with unique ID
  const newTodo = {
    id: Date.now(),       // Timestamp as unique ID
    title: title,
    completed: false
  };

  // 2. Update state by creating a new array
  setTodos((prevTodos) => [
    ...prevTodos,        // Copy all existing todos
    newTodo              // Append the new item
  ]);
}

            


            

              

                
                The 3-Step Spread Process
              

              

                
1Existing Array: prevTodos holds existing tasks.

                
2Copy with ...: [...prevTodos] creates a shallow copy.

                
3Append & Return: [...prevTodos, newTodo] produces the new state array!

              

              

                Fatal Beginner Mistake: prevTodos.push(newTodo) mutates the existing array in-place. React will NOT detect the change and will NOT re-render!
              

            

          

        


        

          

            Why Date.now()?
            
"Explain that `Date.now()` gives the number of milliseconds elapsed since 1970. Since time only moves forward, every time user adds a todo, `Date.now()` produces a unique number."

          

        

      


      
      

        

          

            Section 11: State › TodoForm
          


          

            Controlled Input & Events
            
Building TodoForm.jsx

            
Captures user input with controlled state, handles submit, validates, and notifies App via onAddTodo.

          


          

            

              

                

                  src/components/TodoForm.jsx
                

                

                  JSX
                  
                

              

              
import { useState } from "react";

function TodoForm({ onAddTodo }) {
  const [title, setTitle] = useState("");

  function handleSubmit(e) {
    e.preventDefault();       // Prevent browser page reload

    // Validation: ignore empty input
    if (!title.trim()) return;

    // Call the parent function passed via props!
    onAddTodo(title);

    // Clear the input field after adding
    setTitle("");
  }

  return (
    <form onSubmit={handleSubmit}>
      <input
        value={title}
        onChange={(e) => setTitle(e.target.value)}
        placeholder="What needs to be done?"
      />
      <button type="submit">Add Task</button>
    </form>
  );
}

export default TodoForm;

            


            

              

                
                Key Mechanics Taught Here
              

              
    
                
  • Controlled Input: value={title} synchronizes the input element's text directly with React state.
    • 
                
  • onChange: Fires whenever user types, calling setTitle(e.target.value).
    • 
                
  • e.preventDefault(): Standard HTML forms refresh the entire page upon submission. We prevent that in Single Page Apps!
    • 
                
  • Callback Execution: onAddTodo(title) sends the string back up to App.jsx.
    • 
              

            

          

        


        

          

            Teacher Script
            
"Ask students: What happens if we omit e.preventDefault()? The whole page reloads, our React state is wiped clean, and our task disappears! Always preventDefault() on forms in React."

            Section 11: State › deleteTodo Function
          


          

            Immutable Removal
            
Deleting a Todo with Array.filter()

            
filter() returns a brand new array containing all items that DO NOT match the deleted ID.

          


          

            

              

                

                  src/App.jsx (deleteTodo)
                

                

                  FILTER
                  
                

              

              
function deleteTodo(id) {
  // Keep every todo whose ID is NOT equal to the targeted ID
  setTodos((prevTodos) =>
    prevTodos.filter((todo) => todo.id !== id)
  );
}

            


            

              

                
                How .filter() Works Under the Hood
              

              
    
                
  • Suppose todos has IDs: [1, 2, 3].
    • 
                
  • User clicks delete on Todo #2 (id = 2).
    • 
                
  • Item 1: 1 !== 2 → true (Kept in new array).
    • 
                
  • Item 2: 2 !== 2 → false (Excluded from new array!).
    • 
                
  • Item 3: 3 !== 2 → true (Kept in new array).
    • 
                
  • New Array: [Item 1, Item 3]. State updates cleanly!
    • 
              

            

          

        


        

          

            Why not splice()?
            
"Remind students: `splice()` modifies the original array in place (mutation). `filter()` creates a new array without touching the old one (immutability). React requires immutability."

            Section 11: State › toggleTodo Function
          


          

            Immutable Transformation
            
Toggling Completion with Array.map()

            
Flip the completed boolean immutably using object spread.

          


          

            

              

                

                  src/App.jsx (toggleTodo)
                

                

                  MAP & SPREAD
                  
                

              

              
function toggleTodo(id) {
  setTodos((prevTodos) =>
    prevTodos.map((todo) =>
      todo.id === id
        ? { ...todo, completed: !todo.completed }
        : todo
    )
  );
}

            


            

              

                

                  src/components/TodoItem.jsx (Toggle Button)
                

                

                  JSX
                  
                

              

              
<div className={`todo-item ${todo.completed ? "done" : ""}`}>
  <span>{todo.title}</span>

  <button onClick={() => onToggleTodo(todo.id)}>
    {todo.completed ? "Undo" : "Complete"}
  </button>
</div>

            

          

          

            Ternary Operator Explained: If todo.id === id matches, return a new object with completed: !todo.completed. Otherwise, return the unchanged todo.
          

        


        

          

            Teacher Script
            
"Point out `!todo.completed`. If it was true, it becomes false. If false, it becomes true. Clean, elegant, and 100% immutable."

            Section 13: Traps › 7 Fatal Mistakes
          


          

            Debugging Guide
            
7 Common Beginner Mistakes & Fixes

            
Learn the 7 most common traps so you can debug your code in seconds instead of hours.

          


          

            

              

                
                The Traps
              

              
    
                
  • 1. Lowercase Component: function user() (React ignores it as custom component).
    • 
                
  • 2. Direct Prop Mutation: props.name = "Rahul" (Props are read-only!).
    • 
                
  • 3. Missing Key in .map(): Causes subtle rendering and input focus bugs.
    • 
                
  • 4. Invoking Handlers in JSX: onClick={deleteTodo(id)} executes immediately!
    • 
                
  • 5. Forgetting Export or Import: Component fails to load with "not found" error.
    • 
                
  • 6. Incorrect Relative Paths: Typing ./Header instead of ./components/Header.
    • 
                
  • 7. Monolithic App.jsx: Stuffing 600 lines of UI inside one single file.
    • 
              

            


            

              

                
                The Instant Fixes
              

              
    
                
  • 1. Always PascalCase: Name components User, Header, TodoList.
    • 
                
  • 2. Treat Props as Immutable: Pass callbacks up to the owner of state.
    • 
                
  • 3. Add Unique Key: Always add key={item.id} on outer tag in .map().
    • 
                
  • 4. Wrap in Arrow Function: Write onClick={() => deleteTodo(id)}.
    • 
                
  • 5. Export Default: Add export default ComponentName at the bottom.
    • 
                
  • 6. Verify Relative Path: Check folder location in VS Code sidebar.
    • 
                
  • 7. Modularize: Keep components under 50-80 lines of clean JSX.
    •

            Section 14: Practice › Find the Error
          


          

            Interactive Challenge 2
            
Find the Error

            
Identify the bug in this beginner React component snippet.

          


          

            

              
function userCard() {
  return <h1>User</h1>;
}

// Used in App:
<userCard />

            


            

              
              

                
Error: The component name userCard starts with a lowercase u.

                
Consequence: React will treat <userCard /> as an unknown native HTML element rather than invoking your JavaScript function.

                
Fix: Rename the function and tag to uppercase PascalCase: function UserCard() and <UserCard />.

              

            

          

        


        

          

            Teacher Script
            
"Ask students: Does JavaScript throw a syntax error here? No! That's what makes this bug so dangerous—it fails silently."

            React Day 2 › Final Philosophy
          


          

            The Core Philosophy
            
Think in Components

            

              "Don't memorize React syntax. Understand the data flow."
            

          


          

            

              

                1 UI
              

              
→

              

                2 Components
              

              
→

              

                3 Props
              

              
→

              

                4 State
              

              
→

              

                5 Events
              

              
→

              

                6 Updated UI
              

            


            

              When building any feature in React:
              

              1. Break the UI down into small single-responsibility components.
              

              2. Pass data down cleanly using props.
              

              3. Keep state minimal and lifted up to the common ancestor.
              

              4. Pass callback functions down to handle user interactions!

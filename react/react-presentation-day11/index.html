Core Architecture

Understanding Redux Data Flow

Redux strictly follows a predictable, one-way (unidirectional) data flow. State always flows in a single direction through well-defined stages.

Step 1 User Interaction User clicks "Increment" button in UI
→
Step 2 Dispatch Action dispatch({ type: 'increment' })
→
Step 3 Reducer Executes Calculates: count + 1
→
Step 4 Store Updates Holds new state: { count: 1 }
→
Step 5 React UI Updates Component re-renders with new count
Current Stage: 1. User Interaction — The user initiates an event by clicking a button.
🔍 Why Unidirectional Flow?

In complex applications, two-way data bindings or direct state mutations lead to hard-to-trace bugs. By enforcing a single path, every state transition is traceable, testable, and deterministic.

⚠️ Golden Redux Rule

Components must never modify Redux state directly! Components only dispatch actions. The store passes the action to reducers, which produce the new state.

Redux Concepts • Part 1

What Is an Action?

An action is a plain JavaScript object that describes something that happened in the application. It represents the intention to change state.

📋 Real-World Application Events
  • 1 Increment the counter
  • 2 Decrement the counter
  • 3 Add a product to the cart
  • 4 Remove a product from the cart
  • 5 Log in a user with credentials
💡
Key Takeaway: An action does not modify the state directly. It only describes an event. Think of it as a message or a news headline sent to the store.
action.js (Simple Action)
// A minimal Redux action requires a 'type' property
const action = {
  type: "counter/increment",
};
actionPayload.js (Action with Payload)
// Actions can carry extra data in a 'payload' property
const action = {
  type: "counter/incrementByAmount",
  payload: 5,
};
type: String identifying the event (convention: "feature/eventName")
payload: The data needed by the reducer to perform the update (number, object, etc.)
Redux Concepts • Part 2

What Is an Action Creator?

An action creator is a JavaScript function that creates and returns an action object. It encapsulates action object creation so you don't write boilerplate everywhere.

actionCreators.js
// 1. Action creator function definition
function increment() {
  return {
    type: "counter/increment",
  };
}

// 2. Calling the function
const result = increment();

// 3. Returns the action object:
// {
//   type: "counter/increment"
// }
🪄 Redux Toolkit Magic

In modern Redux with createSlice(), you never have to write action creators manually! Redux Toolkit automatically generates them from your slice reducer names!

❓ Why Use Action Creators?
1
Prevents Repetitive Code:

Avoid typing { type: "counter/increment" } by hand across dozens of components.

2
Easier to Maintain & Refactor:

If the action structure changes, you only update the function in one location instead of searching the entire codebase.

3
Provides a Consistent, Clean API:

Passing parameters like incrementByAmount(5) is clean, intuitive, and less prone to spelling errors.

📌
When you write dispatch(increment()), the inner increment() is the action creator, and dispatch(...) delivers the created action to the store!
Redux Concepts • Part 3

What Is a Reducer?

A reducer is a pure function that calculates the next state based on the current state and an incoming action: (state, action) ⇒ nextState.

counterReducer.js (Traditional Redux)
// Reducer takes (state, action) and returns new state
function counterReducer(state = 0, action) {
  switch (action.type) {
    case "INCREMENT":
      return state + 1;

    case "DECREMENT":
      return state - 1;

    default:
      // Always return the unchanged state for unknown actions
      return state;
  }
}
⚙️ How Does It Work?
• If current state = 5 and action is { type: "INCREMENT" } → next state is 6.
• If current state = 5 and action is { type: "DECREMENT" } → next state is 4.
• If an unrecognized action arrives → default case safely returns the current state unchanged.
🔒 Immutable Reducer Rules
  • ! Never mutate state directly in traditional Redux (do not do state++).
  • ! Reducers must be pure: no API calls, no timers, no Math.random().
  • ! Same input (state, action) must always produce the exact same output.
Redux Concepts • Part 4

Reducers with Payload

Sometimes an action needs to supply dynamic data rather than just a fixed increment of 1. That data travels inside action.payload.

actionWithPayload.js
// Action carries a payload of 5
const action = {
  type: "counter/incrementByAmount",
  payload: 5,
};
reducerWithPayload.js
function counterReducer(state = 0, action) {
  switch (action.type) {
    case "counter/incrementByAmount":
      // Add the dynamic payload to current state
      return state + action.payload;

    default:
      return state;
  }
}
🧮 Step-by-Step Calculation
Current State
state = 10
Action Dispatched
{ type: "...", payload: 5 }
Next State Calculation
10 + 5 = 15
💡
Key Point: The payload property is the standard convention across Redux to deliver the exact parameters a reducer needs for the update.
Redux Concepts • Part 5

What Is the Redux Store?

The Redux store is the central container holding the entire application's state tree. There is only one store in a Redux application (Single Source of Truth).

stateShape.json
// Example centralized state tree in the store
{
  counter: {
    count: 5
  },
  cart: {
    items: []
  }
}
src/app/store.js
import { configureStore } from "@reduxjs/toolkit";

const store = configureStore({
  reducer: {
    counter: counterReducer,
  },
});
🏛️ 4 Primary Responsibilities of the Store
1
Holds Application State:

Stores the complete global state object in memory.

2
Dispatches Actions:

Provides store.dispatch(action) to trigger state updates.

3
Executes Reducers:

Routes dispatched actions through registered reducer functions.

4
Notifies Subscribers:

Notifies React Redux when state updates so UI re-renders instantly.

📌
Important: configureStore() sets up the store, wires up the reducer map, and pre-configures Redux DevTools automatically.

Let's walk through what happens behind the scenes when a user clicks the "Increment" button in our Counter application.

Initial State Store State { counter: { count: 0 } }
→
Step 1: Action Dispatch Action dispatch(increment())
→
Step 2: Reducer Reducer Runs state.count += 1
→
Step 3: Store State Updated { counter: { count: 1 } }
→
Step 4: UI React UI Shows Count: 1
Initial State: The store holds the starting state { counter: { count: 0 } }.
Action → Reducer → Store Update → UI Update
Modern Redux Architecture

Traditional Redux vs Redux Toolkit

In traditional Redux, developers wrote action types, action creators, and reducer switch statements separately across multiple files. Redux Toolkit (RTK) streamlines this entirely.

Feature Traditional Redux Redux Toolkit (RTK)
Action Types Manual Define constant strings like const INCREMENT = 'INCREMENT' Automatic Generated automatically using slice name + reducer name
Action Creators Manual Write separate functions returning { type: ... } Automatic Generated directly from slice reducer functions
Reducer Logic Switch Cases Complex switch statements with default cases Slice Object Clean, focused functions inside createSlice()
State Immutability Manual spread Must write { ...state, count: state.count + 1 } Immer Built-in Safe "mutating" syntax like state.count += 1
Boilerplate Code Heavy, repetitive, split across 3+ files Minimal, concise, everything together in 1 slice file
✨
Recommended Approach: For all modern React applications, Redux Toolkit is the official, industry-standard way to write Redux logic.
💡
Crucial Note: Redux Toolkit does not replace actions, reducers, or the store. It simply makes them significantly faster and safer to build!
Implementation • Step 1

Creating a Counter Slice

A slice bundles the slice name, initial state, reducer functions, and automatically generated action creators together into a single file.

src/features/counter/counterSlice.js
import { createSlice } from "@reduxjs/toolkit";

const counterSlice = createSlice({
  name: "counter",

  initialState: {
    count: 0,
  },

  reducers: {
    increment: (state) => {
      state.count += 1;
    },

    decrement: (state) => {
      state.count -= 1;
    },

    reset: (state) => {
      state.count = 0;
    },

    incrementByAmount: (state, action) => {
      state.count += action.payload;
    },
  },
});

// 1. Export auto-generated action creators
export const {
  increment,
  decrement,
  reset,
  incrementByAmount,
} = counterSlice.actions;

// 2. Export slice reducer for store configuration
export default counterSlice.reducer;
🔍 Anatomy of createSlice()
  • 1 name: Prefix used to namespace generated action types.
  • 2 initialState: The starting state object for this slice.
  • 3 reducers: Functions defining state transitions.
  • 4 slice.actions: Auto-generated action creators.
  • 5 slice.reducer: The combined reducer passed to the store.
🛡️ Why is state.count += 1 Safe?

Redux Toolkit uses Immer internally. Immer detects changes to draft state and automatically converts them into a fresh immutable copy behind the scenes!

Implementation • Step 2

Understanding Generated Actions

Redux Toolkit uses the convention: [slice_name]/[reducer_name] to generate unique action types automatically.

generatedActions.js
// Calling:
increment();

// Automatically generates:
{
  type: "counter/increment"
}

// Calling with argument:
incrementByAmount(5);

// Automatically generates:
{
  type: "counter/incrementByAmount",
  payload: 5
}
💡
Any argument you pass into an RTK action creator function like incrementByAmount(5) automatically becomes the action's payload!
📋 Reducer to Action Creator Mapping
Reducer Function Generated Action Creator Generated Action Type
increment increment() "counter/increment"
decrement decrement() "counter/decrement"
reset reset() "counter/reset"
incrementByAmount incrementByAmount(5) "counter/incrementByAmount"
🚀 Importing in Components

Because action creators are exported as named exports from counterSlice.js, any component simply imports the ones it needs and passes them to dispatch()!

Implementation • Step 3

Configuring the Redux Store

The store registers and combines slice reducers into a single state tree using configureStore().

src/app/store.js
import { configureStore } from "@reduxjs/toolkit";

// Import the default reducer exported from counterSlice
import counterReducer from "../features/counter/counterSlice";

export const store = configureStore({
  reducer: {
    counter: counterReducer,
  },
});
🔍 Detailed Explanation
  • 1
    configureStore(): Creates and initializes the Redux store with built-in development middleware and DevTools support.
  • 2
    reducer: { counter: counterReducer }: Maps the counter state slice to the counterReducer.
  • 3
    State Tree Structure: The resulting state object holds: 
    { counter: { count: 0 } }
📍 How to Select This Value

Because the reducer key is named counter, you select the count property in React using: state.counter.count

Implementation • Step 4

Dispatching Actions from React

React components use two primary hooks from react-redux: useSelector() to read state and useDispatch() to trigger actions.

src/components/Counter.jsx
import { useSelector, useDispatch } from "react-redux";

import {
  increment,
  decrement,
  reset,
  incrementByAmount,
} from "../features/counter/counterSlice";

function Counter() {
  // 1. Read state from the Redux store
  const count = useSelector(
    (state) => state.counter.count
  );

  // 2. Get the dispatch function
  const dispatch = useDispatch();

  return (
    <div>
      <h2>Count: {count}</h2>

      <button onClick={() => dispatch(increment())}>
        Increment
      </button>

      <button onClick={() => dispatch(decrement())}>
        Decrement
      </button>

      <button onClick={() => dispatch(reset())}>
        Reset
      </button>

      <button onClick={() => dispatch(incrementByAmount(5))}>
        Increment by 5
      </button>
    </div>
  );
}

export default Counter;
⚡ useDispatch() Hook

Returns the Redux dispatch function instance. Calling dispatch(action) delivers the action to the store so the reducer can run.

dispatch(increment())
👁️ useSelector() Hook

Takes a selector function (state) => state.counter.count and extracts the required data. Automatically subscribes the component to store updates!

const count = useSelector(s => s.counter.count)
💡
When state.counter.count changes, useSelector detects it and triggers a React re-render for this component only.
State Lifecycle Walkthrough

How Does the Store Update the UI?

Scenario: The current counter displays 10. The user clicks "Increment by 5". Trace the exact step-by-step path.

1. Button Click Click "Increment by 5" User fires onClick event
→
2. Dispatch dispatch(...) dispatch(incrementByAmount(5))
→
3. Action Object Action with Payload { type: "...", payload: 5 }
→
4. Reducer Reducer Runs 10 + 5 = 15
→
5. Store Store Holds 15 { counter: { count: 15 } }
→
6. useSelector useSelector Notified Extracts count: 15
→
7. UI Re-render Updated UI Screen displays Count: 15
Stage 1: Button Click — The user clicks the Increment by 5 button in the component.
✨ Predictability Guaranteed

Every state update follows this identical chain. No matter if the state holds a single number, a shopping cart, or a massive dashboard — the flow remains 100% predictable.

⚡ Performance Optimization

useSelector() compares previous selected values with current values using reference equality. Only components whose selected slice has actually changed re-render!

Classroom Troubleshooting

Common Mistakes and Best Practices

Avoid these frequent beginner hurdles and follow battle-tested Redux conventions to keep your state predictable and maintainable.

❌ Common Beginner Mistakes
  • 1
    Forgetting <Provider store={store}>:

    React Redux hooks will crash with "could not find react-redux context value".

  • 2
    Forgetting to Register Reducer in configureStore:

    Your actions will dispatch without error, but state will remain undefined.

  • 3
    Using Incorrect State Path in useSelector:

    Writing state.count instead of state.counter.count.

  • 4
    Forgetting to Call dispatch():

    Writing onClick={() => increment()} instead of onClick={() => dispatch(increment())}.

  • 5
    Importing Action from Wrong File:

    Always import action creators from the corresponding slice file.

✅ Essential Best Practices
  • 1
    Use Redux Toolkit for All New Apps:

    Reduces boilerplate by 75% and prevents accidental state mutation.

  • 2
    Keep Related Logic Inside One Slice:

    Co-locate initialState, reducers, and actions together in featureSlice.js.

  • 3
    Use Descriptive Action & Reducer Names:

    Names like incrementByAmount or addToCart make Redux DevTools logs easy to read.

  • 4
    Keep Reducers Pure & Focused:

    Reducers should only calculate the next state. No async API calls or side effects inside.

  • 5
    Keep Local UI State in React (useState):

    Dropdown toggles, form input focus, and temporary hover states don't need to be in Redux.

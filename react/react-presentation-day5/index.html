Section 1 • React Hooks

What Are React Hooks?

Special built-in functions that give functional components superpowers

📖
Definition: React Hooks are special functions (starting with use) that allow functional components to "hook into" React features like state and lifecycle capabilities without writing class components.
⚛️ Common React Features Hooks Provide
  • State: useState → Remembering changing values (Today's focus!)
  • Side Effects: useEffect → Fetching data, subscriptions
  • Global Context: useContext → Shared app themes/auth
  • DOM References: useRef → Accessing direct DOM nodes
All Hooks start with the prefix use...
Counter.jsx — A Taste of Hooks 
// 1. Import Hook from react
import { useState } from "react";

function Counter() {
  // 2. Call Hook at top of component
  const [count, setCount] = useState(0);

  return (
    <h2>{count}</h2>
  );
}
Evolution of React

Why Were Hooks Introduced?

Moving from complex class components to simple, functional programming

📜 Before Hooks (React < 16.8)

To use state, developers were forced to write Class Components:

  • Complex this.state and this.setState
  • Confusing JavaScript this binding in constructors
  • Verbose boilerplate code for simple state values
  • Difficult to share and reuse logic between components
✨ With Hooks (Modern React)

Hooks allow plain functional components to manage state directly:

  • No class syntax, no this keyword confusion
  • Simpler, shorter, more readable code
  • Easy to organize related logic together
  • Components remain pure JavaScript functions
💡
Important: Hooks do not replace React components! They enhance functional components with built-in React capabilities.

Functional Components Before State

Real applications require remembering data that changes:

Section 2 • State

What Is State in React?

A component's private, mutable memory that controls what is rendered

📦
Definition: State is data that belongs to a component and can change over time. When state changes, React automatically re-renders the component to update the UI.

Core Distinction

Props vs State

Understanding the two fundamental ways data flows in React

Feature Props (Properties) 📨 State (Component Memory) 🧠
Source Passed from parent component Defined and managed inside component
Mutability Read-only (immutable by child) Can be updated via setter function
Purpose Used to configure & communicate Used to track data that changes over time
Analogy Like function arguments passed in Like local variables inside a function
Props vs State in Action 
function User({ name }) {          // 👈 'name' is a PROP (passed from parent)
  const [age, setAge] = useState(20); // 👈 'age' is STATE (component's own data)

  return <h2>{name} - {age}</h2>;
}
Under The Hood

Why Normal Variables Fail in React

Why let count = 0 does not update the screen

❌ The Broken Approach (Plain Variable) 
let count = 0;

function Counter() {
  const handleClick = () => {
    count++; // Variable changes in memory...
    console.log(count); // Logs: 1, 2, 3
  };

  // But React NEVER re-renders! Screen stays 0!
  return <button onClick={handleClick}>{count}</button>;
}

React doesn't watch plain variables. It has no idea the variable changed!

✅ The React State Approach

React needs a formal contract to manage changing data:

  • Preserve value: Keep the data between renders (plain variables get wiped on each render).
  • Notify React: Calling setCount() triggers React's internal scheduler.
  • Re-render DOM: React calls the component again and updates the screen.
That is exactly what useState() does!
Section 3 • useState

What Is useState?

The fundamental React Hook for declaring and updating component state

💡
useState() is a built-in Hook from React. It returns an array with exactly two elements: the current state value, and a function to update it.
const [count, setCount] = useState(0);
↑ count Current state value
↑ setCount Updater function
↑ 0 Initial value
📦 JavaScript Array Destructuring

useState(0) returns an array like [0, function]. Using JavaScript array destructuring [count, setCount] allows us to give custom names to both items in one clean line.

Understanding the 3 Parts of useState()

🔍 1. The State Variable (count)

This holds the current value of the state during the current render. In your JSX, you display this value using curly braces: <h2>{count}</h2>. React ensures this value persists across component renders!

💡
Convention: By React naming convention, if the state variable is named xyz, the setter is always named setXyz (e.g. name → setName, isOpen → setIsOpen).

Lifecycle

How State Updates Work Step-by-Step

The 5-phase re-rendering lifecycle triggered on every state change

1. User Event
User clicks button
→
2. Setter Called
setCount(count + 1)
→
3. State Changes
React stores new value
→
4. Re-render
Function runs again
→
5. DOM Updates
New number appears on screen
💡
Re-render Meaning: When React re-renders, it simply calls your component function Counter() again. On this second run, useState(0) returns the updated value (1) instead of the initial value (0)!
Code Best Practice

Separating Event Handlers from JSX

Creating named helper functions for cleaner and more readable components

⚠️ Inline Arrow Function

Putting logic directly in the onClick prop can get messy:

// Can become hard to read when logic grows:
<button onClick={() => setCount(count + 1)}>
  Increase
</button>
✨ Named Handler Function (Recommended)

Declare the function above the return statement:

const increase = () => {
  setCount(count + 1);
};

// Clean and easy to read:
<button onClick={increase}>Increase</button>
🚨
Beginner Warning: Pass the function reference onClick={increase}. DO NOT call it directly: onClick={increase()}! Calling it with parentheses will execute it immediately on render, causing an infinite re-render loop!

Immutability

Updating Array State: Spread Operator

Never mutate arrays with .push() — always create a brand new array!

SkillsList.jsx 
const [skills, setSkills] = useState([]);

const addSkill = (newSkill) => {
  // ❌ WRONG: skills.push(newSkill);

  // ✅ CORRECT: Spread old array into a new array!
  setSkills([...skills, newSkill]);
};
⚡ Interactive Array State Demo
Current Array: []
Rendered List:
No skills added yet.
The spread operator (...skills) copies all existing items into a new array!
Object Immutability

Updating Object State

Copying existing properties with spread and overriding only what changed

UserProfile.jsx 
const [user, setUser] = useState({
  name: "Rahul",
  age: 21
});

// ❌ WRONG: user.name = "Arun"; (Mutating state directly)

// ✅ CORRECT: Copy all fields, then override 'name'
const updateName = () => {
  setUser({
    ...user,        // Copies { name: "Rahul", age: 21 }
    name: "Arun"   // Replaces only 'name' with "Arun"
  });
};
🔍 Why Is Spread Necessary?

In React, setUser() does NOT automatically merge objects!

If you write setUser({ name: "Arun" }) without ...user, the age property will be completely wiped out!

✨ Resulting Object
{ name: "Arun", age: 21 }
Advanced Pattern

Functional State Updates (prev → prev + 1)

When the new state depends directly on the previous state value

1️⃣ Direct Value Update
setCount(count + 1);

Fine for simple, single updates. But React state updates are scheduled asynchronously. If multiple updates run close together, count might be stale.

2️⃣ Functional Updater (Reliable)
setCount((prevCount) => prevCount + 1);

React passes the exact guaranteed latest state into your callback function. Always safe, especially when queuing multiple updates!

💡
Rule of Thumb: Whenever your next state calculation relies on the current value (e.g. counters, toggling booleans: setOpen(prev => !prev)), the functional form is the cleanest and most professional React practice.
Mistakes to Avoid

Common useState Mistakes

Never mutate state directly — always use the setter function!

❌ WRONG: Direct Mutation 
// 1. Direct variable re-assignment
count = count + 1;

// 2. Mutating arrays directly
skills.push("React");

// 3. Mutating object fields directly
user.name = "Arun";

React detects changes by checking if the object reference changed. Direct mutations don't trigger re-renders!

✅ CORRECT: Using Setter Function 
// 1. Call setter with new number
setCount(count + 1);

// 2. Create new array with spread
setSkills([...skills, "React"]);

// 3. Create new object with spread
setUser({ ...user, name: "Arun" });

Always pass a brand new value or object through the setter function.

Fundamental Laws

The Two Fundamental Rules of Hooks

Simple guidelines to prevent bugs and ensure React tracks state order correctly

1️⃣ Rule 1: Only Call Hooks at the Top Level

Do NOT call Hooks inside loops, conditions, or nested functions. Always declare them at the very top of your React component: 

// ✅ CORRECT: Top level of component
function App() {
  const [count, setCount] = useState(0);
  // ...
}

// ❌ WRONG: Inside an if condition!
if (isLoggedIn) {
  const [count, setCount] = useState(0); // Breaks!
}
2️⃣ Rule 2: Only Call Hooks from React Functions

Call Hooks only from:

  • React functional components
  • Custom React Hooks (functions starting with use...)

Do not call Hooks inside regular vanilla JavaScript helper functions outside React components.

Keeps Hook order strictly deterministic!
Section 4 • Controlled Components

What Is a Controlled Component?

Form elements whose values are entirely driven by React state

🎯
Definition: A controlled component is a form element (like <input>, <textarea>, or <select>) whose value is controlled by React state rather than the browser DOM.
The Controlled Input Pattern 
const [name, setName] = useState("");

<input
  value={name}                           // 👈 1. Value driven by State
  onChange={(e) => setName(e.target.value)} // 👈 2. User input updates State
/>

React State
↓ value={name}
<input /> on screen
↓ user types → onChange
setName(e.target.value)
↓ state updates & re-renders

Who controls the truth: the browser DOM or React state?

<input />

🎯 What is `e`?

e is the event object created automatically by React when an event fires. It wraps the browser's native event.

🔑 What is `e.target.value`?

e.target refers to the input element itself, and .value is the exact text currently sitting inside that element.

Section 5 • Controlled Forms

Handling Multiple Form Fields in One State

Grouping related inputs into a single state object to avoid declaring 10 useState hooks

StudentRegistration.jsx — Single Form State 
// 1. Single state object for all inputs
const [form, setForm] = useState({
  name: "",
  email: ""
});

// 2. Update specific field while preserving the rest using spread operator:
<input
  value={form.name}
  onChange={(e) => setForm({ ...form, name: e.target.value })}
/>

<input
  value={form.email}
  onChange={(e) => setForm({ ...form, email: e.target.value })}
/>
✨ Clean Scalability

As your form expands to 6 or 10 inputs, managing one state object is much easier than writing 10 individual useState calls!

⚠️ Crucial Rule

Always include ...form so the other fields are not erased when one field updates.

Form Submission

Handling Form Submit & preventDefault()

Stopping browser page reload so React can handle the submission smoothly in JavaScript

Handling Submit in React 
const handleSubmit = (e) => {
  // 🛑 PREVENT default browser form reload:
  e.preventDefault();

  // Process data in React state:
  console.log("Submitting student data:", form);
};

return (
  <form onSubmit={handleSubmit}>
    {/* inputs here */}
    <button type="submit">Register Student</button>
  </form>
);
🛑 Why `preventDefault()`?

By default, HTML forms submit by making an HTTP GET/POST request and reloading the entire browser page.

A page reload wipes all your React state in memory! e.preventDefault() stops the reload so React stays in control.

💡
Always attach onSubmit to the <form> element, not onClick on the button! This ensures pressing Enter also submits.
Complete Component

Complete Controlled Form Example

A full working component putting all state, controlled inputs, and submit handling together

StudentForm.jsx 
import { useState } from "react";

function StudentForm() {
  const [name, setName] = useState("");
  const [course, setCourse] = useState("");

  const handleSubmit = (e) => {
    e.preventDefault();
    console.log({ name, course });
  };

  return (
    <form onSubmit={handleSubmit}>
      <input
        value={name}
        onChange={(e) => setName(e.target.value)}
        placeholder="Enter name"
      />

      <select value={course} onChange={(e) => setCourse(e.target.value)}>
        <option value="">Select course</option>
        <option value="MERN">MERN</option>
        <option value="Python">Python</option>
      </select>

      <button type="submit">Submit</button>
    </form>
  );
}

Troubleshooting

Common Beginner Mistakes & Fixes

6 critical mistakes students frequently encounter with React state & forms

1️⃣ Forgetting Import

Using useState without importing causes: ReferenceError: useState is not defined.

Fix: import { useState } from "react";
2️⃣ Checkbox `e.target.value`

Reading .value on checkbox returns the string "on" instead of true/false.

Fix: Use e.target.checked!
3️⃣ Direct State Mutation

Writing count++ or array.push() fails to trigger re-renders.

Fix: Always call setter function!
4️⃣ Missing `value` Prop

Omitting value={name} turns the input uncontrolled.

Fix: Always bind value={state}!
5️⃣ Missing `onChange`

Setting value={name} without onChange locks the input read-only!

Fix: Provide onChange updater!
6️⃣ Missing `preventDefault()`

Submitting causes a full browser page reload and resets all state.

Fix: Call e.preventDefault() first!

Interactive Review

Quick Classroom Quiz (10 Questions)

Test your mastery of React Hooks, useState, and controlled components

1. What is a React Hook?
A special function (starting with use...) that allows functional components to use React features like state without writing classes.
2. What is state in React?
A component's internal data that can change over time. When state updates, React re-renders the component.
3. What does useState() return?
An array with exactly two items: the current state value and a function to update that state value.
4. What is the purpose of the setter function (e.g. setCount)?
To update the state variable and tell React to schedule a component re-render so the UI reflects the new data.
5. Why shouldn't we directly modify state (e.g. count = count + 1)?
Direct mutation does not notify React, meaning React will never re-render and the screen will remain outdated.
6. What is a controlled component?
An input element whose current value is governed entirely by React state via value and updated via onChange.
7. What is e.target.value?
The current string content typed by the user inside the target DOM form element.
8. What is e.target.checked used for?
Reading the boolean status (true or false) of a checkbox input element.
9. Why do we use e.preventDefault() in form submission?
To prevent the browser from reloading the page, which would erase all React component state in memory.
10. What happens when state changes?
React calls the component function again (re-renders) and updates the Virtual DOM and browser DOM to match the new state.

Section 1 — React Lifecycle

What Is the React Lifecycle?

A React component goes through different stages during its existence on screen.

From Birth to Death of a Component

Just like humans are born, grow, and eventually pass away, every React component has a distinct lifecycle:

  • 1 Birth (Mounting): The component is created and inserted into the browser DOM.
  • 2 Growth / Changes (Updating): The component re-renders when state or props change.
  • 3 Removal (Unmounting): The component is destroyed and removed from the DOM.

Component Lifecycle Flow

Component Created
↓
Mounting (Added to DOM)
↓
Updating (State / Props change)
↓
Unmounting (Removed from DOM)
↓
Component Destroyed 🛑

Stage 2: Updating

A component updates and re-renders whenever its state or incoming props change.

  • 3 Parent Re-render: When parent updates, children re-render by default.

Section 2 — Side Effects

What Is a Side Effect?

A side effect is any operation that reaches outside the pure rendering calculation of JSX.

Pure Rendering vs. Side Effects

In React, a component's primary job is to be a pure function: take props and state, and return JSX. Anything else that interacts with the outside world is a side effect.

Pure JSX Calculation: 
return <h1>Count: {count}</h1>;
Side Effect Example: 
document.title = `Count: ${count}`;

Common Examples of Side Effects

  • 🌐 Data Fetching: Calling a backend API with fetch() or Axios.
  • ⏱️ Timers: Starting a setInterval or setTimeout.
  • 🏷️ Document Title: Changing the browser tab title via document.title.
  • 👂 Event Listeners: Listening to window resize, scrolling, or keypresses.
  • 💾 Local Storage: Reading or saving data to localStorage.
Section 2 — Side Effects

Why Do We Need useEffect?

React components describe the UI, but applications need to synchronize with external systems.

The Synchronization Problem

If you run side effects directly inside the component body, they execute during rendering, which can slow down the UI, cause memory leaks, or trigger infinite re-render loops!

❌ NEVER do this directly in render:
setInterval(() => { ... }, 1000);
(Creates a new timer on EVERY single re-render!)
✅ Wrap side effects in useEffect():
React waits until the DOM is safely painted, then runs the effect cleanly!

Bridge to External Systems

React Component (State & UI)
↕ synchronized by useEffect()
External Systems
Browser Title • Timers • Window Events • Web APIs
Section 2 — Side Effects

What Is useEffect?

useEffect is a built-in React Hook that lets you synchronize a component with an external system.

use-effect-syntax.js
import { useEffect } from "react"; useEffect(() => { // 1. Side effect logic goes here return () => { // 2. Optional cleanup logic }; }, [ /* 3. Dependency array */ ]);

Three Core Parts of useEffect

  • 1 The Effect Function: The callback function containing the side-effect logic to execute after render.
  • 2 The Cleanup Function: An optional function returned to tear down timers or listeners before unmount or next effect.
  • 3 The Dependency Array: An array of reactive values that tells React when to re-execute this effect.
Section 2 — Side Effects

Basic useEffect: No Dependencies

When called without a dependency array, useEffect runs after EVERY completed render.

App.jsx
import { useEffect } from "react"; function App() { useEffect(() => { console.log("Effect executed"); }); // Notice: No array here! return <h1>Hello React</h1>; }

Execution Flow

Component Renders
↓
DOM Updated on Screen
↓
Effect Runs: "Effect executed"

⚠️ Be careful: Because this runs on every render, updating state inside this effect will cause an infinite loop!

Section 2 — Side Effects

useEffect With Empty Array []

Passing an empty dependency array [] tells React to run the effect only once after mounting.

on-mount.js
useEffect(() => { console.log("Component mounted"); }, []); // Empty dependency array []

Why Does It Only Run Once?

The dependency array is empty, which means there are zero reactive values that can ever change. Therefore, React never re-runs the effect after subsequent renders.

Important Strict Mode Note 🔍

In development mode with React Strict Mode enabled:

Mount ➔ Unmount ➔ Mount

React intentionally mounts, unmounts, and re-mounts your component one extra time in local development to help you verify that your cleanup logic works properly!

Section 2 — Side Effects

useEffect With Dependencies [count]

When specific variables are listed in the dependency array, React only re-runs the effect when those values change.

dependency-example.js
useEffect(() => { console.log("Count changed:", count); }, [count]); // Re-runs ONLY when count changes!

Step-by-Step State Tracking

Mount: count = 0 ➔ Effect runs (Initial)
↓
User clicks: count = 1 ➔ Value changed ➔ Effect runs
↓
User clicks: count = 2 ➔ Value changed ➔ Effect runs
↓
Unrelated state changes ➔ count unchanged ➔ Effect skips!
Section 2 — Side Effects

The Dependency Array Rules

The dependency array tells React: "Only re-run this effect if any of these values are different from the previous render."

No Array

useEffect(() => { ... })

Runs after every completed render. Rarely what you want for side effects.

Empty Array: []

useEffect(() => { ... }, [])

Runs once on mount. Ideal for initial data fetching or global event listeners.

Dependencies: [a, b]

useEffect(() => { ... }, [count])

Runs on mount + whenever count or listed items change.

Golden Rule of Dependencies: If your effect uses any reactive value from the component scope (props, state, or variables derived from them), it must be included in the dependency array!
Section 2 — Side Effects

Three Common useEffect Patterns

A direct side-by-side comparison of the three fundamental dependency patterns.

Pattern 1: Every Render
useEffect(() => { console.log("Runs after EVERY render"); });

When to use: Logging, measuring DOM dimensions after every paint.

Pattern 2: Mount Only
useEffect(() => { console.log("Runs ONCE on mount"); }, []);

When to use: Initial API calls, setting up event listeners, starting single timers.

Pattern 3: On Change
useEffect(() => { console.log("Runs when count changes"); }, [count]);

When to use: Auto-saving drafts, updating title, fetching details for an ID.

Section 3 — Practical useEffect

What Is Effect Cleanup?

Some side effects allocate system resources that MUST be released when the component leaves the screen.

cleanup-pattern.js
useEffect(() => { // 1. Setup logic return () => { // 2. Cleanup function // Runs when component unmounts! }; }, []);

💡 The function you return inside useEffect is called the cleanup function. React calls it when the component unmounts.

What Needs to Be Cleaned Up?

  • 1 Timers: clearInterval(timer) or clearTimeout(id).
  • 2 Event Listeners: window.removeEventListener("resize", fn).
  • 3 WebSockets / Subscriptions: Closing active socket connections.
  • 4 Preventing Memory Leaks: Avoiding background code attempting to update deleted components!

Section 3 — Practical useEffect

Cleaning Up Event Listeners

Always pair addEventListener with removeEventListener inside your cleanup function.

WindowResize.jsx
useEffect(() => { const handleResize = () => { console.log(window.innerWidth); }; // 1. Attach listener window.addEventListener("resize", handleResize); // 2. Cleanup: remove listener return () => { window.removeEventListener("resize", handleResize); }; }, []);

The Cost of Forgetting Cleanup

If a user navigates between pages 10 times and you forget removeEventListener:

  • ⚠️ 10 Zombie Listeners: All 10 listeners will continue firing in the background simultaneously!
  • ⚠️ Memory Leaks: Garbage collector cannot free the component from memory.
  • ⚠️ Rule of Thumb: If you add something in an effect, remove it in the cleanup function!
Section 4 — useEffect Mistakes

Common useEffect Mistakes

Three frequent mistakes beginner React developers make with side effects.

Mistake 1: Missing Dependency

useEffect(() => {
  console.log(count);
}, []); // ❌ Missing count

The effect captures stale values and never updates when count changes!

Mistake 2: Forgetting Cleanup

useEffect(() => {
  setInterval(tick, 1000);
}, []); // ❌ No clearInterval

Timer keeps ticking forever in memory even after component is deleted.

Mistake 3: Unnecessary Effects

useEffect(() => {
  setFullName(first + last);
}, [first, last]); // ❌ Unneeded

Don't use effects to calculate values you can compute directly during render!

Section 4 — useEffect Mistakes

The Infinite Effect Loop

What causes the dreaded browser crash and maximum update depth exceeded error?

infinite-loop.js (DANGEROUS)
// ❌ CRITICAL BUG: Infinite Loop! useEffect(() => { setCount(count + 1); }, [count]);

⚠️ Why this happens: The effect updates count. Because count changed, the effect runs again. Which updates count again. An unstoppable infinite cycle!

The Fatal Cycle

1. count Changes
↓
2. Component Re-renders
↓
3. useEffect([count]) Runs
↓
4. setCount() Called Again!
↺ repeats indefinitely

useEffect Decision Guide

A simple rule of thumb: do you actually need an effect?

"Do I need to synchronize with something outside React?"

❌ NO

You Probably Don't Need useEffect!

• Transforming data for rendering
• Filtering a list
• Calculating totals (price * qty)
• Handling user click events

Calculate directly in the component body!
✅ YES

Use useEffect!

• Fetching API data
• Setting up a timer (setInterval)
• Changing document.title
• Adding window event listeners

Synchronize safely after DOM commits!
Section 5 — Custom Hooks

What Is a Custom Hook?

A custom Hook is a standard JavaScript function that starts with use and can call other React Hooks.

useCounter.js
// Custom Hook starts with "use" function useCounter() { const [count, setCount] = useState(0); // Reusable stateful logic... return { count, setCount }; }

Three Characteristics of Custom Hooks

  • 1 Starts with "use": React relies on this naming convention to enforce Hook rules.
  • 2 Calls other Hooks: Can freely call useState, useEffect, or other custom Hooks.
  • 3 Reuses Stateful Logic: Does NOT share state between components; each component calling the Hook gets its own independent state copy!
Section 5 — Custom Hooks

Why Create Custom Hooks?

Eliminating code duplication when multiple components need the exact same stateful logic.

❌ Without Custom Hooks (Code Duplication)

Header Cart Component:

Writes count state, increment fn, decrement fn, reset fn.

Product Page Quantity Component:

Copies and pastes the exact same counter code again!

✅ With Custom Hooks (Single Source of Truth)

useCounter()
↙
Header Cart
↘
Product Page
Section 5 — Custom Hooks

Rules for Custom Hooks

Four strict rules you must follow when designing custom Hooks.

The 4 Golden Rules

  • 1 Prefix with use: Always name your Hook useSomething (e.g. useCounter, useDocumentTitle).
  • 2 Top Level Only: Never call Hooks inside loops, conditions (if), or nested functions.
  • 3 Call from React Functions: Only call Hooks from React components or other custom Hooks.
  • 4 Return Reusable Values: Return an object { count, increment } or array [val, setVal] for the component to consume.
useCounter-structure.js
function useCounter() { // 1. State inside the Hook const [count, setCount] = useState(0); // 2. Handler functions const increment = () => setCount(c => c + 1); // 3. Return what component needs return { count, increment }; }
Section 5 — Custom Hooks

Creating the useCounter Hook

Step-by-step implementation of a reusable counter Hook.

src/hooks/useCounter.js
import { useState } from "react"; function useCounter(initialValue = 0) { const [count, setCount] = useState(initialValue); const increment = () => { setCount(prev => prev + 1); }; const decrement = () => { setCount(prev => prev - 1); }; const reset = () => { setCount(initialValue); }; return { count, increment, decrement, reset }; } export default useCounter;

Code Breakdown

  • 1 initialValue = 0: Allows components to customize where the counter begins.
  • 2 prev => prev + 1: Uses functional state updates to prevent stale closures.
  • 3 return { count, increment, decrement, reset }: Clean object export of state + helper actions.

Using useCounter in a Component

Importing and consuming our custom Hook inside a UI component.

Step 1: useCounter Code

Complete source code for src/hooks/useCounter.js.

src/hooks/useCounter.js
import { useState } from "react"; function useCounter(initialValue = 0) { const [count, setCount] = useState(initialValue); const increment = () => { setCount(prev => prev + 1); }; const decrement = () => { setCount(prev => prev - 1); }; const reset = () => { setCount(initialValue); }; return { count, increment, decrement, reset }; } export default useCounter;

Design Highlights

  • ✓ Configurable Initial State: Defaults to 0, but can start at any number.
  • ✓ Safe Functional Updates: Uses prev => prev + 1 for reliable state changes.
  • ✓ Reset Action: Resets back to whatever initialValue was provided.

Section 7 — Review

Common Mistakes to Avoid

Watch out for these 6 pitfalls when working with React hooks and lifecycles.

1. Calling Hooks Conditionally Inside if Statements
❌ WRONG: if (isLoggedIn) { useEffect(...); }
✅ CORRECT: Always call Hooks unconditionally at the top level of your component!
2. Calling Hooks Inside Loops
❌ WRONG: items.forEach(item => { useEffect(...); });
✅ CORRECT: Keep Hooks top-level. Loop inside the effect callback if needed.
3. Forgetting Dependencies in useEffect
❌ WRONG: Using props or state inside useEffect without adding them to [deps].
✅ CORRECT: Include every reactive value referenced by the effect in [deps].
4. Forgetting Cleanup for Timers and Event Listeners
❌ WRONG: setInterval() without return () => clearInterval().
✅ CORRECT: Always return a cleanup function to halt intervals on unmount.
5. Creating a Custom Hook Without the "use" Prefix
❌ WRONG: function createCounter() { const [c, setC] = useState(0); ... }
✅ CORRECT: function useCounter() { ... } (React requires "use" prefix!)
6. Putting UI Markup Inside a Custom Hook Unnecessarily
❌ WRONG: Having custom hooks return JSX markup like <button>.
✅ CORRECT: Hooks return state and logic; components return JSX!

Quick Classroom Quiz

10 quick check questions. Click "Show Answer" to reveal explanations.

Q1 What are the three main lifecycle stages?
Mounting (creation/insert into DOM), Updating (re-rendering due to state/props), and Unmounting (removal from DOM).
Q2 What happens during mounting?
The component is called, evaluates its JSX, inserts nodes into the real browser DOM, and runs initial mount effects.
Q3 What causes a component to update?
A change in internal component state (setState), receiving updated props from a parent, or the parent re-rendering.
Q4 What is useEffect() used for?
Synchronizing the component with external systems (timers, APIs, browser DOM, document.title, event listeners) after rendering.
Q5 What does the dependency array do?
It tells React which reactive values the effect depends on, so React only re-runs the effect when those values change.
Q6 What does [] mean in a useEffect?
It has zero dependencies, meaning the effect runs only once after the initial mount, and its cleanup runs on unmount.
Q7 Why do we need cleanup functions?
To stop intervals, remove event listeners, cancel subscriptions, and prevent memory leaks when components are removed.
Q8 What is a custom Hook?
A JavaScript function that begins with "use", can call other React hooks, and encapsulates reusable stateful logic.
Q9 Why should custom Hooks start with "use"?
React's linter and runtime rely on the "use" prefix to identify and enforce the Rules of Hooks on that function.
Q10 What is the benefit of custom Hooks?
Sharing complex stateful logic across multiple components cleanly without repeating code or violating separation of concerns.

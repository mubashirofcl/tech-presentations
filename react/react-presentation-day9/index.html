Section 1 • Introduction

What Is Routing?

Routing determines which UI should be displayed for a particular URL in the browser address bar.

🌐 URL to UI Mapping

Instead of creating separate, detached HTML files (about.html, contact.html), React displays different component trees based on the URL path:

/ → Home Component
/about → About Component
/products → Products Component
/contact → Contact Component
✨ Key Concept

In traditional websites, every URL requested an entire fresh HTML document from a remote server, triggering a full browser screen wipe and reload.

⚡
Client-Side Routing: React Router intercepts URL changes in the browser. It unmounts old components and mounts new ones instantly in JavaScript memory with zero page reload!
Section 1 • Introduction

Why Do We Need Routing?

Without routing, applications become monolithic, unshareable, and impossible to bookmark or navigate with browser history.

  • ✅ Bookmarkable and shareable URLs

Section 1 • Introduction

SPA and Routing

React applications are fundamentally Single Page Applications (SPAs).

🔄 The SPA Navigation Lifecycle
1. Initial Page Load
The browser loads index.html, CSS, and the React JS bundle once.
2. URL Changes
User clicks a <Link> or triggers an action. React Router intercepts the event.
3. Component Swap
React unmounts old page components and renders new ones in memory.
4. Zero Screen Flash
No full page reload occurs. Header and state remain active and buttery smooth!
🏎️ Why Users Love SPAs
  • ⚡
    Instantaneous Transitions: Navigation feels as fast as a native desktop or mobile app.
  • 💾
    Preserved Client State: Music players, shopping carts, and input drafts keep running in the background.
  • 🌐
    HTML5 History API: Uses window.history.pushState() under the hood to keep browser address bars accurate.
💡
Golden Rule: The browser never asks the server for another HTML page after the initial load!
Section 2 • Setting Up Router

Installing React Router

React Router does not come pre-bundled with React. It is installed as an external package from npm.

📦 Package Name: react-router-dom

For web applications running in the browser, always install react-router-dom.

Terminal / Bash
# In your React project folder:
npm install react-router-dom
ℹ️
Common Student Confusion: Why react-router-dom instead of react-router?
react-router contains the core routing logic, while react-router-dom adds web/browser-specific components like <BrowserRouter> and <Link>.
📋 What You Get in react-router-dom
  • 🏛️
    BrowserRouter: Connects React to browser history.
  • 🗺️
    Routes & Route: Declares route mappings.
  • 🔗
    Link & NavLink: Client-side navigation components.
  • 🎣
    Hooks: useParams, useSearchParams, useNavigate.
Section 2 • Setting Up Router

Basic Router Setup

To enable routing throughout your entire React tree, wrap the root application component in <BrowserRouter>.

src/main.jsx
import React from 'react';
import ReactDOM from 'react-dom/client';
import { BrowserRouter } from 'react-router-dom';
import App from './App';

ReactDOM.createRoot(document.getElementById('root')).render(
  <React.StrictMode>
    <BrowserRouter>
      <App />
    </BrowserRouter>
  </React.StrictMode>
);
🔍 What Does BrowserRouter Do?
  • 1
    Top-Level Context Provider: Sets up the React context that stores current location and history.
  • 2
    HTML5 History API: Listens to browser back/forward buttons and updates the UI accordingly.
  • 3
    Enables Child Hooks: Any component inside <BrowserRouter> can now use useParams, useNavigate, etc.
⚠️
Rule: You can only use Router components (<Routes>, <Link>) inside a <BrowserRouter>!
Section 2 • Setting Up Router

Creating Routes

Use <Routes> as a container and individual <Route> components to connect paths to React components.

Route Definition Syntax
import { Routes, Route } from 'react-router-dom';
import Home from './pages/Home';
import About from './pages/About';
import Products from './pages/Products';

function App() {
  return (
    <Routes>
      <Route path="/" element={<Home />} />
      <Route path="/about" element={<About />} />
      <Route path="/products" element={<Products />} />
    </Routes>
  );
}
🔍 Props Breakdown
path="..."
The URL pathname in the browser to match against (e.g. "/" or "/products").
element={<Component />}
The JSX component instance to render when the URL path matches.
💡
React Router v6 uses element={<Component />} with JSX tags, NOT component={Component}.
Section 2 • Setting Up Router

Route Structure

Think of the routing hierarchy as a clean tree where <Routes> examines all child <Route> definitions and picks the best match.

BrowserRouter (Provides Router context)
    └── <Routes> (Matches the best child route)
        ├── <Route path="/" element={<Home />} />
        ├── <Route path="/about" element={<About />} />
        └── <Route path="/products" element={<Products />} />
1. BrowserRouter

The root parent wrapper. Connects your React app to the browser's address bar history.

2. <Routes>

The switchboard container. Whenever the location changes, it scans its routes to find the matching path.

3. <Route>

The individual rule. Binds a specific URL string directly to a specific UI React component.

Section 3 • Navigation

The <Link> Component

Use <Link> to allow users to navigate between routes without reloading the browser window.

Link Usage
import { Link } from 'react-router-dom';

function Navigation() {
  return (
    <nav>
      <Link to="/">Home</Link>
      <Link to="/about">About</Link>
      <Link to="/products">Products</Link>
    </nav>
  );
}
🔑 How <Link> Works
  • 📍
    The to="..." Prop: Specifies the destination URL path (replaces HTML's href).
  • 🛑
    Prevents Default: It internally intercepts the standard browser click event with e.preventDefault().
  • 📜
    Updates History: Calls history.pushState() and instructs React Router to render the target component.
💡
Under the hood, <Link> renders a regular HTML <a> tag with an accessible href attribute, so right-click "Open in New Tab" still works!
Section 3 • Navigation

Why Not Use <a href="...">?

Using standard anchor tags inside a React single-page app defeats the purpose of React!

❌ Standard <a href="/about"> 
<!-- Traditional HTML anchor -->
<a href="/about">About</a>
  • 💥 Browser makes an HTTP request to the web server
  • 💥 Full page reload occurs with white flash
  • 💥 All in-memory React state is wiped clean
  • 💥 Slow, jerky user experience
✅ React Router <Link to="/about"> 
// React Router Link component
<Link to="/about">About</Link>
  • ⚡ Client-side transition (zero HTTP page request)
  • ⚡ No page reload or white flashing
  • ⚡ React application state is completely preserved
  • ⚡ Blazing fast, native-like app navigation
⚠️
Rule of Thumb: Use <Link> for all internal routes. Only use <a href="..."> when linking to an external website (like Google or GitHub).

The <NavLink> Component

<NavLink> is a specialized version of <Link> that knows whether its route is currently active.

Active Styling with NavLink
import { NavLink } from 'react-router-dom';

function Navbar() {
  return (
    <nav>
      {/* Receives isActive boolean automatically */}
      <NavLink
        to="/products"
        className={({ isActive }) =>
          isActive ? 'nav-active' : 'nav-idle'
        }
      >
        Products
      </NavLink>
    </nav>
  );
}
🌟 Key Benefits of NavLink
  • 🎨
    Automatic Active Class: By default, it adds an active CSS class to the rendered HTML anchor when selected.
  • 🎯
    Dynamic Class / Style: Accepts a function with ({ isActive }) to conditionally apply styles.
  • 📱
    Ideal For:
    Top Navigation Sidebar Links Dashboard Menus
Section 4 • Route Parameters

What Are Route Parameters?

Web applications often need to display details for hundreds or thousands of unique items using a single template component.

❌ Hardcoding Each Item
/products/101  → <Product101 />
/products/102  → <Product102 />
/products/103  → <Product103 />
/products/104  → <Product104 /> ...

Impossible to maintain when you have hundreds or thousands of products in a database!

✅ Dynamic Route Parameter
/products/:id → <ProductDetails />

A single route pattern matches any product ID and passes it dynamically to one reusable component!

💡
The colon :id marks that segment of the URL as a wildcard variable instead of a literal word.
Section 4 • Route Parameters

Creating a Dynamic Route

Prefix a route segment with a colon : to define a parameter placeholder.

Defining Dynamic Path
<Routes>
  {/* Static routes */}
  <Route path="/" element={<Home />} />
  <Route path="/products" element={<Products />} />

  {/* Dynamic route parameter: :id */}
  <Route
    path="/products/:id"
    element={<ProductDetails />}
  />
</Routes>
🔍 URL Matching Examples
/products/101 { id: "101" }
/products/macbook-pro { id: "macbook-pro" }
/products/499 { id: "499" }
ℹ️
Whatever name follows the colon (:id, :productId, :slug) becomes the property key in the extracted object!
Section 4 • Route Parameters

Reading Parameters with useParams()

The useParams() Hook returns an object containing all dynamic route parameters extracted from the current URL.

src/pages/ProductDetails.jsx
import { useParams } from 'react-router-dom';

function ProductDetails() {
  // Extracts :id from the active URL path
  const { id } = useParams();

  return (
    <div className='product-page'>
      <h2>Product Details</h2>
      <p>Product ID: <strong>{id}</strong></p>
    </div>
  );
}

export default ProductDetails;
📌 Important Technical Notes
  • 🔡
    Always a String: Route parameters are always returned as JavaScript strings (e.g., "101").
  • 🔢
    Converting to Number: If doing numeric lookups or math, parse it:
    const numericId = Number(id);
  • 🏷️
    Matching Names: If your route is /movies/:movieId, extract it as const { movieId } = useParams().

Section 5 • Query Strings

What Is a Query String?

Query strings provide optional key-value pairs appended to the URL after a question mark ?.

🔍 URL Query Anatomy
/products
  ? (Query Separator)
  category=shoes
  & (Parameter Joiner)
  sort=price

Full URL: /products?category=shoes&sort=price

✨ What Are Query Strings Used For?
  • 🔎
    Search Queries: ?search=iphone
  • 🏷️
    Filtering Categories: ?category=electronics
  • 📊
    Sorting Orders: ?sort=asc or ?sort=price
  • 📄
    Pagination: ?page=2&limit=20
ℹ️
Unlike route parameters, query strings are optional and do not alter the base route path matching.
Section 5 • Query Strings

Reading Query Strings with useSearchParams()

React Router provides the useSearchParams() Hook to easily read and set query values.

useSearchParams Hook
import { useSearchParams } from 'react-router-dom';

function Products() {
  // Similar to useState, returns [params, setParams]
  const [searchParams] = useSearchParams();

  // Extract specific query values with .get(key)
  const category = searchParams.get('category');
  const sort = searchParams.get('sort');

  return (
    <div>
      <h2>Category: {category || 'All'}</h2>
      <h3>Sort: {sort || 'None'}</h3>
    </div>
  );
}
🔑 How useSearchParams Works
  • 📦
    URLSearchParams Object: searchParams is an instance of the native browser URLSearchParams API.
  • 🔍
    searchParams.get('key'): Returns the string value for that key, or null if the parameter does not exist.
  • 🔄
    Reactive: If the URL query string changes, the component automatically re-renders with fresh values!
Section 5 • Query Strings

Route Parameter vs Query String

One of the most essential distinctions in web architecture. When should you use which?

🆔 Route Parameter Required
/products/101

Purpose:

Identifies a specific, unique resource. Without this ID, the page cannot exist or render the specific item.

Examples:
• /users/42 (User #42)
• /posts/hello-world (Blog post)
🔍 Query String Optional
/products?category=shoes

Purpose:

Filters, sorts, searches, or paginates an existing list of items. If omitted, the page still renders default items.

Examples:
• /products?search=phone
• /products?sort=price&page=2
💡
Rule of Thumb: Is the value essential to know *which single item* to show? Use a Route Param. Is it just modifying *how a list is displayed*? Use a Query String.

Section 6 • Programmatic Navigation

Programmatic Navigation with useNavigate()

Sometimes navigation should happen imperatively inside JavaScript code — for example after a login submission, checkout completion, or timer expiration.

useNavigate() Syntax
import { useNavigate } from 'react-router-dom';

function Login() {
  const navigate = useNavigate();

  const handleLogin = () => {
    // Perform authentication logic...
    // Navigate to protected area upon success:
    navigate('/dashboard');
  };

  return (
    <button onClick={handleLogin}>
      Login
    </button>
  );
}
🔄 The Execution Flow
1. User Action
User clicks "Log In" button
↓
2. Async Success
Auth checks pass and credentials verified
↓
3. Imperative Redirect
navigate('/dashboard') executes
↓
4. Destination Render
Dashboard component mounts
Section 6 • Programmatic Navigation

Back and Forward Navigation

useNavigate() also accepts numeric delta integers to step backward or forward through browser history.

⏮️ Stepping in History
// Go back 1 page in history (like browser Back button)
navigate(-1);

// Go forward 1 page in history
navigate(1);

// Go back 2 pages in history
navigate(-2);
💡 Replace Option

You can pass { replace: true } to replace the current history entry instead of pushing a new one:

navigate('/login', { replace: true });

This prevents users from hitting "Back" and landing back on an unauthenticated or post-logout page!

🎯 Common Real-World Use Cases
  • ⬅️
    Back / Cancel Buttons: Allow users to cancel a form and return to the previous screen without hardcoding the route.
  • 🛒
    Multi-Step Wizards: Step backward through multi-phase checkout or onboarding forms.
  • 🚫
    404 Return Home: Provide a "Go Back" button on error or not-found pages.
Section 7 • Protected Routes

What Is a Protected Route?

A protected route is a route that should only be accessible when a specific condition is satisfied (such as a logged-in user).

🛡️ Gating Access

If an unauthenticated visitor tries to access /dashboard directly, the application must immediately stop them and redirect them to /login.

1. User requests URL
/dashboard
↓
2. ProtectedRoute Check
Is user authenticated?
YES ✅
Render <Dashboard />
NO ❌
Redirect to <Navigate to="/login" />
📌 Key Component: <Navigate />

React Router provides the <Navigate to="..." /> component to trigger automatic component-based redirects during rendering. 

import { Navigate } from 'react-router-dom';

// Immediately changes browser URL to /login
return <Navigate to="/login" replace />;
Section 7 • Protected Routes

Why Protect Routes?

Modern web applications have distinct zones: public areas accessible to anyone, and private areas reserved for authorized users.

🌐 Public Routes

Accessible to all visitors without logging in:

  • / Home: Landing page and marketing
  • /about About: Company profile
  • /products Products: Public item catalog
  • /login Login: Authentication entry point
🔒 Private / Protected Routes

Strictly require valid user session:

  • /dashboard Dashboard: User analytics & stats
  • /profile Profile: Personal settings & email
  • /orders Orders: Purchase history
  • /settings Settings: Account configuration
⚠️
Security Awareness Note: Frontend protected routes provide user experience protection. Sensitive database data must always also be verified and secured on the backend API!
Section 7 • Protected Routes

Basic Protected Route Concept

A protected route is simply a wrapper component that inspects an authentication condition and either renders its children or returns a redirect.

src/components/ProtectedRoute.jsx
import { Navigate } from 'react-router-dom';

function ProtectedRoute({ children }) {
  // Simple auth condition check
  const isAuthenticated = true;

  if (!isAuthenticated) {
    // Deny access & redirect
    return <Navigate to="/login" replace />;
  }

  // Authorized: render the wrapped page
  return children;
}

export default ProtectedRoute;
🧠 The Mental Model
  • 1
    The Guard: <ProtectedRoute> acts as a security guard standing at the door of private pages.
  • 2
    children Prop: Whatever component is nested inside (<Dashboard />) is passed as children.
  • 3
    Clean Separation: The Dashboard component doesn't need ugly auth checking logic inside it — the wrapper handles everything!
Section 7 • Protected Routes

Using Protected Route in App.jsx

Wrap the target private component directly inside <ProtectedRoute> in your route table.

App.jsx with Protected Route
<Routes>
  {/* Public routes */}
  <Route path="/" element={<Home />} />
  <Route path="/login" element={<Login />} />

  {/* Gated private route */}
  <Route
    path="/dashboard"
    element={
      <ProtectedRoute>
        <Dashboard />
      </ProtectedRoute>
    }
  />
</Routes>
🔍 Step-by-Step Path Resolution
1. User enters: /dashboard
2. Route renders: <ProtectedRoute>
3. If true → renders <Dashboard />
4. If false → redirects to /login

Project Architecture & File Structure

A clean, beginner-friendly directory structure for multi-page React applications.

src/
│
├── pages/ (One component per routed page)
│   ├── Home.jsx
│   ├── Products.jsx
│   ├── ProductDetails.jsx
│   ├── Login.jsx

  • 📄

Section 9 • Review

Common React Router Mistakes

Watch out for these 7 beginner traps when building React Router applications:

❌ 1. Forgetting <BrowserRouter>

Using <Routes>, <Link>, or hooks without wrapping the app in <BrowserRouter> throws an error: "useRoutes() may be used only in the context of a Router component".

❌ 2. Forgetting the Leading Slash in Paths

Writing path="products" instead of path="/products" can cause unexpected relative path stacking like /about/products.

❌ 3. Parameter Name Mismatch

Declaring path="/products/:id" in Route, but trying to read const { productId } = useParams() in the component! The key must match the route string exactly.

❌ 4. Using useParams() for Query Strings

useParams() only reads colon placeholders (:id). To read queries like ?sort=price, you must use useSearchParams()!

❌ 5. Using <a href> for Internal Links

Forces full browser reloads, resetting state and ruining SPA speed. Always use <Link to="..."> or <NavLink>.

❌ 6. Forgetting to Protect Private Routes

Leaving <Route path="/dashboard" element={<Dashboard />} /> exposed without wrapping in <ProtectedRoute>.

Quick Reference Cheat Sheet

All 9 core React Router building blocks summarized for quick revision:

<BrowserRouter>

Root provider enabling HTML5 browser history synchronization.

<Routes>

Container switchboard that matches the current location to a child route.

<Route>

Declares a single URL-to-component mapping (path and element).

<Link>

Client-side navigation link that intercepts clicks and prevents page reload.

<NavLink>

Navigation link with built-in active status detection for styling navbars.

useParams()

Hook that reads dynamic route parameters (e.g., :id) from the URL.

useSearchParams()

Hook to read and manipulate URL query strings (?key=val).

useNavigate()

Hook returning a function to navigate imperatively in event handlers.

<Navigate>

JSX element that triggers an immediate client-side redirect when rendered.

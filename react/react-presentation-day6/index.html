Section 1 — Form Submission

What Happens When a Form Is Submitted?

Comparing native browser behavior with React's controlled handling

🌐 Native HTML Form Behavior

In traditional web development, submitting a form triggers a full page refresh and sends an HTTP GET/POST request to the server specified in the action attribute.

This causes the browser to discard its entire current JavaScript state!

⚛️ How React Handles Submission

In Single Page Applications (SPAs), we do NOT want the page to reload. We intercept the submit event in JavaScript, validate the inputs, and process data inside React state.

React Submission Flow

User fills form Inputs
↓
Clicks Submit Button / Enter
↓
onSubmit <form> event
↓
handleSubmit(event) event.preventDefault()
↓
Validate data Checks
↓
Process / Display State updated

Section 1 — Form Submission

Using the onSubmit Event

Listening for form submissions in React

StudentForm.jsx — Adding onSubmit 
function StudentForm() {

  // 1. Define the submit handler function
  const handleSubmit = (event) => {
    console.log("Form submitted");
  };

  // 2. Attach handler to <form onSubmit={handleSubmit}>
  return (
    <form onSubmit={handleSubmit}>
      <input type="text" />

      <button type="submit">
        Submit
      </button>
    </form>
  );
}
🎯 Key Connections

In React, onSubmit is a synthetic event attribute placed directly on the <form> element.

<form onSubmit={handleSubmit}>
💡
Syntactic Convention: By convention, the event handler is named handleSubmit, and it automatically receives the synthetic event object.

Section 1 — Form Submission

Why Do We Use preventDefault()?

Stopping the browser's default refresh behavior to keep state intact

Preventing Browser Reload 
const handleSubmit = (event) => {
  // 🛑 Essential: stops browser default submission
  event.preventDefault();

  console.log("Form submitted safely without reload!");
};
🛑 What Happens Without It?

If you omit event.preventDefault():

  • 1. Browser tries to reload the page URL
  • 2. All React component state in memory is wiped out
  • 3. Console logs disappear in a flash
  • 4. Form inputs reset back to empty
✅
Golden Rule: In React, always call event.preventDefault() as the first line of your submit handler!

Getting Form Values (Controlled Inputs)

Connecting inputs to useState so React is always in full control of the data

Controlled Input Binding 
// 1. Create state for each input
const [name, setName] = useState("");
const [email, setEmail] = useState("");

// 2. Controlled inputs with value & onChange
<input
  value={name}
  onChange={(e) => setName(e.target.value)}
/>

<input
  value={email}
  onChange={(e) => setEmail(e.target.value)}
/>

// 3. On submit, values are immediately ready in state!
const handleSubmit = (e) => {
  e.preventDefault();
  console.log("Name:", name);
  console.log("Email:", email);
};
🔄 What Is a Controlled Component?

An input whose value is governed by React state.

value = React State
onChange = Updates React State
💡
Advantage: You never have to query the DOM with document.getElementById! The current values are always stored and ready inside your state variables.

Multiple Form Fields in One State Object

Grouping related inputs into a single JavaScript object

Form Object State 
// Instead of 4 separate useState variables:
const [form, setForm] = useState({
  name: "",
  email: "",
  age: ""
});

// Updating a specific property using spread operator:
setForm({
  ...form,
  name: e.target.value
});
📦 Why Store in an Object?
  • • Keeps related form values together in one place
  • • Enables a single, reusable handleChange function for all inputs
  • • Easier to reset (setForm(initialState))
  • • Ready to send directly to backend or display
💡
Remember the Spread Operator: Always write ...form when updating state so you don't accidentally overwrite the other field values!
Section 2 — Form Validation

What Is Form Validation?

Checking whether user input satisfies business rules before submission

🛡️ The Purpose of Validation

Form validation is the process of testing user input against specified rules before processing or sending the data.

It protects your application from broken, incomplete, or malicious data while guiding the user toward correct input.

📋 Standard Form Validation Rules
  • Name: Required, cannot be blank spaces
  • Email: Must match a valid email format
  • Age: Must be a valid number ≥ 18
  • Course: Must select an option from dropdown
💬
User Experience First: Validation should always provide immediate, clear, friendly feedback so users know exactly how to fix mistakes!

Required Field Validation & .trim()

Why checking !form.name.trim() is much safer than !form.name

Checking for Non-Empty Strings 
// ❌ Weak check: Passing "   " bypasses this!
if (!form.name) {
  errors.name = "Name is required";
}

// ✅ Best Practice: .trim() removes padding spaces first
if (!form.name.trim()) {
  errors.name = "Name is required";
}
🔍 Why .trim() Matters
"Rahul" → Valid
" Rahul" → Valid ("Rahul")
" " → Invalid (Trims to "")
"" → Invalid (Empty)
Section 2 — Form Validation

Email Validation

From simple .includes("@") to clean beginner-friendly regular expressions

Method 1: Simple Check 
// Beginner check
if (!form.email.includes("@")) {
  errors.email = "Enter a valid email";
}
Pros: Very simple. Cons: Accepts "@" or "abc@".
Method 2: Clean Regex Pattern (Recommended) 
const emailPattern =
  /^[^\s@]+@[^\s@]+\.[^\s@]+$/;

if (!emailPattern.test(form.email)) {
  errors.email = "Enter a valid email";
}
Explanation: Checks for characters before @, a domain name, and a dot extension (like .com).
Section 2 — Form Validation

Number Validation & String Conversion

Remember: HTML form inputs always store their values as strings!

Converting String to Number for Validation 
// In form inputs, typing 21 produces the string "21"
if (!form.age) {
  errors.age = "Age is required";
} else if (Number(form.age) < 18) {
  errors.age = "Age must be at least 18";
}
⚠️ The Common "String" Trap

Even if type="number" is on the input, JavaScript's e.target.value is always a string ("21").

Always wrap in Number(form.age) or parseInt(form.age, 10) when doing mathematical comparisons!

💡
Bonus check: isNaN(Number(form.age)) can be used to ensure the user didn't type non-numeric text.

const validateForm = () => {
  const errors = {};

    errors.name = "Name is required";

};

  • 1. Cleaner Code: Keeps your handleSubmit slim and readable.
  • 2. Testable: You can test validation rules independently.

Section 2 — Form Validation

Handling Validation Errors in State

Using Object.keys(errors).length to decide whether to abort or proceed

Checking for Errors in handleSubmit 
const [errors, setErrors] = useState({});

const handleSubmit = (e) => {
  e.preventDefault();

  // 1. Run validation
  const validationErrors = validateForm();

  // 2. If errors exist, update error state and HALT
  if (Object.keys(validationErrors).length > 0) {
    setErrors(validationErrors);
    return; // 🛑 Abort submission
  }

  // 3. If no errors, clear previous errors and continue!
  setErrors({});
  console.log("Data ready to submit:", form);
};
🔍 Why Object.keys().length?

In JavaScript, an empty object {} is truthy (Boolean({}) === true).

To check if an object has no keys, we check:

Object.keys(validationErrors).length > 0

Section 3 — Complete Form

          
Complete StudentForm.jsx Component

          
The full beginner-friendly component ready for production use

        

        

          

            

              

                

                

                

              

              src/components/StudentForm.jsx
              
            

            
import { useState } from "react";

function StudentForm() {
  const [form, setForm] = useState({
    name: "",
    email: "",
    age: "",
    course: ""
  });

  const [errors, setErrors] = useState({});

  const handleChange = (e) => {
    const { name, value } = e.target;
    setForm({ ...form, [name]: value });
  };

  const validateForm = () => {
    const errors = {};
    if (!form.name.trim()) errors.name = "Name is required";
    if (!form.email.includes("@")) errors.email = "Enter a valid email";
    if (!form.age) errors.age = "Age is required";
    if (!form.course) errors.course = "Select a course";
    return errors;
  };

  const handleSubmit = (e) => {
    e.preventDefault();
    const validationErrors = validateForm();
    if (Object.keys(validationErrors).length > 0) {
      setErrors(validationErrors);
      return;
    }
    setErrors({});
    console.log(form);
  };

  return (
    <form onSubmit={handleSubmit}>
      {/* Inputs & Error Messages */}
    </form>
  );
}

export default StudentForm;

Section 4 — Import & Export

          
Named Exports

          
Exporting specific functions or components using { curly braces }

        

        

          

            

              

                

                  

                  

                  

                

                Named Export & Import Syntax
                
              

              
// In Header.jsx: Notice 'export' before function
export function Header() {
  return <h1>Student App</h1>;
}

// In App.jsx: Must use { curly braces } matching the name!
import { Header } from "./Header";

            


            

              

                
🔑 Crucial Difference: Curly Braces

                

                  Named imports MUST use { } curly braces.
                

                

                  The name inside { Header } must match the exported identifier exactly.
                

              


              

                ⚠️
                

                  Common Trap: Writing import Header from "./Header" when the file used a named export will result in an undefined import error!

Troubleshooting

          
Common Beginner Mistakes & Fixes

          
Six frequent traps when working with React forms and module imports

        

        

          

            

              1. Forgetting e.preventDefault()
              
Causes the browser to immediately reload, wiping your React state.

              
Fix: e.preventDefault() at top of submit handler.

            


            

              2. onClick Instead of onSubmit
              
Attaching click handler to the button prevents submission when pressing Enter.

              
Fix: Put onSubmit on <form>.

            


            

              3. Missing name Attribute
              
Using [name]: value in handleChange fails if name is omitted.

              
Fix: Add name="email" to input.

            


            

              4. Forgetting { } on Named Imports
              
Writing import Header from "./Header" for a named export causes undefined error.

              
Fix: import { Header } from "./Header".

            


            

              5. Using { } on Default Exports
              
Adding curly braces to a file exported via export default.

              
Fix: import Header from "./Header".

            


            

              6. Silently Failing Validation
              
Returning on error without rendering error messages in the JSX.

              
Fix: {errors.name && <p>{errors.name}</p>}.

            

          

        

      


      
      

        

          

            

              
Review

              
Quick Classroom Quiz

            

            

              
              
            

          

          
Test your understanding with 10 questions covering all Day 6 concepts

        

        

          

            
            

              
Q1 What is onSubmit?

              
              
A React form event listener attached to the <form> element that fires whenever the form is submitted.

            


            
            

              
Q2 Why do we use preventDefault()?

              
              
It prevents the browser's native behavior of reloading the page and making a full HTTP request, allowing React to handle data in state.

            


            
            

              
Q3 What is form validation?

              
              
The process of checking whether user input satisfies defined constraints (required, email format, age limits) before processing.

            


            
            

              
Q4 Why do we use an errors object?

              
              
It maps specific field names to their respective error messages (e.g. { name: "Name is required" }), making it easy to display errors under the matching input.

            


            
            

              
Q5 What does Object.keys(errors).length tell us?

              
              
It returns the total number of validation errors. If length > 0, errors exist and submission must be halted.

            


            
            

              
Q6 What is export default?

              
              
It marks the main entity exported from a file. Only one default export is permitted per file, and it is imported without curly braces.

            


            
            

              
Q7 What is a named export?

              
              
An export that exports variables or functions by their exact name. A single file can contain multiple named exports.

            


            
            

              
Q8 How do you import a named export?

              
              
By wrapping the imported name inside { curly braces }, e.g.: import { Header } from "./Header".

            


            
            

              
Q9 Difference between default and named export?

              
              
Default: 1 per file, imported without {}. Named: multiple per file, imported with {}.

            


            
            

              
Q10 Why split React code into multiple files?

              
              
For modularity, reusability, testability, and maintaining clean separation of concerns as the project scales.

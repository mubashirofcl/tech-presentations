Foundation

What Is State in React?

State is data that a component remembers and uses to render its UI.

🧠 Component Memory

Unlike normal JavaScript variables that disappear when a function finishes executing, React state persists between renders. When state changes, React automatically re-renders the component.

📋 Common Examples of State
  • • Counter value
  • • Logged-in user information
  • • Shopping cart items
  • • Selected UI theme (dark/light)
  • • Product search filters
📌
Key point: React's built-in useState is sufficient for managing state inside an individual component.
Counter.jsx (Local Component State)
JSX 
import { useState } from "react";

function Counter() {
  // count is stored locally inside this component
  const [count, setCount] = useState(0);

  return (
    <div>
      <h2>Count: {count}</h2>
      <button onClick={() => setCount(count + 1)}>
        Increment
      </button>
    </div>
  );
}

export default Counter;
The Challenge

When Does State Management Become Difficult?

Imagine building an e-commerce application with multiple separate pages and components.

🧭 Navbar

Needs the cart count to display how many items are in the shopping cart badge (e.g. 🛒 3).

📦 Product Page

Needs to add items into the cart when a user clicks the "Add to Cart" button.

🛒 Cart Page

Needs the cart items to show item names, images, and allow quantity adjustments.

💳 Checkout Page

Needs the cart total and taxes to process final payment and order confirmation.

⚠️ If Each Component Manages Its Own State

If every component keeps its own cart state, data gets out of sync. Adding a product in Product Page won't update the Navbar badge, and Checkout won't see the latest items. The app quickly becomes fragmented and difficult to maintain.

🎯 The Core Problem & Solution

The Problem: How can multiple components across different branches of the component tree share and update the same state efficiently?

The Solution: This is where centralized state management can help!

Anti-Pattern

What Is Prop Drilling?

Prop drilling happens when data is passed through multiple intermediate components just to reach a component that needs it.

🏠 App Holds state: user = "Mubashir"
user={user} ➔
📦 Parent Doesn't need user
user={user} ➔
📦 Child Doesn't need user
user={user} ➔
👤 Profile Displays: Welcome, {user}
❌ Why Prop Drilling Hurts
  • 1 Too many props: Components get cluttered with props they never consume.
  • 2 Tightly connected: Intermediate components become fragile and harder to reuse.
  • 3 Refactoring nightmare: Changing component hierarchy requires updating props across every layer.
💡
Important: Prop drilling is not always bad. For small applications with 1 or 2 layers, passing props is completely normal and fine!
PropDrillingExample.jsx 
function App() {
  const [user, setUser] = useState("Mubashir");
  return <Parent user={user} />;
}

// Parent passes user, but doesn't need it!
function Parent({ user }) {
  return <Child user={user} />;
}

// Child passes user, but doesn't need it!
function Child({ user }) {
  return <Profile user={user} />;
}

// Profile finally uses user!
function Profile({ user }) {
  return <h2>Welcome, {user}</h2>;
}
Core Definition

What Is Redux?

Redux is a state management library that helps applications manage shared state in a predictable way.

🟣 Centralized Store

In a React application, Redux provides a single centralized store for state that multiple components need to access across different parts of the application.

Simple Idea:

Instead of passing shared data through many layers of components, any component can access the state directly from the Redux store!

🌐 Typical Shared State in Redux
  • 1
    Authentication Information: User profile, login tokens, permissions.
  • 2
    Shopping Cart: Items selected, quantity, discount codes.
  • 3
    User Preferences: Dark mode / Light mode, language, currency.
  • 4
    Application-Wide Filters: Search queries, sorting rules across pages.
⚡
Remember: Redux manages the application state. React is responsible for rendering the UI.
Decision Framework

Why Use Redux?

Redux can be useful when an application grows in size and shared state complexity.

✅ Redux Can Be Useful When:
  • ✓ Multiple components in different places need the same state.
  • ✓ Many components need to update the same shared data.
  • ✓ State update logic is becoming large and difficult to maintain.
  • ✓ You want predictable, centralized, and traceable state updates.
  • ✓ You need easier debugging and time-travel inspection of state changes.
🛒 E-Commerce Shared State Example
Component Shared State Needed
Navbar Cart count badge
Product Page Cart items (adds new items)
Cart Page Cart items and calculated total
Checkout Page Cart details & order pricing
Redux provides a single shared source of truth for all these components.
⚠️
Note: Not every React application needs Redux! Local component state (useState) and React's Context API are completely sufficient for many small-to-medium applications.
Modern Standard

What Is Redux Toolkit (RTK)?

Redux Toolkit is the official, recommended way to write Redux logic today.

🧰 Why Redux Toolkit Exists

Without Redux Toolkit, traditional "vanilla" Redux code required lots of repetitive boilerplate: action types, action creators, handwritten immutable spreads, and complex store configs.

Redux Toolkit (RTK) was created by the Redux team to eliminate boilerplate and make writing Redux logic fast, simple, and clean.

✨ What RTK Simplifies
  • • Creating a Redux store: One simple function handles everything.
  • • Writing reducers: Update state cleanly without manual cloning.
  • • Defining actions: Automatically generates action creators.
  • • Organizing Redux logic: Groups logic into clean "slices".
configureStore()

Creates and configures the Redux store with sensible defaults, including Redux DevTools extension support automatically.

createSlice()

Accepts a name, initial state, and reducer functions. It automatically generates action creators and action types for you!

⭐
Golden Rule: For any new Redux application, always use Redux Toolkit instead of setting up traditional Redux manually.
Ecosystem Breakdown

Redux vs Redux Toolkit vs React Redux

Beginners often get confused by these three names. They have very distinct roles.

1. Redux
Core State Library

The foundational state management library. It provides the architectural concepts: the store, actions, and reducers.

Role: State management engine (UI-independent).
2. Redux Toolkit
Recommended Toolset

The official package that simplifies Redux. It provides configureStore() and createSlice().

Role: Makes writing Redux logic fast and painless.
3. React Redux
React UI Bridge

The official bridge connecting Redux to React. Provides the <Provider> component and React hooks like useSelector() and useDispatch().

Role: Lets React components talk to Redux.
🤝 How They Work Together Today:
🔹 Redux gives us the state management concept.
🔹 Redux Toolkit helps us create the store and reducers.
🔹 React Redux connects the store into our React components.
Architecture

Understanding the Redux Data Flow

Redux follows a strict, predictable unidirectional data flow cycle.

Step 1
👆
User Interaction
User clicks a button in React (e.g., Increment)
➔
Step 2
⚡
Dispatch Action
Component dispatches an action object
➔
Step 3
⚙️
Reducer Executes
Reducer receives action and calculates new state
➔
Step 4
🏬
Store Updates
Redux store saves the updated state object
➔
Step 5
🔄
React UI Updates
Subscribed components re-render with new data
🔍 Example Walkthrough

1. Click "Increment" button
2. dispatch(increment())
3. Reducer: state.count += 1
4. Redux Store count updates (0 ➔ 1)
5. React displays the new count 1!

🛑 Unidirectional Rule

Redux state is read-only to components. Components cannot directly write state.count = 5. Every state change MUST follow this explicit cycle!

Core Building Blocks

The Three Main Redux Concepts

Master these three terms and you understand the foundation of Redux.

1. 🏬 Store

The Store holds the entire application's Redux state in a centralized location.

// Example Store State:
{
  counter: {
    count: 5
  }
}
2. ⚡ Action

An Action is an object that describes something that happened in the application.

// Examples:
• Increment the counter
• Decrement the counter
• Reset the counter
type: "counter/increment"
3. ⚙️ Reducer

A Reducer defines how the state changes in response to an action.

// Reducer logic:
(state, action) => {
  // returns updated state
  state.count += 1;
}
🧠
Quick Formula to Remember:
The Store holds state, Actions describe events, and Reducers define state updates.
RTK Building Block

What Is a Redux Slice?

A slice represents one part of the Redux state, packaging its initial state and reducers together.

🍰 What a Slice Bundles:
  • 1 Slice Name: Used as action type prefix (e.g. "counter").
  • 2 Initial State: Starting value (count: 0).
  • 3 Reducers: Functions for increment, decrement, and reset.
  • 4 Action Creators: Automatically created and exported!
✨
Important: Immer Magic
Redux Toolkit uses Immer internally. This allows us to write updates like state.count += 1 while preserving Redux's strict immutable update behavior under the hood!
⚠️
Never mutate state directly outside Redux Toolkit's reducer functions.
counterSlice.js
JS 
import { createSlice } from "@reduxjs/toolkit";

const counterSlice = createSlice({
  name: "counter",

  initialState: {
    count: 0,
  },

  reducers: {
    increment: (state) => {
      state.count += 1;
    },

    decrement: (state) => {
      state.count -= 1;
    },

    reset: (state) => {
      state.count = 0;
    },
  },
});

// Automatically generated action creators:
export const { increment, decrement, reset } =
  counterSlice.actions;

export default counterSlice.reducer;

Implementation Step 1

Step 1 — Create the Counter Slice

File: src/features/counter/counterSlice.js

🔍 What Happens Here?
  • 1
    createSlice(): Creates the slice with a single configuration object.
  • 2
    initialState: Sets the starting count value to 0.
  • 3
    reducers: Defines available state updates (increment, decrement, reset).
  • 4
    counterSlice.actions: Automatically generated actions exported for React components.
  • 5
    counterSlice.reducer: Exported as default to be registered in the Redux store.
💡
Notice how clean this is! We did not write any action constants or complex switch statements!
src/features/counter/counterSlice.js
JS 
import { createSlice } from "@reduxjs/toolkit";

const counterSlice = createSlice({
  name: "counter",

  initialState: {
    count: 0,
  },

  reducers: {
    increment: (state) => {
      state.count += 1;
    },

    decrement: (state) => {
      state.count -= 1;
    },

    reset: (state) => {
      state.count = 0;
    },
  },
});

export const { increment, decrement, reset } =
  counterSlice.actions;

export default counterSlice.reducer;
Implementation Step 2

Step 2 — Configure the Redux Store

File: src/app/store.js

⚙️ Key Explanations
  • 1
    configureStore(): Creates and configures the centralized Redux store.
  • 2
    reducer: An object that registers all reducers used across the application.
  • 3
    counter: counterReducer: Defines the state key under which this slice's data will be stored.
📦 Resulting Redux State Shape:
{
  counter: {
    count: 0
  }
}

Therefore, any React component can access this value using: state.counter.count

src/app/store.js
JS 
import { configureStore } from "@reduxjs/toolkit";
import counterReducer from "../features/counter/counterSlice";

export const store = configureStore({
  reducer: {
    // Registered under the key "counter"
    counter: counterReducer,
  },
});
Implementation Step 3

Step 3 — Connect Redux to React Using Provider

File: src/main.jsx

🔌 What Does Provider Do?

The <Provider> component makes the Redux store available to the entire React component tree nested inside it.

📋 Important Points:
  • 1 Import Provider from react-redux.
  • 2 Import the configured store from ./app/store.
  • 3 Pass the store via the store={store} prop.
  • 4 Wrap the <App /> component inside <Provider>.
⚠️
Without the correct Provider setup, components cannot use the store through React Redux hooks (useSelector & useDispatch will throw an error).
src/main.jsx
JSX 
import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import { Provider } from "react-redux";

import App from "./App";
import { store } from "./app/store";

createRoot(document.getElementById("root")).render(
  <StrictMode>
    {/* Provider makes Redux available to all components */}
    <Provider store={store}>
      <App />
    </Provider>
  </StrictMode>
);
Implementation Step 4

Step 4 — Read and Update Redux State

File: src/components/Counter.jsx

👀 1. useSelector()

Reads data directly from the Redux store.

const count = useSelector((state) => state.counter.count);

It automatically subscribes the component to updates: when count changes, Counter re-renders!

⚡ 2. useDispatch()

Returns the Redux dispatch function.

const dispatch = useDispatch();
dispatch(increment());

Allows the component to trigger actions and update state.

src/components/Counter.jsx
JSX 
import { useSelector, useDispatch } from "react-redux";

import {
  increment,
  decrement,
  reset,
} from "../features/counter/counterSlice";

function Counter() {
  // Read count from Redux store
  const count = useSelector((state) => state.counter.count);

  // Get dispatch function
  const dispatch = useDispatch();

  return (
    <div>
      <h2>Count: {count}</h2>

      <button onClick={() => dispatch(increment())}>
        Increment
      </button>

      <button onClick={() => dispatch(decrement())}>
        Decrement
      </button>

      <button onClick={() => dispatch(reset())}>
        Reset
      </button>
    </div>
  );
}

export default Counter;

Full Architecture Cycle

How the Complete Application Works

Let's connect every single moving part from user action to visual render.

1 User Clicks Button

The user clicks the Increment button inside the <Counter /> component.

2 Dispatches Action

The component calls dispatch(increment()) sending { type: "counter/increment" }.

3 Reducer Updates

The counterSlice reducer receives the action and runs state.count += 1.

4 Store Holds State

The central Redux store now holds the new updated state: { counter: { count: 1 } }.

5 useSelector() Reads

useSelector() detects that state.counter.count has changed.

6 React Updates UI

React re-renders the <Counter /> component to display the new number 1!

User Clicks ➔ dispatch(increment()) ➔ Counter Reducer ➔ Redux Store ➔ useSelector() ➔ React Re-renders
💎
Key Takeaway: Redux Toolkit manages shared state, and React Redux helps React components read and update it with clean hooks.

Summary and Quick Questions

📝 Today's Summary
  • ✓ State is component memory in React.
  • ✓ Prop drilling causes unnecessary intermediate coupling.
  • ✓ Redux provides a centralized, predictable state store.
  • ✓ Redux Toolkit (RTK) eliminates legacy Redux boilerplate.
  • ✓ Slices group initial state, reducers, and actions together.
  • ✓ configureStore() sets up the central store.
  • ✓ <Provider> connects Redux into the React tree.
  • ✓ useSelector() reads; useDispatch() updates.
1. What is Redux? ▼
A predictable, centralized state management library for JavaScript applications that stores shared state in a single store.
2. What problem does Redux solve? ▼
It solves prop drilling and state synchronization issues across multiple distant components that need access to the same shared data.
3. What is a Redux store? ▼
The centralized container that holds the entire application's Redux state tree as a single source of truth.
4. What is a slice? ▼
A module created with createSlice() that bundles initial state, reducer logic, and generated actions for a specific feature.
5. What does configureStore() do? ▼
Initializes and configures the Redux store, combines reducers, and enables Redux DevTools automatically.
6. Why do we use Provider? ▼
It wraps the React app and uses React Context internally to make the Redux store accessible to all nested components.
7. useSelector() vs useDispatch()? ▼
useSelector() reads state from the store and subscribes to changes. useDispatch() sends actions to update state.
8. Which package provides createSlice()? ▼
@reduxjs/toolkit (Redux Toolkit), not react-redux!

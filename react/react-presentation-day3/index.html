React Masterclass › Day 3 › What is an Event?
Part 1 • React Events

What is an Event?

An event is a signal that an action has taken place in the browser—initiated by either the user or the runtime environment.

Common Real-World Events
  • Clicking a button: Adding an item to a cart or deleting a todo.
  • Typing in an input: Entering username, password, or search term.
  • Submitting a form: Logging in or sending registration data.
  • Hovering with the mouse: Showing a tooltip or dropdown menu.
  • Pressing a keyboard key: Hitting Enter to submit or Escape to close a modal.
  • Changing a checkbox: Toggling task completion or dark mode.
Vanilla JavaScript: button.addEventListener("click", handleClick);
The React Event Lifecycle

React handles events declaratively using camelCase props directly on JSX elements:

1. User ActionUser clicks button or types into input
↓
2. React EventReact intercepts action via SyntheticEvent prop
↓
3. Event HandlerYour custom JavaScript function executes
↓
4. Logic / StateState updates or business logic performs work
↓
5. UI Re-rendersReact efficiently refreshes the changed UI
Speaker Guidance — Slide 3:
  • Contrast vanilla JS with React: In vanilla JS we find the DOM element (`document.getElementById`) and attach an event listener. In React, we pass the handler directly as a prop in JSX.
  • Reinforce the 5-step lifecycle: Action -> Event prop -> Handler execution -> State update -> UI refresh. This is the heartbeat of React reactivity.
React Masterclass › Day 3 › React Event Syntax
Syntax Anatomy

React Event Handling

React events are named using camelCase (e.g., onClick instead of lowercase HTML onclick), and functions are passed as values wrapped in JSX curly braces {}.

src/App.jsx 
function App() {

  // 1. Define the event handler function
  function handleClick() {
    console.log("Button clicked!");
  }

  // 2. Pass function reference to onClick prop
  return (
    <button onClick={handleClick}>
      Click Me
    </button>
  );
}

export default App;
Anatomy Breakdown
  • Function Declaration: handleClick() lives inside the component body, giving it access to component state and props.
  • camelCase Prop: Always write onClick with capital C. In React, onclick (lowercase) will not work properly or throw a warning.
  • Curly Braces {}: We use JSX curly braces to inject JavaScript identifiers into HTML tags.
  • Passing by Reference: Notice there are no parentheses after handleClick. We pass the function object itself, so React can call it later when the click occurs.
Speaker Guidance — Slide 4:
  • Make sure students see the difference between HTML inline strings: `onclick="handleClick()"` vs React JSX object references: `onClick={handleClick}`.
  • Highlight that inside React, everything is JavaScript. We are not passing strings; we are passing real first-class function references.
React Masterclass › Day 3 › onClick Pitfall
Crucial Concept

onClick & The Invocation Trap

The #1 most common mistake beginners make is adding parentheses () to their handler inside JSX.

✕ INCORRECT — Immediate Invocation
BadPractice.jsx
function App() {
  function handleClick() {
    alert("Hello!");
  }

  // ❌ WRONG: Calls handleClick immediately during render!
  return (
    <button onClick={handleClick()}>
      Click Me
    </button>
  );
}
Why it breaks: The JavaScript runtime evaluates handleClick() immediately when rendering the component before the user touches anything. If handleClick updates state, this triggers an infinite re-render loop crashing the browser!
✓ CORRECT — Pass Function Reference
GoodPractice.jsx
function App() {
  function handleClick() {
    alert("Hello!");
  }

  // ✓ CORRECT: Passes the function reference to React
  return (
    <button onClick={handleClick}>
      Click Me
    </button>
  );
}
The Mental Model: Think of onClick={handleClick} as saying: "Hey React, here is a reference to my function. Do not run it now; please hold on to it and invoke it only when the user clicks this button."
Speaker Guidance — Slide 5:
  • Spend extra time on this slide! Every beginner encounters the "Too many re-renders. React limits the number of renders to prevent an infinite loop" error because of `onClick={handleClick()}`.
  • Draw on the whiteboard: `foo()` means RUN NOW. `foo` means RUN LATER.
React Masterclass › Day 3 › Inline Event Handlers
Syntax Styles

Inline Event Handlers

You can also write anonymous ES6 arrow functions directly inside the JSX prop.

InlineHandlers.jsx 
function App() {
  return (
    <div>
      {/* 1. Concise single-line inline arrow function */}
      <button onClick={() => console.log("Quick click!")}>
        Log Quick
      </button>

      {/* 2. Multi-line inline arrow function */}
      <button
        onClick={() => {
          console.log("Step 1");
          console.log("Step 2");
        }}
      >
        Multi Step
      </button>
    </div>
  );
}
When to Use What?
Use Inline Handlers for:
Tiny one-liners (e.g. toggling a boolean () => setOpen(!open)) or passing an argument (e.g. () => handleDelete(user.id)).
Use Dedicated Handler Functions for:
Multi-step logic, form validation, API calls, and keeping JSX markup readable and clean.
Speaker Guidance — Slide 6:
  • Show that the arrow function `() => ...` creates a wrapper function. When the user clicks, React calls the arrow function, which then runs the inside code.
  • Advise students to avoid putting 10+ lines of logic inside an inline JSX prop; write a dedicated function at the top of the component instead.
React Masterclass › Day 3 › Naming Conventions
Industry Best Practices

Event Handler Naming

Clear naming distinguishes functions that handle events from props that receive event listeners.

The Standard React Convention
  • Internal Handlers: Prefix with handle + event/action name.
    handleClick, handleChange, handleSubmit, handleDelete, handleLogin
  • Component Props: Prefix with on + event/action name.
    onClick, onChange, onDelete, onUserAdd
Rule of Thumb:
"on[Event]" describes when something happens (prop).
"handle[Event]" describes what executes (function).
ExampleNaming.jsx
// Good naming in action:
function UserProfile() {

  function handleDelete(userId) {
    console.log("Deleting user:", userId);
  }

  function handleToggleActive() {
    console.log("Status toggled");
  }

  return (
    <div>
      <UserCard
        onDelete={handleDelete}
        onToggle={handleToggleActive}
      />
    </div>
  );
}
Speaker Guidance — Slide 7:
  • Point out that while React doesn't force this naming convention at compile time, adhering to `handle*` and `on*` is the universal pattern used in professional React engineering teams.

React Masterclass › Day 3 › The Event Object
SyntheticEvent

The Event Object

When an event occurs, React automatically passes a cross-browser wrapper called SyntheticEvent into your handler.

Object Navigation Flow
eventThe top-level SyntheticEvent wrapper
↓
event.targetThe DOM element that triggered the event
↓
event.target.valueThe current text/number entered in the element
Why SyntheticEvent? Different browsers (Chrome, Safari, Firefox, Edge) historically implemented event objects with subtle inconsistencies. React wraps native browser events in a single consistent interface that behaves identically everywhere.
Essential Event Properties
PropertyDescriptionCommon Use
event.target The originating element Inspecting attributes
event.target.value Input text or selected option Text fields, select dropdowns
event.target.name The name="..." attribute Handling multi-input forms
event.target.checked Boolean checked status Checkboxes & radio buttons
event.preventDefault() Stops browser default behavior Forms, navigation anchors
Speaker Guidance — Slide 9:
  • Clarify the distinction between `event.target` (the DOM node) and `event.target.value` (the string inside it). Beginners often try to log `event.value` which is undefined!
  • Mention `event.target.checked` for checkboxes—an extremely frequent interview question.

React Masterclass › Day 3 › Passing Arguments
Essential Technique

Passing Arguments to Event Handlers

How do we pass an ID or specific value to a handler function without triggering it immediately?

✕ INCORRECT — Executes Instantly
WrongArgument.jsx
function UserList() {
  function deleteUser(id) {
    console.log("Delete:", id);
  }

  // ❌ ERROR: Invoked during render with 10!
  return (
    <button onClick={deleteUser(10)}>
      Delete User 10
    </button>
  );
}
As soon as React parses the JSX, deleteUser(10) executes immediately. The return value (which is undefined) gets assigned to onClick!
✓ CORRECT — Wrap in Arrow Function
CorrectArgument.jsx
function UserList() {
  function deleteUser(id) {
    console.log("Delete:", id);
  }

  // ✓ CORRECT: Wrapped inside an arrow function
  return (
    <button onClick={() => deleteUser(10)}>
      Delete User 10
    </button>
  );
}
Execution Flow:
User Clicks → Arrow runs: () => ... → deleteUser(10)
Speaker Guidance — Slide 13:
  • This is a pivotal moment in the lecture. Emphasize: "Any time you need to pass an argument like an ID into an event handler, you MUST wrap it in an arrow function: `onClick={() => handleDelete(item.id)}`."

How child components communicate back to parent components by invoking functions received via props.

      </button>

}

→
3 Child listens for user click
→
4 Child invokes onDelete(id)
→
5 Parent executes & updates UI

React Masterclass › Day 3 › Conditional Rendering
Part 2 • Conditional Rendering

What is Conditional Rendering?

Conditional rendering means displaying different UI components or elements depending on specific state, props, or conditions.

Why Do Real Apps Need It?

Every web application you use daily constantly switches between different UI views based on live conditions:

Authentication: isLoggedIn === true → <Dashboard /> | false → <Login />
Data Fetching: isLoading === true → <Spinner /> | false → <DataTable />
Errors: error !== null → <AlertBanner /> | null → <Content />
Empty Lists: items.length === 0 → "No items found" | items.length > 0 → <List />
The 4 Main Techniques in React
  • 1. Traditional if / else: Best for full page swaps and early returns outside JSX.
  • 2. Ternary Operator (? :): Best for inline choosing between two alternative elements inside JSX.
  • 3. Logical AND (&&): Best for rendering an element only if a condition is true (otherwise nothing).
  • 4. Logical OR (||): Best for providing fallback display text when data is missing or empty.
Speaker Guidance — Slide 15:
  • Give students a real-world analogy: When you open Netflix or YouTube, if you aren't signed in, you see a "Sign In" button. Once signed in, it changes to your profile avatar. That is conditional rendering.
  • Assure them that React does not introduce a new language for conditions—it uses pure JavaScript!
React Masterclass › Day 3 › if Statement
Pattern 1

Conditional Rendering Using if

Using standard JavaScript if statements outside JSX with early returns.

EarlyReturn.jsx
function App() {
  const isLoggedIn = true;

  // Early return if authenticated
  if (isLoggedIn) {
    return (
      <div>
        <h1>Welcome to your Dashboard!</h1>
      </div>
    );
  }

  // Default return if not logged in
  return (
    <div>
      <h1>Please Login to continue.</h1>
    </div>
  );
}
When is `if` the Best Choice?
  • Early Guard Clauses: Exit early if data is still loading, unauthorized, or an error occurred.
  • Complex Business Logic: When calculating multiple conditions before choosing what UI tree to output.
  • Readability: Avoids cramming huge blocks of JSX into nested ternary operators.
Important Note: You cannot place a standard if statement directly inside JSX curly braces {if (x) ...}. In JSX, you must use expressions, which is why we look at variables and ternaries next!
Speaker Guidance — Slide 16:
  • Explain the difference between a statement (`if (x) { ... }`) and an expression (`x ? y : z`).
  • In JSX `{ }`, React only accepts JavaScript expressions that evaluate to a value. That's why `if` goes outside the return!
React Masterclass › Day 3 › Conditional Variables
Pattern 2

Conditional Variable Pattern

Compute your JSX in a variable outside the return statement, then embed {content} inside a shared layout.

VariableContent.jsx
function App() {
  const isLoggedIn = false;

  // 1. Declare variable to hold JSX
  let content;

  // 2. Assign JSX based on condition
  if (isLoggedIn) {
    content = <Dashboard />;
  } else {
    content = <Login />;
  }

  // 3. Render common wrapper + dynamic content
  return (
    <div className="app-layout">
      <Navbar />
      <main>{content}</main>
      <Footer />
    </div>
  );
}
Advantages of this Pattern
  • No Code Duplication: Notice that <Navbar /> and <Footer /> are written only once, rather than repeated in two separate return statements.
  • Clean JSX Tree: The main JSX markup remains clean and uncluttered by avoiding nested logic.
  • Scalable: You can add multiple else if branches (e.g. for Admin, Editor, Guest) cleanly above the return.
Speaker Guidance — Slide 17:
  • Remind students that JSX elements (``) are just JavaScript objects behind the scenes. You can assign them to variables, pass them as arguments, or store them in arrays.
React Masterclass › Day 3 › Ternary Operator
Pattern 3

The Ternary Operator

The standard inline syntax for choosing between two values or UI elements inside JSX.

Ternary Syntax Formula
condition ? trueValue : falseValue
1. conditionExpression evaluated to truthy or falsy
2. ? (Question mark)If TRUE, execute/render the left branch
3. : (Colon)If FALSE, execute/render the right branch
TernaryInline.jsx
function App() {
  const isLoggedIn = true;

  return (
    <div className="header-nav">
      {/* Inline ternary directly in JSX */}
      {isLoggedIn ? (
        <Dashboard />
      ) : (
        <Login />
      )}
    </div>
  );
}
Speaker Guidance — Slide 18:
  • Because the ternary operator is an EXPRESSION (it resolves to a single value), it is 100% legal to embed inside JSX curly braces.
  • Teach them to format multi-line ternaries neatly with parentheses for readability.

React Masterclass › Day 3 › Logical AND (&&)
Pattern 4

Logical AND (&&) Operator

Use && when you want to render an element only when a condition is true, and render nothing when false.

LogicalAnd.jsx
function Notification({ hasUnreadMessages, unreadCount }) {
  return (
    <div>
      <h2>Inbox</h2>

      {/* Renders badge ONLY if hasUnreadMessages is TRUE */}
      {hasUnreadMessages && (
        <span className="badge">
          {unreadCount} New Messages!
        </span>
      )}
    </div>
  );
}
Short-Circuit Evaluation Truth Table
ConditionOperatorElementResult in DOM
true && <Badge /> Renders <Badge />
false && <Badge /> Renders nothing (ignored)
Why does this work? In JavaScript, true && expression evaluates directly to expression. Conversely, false && expression short-circuits to false. React automatically ignores boolean false during JSX rendering!
Speaker Guidance — Slide 20:
  • Remind students that `null`, `undefined`, and `false` are valid JSX children that render absolutely nothing on screen.
  • Plant the seed for the upcoming common trap: What happens if condition is `0`? We will explore that in Slide 42.
React Masterclass › Day 3 › Loading Pattern
Real World Pattern

The Loading State Pattern

Providing immediate visual feedback while asynchronous operations or data requests are pending.

LoadingExample.jsx
function UserCard({ loading, user }) {
  return (
    <div className="card">
      {/* 1. Show spinner if loading is true */}
      {loading && (
        <div className="spinner">
          Loading user profile...
        </div>
      )}

      {/* 2. Show user details once loading finishes */}
      {!loading && (
        <div>
          <h3>{user.name}</h3>
          <p>{user.email}</p>
        </div>
      )}
    </div>
  );
}
Best Practices for Loading UX
  • No Blank Screens: Never leave users staring at an empty white screen while data is loading.
  • Skeleton Screens / Spinners: Use loaders to communicate that the system is actively working.
  • Disable Buttons: Combine loading states with disabled props on buttons (disabled={loading}) to prevent accidental duplicate submissions.
Speaker Guidance — Slide 21:
  • Ask students: "What happens when you click Submit on a slow 3G connection?" If there's no loading state, users click it 5 times and create 5 duplicate orders!
React Masterclass › Day 3 › Logical OR Fallback
Pattern 5

Logical OR (||) Fallback

Provide sensible default values when dynamic data properties are missing, undefined, or empty.

FallbackDemo.jsx
function UserProfile({ user }) {
  // If user.name is empty/falsy, fallback to "Guest"
  const displayName = user.name || "Guest";

  return (
    <div className="profile-header">
      {/* Embedded directly in JSX */}
      <h2>Welcome, {user.name || "Valued Customer"}!</h2>

      <p>
        Bio: {user.bio || "No biography provided yet."}
      </p>
    </div>
  );
}
Defensive React Programming
  • Prevents UI Gaps: Protects your UI layout from looking broken when optional fields are omitted.
  • Nullish Coalescing (??): In modern JS, you can also use ?? if you want to allow empty strings "" or 0 as valid inputs without falling back.
  • Clean Code: Avoids writing verbose user.name ? user.name : "Guest" ternaries.
Speaker Guidance — Slide 22:
  • Show how `||` acts as a safety net for profile headers, user avatars, and default labels.
React Masterclass › Day 3 › Conditional Components
Architecture

Rendering Conditional Components

Conditions don't just change text—they dynamically swap entire subtrees of components.

RoleBasedView.jsx
function MainScreen({ userRole }) {
  return (
    <div className="container">
      <Header />

      {/* Entire components swapped conditionally */}
      {userRole === "admin" ? (
        <AdminControlPanel />
      ) : (
        <StandardUserDashboard />
      )}

      <Footer />
    </div>
  );
}
Component Unmounting & Mounting

When a condition changes in React, the previously rendered component is completely unmounted from the DOM, and the new component is mounted.

userRole changesState/prop updates from "user" to "admin"
Unmount<StandardUserDashboard /> removed from DOM
Mount<AdminControlPanel /> inserted into DOM

Clean Code Rules

Avoid Nested Ternary Hell

While JavaScript allows chaining ternaries, doing so inside JSX quickly produces unreadable "pyramids of doom".

✕ MESSY — Deeply Nested Ternaries 
{/* Hard to read, scan, and debug */}
{loading ? (
  <LoadingSpinner />
) : error ? (
  <ErrorMessage />
) : isGuest ? (
  <GuestView />
) : (
  <FullDashboard />
)}
✓ CLEAN — Guard Clauses or Sub-Components 
// Clear, early exits before JSX return:
if (loading) return <LoadingSpinner />;
if (error)   return <ErrorMessage />;
if (isGuest) return <GuestView />;

return <FullDashboard />;
Golden Summary for Conditional Rendering
Binary choice (A vs B): Use condition ? <A/> : <B/>
Show if true: Use condition && <A/>
Multi-condition: Use if / else guard clauses

React Masterclass › Day 3 › The JSX Problem
Part 3 • React Fragment

The Single-Root JSX Constraint

React components must return a single enclosing root element. Attempting to return adjacent siblings causes a syntax error.

✕ SYNTAX ERROR: Adjacent Siblings
SyntaxError.jsx
function Header() {
  // ❌ ERROR: Adjacent JSX elements must be
  // wrapped in an enclosing tag!
  return (
    <h1>Welcome</h1>
    <p>Explore your dashboard.</p>
  );
}
Why Does This Happen?

Remember that JSX is syntactic sugar for JavaScript function calls. Under the hood, Babel or Vite transpiles JSX into:

React.createElement('h1', null, 'Welcome')

A JavaScript function cannot return two separate values at the same time:
return a, b; // Invalid
Everything returned from a function must be encapsulated inside one single container!

Speaker Guidance — Slide 27:
  • Connect JSX to raw JavaScript: "If I ask you to write `function test() { return 1 2; }`, it's a syntax error. React components are just JavaScript functions!"
React Masterclass › Day 3 › The Extra <div>
DOM Bloat

The Extra <div> Problem

Wrapping everything in a <div> fixes the syntax error, but pollutes the DOM tree with unnecessary nodes.

DivWrapper.jsx
function Header() {
  // Works syntactically, BUT adds a pointless <div>
  return (
    <div>
      <h1>Welcome</h1>
      <p>Explore your dashboard.</p>
    </div>
  );
}
Why is "div soup" bad?
  • Breaks CSS Grid & Flexbox: CSS layout rules rely on parent-to-direct-child relationships. An intermediate <div> breaks your grid columns!
  • Invalid HTML Semantics: Elements like <table>, <tr>, <ul>, and <dl> cannot have arbitrary <div> wrappers inside them according to W3C standards.
  • DOM Bloat & Performance: Thousands of useless elements increase memory consumption and slow down browser reflows.

  • Illustrate with CSS Flexbox: If the parent has `display: flex`, and the child component returns a wrapper `
    `, the flex items become trapped inside that wrapper instead of aligning with the parent flexbox!

Fragment with Key in Lists

When mapping an array where each item needs to return multiple sibling elements without a wrapper container.

The Fatal Fragment Mistake
< key={user.id}> <!-- SYNTAX ERROR -->

The short syntax <> does not have a tag name to attach attributes to. If you write < key={...}>, the JSX parser fails with a fatal compilation error.

Always write: <Fragment key={user.id}>

React Masterclass › Day 3 › Event Mistakes
Traps & Pitfalls

Common Event Mistakes

Four dangerous event traps that catch almost every beginner developer.

Mistake 1: Immediate Invocation
<button onClick={handleClick()}> ❌

Runs immediately on render. Fix: onClick={handleClick}.

Mistake 2: Missing Arrow Wrapper for Arguments
<button onClick={deleteUser(id)}> ❌

Runs with ID during render! Fix: onClick={() => deleteUser(id)}.

Mistake 3: Forgetting preventDefault()
function handleSubmit() { /* missing e.preventDefault() */ } ❌

Browser reloads the page, wiping all React component state! Fix: e.preventDefault().

Mistake 4: Lowercase Event Casing
<button onclick={handleClick}> ❌

React requires camelCase event props! Fix: onClick, onChange.

  • Review these 4 traps carefully. Every single one has caused hours of debugging for beginners.
React Masterclass › Day 3 › Conditional Traps
Subtle Bugs

The Infamous "0" in the DOM Trap

Why writing {items.length && <List />} accidentally prints the number 0 on screen.

✕ THE "0" TRAP 
function TodoList({ todos }) {
  // When todos.length is 0, this evaluates to:
  // 0 && <List /> === 0
  return (
    <div>{todos.length && <List />}</div>
  );
}
Why 0 renders: In JavaScript, numbers are valid content! React ignores booleans (false), but React always renders numbers (including 0). So your users see an awkward "0" floating on the page!
✓ SAFE SOLUTIONS 
// Option A: Compare with > 0 (produces boolean true/false)
{todos.length > 0 && <List />}

// Option B: Explicit Boolean() conversion
{Boolean(todos.length) && <List />}

// Option C: Ternary with null
{todos.length > 0 ? <List /> : null}
Golden Rule: Never use a bare numeric length with &&. Always make it an explicit comparison: array.length > 0 && ...!
Speaker Guidance — Slide 42:
  • This is one of the most famous React gotchas. Junior devs frequently open bugs saying "Why is there a stray 0 at the bottom of my navbar?". Answer: `unreadCount && ` when unreadCount is 0!

Pass function without invoking:
<button onClick={handleClick}>Click</button>
Events
onClick with Arguments (ID)
Wrap in arrow function to defer call:
<button onClick={() => deleteUser(id)}>Del</button>
Events
onChange (Form Inputs)
Captures input keystrokes:
<input onChange={(e) => setVal(e.target.value)} />
Events
onSubmit & preventDefault()
Prevents browser page reload:
function handleSubmit(e) {
  e.preventDefault();
}
Conditions
Ternary Operator (? :)
Choose between two elements:
{isLoggedIn ? <Dashboard /> : <Login />}
Conditions
Logical AND (&&)
Render element only if condition is true:
{hasError && <p className="err">Error!</p>}
Conditions
Logical OR (||) Fallback
Safe default text:
<h2>Hello, {user.name || "Guest"}!</h2>
Conditions
Safe Array Length Check
Avoid rendering "0" in the DOM:
{items.length > 0 && <ItemList />}
Fragments
Short Fragment Syntax
Zero extra DOM wrapper elements:
<>
  <h1>Title</h1>
  <p>Description</p>
</>
Fragments
Explicit Fragment with Key
Required when mapping lists of siblings:
<Fragment key={item.id}>
  <dt>{item.term}</dt>
  <dd>{item.desc}</dd>
</Fragment>

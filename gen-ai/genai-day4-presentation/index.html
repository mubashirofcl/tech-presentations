Section 1 • Foundations

What Is Prompt Engineering?

Definition & Core Meaning

Prompt Engineering is the practice of designing, structuring, and refining the instructions provided to an AI model to produce useful, accurate, and relevant responses.

  • What is a Prompt? A prompt is the exact input text or instruction we supply to an AI model.
  • The Core Principle Better instructions produce better results. The model does not read our minds; it responds to our words!
Prompt Evolution Example:
• Weak prompt: "Tell me about Node.js."
• Improved prompt: "Explain Node.js to a beginner in simple English. Include its definition, three important features, and one practical example."
Prompt to Model Response Pipeline
1. Input Prompt
"Explain Express simply"
→
2. AI Model
Follows instructions
→
3. Target Output
Clear, actionable reply
Why Programmers Need Prompt Engineering

In traditional code, we write deterministic logic. In GenAI applications, our Node.js backends construct prompts dynamically. Writing precise prompts is the new form of specification design!

Section 1 • Foundations

Why Is Prompt Engineering Important?

5 Factors Determining Response Quality

An AI model does not automatically know our target audience or technical goals. The response depends directly on:

  • 1. Task Clarity: How clearly we state what to do.
  • 2. Relevant Context: What background information is provided.
  • 3. Explicit Instructions: How the task must be completed.
  • 4. Output Format: Plain text, bullet points, or structured JSON.
  • 5. Constraints: Word limits, library restrictions, or forbidden terms.
Contrast:
• Prompt A: "Write something about JavaScript." → (Vague, unfocused)
• Prompt B: "Write a 100-word introduction to JavaScript for a beginner. Use simple English and include two real-world applications." → (Crisp, targeted)
Diagram 3 • The Prompt Engineering Iteration Cycle
Step 1 Understand Task: Clarify user intent, target audience, and output goal.
Step 2 Build Prompt: Combine role, task, context, and clear constraints.
Step 3 Send to Model: Execute via Node.js API (client.responses.create).
Step 4 Review Response: Check for hallucinations, formatting flaws, or vagueness.
Step 5 Refine Prompt: Add negative constraints or few-shot examples and re-test.

          Section 2 • Prompt Construction
          
System Prompt vs User Prompt

        


        

          

            

              
System Prompt (Instructions)

              

                Defines the model's overall role, persona, tone, and high-level boundaries across requests.
              

              

                

                  Example: "You are a helpful programming tutor. Always explain technical concepts using simple English."
                

                

                  Where it lives: Passed in the instructions parameter in the OpenAI SDK.
                

              

            


            

              
User Prompt (Input)

              

                Contains the specific question or task provided dynamically by the end-user.
              

              

                

                  Example: "What is an Express middleware?"
                

                

                  Where it lives: Passed in the input parameter in the OpenAI SDK.
                

              

            


            

              Important Caveat: System instructions guide behavior; they do not guarantee that the model will follow every instruction 100% of the time.

          Section 2 • Prompt Construction
          
Context, Instructions and Constraints

        


        

          

            

              
Three Roles Solving Different Problems

              
    
                
  • 
                  1. Context (What should the AI know?)
                  Provides relevant background so the model doesn't make assumptions.
    
                  Example: "I am teaching Node.js to students who know JavaScript but are new to Express."
                
    • 
                
  • 
                  2. Instructions (What should the AI do?)
                  Specifies the exact procedure and educational deliverables.
    
                  Example: "Explain Express routing step by step with a practical example."
                
    • 
                
  • 
                  3. Constraints (What boundaries must it respect?)
                  Rules that prevent unwanted libraries, bloated text, or off-topic tangents.
    
                  Example: "Use CommonJS, avoid MongoDB, and keep the example beginner-friendly."
                
    • 
              

            

          


          

            

              
The Unified Production Prompt

              

                "You are teaching Node.js to students who know JavaScript but are new to Express. Explain Express routing step by step using CommonJS. Include a runnable example and do not use MongoDB."
              


              

                

                  
                    
ElementPurposeRisk If Missing

InstructionsDefines exact taskRambling explanations

          Section 3 • Practical Basic API
          
Practical 2: Build POST /ask

        


        

          

            

              

                

                  

                  server.js
                  JAVASCRIPT
                

                

              

              

                
require("dotenv").config();
const express = require("express");
const OpenAI = require("openai");

const app = express();
app.use(express.json());

const client = new OpenAI({
  apiKey: process.env.OPENAI_API_KEY
});

app.post("/ask", async (req, res) => {
  try {
    const { question } = req.body;

    if (!question) {
      return res.status(400).json({
        message: "Question is required"
      });
    }

    const response = await client.responses.create({
      model: process.env.OPENAI_MODEL,
      input: question
    });

    res.json({
      answer: response.output_text
    });
  } catch (error) {
    console.error(error);
    res.status(500).json({
      message: "AI request failed"
    });
  }
});

app.listen(process.env.PORT || 3000, () => {
  console.log("Server running on port 3000");
});

          Section 4 • Prompt Techniques
          
Role Prompting: Establishing Perspectives

        


        

          

            

              
What Is Role Prompting?

              

                Role Prompting means instructing the AI model to respond from the perspective of
                a specific profession, persona, or viewpoint.
              

              
    
                
  • • Act as a Node.js Teacher: Patient, simplified explanations, relatable metaphors.
    • 
                
  • • Act as a Senior Software Engineer: Architectural tradeoffs, scalability, clean code.
    • 
                
  • • Act as a Technical Interviewer: Rigorous edge-case questions, evaluation criteria.
    • 
                
  • • Act as a Database Administrator: Indexing, connection pooling, security audits.
    • 
                
  • • Act as a Code Reviewer: Constructive critique, naming conventions, linting checks.
    • 
              

            


            

              Reality Check: Giving a model a role does not grant it real-world credentials or guarantee infallible expertise. It shapes style and focus.
            

          


          

            

              
Same Question, Two Different Personas


              

                
Question: "Explain REST APIs"

              


              

                

                  Without Role
                  "A REST API uses HTTP methods like GET and POST to transfer data representations over networks." (Generic)
                

                

                  With Role: Senior Dev
                  "In production microservices, think of REST as a contract: we use stateless JSON endpoints to decouple our frontend from our SQL database." (Pragmatic)

          Section 5 • Shot Prompting
          
Zero-Shot Prompting: Zero Examples

        


        

          

            

              
What Is Zero-Shot Prompting?

              

                Zero-shot prompting means asking an AI model to perform a task
                without providing any examples of the expected input-output format.
              

              
    
                
  • 
                  How the Model Answers
                  It relies completely on its pre-trained knowledge base and the direct instructions in the prompt.
                
    • 
                
  • 
                  When to Use
                  Great for simple questions, general translations, and straightforward text classifications.
                
    • 
              

            


            

              Concrete Example:

              Prompt: "Classify this review as Positive, Negative, or Neutral: 'The application is very easy to use.'"

              Expected Output: "Positive"
            

          


          

            

              
Core Characteristics of Zero-Shot


              

                

                  Fast & Simple
                  Requires minimal prompt engineering time and lowest token consumption.
                

                

                  No Demonstration Shots
                  We tell the model what to do, but we do not show it examples.
                

                

                  Potential Format Drift
                  Without examples, the model might reply: "The review is Positive!" instead of just "Positive".
                

              

            

          

        

      


      
      

        

          Section 5 • Shot Prompting
          
Few-Shot Prompting: Learning from Demonstrations

        


        

          

            

              
What Is Few-Shot Prompting?

              

                Few-shot prompting means embedding a small number of demonstration examples
                (shots) inside the prompt before asking the model to perform the final task.
              

              
    
                
  • 
                  In-Context Pattern Matching
                  The model analyzes the demonstration shots and matches the exact response pattern.
                
    • 
                
  • 
                  No Model Retraining
                  Weights remain frozen; the model learns purely "in-context" during runtime inference!
                
    • 
              

            

          


          

            

              

                

                  

                  Few-Shot Demonstration Prompt
                  PROMPT
                

                

              

              

                
Classify each review as Positive or Negative.

Example 1:
Review: The product is excellent.
Answer: Positive

Example 2:
Review: The application crashes frequently.
Answer: Negative

Now classify:
Review: The service is really helpful.
Answer: [Model Outputs: Positive]

              

            

          

        

      


      
      

        

          Section 5 • Shot Prompting
          
Zero-Shot vs Few-Shot: Comparison Guide

        


        

          

            

              

                
                  

                    Dimension
                    Zero-Shot
                    Few-Shot
                  

                
                
                  

                    Examples Included
                    0 examples
                    2 to 5 curated examples
                  

                  

                    Prompt Length
                    Shorter (saves input tokens)
                    Longer (costs more input tokens)
                  

                  

                    Format Control
                    Moderate
                    High & Consistent
                  

                  

                    Best For
                    General Q&A, common tasks
                    Custom schemas, edge-case rules
                  

                  

                    Setup Effort
                    Minimal
                    Requires creating good examples
                  

                
              

            


            

              Quality Over Quantity: 2 clear, accurate examples are far more effective than 10 messy, conflicting examples!

          Section 5 • Practical Comparison
          
Practical Comparison: Zero-Shot vs Few-Shot

        


        

          

            

              
Testing the Same Mixed Review

              

                Target Review: "The application is useful, but it crashes sometimes."
              

              

                This sentence has conflicting emotional valence: "useful" (positive) vs "crashes" (negative).
              

              
    
                
  • 
                  Zero-Shot: Lacking guidance, the model may anchor on "useful" and return Positive, or get indecisive.
                
    • 
                
  • 
                  Few-Shot: By demonstrating how mixed feedback maps to Neutral, the model adheres strictly to your expected business logic!

          Section 6 • Best Practices
          
Common Prompt Engineering Mistakes

        


        

          

            

              
7 Traps to Avoid

              
    
                
  • 1. Vague Prompts: "Tell me about coding." (Far too broad).
    • 
                
  • 2. Missing Context: Expecting custom answers without providing your framework version.
    • 
                
  • 3. Conflicting Instructions: "Explain in depth in only 5 words."
    • 
                
  • 4. Unspecified Formats: Wanting JSON but not telling the model to return JSON.
    • 
                
  • 5. Prompt Clutter: Dumping 500 lines of irrelevant logs that confuse the model.
    • 
                
  • 6. Contradictory Examples: Few-shot examples that contradict your instructions.
    • 
                
  • 7. Blind Trust: Assuming AI output is always correct without schema validation.
    • 
              

            

          


          

            

              
The Professional Prompt Checklist


              

                

                  ✓
                  Clear Task: Use active action verbs (e.g. Classify, Extract, Summarize).
                

                

                  ✓
                  Targeted Context: Provide only the relevant facts needed for this turn.
                

                

                  ✓
                  Explicit Schema: Specify exact output keys (e.g. { "status": ..., "code": ... }).
                

                

                  ✓
                  Negative Constraints: Tell the model what not to do (e.g. "Do not use external libraries").
                

                

                  ✓
                  Sanitize in Node.js: Always wrap responses in validation layers (Zod / JSON.parse).

Section 1 AI Agent Fundamentals

What is an AI Agent?

Moving beyond static text generation to goal-oriented decision making and execution

AGENT DEFINITION
💡 Passive LLM vs Autonomous Agent

An AI Agent is a system that uses an AI model to understand a goal, make decisions, and perform actions in an environment to achieve that goal.

1
Understand: Interprets the user's ultimate goal from natural language.
2
Decide: Evaluates what steps and external capabilities are required.
3
Select Tool: Chooses a tool and formats exact arguments.
4
Execute & Observe: The host application executes the tool and returns the outcome.
5
Answer: Continues the loop until the final answer is ready.
🛒 Concrete Scenario Walkthrough

User Request: "Find the total price of 3 products, each costing ₹500."

Agent Execution Trace:
  • Reasoning: Needs mathematical multiplication (500 × 3).
  • Tool Selected: calculate({ a: 500, b: 3, operation: "multiply" })
  • Observation: Backend executes function, returns 1500.
  • Reasoning: Calculation complete, no further tools required.
  • Final Answer: "The total price for 3 products at ₹500 each is ₹1500."
Key Definition
An AI agent is not just an LLM. It is a system combining an AI model, system instructions, tools, context, and an execution loop.

What is an Agent Loop?

The iterative cycle through which an agent makes decisions, executes tools, and completes goals

EXECUTION LOOP
1. Decide LLM evaluates prompt & decides whether a tool is required
2. Tool Call Model generates function name & JSON arguments
3. Execute Node.js backend runs JavaScript function safely
4. Observe Tool output injected back into messages context
5. Evaluate Task done? Return answer. More work? Loop again!
🔍 The 5 Essential Stages Explained
  • 1. Decide: The LLM reads instructions, history, and available tool schemas to formulate a plan.
  • 2. Tool Selection: If external data or calculations are needed, the LLM emits a structured tool call.
  • 3. Observation: Node.js parses arguments, calls the local function, and gathers the result.
  • 4. Decide Again: The LLM inspects the tool result: does it answer the prompt, or is another tool required?
  • 5. Final Answer: When no further tools are requested, the LLM responds in natural conversational text.
🧮 Concrete Calculation Walkthrough

Prompt: "Calculate total price of 5 products costing ₹200 each."

A
Decide: Arithmetic needed -> Call calculate(5, 200, "multiply").
B
Observe: Node.js returns 1000.
C
Decide Again: Goal satisfied. No additional tools needed.
D
Answer: "The total price of 5 products at ₹200 each is ₹1000."

What is Autonomous Action?

Executing multi-step sequences independently while establishing necessary safety boundaries

AUTONOMY & SAFETY
🪜 Levels of Agent Autonomy
Level System Behavior
Basic Responds to direct user prompts with plain text.
Tool-Assisted Uses a single tool when explicitly requested.
Multi-Step Performs a sequence of actions toward a goal.
Autonomous Plans, executes, evaluates, and self-corrects steps.
Multi-Step Example
User: "Find total price of these products and tell me if our budget of ₹2000 is enough."
1. Reads product prices → 2. Calculates sum → 3. Compares with budget → 4. Answers!
🛡️ Critical Safety: Guardrails & Human-in-the-Loop

Autonomy does not mean unlimited permission. In production, agents must never execute irreversible actions without explicit confirmation.

⚠️ High-Risk Actions Requiring User Confirmation:
  • Sending real emails or external messages.
  • Processing payments or financial transactions.
  • Deleting records from databases.
  • Modifying user account passwords or permissions.
Engineering Principle
Read actions (calculating, querying) can be automated; write/delete actions must require authentication and user approval.

What is Agent State?

Capturing the real-time execution snapshot while performing multi-step tasks

AGENT STATE
📌 State: The Current Snapshot

Agent state is the structured information that represents the agent's current situation, progress, and intermediate data while performing a task.

agentState.js
// State initialized at start of task
const agentState = {
  goal: "Find student 101 and calculate score",
  studentId: 101,
  selectedTool: "get_student",
  toolResult: null,
  completed: false
};

// State updated after tool execution
agentState.toolResult = { name: "Ali", marks: 85 };
agentState.completed = true;
⚙️ Why Do Agents Need State?
1
Track Current Task: Remembers what the overarching goal is during intermediate steps.
2
Store Intermediate Outputs: Holds API responses needed for subsequent steps.
3
Prevent Duplicate Actions: Records which tools have already been executed.
4
Check Completion: Evaluates if task goals are satisfied.
Core Insight
State describes what is happening right now in the active task execution.
Section 2 State, Memory & Context

State vs Memory vs Chat History vs RAG

Clear distinction between task execution, retained facts, conversation logs, and external retrieval

THE 4 CONCEPTS
1. Agent State Current Task

Temporary information tracking the active execution step and intermediate tool data.

State: Currently querying student 101 records.
2. Memory Retained Facts

Useful facts or preferences remembered across turns or future sessions.

Memory: User's name is Ali; prefers concise responses.
3. Chat History Message Log

Verbatim sequence of previous user and assistant messages in the session.

History: [{ role: "user", content: "Hi" }, { role: "assistant", ... }]
4. RAG (Retrieval) External Knowledge

Retrieval-Augmented Generation: searching external documents/databases to augment prompt.

RAG: Fetching course handbook PDF excerpt for syllabus details.
Crucial Distinction
RAG is a retrieval technique, not a memory type. An agent can use RAG to query external documentation, while using memory to remember who the user is.
Section 2 State, Memory & Context

Short-Term Memory vs Long-Term Memory

Session-based in-memory caching vs durable cross-session persistent storage

MEMORY HORIZONS
⏱️ Short-Term Memory

Information needed strictly during the current conversation session or active task.

  • • Current user query and recent 5–10 messages.
  • • Active task execution step and intermediate tool results.
  • • Stored in: Server RAM (e.g., JavaScript Map or Redis session).
  • • Lifecycle: Lost when conversation ends or server restarts.
Limitation
In-memory JavaScript Maps are ephemeral. Server crashes or deployments instantly wipe them out.
💾 Long-Term Memory

Information retained across future conversations, days, or weeks.

  • • User profile preferences (preferred language, role).
  • • Historical interaction summaries and past completed tasks.
  • • Stored in: Persistent database (PostgreSQL, MongoDB, Vector DB).
  • • Lifecycle: Permanent until explicitly deleted.
Implementation Rule
Long-term memory requires durable database storage. Never rely on Node.js process variables for long-term data.

What is Context?

The complete body of information assembled and delivered to the LLM for a given prompt

CONTEXT ASSEMBLY

An LLM has no memory between API calls. Context is everything you assemble and send into messages so the model can generate an accurate response.

Section 2 State, Memory & Context

Context Window and Its Limits

Understanding token budgets, cost implications, and attention degradation

TOKEN BUDGET
🪙 What is a Token?

LLMs do not read words or characters directly; they process tokens (sub-word fragments).

Text: "Hello, how are you?"
Tokens: ["Hello", ",", " how", " are", " you", "?"] (6 tokens)
  • ~1000 tokens ≈ 750 English words.
  • Code and non-English scripts often require significantly more tokens per word.
⚠️ Why Context Limits Matter
  • Token Overflow: Exceeding max model window results in hard API rejection errors.
  • Rising Latency & Cost: Processing 64k tokens costs exponentially more time and money than 2k tokens.
  • "Lost in the Middle": Models pay highest attention to the start and end of context; middle facts can be missed.
  • Output Space: The context window covers input tokens + generated output tokens combined.
Engineering Truth
A larger context window does not automatically mean better reasoning. Focused, clean context outperforms bloated dumps every time.

Context Management Techniques

Five proven strategies to keep prompts concise, relevant, and budget-efficient

CONTEXT STRATEGIES
🛠️ 5 Core Context Management Strategies
1
Sliding Window: Keep only the latest N messages (e.g. history.slice(-10)). Discard oldest turns.
2
Summarization: Periodically condense older messages into a 2-sentence summary using a fast model.
3
Semantic Retrieval (RAG): Only fetch documents and facts specifically relevant to current query.
4
Tool Output Pruning: Truncate massive JSON outputs before feeding them back into context.
5
Token Budget Caps: Monitor cumulative token counts before sending each API payload.
✨ Practical Compaction Example
// Instead of sending 100 raw messages:

[System Summary]
"User is Ali, studying MERN Stack. Prefers brief Node.js code examples."

[Recent Turns - Last 4]
User: "How do I add tools?"
Agent: "Provide a tools array to Groq."
User: "Can you give me an example?"
Cuts token usage by up to 90%!

Section 3 Practical Implementation

Understanding Tools and Tool Schemas

Crafting JSON Schema contracts that explain parameters and constraints to the LLM

TOOL SCHEMAS
📋 Calculator Tool Schema Definition
toolSchema.js
const calculatorTool = {
  type: "function",
  function: {
    name: "calculate",
    description: "Add two numbers together",
    parameters: {
      type: "object",
      properties: {
        a: { type: "number", description: "First number" },
        b: { type: "number", description: "Second number" }
      },
      required: ["a", "b"],
      additionalProperties: false
    }
  }
};
🔍 What the Schema Communicates
  • name: Identifier used by the model to request this specific function.
  • description: Tells the model when and why to choose this tool over others.
  • properties: Defines required argument keys and their strict data types (number, string).
  • required: Guarantees the LLM provides both a and b.
Contract Notice
The schema is a contract. While modern models follow schemas accurately, your backend must still validate types before execution.
Section 3 Practical Implementation

Implementing Tools & The Tool Registry

Writing JavaScript functions and binding them securely through a lookup map

TOOL REGISTRY
⚙️ JavaScript Tool Implementations
tools.js
// Sample mock student database
const students = [
  { id: 101, name: "Ali", course: "MERN Stack" },
  { id: 102, name: "Sara", course: "Python" }
];

// Tool 1: Math Calculator
function calculate(a, b) {
  if (typeof a !== "number" || typeof b !== "number") {
    throw new Error("Invalid numbers provided");
  }
  return a + b;
}

// Tool 2: Database Finder
function getStudent(studentId) {
  const student = students.find(s => s.id === studentId);
  return student || { error: "Student not found" };
}

// Secure Tool Registry Map
const toolFunctions = {
  calculate: ({ a, b }) => calculate(a, b),
  get_student: ({ studentId }) => getStudent(studentId)
};
🛡️ Security: The Registry Pattern

Notice that tool names map directly into toolFunctions[toolName].

Never Use eval()!
Never use eval() or execute arbitrary dynamic string function calls requested by an AI model. Only execute functions registered in your explicit whitelist dictionary.
  • ✓ Whitelisted function execution only.
  • ✓ Protects against prompt injection attacks.

Executing the Tool & Observing the Result

Parsing JSON arguments, executing the registered function, and capturing output

TOOL EXECUTION
⚡ Execution Logic in Node.js
executeTool.js
const message = response.choices[0].message;

if (message.tool_calls) {
  for (const toolCall of message.tool_calls) {
    const toolName = toolCall.function.name;
    const toolFunction = toolFunctions[toolName];

    if (!toolFunction) {
      throw new Error(`Unknown tool: ${toolName}`);
    }

    // Parse JSON string arguments
    const args = JSON.parse(toolCall.function.arguments);

    // Execute function and observe outcome
    const result = await toolFunction(args);
    console.log("Tool Result:", result); // 300
  }
}

Returning the Tool Result to the LLM

Constructing the tool role message and calling Groq for final natural synthesis

TOOL RESPONSE
📬 Formatting the Tool Response Message
returnResult.js
// 1. Push model's tool call message into history
messages.push(message);

// 2. Push tool result with role: "tool" & matching tool_call_id
messages.push({
  role: "tool",
  tool_call_id: toolCall.id,
  name: toolCall.function.name,

const finalResponse = await groq.chat.completions.create({
  model: "openai/gpt-oss-120b",
  messages
});

// Output: "The total of 100 and 200 is 300."
🔑 Why the Tool Result Must Be Sent Back
  • The LLM needs the result in its context window to summarize and explain it to the human user.
  • tool_call_id connects the result directly to the specific invocation requested by the model.
  • content must be a string (use JSON.stringify for objects and numbers).

The Complete Agent Loop Architecture

Unifying multi-step cycles, implementing step limits, and handling termination

AGENT LOOP STATE
🔄 Complete Multi-Step Flowchart
👤 User Request Received
↓
🧠 LLM Evaluates & Decides
↓
❓ Tool Requested?
No → Return Final Answer
Yes → Run Tool → Feed Back → Loop Again
🛑 Mandatory Guardrail: Step Limits

Production agents must always establish a strict maximum step limit:

stepGuard.js
const MAX_STEPS = 3;

for (let step = 0; step < MAX_STEPS; step++) {
  // Call Groq...
  if (!message.tool_calls?.length) {
    return res.json({ answer: message.content });
  }
  // Run tools...
}
Why MAX_STEPS is Mandatory
Prevents infinite loops if the model repeatedly re-requests failing tools, protecting server resources and API budgets.

Complete Tool-Using Agent Implementation

Production-ready Express server with live interactive simulator embedded in the slide

PROJECT 1 DEMO
💻 Complete server.js Source Code
server.js
require("dotenv").config();
const express = require("express");
const Groq = require("groq-sdk");

const app = express();
app.use(express.json());

const groq = new Groq({ apiKey: process.env.GROQ_API_KEY });

// Tool registry & schemas defined...
app.post("/api/agent", async (req, res) => {
  try {
    const { question } = req.body;
    const messages = [
      { role: "system", content: "You are a helpful student assistant. Use tools when needed." },
      { role: "user", content: question }
    ];

    const MAX_STEPS = 3;
    for (let step = 0; step < MAX_STEPS; step++) {
      const response = await groq.chat.completions.create({
        model: "openai/gpt-oss-120b",
        messages, tools, tool_choice: "auto"
      });
      const msg = response.choices[0].message;
      messages.push(msg);

      if (!msg.tool_calls?.length) {
        return res.json({ answer: msg.content });
      }

      for (const call of msg.tool_calls) {
        const fn = toolFunctions[call.function.name];
        const args = JSON.parse(call.function.arguments);
        const result = await fn(args);
        messages.push({
          role: "tool",
          tool_call_id: call.id,
          name: call.function.name,
          content: JSON.stringify(result)
        });
      }
    }
  } catch (err) {
    res.status(500).json({ error: err.message });
  }
});
app.listen(3000, () => console.log("Server ready"));

Implementing Session Memory in Node.js

Using JavaScript Map for key-value conversation caching and sliding window truncation

SESSION MEMORY
🗂️ The Session Storage Implementation
sessionManager.js
// Step 1: Create session storage map
const sessions = new Map();

// Step 2: Get or initialize session history
function getSession(sessionId) {
  if (!sessions.has(sessionId)) {
    sessions.set(sessionId, []);
  }
  return sessions.get(sessionId);
}

// Step 3: Append user message
const history = getSession("session-101");
history.push({ role: "user", content: "I am learning Node.js" });

// Step 4: Sliding window truncation (keep last 10 turns)
const recentHistory = history.slice(-10);
🔍 Why a Map?
  • ✓ O(1) Lookup: Instant retrieval by sessionId.
  • ✓ Sliding Window: .slice(-10) prevents token bloat.
  • ✓ Isolation: Each user has an independent conversation history.
Important Note
A message count limit (e.g. 10 messages) is a simple context strategy. In production with long prompts, measure actual token count!

  }
});

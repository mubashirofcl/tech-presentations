Section 1 Quick Look at Workflows

What is an Agent Workflow?

The Assembly Line Analogy: Breaking Big Problems into Small, Easy Steps

WORKFLOW BASICS
🏭 The Factory Assembly Line

If you ask an AI in one giant prompt: "Read this 20-page document, do math calculations, check our SQL database, and email the client"—the AI will get confused and fail!

An Agent Workflow is simply like an assembly line in a car factory:

Step 1 Understand AI reads the request
→
Step 2 Verify Node.js checks DB
→
Step 3 Execute Send email/save
🛡️ Why This Makes Your Code Reliable
  • ✓ AI does what it's good at: Reading unstructured English and writing friendly replies.
  • ✓ JavaScript code does what it's good at: Exact math calculations, database queries, and checking passwords.
  • ✓ Easy to debug: If Step 2 fails, you immediately know where the bug is!
💡 Golden Rule: Never let AI do math or check permissions alone. Always let simple JavaScript code handle the strict checks!
Section 1 Quick Look at Workflows

Sequential vs Parallel Workflows

One Step at a Time vs Doing Independent Tasks Together

WORKFLOW PATTERNS
➡️ 1. Sequential Workflow (Step-by-Step)

Step B must wait for Step A to finish because it needs Step A's result.

A
Step A: Check user password.
B
Step B: If password correct, fetch profile.
C
Step C: Render user dashboard.
Analogy: Putting on your socks before putting on your shoes!
⚡ 2. Parallel Workflow (At the Same Time)

When tasks have no dependencies on each other, run them together using Promise.all() to save time!

1
Task 1: Check customer sentiment (Happy/Angry).
2
Task 2: Detect language (English/Spanish).
3
Task 3: Categorize topic (Billing/Tech Support).
🚀 All 3 tasks finish in ~1 second total instead of waiting 3 seconds!
⚡ Summary: If Task 2 needs Task 1's output → use Sequential. If tasks are independent → use Parallel.

Section 2 RAG Fundamentals

What is RAG? (The Open-Book Exam)

Retrieval-Augmented Generation Explained in Plain Everyday English

RAG BASICS
📖 What Does "RAG" Stand For?

RAG stands for Retrieval-Augmented Generation. Don't let the fancy name scare you! It just means:

R
Retrieval: Search your company files and find the right paragraphs.
A
Augmentation: Paste those paragraphs into the prompt alongside the question.
G
Generation: The AI reads those paragraphs and writes the answer!
🎓 The "Exam" Analogy
❌ Without RAG (Closed Book)

The AI has to guess from whatever it memorized years ago on Wikipedia. If you ask about your company's secret policy, it bluffs and guesses!

✅ With RAG (Open Book)

You open your company policy handbook to Page 14 and hand it to the AI. The AI reads the page and answers with 100% accuracy!

✨ Simple Definition: RAG is giving an AI the exact document it needs before asking it to answer!

What is Hallucination?

Why AI Confidently Lies & How RAG Keeps It 100% Honest

STOPPING HALLUCINATIONS
🎭 What is a Hallucination?

A Hallucination is when an AI doesn't know the answer, but instead of saying "I don't know", it invents a fake answer with complete confidence!

🤖
Why Does AI Do This?
An AI is not a database. It is a word-guessing machine. It predicts which word sounds good next. If it doesn't have the real facts, it invents something that sounds convincing!
🛡️ How RAG Stops Hallucinations

With RAG, we give the AI a very strict rule in the prompt:

"Answer the question ONLY using the facts in the <context> below.
If the context does not contain the answer, say strictly:
'I do not have this information in the documents.'"
🎯 The Grounding Guarantee: RAG forces the AI to stick to the facts written right in front of it!

The 3 Steps of RAG: Retrieve → Augment → Generate

How RAG Works Behind the Scenes in 3 Simple Steps

THE 3 STEPS
Step 1 1. Retrieve (Search)

The user types a question. The search engine searches your document library and finds the 2 or 3 paragraphs that talk about that topic.

Found: Page 14 of HR_Policy.pdf
Step 2 2. Augment (Combine)

Your code builds a new prompt combining the retrieved text + the user's question into one clean package:

Prompt: [Context: Page 14] + [Question]
Step 3 3. Generate (Answer)

The AI reads the prompt, extracts the exact facts from the context, and writes a helpful, grounded response to the user.

Answer: Clean, cited, and 100% accurate!
💡 Remember: Retrieve = Search the files • Augment = Paste into prompt • Generate = AI writes the answer.

Step 1: Loading Documents in Node.js

Reading Files from Disk into Plain JavaScript Strings

STEP 1 • LOAD
step1_load.js 
// 1. Reading a plain text or Markdown file
const fs = require('fs');
const rawText = fs.readFileSync('./policy.txt', 'utf-8');
console.log(`Loaded ${rawText.length} characters.`);

// 2. Reading a PDF file (using pdf-parse)
const pdfParse = require('pdf-parse');
async function loadPDF(filePath) {
  const buffer = fs.readFileSync(filePath);
  const data = await pdfParse(buffer);
  return data.text; // plain text string!
}
📦 How Simple It Is
  • • Text Files (.txt / .md): Use built-in fs.readFileSync(). No extra libraries needed!
  • • PDF Files (.pdf): Use pdf-parse. It turns binary PDF buffers into readable string text.
  • • Installation: Simply run npm install pdf-parse in your terminal.
✨ Goal of Step 1: Turn any file into a single plain JavaScript string!

Step 2: Cleaning the Text

Wiping Away Messy Spaces, Strange Symbols & Blank Lines

STEP 2 • CLEAN
step2_clean.js 
function cleanText(rawText) {
  if (!rawText) return '';

  return rawText
    // 1. Standardize line breaks
    .replace(/\r\n/g, '\n')
    // 2. Replace multiple spaces with a single space
    .replace(/[ \t]+/g, ' ')
    // 3. Avoid excessive empty lines (max 2)
    .replace(/\n{3,}/g, '\n\n')
    // 4. Trim leading and trailing spaces
    .trim();
}
🧹 Before vs After Cleaning
Dirty Text (Raw PDF)
"Leave    Policy\r\n\r\n\r\nSection  4.2"
Cleaned Text
"Leave Policy\n\nSection 4.2"
💡 Cleaning saves up to 20% of tokens and prevents the AI from getting confused by strange spaces!

Step 3: What is Text Chunking?

The "Index Card" Concept: Splitting Long Documents into Bite-Sized Pieces

STEP 3 • CHUNKING
📇 The Index Card Concept

Chunking simply means cutting a long text into smaller pieces (chunks), like writing paragraphs onto small index cards:

1
Card #1: Section 4.1 – Working Hours (350 chars)
2
Card #2: Section 4.2 – Annual Leave (320 chars)
3
Card #3: Section 4.3 – Sick Leave (340 chars)
🎯 Why Bite-Sized Cards are Perfect
  • ✓ Super Fast to Search: You search 50 small cards instead of re-reading a 50-page book.
  • ✓ High Relevance: Each card talks about ONE specific thing.
  • ✓ Saves Money: When the user asks about "Annual Leave", you only send Card #2 to the AI!
📏 Typical Size: 300 to 500 characters (about 50 to 80 words per card).
Section 3 Document Processing

Step 4: Chunk Size & Chunk Overlap

Why We Must Overlap Chunks So Sentences Don't Get Cut in Half!

CHUNK OVERLAP
⚠️ The Danger: Cutting a Sentence in Half!

If you cut text strictly every 300 characters, sentences get sliced right in the middle:

Card 1 ends with:
"...the main office will remain closed on"
(Incomplete! When is it closed?)
Card 2 starts with:
"Mondays and public holidays."
(Incomplete! What is closed?)
🛡️ The Fix: Chunk Overlap (10% to 20%)

We let consecutive chunks share 30–50 characters. This way, the boundary sentence appears on both cards:

Card 1: "...office will remain closed on Mondays and public holidays"
Card 2: "Mondays and public holidays due to city utility maintenance..."

Practical: Writing a Simple Chunking Function

A Beginner-Friendly Sliding Window Function in Pure JavaScript

PRACTICAL CODE
simpleChunker.js 
function splitText(text, chunkSize = 300, overlap = 50) {
  const chunks = [];
  const step = chunkSize - overlap; // e.g. 300 - 50 = 250
  let start = 0;

  while (start < text.length) {
    const end = Math.min(start + chunkSize, text.length);
    const piece = text.substring(start, end).trim();

    if (piece) chunks.push(piece);
    if (end >= text.length) break;

    start += step; // Slide forward by 250 characters!
  }

  return chunks;
}
🔍 How the Math Works

Notice line 3: const step = chunkSize - overlap.

1
Chunk 1: Takes characters 0 to 300.
2
Advance by Step: Advances by 250 (300 - 50).
3
Chunk 2: Takes characters 250 to 550.
✨ Characters 250–300 appear in both chunks, keeping the sentence intact!

Step 5: Adding Metadata to Chunks

Labeling Each Card So You Know Exactly Where It Came From

METADATA TAGS
🏷️ What is Metadata?

If you have 1,000 index cards scattered on a table without labels, you won't know which book or page they came from!

Metadata is just the sticky note attached to each chunk:

  • • source: The file name (e.g. HR_Policy.pdf)
  • • page: Page number (e.g. Page 14)
  • • department: Who it belongs to (e.g. "HR" or "Engineering")
  • • chunkIndex: Which piece it is (Chunk #1, #2...)
📋 Standard Chunk Object Schema
{
  "chunkId": "hr_policy_chk_001",
  "source": "HR_Policy_2025.pdf",
  "department": "Human Resources",
  "page": 14,
  "text": "Employees may carry forward a max of 5 days..."
}
🛡️ Security: Metadata lets you filter so regular employees cannot read executive documents!

Putting It All Together: Complete Document Processor

A Complete 15-Line Node.js Function for Ingesting Documents

COMPLETE PROCESSOR
processDocument.js 
// Complete 15-line Document Processor Function
function processDocument(fileName, rawText, department) {
  // 1. Clean the messy text
  const clean = cleanText(rawText);

  // 2. Split into 300-char chunks with 50-char overlap
  const pieces = splitText(clean, 300, 50);

  // 3. Attach metadata to every chunk
  return pieces.map((chunk, index) => ({
    chunkId: `${fileName}_chk_${index}`,
    source: fileName,
    department: department,
    chunkIndex: index,
    text: chunk
  }));
}
🚀 That's All There Is To It!

Notice how clean and simple production document processing really is:

1
Call cleanText() to sanitize whitespace.
2
Call splitText() to create overlapping pieces.
3
Call .map() to label each card with metadata!
📦 Output: Returns a clean JSON array of ready-to-search chunks!

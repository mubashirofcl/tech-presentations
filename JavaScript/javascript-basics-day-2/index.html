Core Foundation Memory Architecture

Reference vs Value in JavaScript

Understanding how primitives and objects behave in memory to prevent accidental mutations

MEMORY MODEL
📌 Primitives: Copied by Value

Numbers, strings, booleans, null, and undefined are stored directly in the execution stack. Copying creates an independent duplicate.

primitives.js
let scoreA = 100;
let scoreB = scoreA; // Independent copy created

scoreB = 200;

console.log(scoreA); // 100 (Unchanged!)
console.log(scoreB); // 200
Stack Storage
Primitive variables hold the actual value. Changing one variable never affects another.
⚠️ Objects & Arrays: Copied by Reference

Objects and arrays are stored in the memory heap. The variable only stores a memory address (pointer).

references.js
const userA = { name: "Arun", role: "Member" };
const userB = userA; // Copies POINTER, not the object!

userB.role = "Admin";

console.log(userA.role); // "Admin" (Accidentally mutated!)
console.log(userA === userB); // true (Same memory address)
React State Rule
Never mutate objects directly! In React, direct mutation fails to trigger re-renders. Always create new copies using spread or immutable methods.
Iteration Loop Constructs

Loops in JavaScript: for, for...of & for...in

Choosing the right loop for arrays, strings, and objects

ITERATION
1️⃣ Standard for Loop

Classic counter-based loop. Ideal when you need precise index control or stepping.

for.js
const items = ["A", "B", "C"];

for (let i = 0; i < items.length; i++) {
  console.log(i, items[i]);
}
Index-based control
2️⃣ for...of Loop (Values)

Iterates over VALUES of iterable collections (Arrays, Strings, Maps, Sets). Clean and readable.

forOf.js
const colors = ["Red", "Blue"];

for (const color of colors) {
  console.log(color);
}
// Logs: "Red", "Blue"
Best for Array Values
3️⃣ for...in Loop (Keys)

Iterates over enumerable property KEYS of an object. Do NOT use for arrays!

forIn.js
const user = { id: 1, city: "Pune" };

for (const key in user) {
  console.log(key, user[key]);
}
// Logs: "id" 1, "city" "Pune"
For Object Keys Only
Higher-Order Methods Side Effects vs Purity

forEach() vs map(): Side Effects vs Pure Transformation

Understanding return values, immutability, and why React renders with map()

HIGHER ORDER
🔁 forEach(): Executes Side Effects

Runs a function for each item. Always returns undefined. Used for logging or mutations.

forEach.js
const prices = [10, 20, 30];

const result = prices.forEach(price => {
  console.log(`Price with tax: ${price * 1.18}`);
});

console.log(result); // undefined (Always!)
No Return Value
Use forEach only when you do NOT need a new array.
✨ map(): Returns a Brand New Array

Transforms every item using a callback. Returns a new array of the exact same length.

map.js
const prices = [10, 20, 30];

const doubled = prices.map(price => price * 2);

console.log(doubled); // [20, 40, 60]
console.log(prices);  // [10, 20, 30] (Original untouched)
Essential for React
In React JSX, we render UI lists exclusively with items.map(item => <Card key={item.id} />).
Array Filtering Conditional Selection

filter(): Selecting Elements by Condition

Creating a sub-array containing only items that satisfy a predicate function

ARRAY FILTER
🔍 How filter() Works

Calls a predicate function for every element. If the callback returns true, the item is kept; if false, it is discarded. The original array remains untouched.

filter.js
const students = [
  { name: "Rahul", score: 82, enrolled: true },
  { name: "Neha",  score: 48, enrolled: false },
  { name: "Vikram",score: 91, enrolled: true }
];

// Keep only enrolled students with passing score (>= 50)
const passedEnrolled = students.filter(s => s.enrolled && s.score >= 50);

console.log(passedEnrolled);
// Logs: [{ name: "Rahul", ... }, { name: "Vikram", ... }]
💡 React State Pattern: Deletion

Because filter() is immutable, it is the standard way to delete an item from state in React!

deleteItem.js
// Remove item with id 2
const remaining = items.filter(
  item => item.id !== 2
);
  • ✓ Preserves original array.
  • ✓ Returns empty array [] if no elements match.
Aggregation Universal Reducer

reduce(): Aggregating Data into Single Values

Accumulating numbers, combining objects, and computing complex metrics

REDUCE PATTERN
🧮 The Accumulator Pattern

reduce((acc, curr, index) => { ... }, initialValue) iterates through each item, carrying forward an accumulator value.

reduce.js
const cart = [
  { item: "Keyboard", price: 1500, qty: 1 },
  { item: "Mouse",    price: 600,  qty: 2 },
  { item: "Pad",      price: 250,  qty: 1 }
];

// Calculate grand total: sum of (price * qty)
const totalCost = cart.reduce((acc, item) => {
  return acc + (item.price * item.qty);
}, 0); // Initial value = 0

console.log(`Grand Total: ₹${totalCost}`); // ₹2950
🔑 Crucial Parameters
accumulator (acc)

The running accumulated result returned from previous iteration.

initialValue

Always pass an explicit initial value (e.g. 0, {}, []) to avoid bugs on empty arrays!

Data Pipelines Functional Composition

Method Chaining: filter() + map() + reduce()

Composing operations into readable, declarative data transformation pipelines

PIPELINES
🔗 Multi-Stage Processing Pipeline

Because filter() and map() return brand new arrays, they can be chained directly in sequence without saving intermediate variables.

chaining.js
const transactions = [
  { id: 1, type: "sale", amount: 1200, taxRate: 0.18 },
  { id: 2, type: "refund",amount: 300,  taxRate: 0.18 },
  { id: 3, type: "sale", amount: 4500, taxRate: 0.18 }
];

// 1. Filter sales -> 2. Calculate tax -> 3. Sum total tax
const totalTaxCollected = transactions
  .filter(t => t.type === "sale")
  .map(t => t.amount * t.taxRate)
  .reduce((sum, tax) => sum + tax, 0);

console.log(totalTaxCollected); // 1026
📊 Pipeline Execution Flow
1
filter(): Discards refunds, leaves only 2 sale records.
2
map(): Extracts tax amount [216, 810].
3
reduce(): Sums array into final scalar 1026.
Searching Record Lookup

Searching Arrays: find() & findIndex()

Locating specific items or their array indices by custom conditions

ARRAY SEARCH
🔎 find(): Returns First Matching Item

Returns the FIRST element that satisfies the condition. Returns undefined if no match exists.

find.js
const users = [
  { id: 101, name: "Anita", tier: "Silver" },
  { id: 102, name: "Bala",  tier: "Gold" },
  { id: 103, name: "Charan",tier: "Gold" }
];

// Find user by ID
const user = users.find(u => u.id === 102);
console.log(user); // { id: 102, name: "Bala", tier: "Gold" }

// No match
const missing = users.find(u => u.id === 999);
console.log(missing); // undefined
📍 findIndex(): Returns Matching Index

Returns the index of the first match. Returns -1 if not found.

findIndex.js
const index = users.findIndex(u => u.id === 102);
console.log(index); // 1

if (index !== -1) {
  console.log(`Record found at position ${index}`);
}
Performance Tip
Both find() and findIndex() short-circuit as soon as a match is discovered, making them faster than filter()[0].
Validation Predicate Checks

Testing Conditions: some() & every()

Boolean array validation for access control, inventory, and form validation

ARRAY VALIDATION
⚡ some(): At Least One Element Passes

Returns true if AT LEAST ONE item satisfies the condition. Short-circuits immediately on first truthy value.

some.js
const cart = [
  { name: "Book", inStock: true },
  { name: "Phone", inStock: false },
  { name: "Pen",  inStock: true }
];

// Are any items out of stock?
const hasOutOfStock = cart.some(item => !item.inStock);
console.log(hasOutOfStock); // true
🛡️ every(): All Elements Must Pass

Returns true ONLY IF ALL items satisfy the condition. Short-circuits immediately on first falsy value.

every.js
const formFields = [
  { field: "email", valid: true },
  { field: "password", valid: true },
  { field: "terms", valid: false }
];

// Can form be submitted?
const isFormReady = formFields.every(f => f.valid);
console.log(isFormReady); // false
Primitive Search Membership Checking

Element Lookup: includes() & indexOf()

Fast primitive checks in arrays and strings without needing callback functions

MEMBERSHIP
✅ includes(): Modern Boolean Membership

Returns simple true or false. Correctly identifies NaN.

includes.js
const roles = ["admin", "editor", "viewer"];

console.log(roles.includes("editor"));  // true
console.log(roles.includes("manager")); // false

// Role permission guard
function canPublish(userRole) {
  return ["admin", "editor"].includes(userRole);
}
🔢 indexOf(): Index Position Lookup

Returns the index position or -1. Older pattern replaced by includes() when only boolean check is needed.

indexOf.js
const cities = ["Mumbai", "Delhi", "Bengaluru"];

console.log(cities.indexOf("Delhi"));   // 1
console.log(cities.indexOf("Chennai")); // -1
Clean Code Standard
Prefer arr.includes(val) instead of the legacy arr.indexOf(val) !== -1.
State Safety Pure vs Impure Operations

Array Immutability: slice() vs splice()

The critical distinction between creating copies and mutating existing memory in-place

IMMUTABILITY
✨ slice(): Pure & Non-Destructive

Extracts a portion of an array and returns a brand new array. The original array is never modified.

slice.js
const colors = ["Red", "Green", "Blue", "Yellow"];

// slice(start, endNonInclusive)
const firstTwo = colors.slice(0, 2);

console.log(firstTwo); // ["Red", "Green"]
console.log(colors);   // ["Red", "Green", "Blue", "Yellow"]
Safe for React State
⚠️ splice(): Mutates Original Array In-Place

Modifies the original array directly by deleting, replacing, or inserting items. Returns deleted elements.

splice.js
const items = ["A", "B", "C", "D"];

// splice(startIndex, deleteCount, ...insertItems)
const removed = items.splice(1, 2, "X");

console.log(removed); // ["B", "C"]
console.log(items);   // ["A", "X", "D"] (MUTATED!)
Avoid in React State
Sorting Custom Comparators

Sorting Mechanics: sort() & reverse()

Avoiding lexicographical sorting bugs and writing comparator functions

SORTING
🪤 The Default sort() Pitfall

Default sort() converts numbers into strings before comparing them alphabetically!

pitfall.js
const numbers = [25, 8, 7, 100];
numbers.sort();

console.log(numbers);
// Output: [100, 25, 7, 8]  (100 comes before 25 alphabetically!)
Alphabetical Bug
"100" < "25" because character '1' precedes character '2'.
✅ The Fix: Numeric Comparator Function

Always provide a comparator function (a, b) => a - b. Also remember: sort() mutates, so copy first!

comparator.js
const scores = [25, 8, 7, 100];

// Immutable Ascending: a - b
const asc = [...scores].sort((a, b) => a - b);
console.log(asc); // [7, 8, 25, 100]

// Immutable Descending: b - a
const desc = [...scores].sort((a, b) => b - a);
console.log(desc); // [100, 25, 8, 7]

Using bracket expressions to evaluate dynamic property keys in object literals

COMPUTED KEYS
🏷️ Dynamic Keys with [expression]

In ES6, square brackets [key] inside an object literal compute the key from variables, expressions, or function returns.

const dynamicField = "favoriteCourse";

const student = {

Object Composition Merging & Defaults

Object Merging: Object.assign() vs Spread

Combining multiple configuration objects and managing fallback defaults

OBJECT MERGING
📦 Object.assign(): Method Approach

Copies own properties from source objects into a target object. Modifies target unless empty object {} is passed.

assign.js
const defaults = { theme: "light", fontSize: 14 };
const custom = { theme: "dark" };

// Safe merge: passes empty object as target
const config = Object.assign({}, defaults, custom);

console.log(config);
// { theme: "dark", fontSize: 14 }
✨ Modern Object Spread: Preferred Standard

Concise, declarative, and guaranteed immutable. Later properties naturally override earlier ones.

spreadMerge.js
const baseUser = { role: "Student", status: "Active" };
const inputData = { name: "Karthik", role: "Mentor" };

const userProfile = {
  ...baseUser,
  ...inputData,
  joinedAt: "2026-11-25"
};

console.log(userProfile);
// role becomes "Mentor" because inputData came second!
State Protection Immutability Utilities

Object Immutability: Object.freeze() vs Object.seal()

Protecting configuration objects and application state from unintended runtime modifications

OBJECT PROTECTION
🔒 Object.freeze(): Full Lock

Completely freezes an object. Cannot add new properties, delete properties, or modify existing property values.

freeze.js
const CONFIG = Object.freeze({
  API_URL: "https://api.groq.com",
  MAX_TOKENS: 1024
});

CONFIG.MAX_TOKENS = 2048; // Silent fail (throws in strict mode)
CONFIG.NEW_KEY = true;    // Cannot add!

console.log(CONFIG.MAX_TOKENS); // 1024
Shallow Freeze: Nested objects remain mutable
🛡️ Object.seal(): Fixed Schema

Prevents adding or removing properties, but allows modifying existing property values.

seal.js
const counter = Object.seal({
  value: 10,
  step: 1
});

counter.value = 15; // Allowed! Value updates
delete counter.step; // Forbidden! Cannot delete
counter.limit = 100; // Forbidden! Cannot add
Modern ES6 Unpacking Syntax

Destructuring: Arrays and Objects

Unpacking values from arrays and properties from objects into distinct variables

DESTRUCTURING
📦 Object Destructuring

Matches property names directly. Supports renaming and default fallback values.

objectDestruct.js
const student = { name: "Divya", age: 23, role: "Leader" };

// Unpack and rename role -> userRole
const { name, age, role: userRole, batch = 2026 } = student;

console.log(name);     // "Divya"
console.log(userRole); // "Leader"
console.log(batch);    // 2026 (Used default)
📑 Array Destructuring

Unpacks items strictly by position/order. You can skip unwanted items with commas.

arrayDestruct.js
const scores = [98, 85, 72];

// Unpack first and third, skip second
const [topScore, , thirdScore] = scores;

console.log(topScore);   // 98
console.log(thirdScore); // 72

// React useState preview
const [count, setCount] = [0, () => {}];

Modern ES6 Expansion & Copying

The Spread Operator (...) in Arrays & Objects

Expanding collections into individual items to create copies and merge data immutably

SPREAD OPERATOR
📑 Spreading Arrays

Unpacks all elements into a new array. Combines lists without mutating either source.

spreadArray.js
const frontend = ["HTML", "CSS", "JS"];
const backend = ["Node", "Express"];

// Combine + add extra elements
const fullstack = [...frontend, "React", ...backend];

console.log(fullstack);
// ["HTML", "CSS", "JS", "React", "Node", "Express"]
📦 Spreading Objects (Updating State)

Copies all key-value pairs into a new object and allows updating specific fields.

spreadObject.js
const task = { id: 1, title: "Practice JS", done: false };

// Toggle done to true immutably
const completedTask = {
  ...task,
  done: true
};

console.log(task.done);          // false (Original safe)
console.log(completedTask.done); // true
Modern ES6 Parameter Gathering

The Rest Operator (...) in Parameters & Destructuring

Collecting remaining arguments into an array or separating sensitive fields

REST OPERATOR
📥 Rest Parameters in Functions

Gathers unlimited function arguments into a genuine JavaScript array. Must be the last parameter.

restParams.js
function calculateTotal(discount, ...prices) {
  // 'prices' is an authentic array!
  const sum = prices.reduce((acc, p) => acc + p, 0);
  return sum - discount;
}

console.log(calculateTotal(50, 100, 200, 300)); // 550
🛡️ Rest in Destructuring (Excluding Keys)

Extracts specific properties and gathers the rest. Ideal for removing passwords or internal tokens.

excludeKeys.js
const account = {
  id: 101,
  name: "Sanjay",
  passwordHash: "secret99",
  role: "Developer"
};

// Isolate sensitive passwordHash
const { passwordHash, ...publicProfile } = account;

console.log(publicProfile);
// { id: 101, name: "Sanjay", role: "Developer" }
Defensive Coding Safe Traversal

Optional Chaining (?.): Safe Property Access

Safely navigating deeply nested API data structures without throwing TypeError crashes

OPTIONAL CHAINING
💥 The Classic TypeError Crash

Accessing a nested property on undefined throws an unhandled exception that crashes the frontend or API handler.

crash.js
const user = { id: 1, name: "Pooja" };

// user.address is undefined!
// user.address.city THROWS:
// TypeError: Cannot read properties of undefined (reading 'city')
Production Bug
LLM responses and asynchronous JSON APIs frequently omit nested fields when data is optional.
🛡️ The Solution: Optional Chaining (?.)

Short-circuits to undefined as soon as any segment is null or undefined.

safeAccess.js
const user = { id: 1, name: "Pooja" };

// Safe property access
const city = user?.address?.city;
console.log(city); // undefined (No error thrown!)

// Safe array element & method calls
const firstSkill = user?.skills?.[0];
const greeting = user?.sayHello?.();
Defensive Coding Default Fallbacks

Nullish Coalescing (??): Safe Default Values

Distinguishing null and undefined from falsy values like 0, empty string, and false

NULLISH OPERATOR
⚠️ The Flaw with Logical OR (||)

|| checks for ANY falsy value: 0, "", false, null, undefined.

orFlaw.js
const userScore = 0; // Valid score of zero!
const score = userScore || 50;
console.log(score); // 50 (Bug! Overrode valid 0)

const notifications = false; // Explicitly turned off
const notify = notifications || true;
console.log(notify); // true (Bug! Forced true)
🎯 Nullish Coalescing (??) Precision

Only falls back if the left-hand side is strictly null or undefined.

nullish.js
const userScore = 0;
const score = userScore ?? 50;
console.log(score); // 0 (Preserved correctly!)

const bio = null;
const userBio = bio ?? "No bio provided.";
console.log(userBio); // "No bio provided."

let tasks = [];

function addTask(title) {
  tasks.push({ id: Date.now(), title, completed: false });
  render();
}

function toggleTask(id) {
  tasks = tasks.map(t => 
    t.id === id ? { ...t, completed: !t.completed } : t
  );
  render();
}

function deleteTask(id) {
  tasks = tasks.filter(t => t.id !== id);
  render();
}

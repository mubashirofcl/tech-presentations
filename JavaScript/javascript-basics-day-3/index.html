Section 1 DOM Manipulation

What is the DOM?

Document Object Model: The structured tree representation of HTML in browser memory

DOM ARCHITECTURE
🌳 The Browser's Object Tree

When a web browser loads an HTML file, it parses the markup and constructs a structured object tree called the Document Object Model (DOM).

Through the DOM, JavaScript gains programmatic access to:

  • • Access and inspect HTML tags, text, and attributes.
  • • Update content and typography dynamically.
  • • Modify CSS styles and toggle animation classes.
  • • Create brand new elements or remove existing nodes.
  • • Listen and react to user clicks, keyboard inputs, and scrolls.

Section 1 DOM Manipulation

Selecting HTML Elements

Targeting nodes with getElementById, querySelector, and querySelectorAll

DOM SELECTION
🔍 Selection Methods in Practice
selectors.js
// HTML: <h1 id="title">Welcome</h1>
//       <p class="message">Hello Students</p>
//       <button>Click Me</button>

// 1. Select by unique ID
const title = document.getElementById("title");

// 2. Select first matching element using CSS selector (# for ID, . for class)
const mainTitle = document.querySelector("#title");
const firstMsg  = document.querySelector(".message");

// 3. Select ALL matching elements (returns NodeList collection)
const allButtons = document.querySelectorAll("button");

console.log(`Found ${allButtons.length} buttons on page`);
📋 Selection Rules Summary
Method Returns
getElementById() Single element or null
querySelector() First matching element
querySelectorAll() NodeList of all matches
CSS Selector Syntax
#idName selects by ID.
.className selects by class.
tagName selects by HTML tag name.
Section 1 DOM Manipulation

Modifying HTML Content: textContent vs innerHTML

Safely updating text strings versus rendering HTML markup

CONTENT UPDATES
📝 textContent: Safe Plain Text

Inserts raw text. Does NOT parse HTML tags. Completely safe against injection.

textContent.js
const heading = document.getElementById("title");

// Replaces old content with clean text
heading.textContent = "JavaScript DOM Manipulation";

// Inserting tags displays literally as text:
heading.textContent = "<b>Bold Text</b>";
// Browser displays: <b>Bold Text</b> (Not bolded!)
Recommended for User-Provided Data
⚠️ innerHTML: Parses HTML Tags

Parses and interprets HTML markup directly into new DOM nodes.

innerHTML.js
const msg = document.getElementById("message");

// Parses <strong> and renders bold text
msg.innerHTML = "<strong>Welcome Students!</strong>";
Security Alert (XSS)
Never insert untrusted user input with innerHTML! Attackers can inject malicious <script> or <img onerror="..."> tags. Use textContent!

Section 1 DOM Manipulation

Creating HTML Elements Dynamically

Constructing new elements in memory and appending them to the DOM tree

ELEMENT CREATION
🔨 The 3-Step Creation Lifecycle
createElement.js
const container = document.getElementById("container");

// Step 1: Create element in memory
const card = document.createElement("div");
card.classList.add("card");

// Step 2: Populate content and attributes
const heading = document.createElement("h3");
heading.textContent = "Learn JavaScript";

// Step 3: Insert into the live DOM tree
card.appendChild(heading);
container.appendChild(card);
💡 Vital Rule of Creation

document.createElement() creates the element in browser RAM. It will never become visible until you explicitly mount it using:

  • parent.appendChild(child)
  • parent.append(child1, child2)
  • parent.prepend(child)
Performance Tip
Configure styles and inner text before appending to the live DOM to prevent redundant page reflows.
Section 1 DOM Manipulation

Removing HTML Elements

Detaching nodes from the page with remove, removeChild, and replaceChildren

ELEMENT REMOVAL
🗑️ Modern Removal Methods
removeElements.js
const banner = document.getElementById("announcement");

// 1. Direct removal (Modern Standard)
banner.remove();

// 2. Remove child from parent (Traditional)
const list = document.getElementById("todoList");
list.removeChild(list.firstElementChild);

// 3. Clear all children at once!
list.replaceChildren(); // Fast & clean innerHTML = ""
📋 Methods Comparison
Method Action
node.remove() Removes itself directly from parent
parent.removeChild(node) Removes specific child from parent
parent.replaceChildren() Empties all children instantly
parent.appendChild(node) Appends child to the end
Clean Reset Tip
Prefer container.replaceChildren() over container.innerHTML = "" when re-rendering lists.

Section 2 Event Handling

Event Object & Form Handling: preventDefault()

Intercepting browser defaults and inspecting event properties

FORM HANDLING
📋 Form Submission Handling
formHandler.js
const studentForm = document.getElementById("studentForm");
const nameInput   = document.getElementById("studentName");

studentForm.addEventListener("submit", (event) => {
  // 1. CRITICAL: Stop browser from refreshing the page!
  event.preventDefault();

  // 2. Read input value cleanly
  const name = nameInput.value.trim();

  console.log(`Submitted Name: ${name}`);
  console.log("Target Element:", event.target);
});
🛑 Why preventDefault() is Mandatory

By default, when an HTML form submits, the browser attempts an HTTP POST request and reloads the entire webpage, wiping out all JavaScript state!

Single Page Apps (SPA)
event.preventDefault() stops the page reload so our JavaScript can validate inputs and call APIs asynchronously without page refreshes.
  • event.target: The element triggering the event.
  • event.type: Event name (e.g. "submit").

Section 3 Asynchronous JavaScript

Synchronous vs Asynchronous JavaScript

Understanding single-threaded non-blocking execution and the event timeline

SYNC VS ASYNC
🛑 Synchronous (Blocking)

Code executes sequentially line by line. Each line must wait for previous line to finish.

sync.js
console.log("First");
console.log("Second");
console.log("Third");

// Output:
// First
// Second
// Third
⚡ Asynchronous (Non-Blocking)

Long-running operations (APIs, timers) run in background while main execution continues uninterrupted.

async.js
console.log("Start");

setTimeout(() => {
  console.log("Inside Timeout (2s later)");
}, 2000);

console.log("End");

// Output Order:
// 1. Start → 2. End → 3. Inside Timeout
⏱️ Non-Blocking Execution Timeline
Main Thread
console.log("Start") → Schedules Timer → console.log("End") (Page stays responsive!)
Browser Timer
Waiting 2000ms in background...
Timer Callback Runs
Section 3 Asynchronous JavaScript

What are Callbacks?

Functions passed as arguments to other functions to be invoked at a later time

CALLBACKS
📦 Synchronous Callback Example

Passed into another function and executed immediately:

syncCallback.js
function greet(name, callback) {
  console.log("Hello " + name);
  callback(); // Invokes passed function
}

function sayWelcome() {
  console.log("Welcome to JavaScript!");
}

greet("Ali", sayWelcome);
// Output:
// Hello Ali
// Welcome to JavaScript!
⏱️ Asynchronous Callback with Timers

Executed after an asynchronous background event completes:

asyncCallback.js
console.log("Start");

setTimeout(() => {
  console.log("Task completed");
}, 2000);

console.log("End");
Important Distinction
A callback is simply a function passed to another function. Not every callback is asynchronous (e.g. array.map() is synchronous).
Section 3 Asynchronous JavaScript

The "Callback Hell" Problem

The Pyramid of Doom: Deeply nested callbacks for sequential dependent tasks

CALLBACK HELL
🌋 The Pyramid of Doom
callbackHell.js
getUser(101, function(user) {
  getOrders(user.id, function(orders) {
    getPayment(orders[0].id, function(payment) {
      sendReceipt(payment.id, function(receipt) {
        console.log("Receipt sent:", receipt);
      });
    });
  });
});
⚠️ Why Is This Problematic?
  • • Unreadable: Growing indentation moves code horizontally off-screen.
  • • Error Handling Nightmare: Each level requires separate error handling logic.
  • • Fragile & Tight Coupling: Modifying step 2 breaks steps 3 and 4.
The Modern Solution
JavaScript introduced Promises (ES6) and async/await (ES2017) to flatten this structure into clean, readable code!
Section 3 Asynchronous JavaScript

What is a Promise?

A placeholder object representing the eventual completion or failure of an async operation

PROMISES
State 1: Pending

Initial state. Operation is currently running in the background.

State 2: Fulfilled

Completed successfully. Handled via .then().

State 3: Rejected

Operation failed. Handled via .catch().

🔨 Creating a Promise
createPromise.js
const myPromise = new Promise((resolve, reject) => {
  const success = true;
  if (success) {
    resolve("Task completed successfully!");
  } else {
    reject("Task failed with error.");
  }
});
🎧 Consuming a Promise
consumePromise.js
myPromise
  .then((result) => {
    console.log("Success:", result);
  })
  .catch((error) => {
    console.log("Error:", error);
  })
  .finally(() => {
    console.log("Execution settled (Done)");
  });
Section 3 Asynchronous JavaScript

Promise Chaining

Sequencing multiple asynchronous operations cleanly without callback nesting

PROMISE CHAINING
🔗 Linear Chaining Flow
chaining.js
function getNumber() {
  return new Promise((resolve) => {
    setTimeout(() => resolve(10), 1000);
  });
}

getNumber()
  .then((number) => {
    console.log("Step 1:", number); // 10
    return number * 2;              // Passes 20 to next .then()
  })
  .then((doubled) => {
    console.log("Step 2:", doubled); // 20
    return doubled + 5;              // Passes 25
  })
  .then((final) => {
    console.log("Step 3:", final);   // 25
  })
  .catch((err) => {
    console.error("Chain error:", err);
  });
💡 How Chaining Works
  • 1. Each .then() receives the value returned by the preceding .then().
  • 2. If a .then() returns a new Promise, subsequent handlers wait for it to resolve.
  • 3. A single .catch() at the end intercepts errors thrown anywhere along the pipeline.
Section 3 Asynchronous JavaScript

What is async/await?

Modern syntax making asynchronous Promise consumption read like synchronous code

ASYNC / AWAIT
📜 Traditional Promise Approach
promiseStyle.js
function getData() {
  return new Promise((resolve) => {
    setTimeout(() => resolve("Data received"), 1500);
  });
}

function displayData() {
  getData().then((result) => {
    console.log(result);
  });
}
✨ Modern async/await Approach
asyncAwaitStyle.js
// 'async' marks function to return a Promise
async function displayData() {
  // 'await' pauses function until Promise settles
  const result = await getData();
  console.log(result); // "Data received"
}

displayData();
4 Golden Rules of async/await
1. async functions always return a Promise.
2. await can only be used inside async functions.
3. await pauses only the surrounding async function, never the browser.
4. The resolved value is assigned directly to the variable!

Section 4 Fetch & JSON

What is the Fetch API?

Native browser interface for issuing HTTP network requests and streaming responses

FETCH API
🌐 Basic fetch() Request
fetchBasic.js
fetch("https://jsonplaceholder.typicode.com/users")
  .then((response) => {
    // Check if HTTP status is 200-299
    if (!response.ok) {
      throw new Error(`HTTP error: ${response.status}`);
    }
    return response.json(); // Parse JSON asynchronously
  })
  .then((users) => {
    console.log("Users received:", users);
  })
  .catch((error) => {
    console.error("Network failure:", error.message);
  });
⚠️ The response.ok Trap

fetch() returns a Promise. However:

Crucial Architecture Rule
fetch() does NOT reject on HTTP 404 or 500 errors! It only rejects on real network failures (offline, DNS failure).

You must check response.ok before calling response.json()!

Section 4 Fetch & JSON

What is JSON? JSON.stringify() vs JSON.parse()

JavaScript Object Notation: The text-based format for exchanging data across the web

JSON FORMAT
📤 JSON.stringify(): Object → String

Serializes a JavaScript object into a JSON string to transmit over the network.

stringify.js
const student = { name: "Ali", age: 22, active: true };

const jsonString = JSON.stringify(student);

console.log(typeof jsonString); // "string"
console.log(jsonString);
// '{"name":"Ali","age":22,"active":true}'
📥 JSON.parse(): String → Object

Deserializes an incoming JSON string back into a live JavaScript object.

parse.js
const rawJson = '{"name":"Ali","age":22,"active":true}';

const parsed = JSON.parse(rawJson);

console.log(typeof parsed); // "object"
console.log(parsed.name);   // "Ali"
Universal Format
REST APIs, database records, and AI LLM response bodies all communicate via JSON.
Section 4 Fetch & JSON

Handling API Requests Using Async/Await

Combining fetch, status verification, and JSON parsing in clean sequential code

FETCH WITH ASYNC
🚀 Modern API Request Pattern
getUsers.js
async function getUsers() {
  // 1. Await network fetch response
  const response = await fetch(
    "https://jsonplaceholder.typicode.com/users"
  );

  // 2. Verify response status
  if (!response.ok) {
    throw new Error(`HTTP Error: ${response.status}`);
  }

  // 3. Await asynchronous JSON parsing
  const users = await response.json();

  console.log(`Loaded ${users.length} users successfully!`);
  return users;
}

getUsers();
🔍 Execution Steps Breakdown
1
await fetch(...) sends HTTP request and pauses until server headers return.
2
if (!response.ok) guards against 404/500 errors before attempting parsing.
3
await response.json() reads body stream and converts to JavaScript objects.
Section 4 Fetch & JSON

Error Handling Using try/catch/finally

Gracefully managing network dropouts, HTTP rejections, and UI loading cleanup

ERROR HANDLING
🛡️ Robust Production try/catch/finally
safeFetch.js
async function loadData() {
  try {
    showSpinner(true); // Start loading

    const res = await fetch("https://api.example.com/data");
    if (!res.ok) throw new Error("Server returned failure");

    const data = await res.json();
    renderData(data);

  } catch (error) {
    // Catches network failure or thrown error
    console.error("Error caught:", error.message);
    showErrorMessage(error.message);

  } finally {
    // ALWAYS runs: success or failure!
    showSpinner(false); // Stop loading
  }
}
💡 The Role of finally

The finally block is guaranteed to execute whether the try succeeded or the catch was triggered.

Essential UI Cleanup
Use finally to re-enable disabled submit buttons, hide progress spinners, and clear timeout timers.
Section 5 ES Modules

What are ES Modules?

Splitting applications across multiple files using native browser import and export

ES MODULES
📁 Modular Architecture Structure
js/math.js (Module)
// Export function
export function add(a, b) {
  return a + b;
}
js/main.js (Entry)
// Import function
import { add } from "./math.js";

console.log(add(10, 20)); // 30
index.html (HTML Script Tag)
<!-- Must include type="module" to enable import/export in browser! -->
<script type="module" src="./js/main.js"></script>
🌟 Why Modularize Code?
  • ✓ Separation of Concerns: API logic, UI rendering, and event controllers stay separated.
  • ✓ Reusability: Functions can be imported into multiple pages and modules.
  • ✓ No Global Scope Pollution: Variables defined inside a module do not leak into the global window scope.
React Alignment
Modern frameworks like React and Vite rely 100% on ES module exports and imports.
Section 5 ES Modules

Named Export vs Default Export

Understanding export patterns, import syntax differences, and local server requirements

EXPORTS & IMPORTS
🏷️ 1. Named Exports: Multiple per file
mathUtils.js & main.js
// Exporting multiple named entities:
export function add(a, b) { return a + b; }
export function subtract(a, b) { return a - b; }

// Importing with curly braces matching exact names:
import { add, subtract } from "./mathUtils.js";
📦 2. Default Export: One primary entity
greeting.js & main.js
// Exactly one default export per module:
export default function greet(name) {
  return `Hello ${name}`;
}

// Imported WITHOUT curly braces (custom alias allowed):
import greet from "./greeting.js";
Browser Module Rule (CORS Security)
Browser ES Modules cannot be loaded directly through the file:/// protocol due to browser security restrictions. Always test modular apps using a local development server (such as VS Code Live Server, Vite, or npx serve).
Section 6 Practical Project

Practical Project: User Explorer Application

Modular architecture combining DOM manipulation, Fetch API, async/await, and ES modules

CAPSTONE PROJECT 
// js/api.js - Network Service Module
export async function fetchUsers() {
  const response = await fetch(
    "https://jsonplaceholder.typicode.com/users"
  );
  if (!response.ok) {
    throw new Error("Unable to fetch user records");
  }
  const users = await response.json();
  return users;
}
// js/ui.js - DOM Rendering Module
export function renderUsers(users) {
  const container = document.getElementById("userContainer");
  container.replaceChildren();

  users.forEach((user) => {
    const card = document.createElement("div");
    card.className = "user-card";

    const name = document.createElement("h3");
    name.textContent = user.name;

    const email = document.createElement("p");
    email.textContent = user.email;

    card.append(name, email);
    container.appendChild(card);
  });
}

export function showStatus(msg) {
  document.getElementById("status").textContent = msg;
}
// js/main.js - Application Controller
import { fetchUsers } from "./api.js";
import { renderUsers, showStatus } from "./ui.js";

const button = document.getElementById("loadButton");

button.addEventListener("click", async () => {
  try {
    showStatus("Loading users...");
    button.disabled = true;

    const users = await fetchUsers();
    renderUsers(users);
    showStatus(`${users.length} users loaded successfully!`);
  } catch (err) {
    showStatus(err.message);
  } finally {
    button.disabled = false;
  }
});

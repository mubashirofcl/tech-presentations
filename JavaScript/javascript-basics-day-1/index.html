What Is JavaScript?

A high-level, dynamically typed language that transforms static web pages into interactive software

LANGUAGE OVERVIEW
⚡ Core Characteristics
  • ✓
    High-Level: You do not manage computer memory or CPU registers manually; the JavaScript engine handles memory allocation and garbage collection automatically.
  • ✓
    Dynamically Typed: Variables can hold values of any data type without explicit type declarations.
  • ✓
    Interpreted & JIT-Compiled: Modern engines (like Google Chrome's V8) compile JavaScript code directly into optimized machine code just-in-time for maximum execution speed.
  • ✓
    Single-Threaded with Non-Blocking I/O: Executes instructions sequentially on one main thread while delegating asynchronous tasks (like timers and network requests) to the browser environment.
Key Takeaway:

JavaScript was initially built for browser interactivity in 1995. Today, through modern runtimes like Node.js, it powers servers, desktop apps, mobile applications, and AI integrations.

What Are Functions?

Encapsulating reusable blocks of instructions to make programs clean, modular, and maintainable

FUNCTIONS
⚙️ Understanding Functions

A function is a self-contained block of code designed to perform a specific action. You define the function once, and can then execute (call) it as many times as needed throughout your program.

1. DRY Principle (Don't Repeat Yourself)
Instead of writing the same 10 lines of code five times, put them inside a function and call it five times.
2. Modularity & Readability
Breaking large complex problems into small, named units makes your application understandable and easy to debug.
3. Reusability
Functions can be called from different files, triggered by button clicks, or run when network responses arrive.
📝 Declaring and Calling a Function
greet.js Syntax 
// Step 1: Function Declaration
function greet() {
    console.log("Welcome to JavaScript");
}

// Step 2: Calling (invoking) the function
greet();
greet();
💻 Expected Output
Welcome to JavaScript
Welcome to JavaScript
💡 Important Syntax Note:

Writing greet refers to the function itself. Adding parentheses greet() tells the engine to execute the function now!

Passing dynamic values into functions to make them versatile and reusable across different inputs

⚖️ Parameter vs Argument
Parameter (The Placeholder)

A variable listed inside the parentheses of the function definition. It acts as an empty slot waiting to receive data:

The concrete data value you pass into the function when invoking it:

Section 2 Functions and ES6 Basics

Types of Functions – Declaration, Expression and Arrow

Three foundational syntax forms for defining functions in modern JavaScript

FUNCTION TYPES
1 Function Declaration

The traditional way to define a function using the function keyword. It is hoisted (can be called before its definition in code).

function add(a, b) {
    return a + b;
}

console.log(add(10, 20));
Output: 30
2 Function Expression

An anonymous function assigned directly into a variable. It is not hoisted (cannot be called before the line it is defined on).

const add = function(a, b) {
    return a + b;
};

console.log(add(10, 20));
Output: 30
3 Arrow Function (ES6)

A modern, concise syntax using => introduced in ES6 (2015). The de facto standard in React components and array callbacks.

const add = (a, b) => {
    return a + b;
};

console.log(add(10, 20));
Output: 30
Section 2 Functions and ES6 Basics

ES6: Arrow Functions

Shorter function syntax, implicit returns, and why arrow functions power modern React development

ES6 ARROWS
🏹 Arrow Function Anatomy

An arrow function removes the function keyword and places a "fat arrow" => between parameters and body:

Standard Arrow Function
const greet = () => {
    console.log("Hello");
};

greet(); // Output: Hello
Single-Line Implicit Return
// If body is one expression, omit {} and 'return'
const add = (a, b) => a + b;

console.log(add(10, 20)); // Output: 30
⚛️ Why Arrow Functions in React?
  • ✓
    Functional Components: Modern React components are written cleanly as arrow functions: const Header = () => <header />;
  • ✓
    Inline Event Handlers: Ideal for passing inline callbacks to button clicks: onClick={() => setCount(count + 1)}
  • ✓
    Array Methods: Fits seamlessly into .map(), .filter(), and .reduce() for rendering lists of UI elements.
  • ✓
    Lexical this: Arrow functions inherit this from the surrounding code scope instead of rebinding it.

Section 3 Operators and Conditionals

Logical Operators – &&, ||, !

Combining, altering, and reversing boolean conditions to control decision flow

LOGIC OPERATORS
&& Logical AND

Returns true ONLY if both conditions evaluate to true.

const age = 22;

console.log(
  age >= 18 && age <= 60
);
Output: true
Both conditions (22 >= 18 and 22 <= 60) are true.
|| Logical OR

Returns true if at least one condition evaluates to true.

const isAdmin = false;
const isMentor = true;

console.log(
  isAdmin || isMentor
);
Output: true
Even though isAdmin is false, isMentor is true.
! Logical NOT

Reverses a boolean value: converts true to false and vice versa.

const isLoggedIn = false;

console.log(!isLoggedIn);
Output: true
Inverts false to true. Used for toggling modal and menu states.

Section 3 Operators and Conditionals

Conditional Statements: if, else if and else

Guiding code execution down different pathways depending on dynamic conditions

DECISION MAKING
🔀 How Conditional Branching Works

Conditional statements allow a program to make decisions and execute specific blocks of code only when their corresponding condition evaluates to true.

1. if (condition)
The primary gatekeeper. Executes the block if the condition is truthy.
2. else if (condition)
Evaluated only if all previous conditions above it were false. You can chain as many as needed.
3. else
The final catch-all. Executes if none of the preceding conditions were satisfied.
📝 Practical Example: Student Grade Checker
gradeChecker.js 
const marks = 75;

if (marks >= 90) {
    console.log("Grade A");
} else if (marks >= 75) {
    console.log("Grade B");
} else if (marks >= 50) {
    console.log("Grade C");
} else {
    console.log("Failed");
}
💻 Expected Output
Grade B
Section 3 Operators and Conditionals

switch and Ternary Operator

Clean multi-case matching with switch and concise inline decision-making with ternary expressions

CLEAN CODE
🎚️ 1. Switch Statement

Compares a single variable against multiple possible constant values. Much cleaner than writing 10 consecutive else if statements. 

const day = 2;

switch (day) {
    case 1:
        console.log("Monday");
        break;
    case 2:
        console.log("Tuesday");
        break;
    default:
        console.log("Invalid day");
}
Output: Tuesday
break prevents falling through to subsequent cases. default acts as fallback.
⚡ 2. Ternary Operator (Inline If/Else)

A concise one-line syntax: condition ? exprIfTrue : exprIfFalse. 

const age = 20;

const result = age >= 18
    ? "Eligible"
    : "Not Eligible";

console.log(result);
Output: Eligible
⚛️ Vital in React:

Because standard if statements cannot be embedded inside JSX elements, ternary operators are the #1 way to render UI conditionally in React!

Section 5 Scope and Closures

Understanding Scope: Global, Function and Block Scope

Where variables live, who can access them, and how variable isolation prevents naming bugs

SCOPE RULES
1 Global Scope

Variables declared outside of any function or curly block { }. Accessible from anywhere in the entire file.

const name = "Arun";

function greet() {
    console.log(name); // OK!
}

greet();
Output: Arun
2 Function Scope

Variables declared inside a function. They cannot be accessed or seen from outside that function.

function greet() {
    const message = "Hello";
    console.log(message);
}

greet();
// console.log(message); // ERROR!
Output: Hello
3 Block Scope (let/const)

Variables declared with let or const inside { } (like if, for) are trapped inside that block!

if (true) {
    let age = 22;
    const course = "JavaScript";
    console.log(age);
}

// console.log(age); // ReferenceError!
Output: 22
Section 5 Scope and Closures

Introduction to Closures

How inner functions remember and preserve variables from their outer lexical environment

CLOSURES
🎒 What is a Closure?

A closure happens when an inner function remembers variables from its outer function, even after the outer function has finished executing and returned.

Step 1: Outer Function Runs
outerFunction() initializes variable name = "Arun" and returns the inner function.
Step 2: Outer Scope Closes
Normally, local variables disappear when a function finishes. But JavaScript keeps variables alive if an inner function still references them!
Step 3: Inner Function Invoked
Calling myFunction() later successfully accesses name from its closure "backpack"!
📝 Practical Example
closure.js 
function outerFunction() {
    const name = "Arun";

    function innerFunction() {
        console.log(name); // Remembers 'name'
    }

    return innerFunction;
}

// outerFunction executes and returns innerFunction
const myFunction = outerFunction();

// Executes innerFunction with remembered variable
myFunction();
💻 Expected Output
Arun
Section 5 Scope and Closures

Practical Closure: Counter

Creating an encapsulated, private state counter that cannot be corrupted from outside

STATE ENCAPSULATION
💻 Stateful Counter Factory
createCounter.js 
function createCounter() {
    let count = 0; // Private variable

    return function() {
        count++;
        return count;
    };
}

const counter = createCounter();

console.log(counter()); // 1
console.log(counter()); // 2
console.log(counter()); // 3

Section 6 JavaScript Event Loop

What Is the JavaScript Event Loop?

How single-threaded JavaScript coordinates non-blocking asynchronous operations

CONCURRENCY
⚡ The Single-Threaded Conundrum

JavaScript is a single-threaded language. It has one call stack and can execute exactly one piece of code at any given instant.

The Problem:

If JavaScript waited synchronously for a 3-second network request or a database query, the entire browser tab would completely freeze—users couldn't click, scroll, or type!

The Solution: The Event Loop

JavaScript offloads long-running asynchronous tasks (timers, fetch requests, user events) to the browser environment (Web APIs). When ready, callbacks are queued, and the Event Loop schedules them back onto the Call Stack when it is empty!

🏛️ The 5 Core Pillars
1. Call Stack
Executes synchronous JavaScript code step-by-step (LIFO: Last In, First Out).
2. Web APIs (Browser Environment)
Handles timers (setTimeout), DOM events (click), and network requests (fetch) in background threads.
3. Priority / Microtask Queue
Holds higher-priority asynchronous callbacks, specifically Promise.then() and queueMicrotask().
4. Callback Queue (Task Queue)
Holds standard asynchronous callbacks such as setTimeout timers and UI events.
5. Event Loop
Continuously checks if the Call Stack is empty. When empty, it schedules queued callbacks to run!

🌐 2. Browser Web APIs Offloading

Browser Web APIs run outside the JavaScript engine thread: 

console.log("Start");

setTimeout(() => {
    console.log("Timer completed");
}, 2000);

console.log("End");
Output:
Start
End
Timer completed (after 2 seconds)
Why does "End" print before the timer?

setTimeout is handed to the browser's background timer API. The main call stack immediately moves to the next line (logging "End") without freezing!

⭐ Golden Rule of the Event Loop:

1. Synchronous code executes first on Call Stack (Start, End).
2. When Call Stack empties, JavaScript executes ALL Microtasks before touching the Task Queue (Promise runs before Timeout).
3. setTimeout(..., 0) does NOT mean immediate execution; it waits for the current tick and microtasks to clear!

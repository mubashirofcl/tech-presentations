What Is Asynchronous Programming?

Non-blocking execution and time-delayed operations

Slide 03 / 25
⚡ Core Definition

Asynchronous programming allows a program to start an operation and continue doing other work while waiting for that operation to finish.

🌐 Common Asynchronous Operations in Node.js
  • ▸ Calling an external API: Waiting for an HTTP response over the internet.
  • ▸ Reading a file: Waiting for disk storage to retrieve bytes.
  • ▸ Querying a database: Waiting for PostgreSQL or MongoDB queries.
  • ▸ Waiting for a network response: Connecting to microservices or AI models.
🔑
Key Takeaway: The timer does not stop the remaining synchronous statements from running. This is the foundation for understanding asynchronous code.

  console.log("2. Timer completed");
}, 2000);

console.log("3. Continue working");

Understanding Callbacks

Functions passed as arguments for delayed or event-driven invocation

Slide 05 / 25
📌 Definition of a Callback

A callback is a function passed to another function so that it can be called later when an event happens or a task finishes.

🔍 How It Works in This Example
  • ▸ completed is passed as a function reference into processUser.
  • ▸ processUser executes its own work, then invokes callback().
  • ▸ Callbacks are fundamental to JavaScript's event-driven architecture.
⚠️
The Pitfall: When multiple asynchronous operations depend on each other, deeply nested callbacks create the infamous "Callback Hell" or "Pyramid of Doom", making error handling and maintenance very difficult.

  console.log("User processing completed");
}

🎯 The "Error-First" Convention

In traditional Node.js callback APIs, the callback function always takes (error, data):

Understanding Promises

A standardized object representing the eventual completion or failure of an async operation

Slide 07 / 25
🤝 What Is a Promise?

A Promise is an object representing the eventual success or failure of an asynchronous operation and its resulting value.

⏳ Pending
Initial state. Operation is currently ongoing.
✅ Fulfilled
Operation succeeded. Handled via .then().
❌ Rejected
Operation failed. Handled via .catch().
⚙️ Core Methods
  • ▸ resolve(value): Fulfills the Promise with a result value.
  • ▸ reject(error): Rejects the Promise with an Error object.
  • ▸ .then(cb): Runs when the promise fulfills successfully.
  • ▸ .catch(cb): Catches any errors or rejected promises.
promise-demo.js 
const task = new Promise((resolve, reject) => {
  const success = true;

  if (success) {
    resolve("Task completed");
  } else {
    reject(new Error("Task failed"));
  }
});

task
  .then((result) => {
    console.log(result);
  })
  .catch((error) => {
    console.error(error.message);
  });

$ node promise-demo.js Task completed
Section 2: Asynchronous Patterns

async/await

Writing asynchronous code that looks and reads like clean synchronous code

Slide 08 / 25
🚀 What is async/await?

async/await is modern JavaScript syntax built on top of Promises. It eliminates promise chaining callbacks and makes asynchronous workflows easy to read and debug.

🔑 How It Operates
  • ▸ async keyword: Marks a function as asynchronous and guarantees it returns a Promise.
  • ▸ await keyword: Pauses execution inside the async function until the Promise settles.
  • ▸ Non-blocking: await does not block the entire Node.js runtime or event loop; other tasks continue to run freely.
💡
Sequence of Events: Displays Loading user... → waits 1000ms for Promise to fulfill → logs user object → displays Finished.
async-await.js 
function getUser() {
  return new Promise((resolve) => {
    setTimeout(() => {
      resolve({ name: "Anu", role: "Student" });
    }, 1000);
  });
}

async function main() {
  console.log("Loading user...");

  const user = await getUser();

  console.log(user);
  console.log("Finished");
}

main();
Execution Output
$ node async-await.js Loading user... { name: 'Anu', role: 'Student' } Finished

Evolution, trade-offs, and best practices across the three paradigms

Slide 09 / 25

💡 Core Teaching Point

async/await does not replace Promises! Under the hood, an async function literally returns a Promise, and await consumes a Promise. It is cleaner syntax for working with them.

Section 3: Parallelism & Errors

Promise.all: Important Behavior

Understanding "All-or-Nothing" resolution, fail-fast mechanics, and best use

Slide 11 / 25
📋 5 Essential Rules of Promise.all
  • 1. All Fulfill: Fulfills only when every single input Promise fulfills, returning an array of results in the exact same input order.
  • 2. Fail-Fast Rejection: It rejects immediately as soon as one single input Promise rejects.
  • 3. No Auto-Cancellation: Other running operations are not automatically cancelled when one rejects; they keep executing in the background.
  • 4. When to Use: For independent operations that do not depend on each other's output.
  • 5. When to Avoid: Avoid when task B requires data computed by task A (use sequential await instead).
💡
ES Module Top-Level Await: In modern Node.js ES modules (files with .js when "type": "module" is set in package.json or .mjs), await can be used directly at the top level without wrapping in an async function.
promise-all-behavior.js 
// Demonstrating resolved promises with Promise.all
const first = Promise.resolve("First");
const second = Promise.resolve("Second");

// Top-level await in Node.js ES Modules
const results = await Promise.all([first, second]);

console.log(results);

Section 3: Parallelism & Errors

Error Handling with try/catch

Intercepting failures and verifying HTTP status codes defensively

Slide 12 / 25
🛡️ Defensive Asynchronous Programming

Use try/catch blocks around await expressions to gracefully intercept network timeouts, parsing issues, and thrown exceptions without crashing the Node.js process.

🔍 Anatomy of try/catch
  • ▸ try block: Encloses risky operations (network calls, file reads, JSON parsing).
  • ▸ throw statement: Generates an explicit Error when business conditions fail.
  • ▸ catch(error): Intercepts any thrown error and allows recovery or logging.
🚨
Critical Fetch Pitfall: fetch() does not reject on HTTP 404 or 500 errors! It only rejects on severe network failures. You must manually verify if (!response.ok) and throw an Error!
fetch-trycatch.js 
async function getData() {
  try {
    const response = await fetch(
      "https://jsonplaceholder.typicode.com/users"
    );

    // Must verify response.ok manually!
    if (!response.ok) {
      throw new Error(`HTTP error: ${response.status}`);
    }

    const users = await response.json();

    console.log("Users:", users.length);
  } catch (error) {
    console.error("Failed to load users:", error.message);
  }
}

getData();
Execution Output

Section 5: Timeouts & AbortController

Why Do We Need Request Timeouts?

Preventing hanging connections, deadlocks, and system resource exhaustion

Slide 15 / 25
⏳ The Hanging Request Problem

By default, a network request can hang for minutes if a remote server drops packets, experiences internal deadlocks, or becomes unresponsive. Your Node.js server keeps memory allocated and sockets open, leading to memory leaks and cascaded failure.

⚡ What a Timeout Solution Provides
  • ▸ Guaranteed Bound: Caps the maximum time your app is willing to wait (e.g. 3,000ms).
  • ▸ Request Cancellation: Informs the underlying network socket to terminate immediately.
  • ▸ Predictable Error Handling: Translates hanging requests into catchable timeout errors.
🤖 Critical for Third-Party & AI APIs

When calling external services (payment gateways, CRM webhooks, and generative AI LLMs):

  • ▸ Serverless cold starts or LLM generation queues can unexpectedly freeze.
  • ▸ Without timeouts, your downstream users see an indefinite spinning wheel.
  • ▸ With a timeout, you can fail fast, trigger a fallback, or alert the user cleanly.
💡
The Web Standard: JavaScript provides the native AbortController and AbortSignal APIs to cancel asynchronous operations cleanly across the browser and Node.js.
Section 5: Timeouts & AbortController

AbortController with Fetch

Building a reusable timeout helper with AbortController and finally cleanup

Slide 16 / 25
fetch-with-timeout.js 
async function fetchWithTimeout(url, timeoutMs = 3000) {
  const controller = new AbortController();

  const timeoutId = setTimeout(() => {
    controller.abort();
  }, timeoutMs);

  try {
    const response = await fetch(url, {
      signal: controller.signal,
    });

    if (!response.ok) {
      throw new Error(`HTTP error: ${response.status}`);
    }

    return await response.json();
  } finally {
    clearTimeout(timeoutId);
  }
}
calling-fetch-with-timeout.js 
try {
  const users = await fetchWithTimeout(
    "https://jsonplaceholder.typicode.com/users",
    3000
  );
  console.log("Users:", users.length);
} catch (error) {
  if (error.name === "AbortError" || error.name === "TimeoutError") {
    console.error("Request timed out");
  } else {
    console.error("Request failed:", error.message);
  }
}
🔍 Key Architecture Elements
  • ▸ new AbortController(): Creates a controller instance with a cancellation signal.
  • ▸ controller.abort(): Fires when the timer expires, cancelling the pending fetch.
  • ▸ finally { clearTimeout(timeoutId) }: Guarantees the pending timer is cleared whether the fetch succeeds or fails!
Section 6: Retry & Exponential Backoff

Why Retry Failed Requests?

Distinguishing transient recoverable glitches from permanent failures

Slide 17 / 25
✅ When Retrying IS Appropriate

Distributed systems experience transient errors — temporary hiccups that resolve themselves within milliseconds:

  • ▸ Service temporarily unavailable: HTTP 503 during rolling server restarts.
  • ▸ Temporary connection drops: Brief Wi-Fi or router socket resets (ECONNRESET).
  • ▸ Rate limiting: HTTP 429 Too Many Requests where a short wait will reset the token bucket.
💡
Idempotent Operations: Safe retries are easiest on GET requests where reading data does not create side effects on the server.
❌ When Retrying IS DANGEROUS & WRONG

Never retry blindly:

  • ▸ Permanent 4xx Client Errors: HTTP 400 Bad Request, 401 Unauthorized, or 404 Not Found will never succeed on retry and only waste resources.
  • ▸ State Mutations: Retrying non-idempotent POST payment or order requests blindly could charge a customer multiple times!
⚠️
Rule of Thumb: Immediate retries hammer an already struggling server. Always introduce an increasing delay between attempts!

🎲
Production Jitter: Adding ±10% random noise prevents thousands of clients from retrying at the exact same microsecond.
retry-helper.js 
function delay(ms) {
  return new Promise((resolve) => setTimeout(resolve, ms));
}

async function retryOperation(operation, maxAttempts = 3) {
  for (let attempt = 1; attempt <= maxAttempts; attempt++) {
    try {
      return await operation();
    } catch (error) {
      if (attempt === maxAttempts) {
        throw error;
      }

      const waitTime = 500 * 2 ** (attempt - 1);

      console.log(
        `Attempt ${attempt} failed. Retrying in ${waitTime}ms`
      );

      await delay(waitTime);
    }
  }
}

Retry a Fetch Request

Combining the reusable retry helper with network calls and top-level error propagation

retry-fetch.js 
async function fetchUsers() {

    );
  }

🔄 Execution Lifecycle
1 Attempt 1: Runs fetchUsers() immediately (0ms delay). If successful, returns data instantly.
2 Attempt 2: If Attempt 1 throws, logs message and pauses 500ms before Attempt 2.
3 Attempt 3: If Attempt 2 throws, pauses 1,000ms before the final attempt.
4 Exhaustion: If Attempt 3 fails, the final error re-throws into main()'s catch block.
👨‍🏫
Instructor Note: In production applications, inspect response headers: if a server sends a Retry-After: 5 header (common on HTTP 429 rate limits), respect that duration rather than calculating an arbitrary backoff.

Understanding fs/promises

Modern Promise-based asynchronous file reading, writing, and directory creation

Slide 20 / 25
📁 Why node:fs/promises?

Node.js provides node:fs/promises which delivers clean, Promise-returning methods instead of legacy callback wrappers.

🛠️ Common Promise Filesystem Methods
  • ▸ readFile(path, encoding): Asynchronously reads entire file contents.
  • ▸ writeFile(path, data, encoding): Writes data; creates or overwrites the file.
  • ▸ appendFile(path, data): Appends content to the end of a file.
  • ▸ mkdir(path, { recursive: true }): Creates directories and nested parents.
  • ▸ readdir(path): Lists all filenames inside a directory.
💡

async function main() {

    const content = await readFile("message.txt", "utf8");

    console.log("Original content:", content);

    await writeFile("output.txt", content.toUpperCase());

    console.log("Output file created");
  } catch (error) {
    console.error("File operation failed:", error.message);
  }
}

Section 7: Filesystem & Paths

Working with File Paths

Cross-platform path resolution with node:path to eliminate OS-specific bugs

Slide 21 / 25
⚠️ The Problem with Hardcoded Paths

Hardcoded string concatenation like folder + "/" + file or Windows backslashes "reports\\file.txt" breaks when moving code between Windows, macOS, Linux, Docker containers, and cloud hosts.

🧭 Essential node:path Methods
  • ▸ path.join(...segments): Joins segments using the host operating system's specific separator (\ on Windows, / on Linux/Mac).
  • ▸ path.resolve(...segments): Resolves a sequence of paths into an absolute path from the current directory.
  • ▸ path.dirname(p): Extracts the directory part of a path.
  • ▸ path.basename(p): Extracts the file name and extension.

Section 7: Filesystem & Paths

Practical File Report Generator

Combining fetch, map, path, and fs/promises into an integrated report generator

Slide 22 / 25
generate-report.js 
import { mkdir, writeFile } from "node:fs/promises";
import path from "node:path";

async function main() {
  const response = await fetch(
    "https://jsonplaceholder.typicode.com/users"
  );

  if (!response.ok) {
    throw new Error(`HTTP error: ${response.status}`);
  }

  const users = await response.json();
  const names = users.map((user) => user.name);
  const report = names.join("\n");

  const outputDirectory = path.resolve("reports");
  const outputFile = path.join(outputDirectory, "users.txt");

  await mkdir(outputDirectory, { recursive: true });
  await writeFile(outputFile, report, "utf8");

  console.log(`Report saved to: ${outputFile}`);
}

main().catch((error) => {
  console.error("Report generation failed:", error.message);
});
⚙️ How the Pieces Fit Together
1 Fetch Data: fetch() queries JSONPlaceholder asynchronously.
2 Transform: map() extracts user names and join("\n") formats text lines.
3 Path Safety: path.resolve() and path.join() build reliable absolute paths.
4 Recursive mkdir: mkdir(..., { recursive: true }) creates the directory if it doesn't already exist.
5 Safe Persistence: writeFile() writes the report cleanly to disk.

}

async function retryOperation(operation, maxAttempts) {
  for (let attempt = 1; attempt <= maxAttempts; attempt++) {
    try {
      return await operation();
    } catch (error) {
      if (attempt === maxAttempts) {
        throw error;
      }

      const waitTime = 500 * 2 ** (attempt - 1);

      console.log(
        `Attempt ${attempt} failed. Retrying in ${waitTime}ms`
      );

      await delay(waitTime);
    }
  }
}

async function main() {
  try {
    const users = await retryOperation(
      () => fetchWithTimeout(API_URL, TIMEOUT_MS),
      MAX_ATTEMPTS
    );

    const userDetails = users.map((user) => ({
      name: user.name,
      email: user.email,
    }));

    const report = userDetails
      .map((user) => `${user.name} - ${user.email}`)
      .join("\n");

    const outputDirectory = path.resolve("reports");
    const outputFile = path.join(outputDirectory, "users.txt");

    await mkdir(outputDirectory, { recursive: true });
    await writeFile(outputFile, report, "utf8");

    console.log(`Fetched ${userDetails.length} users`);
    console.log(`Report saved to: ${outputFile}`);
  } catch (error) {
    console.error("Unable to generate report:", error.message);
    process.exitCode = 1;
  }
}

main();

🎓 Day 2 Key Takeaways
  • ▸ Event Loop: Single-threaded JavaScript coordinates non-blocking I/O through task queues.
  • ▸ async/await: Syntactic sugar over Promises; pauses only inside async functions.
  • ▸ Promise.all: Boosts throughput for independent tasks; fails fast on single rejection.
  • ▸ fetch() & response.ok: Global native HTTP; always verify status codes defensively.
  • ▸ AbortController: Standardized timeout cancellation with clearTimeout in finally.
  • ▸ Exponential Backoff: Progressively delays retries to protect upstream services.
  • ▸ fs/promises & path: Asynchronous filesystem with cross-platform OS path safety.

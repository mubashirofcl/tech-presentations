SECTION 1 • COMPASS

What Is MongoDB Compass?

The official Graphical User Interface (GUI) for MongoDB database administration

GUI vs Terminal Shell

Instead of typing shell commands into mongosh in a black terminal window, MongoDB Compass gives you an intuitive desktop interface to visually manage your databases.

Compass Capabilities

  • ✓ View Databases: See all databases at a glance
  • ✓ View Collections: Explore collections within any database
  • ✓ Inspect Documents: View records in Tree, JSON, or Table view
  • ✓ Insert & Edit: Add new documents and edit fields point-and-click
  • ✓ Delete Records: Safely remove documents with confirmation
  • ✓ Run Visual Queries: Filter with { genre: "Sci-Fi" } easily
  • ✓ Inspect Indexes & Schema: Analyze field distributions & performance

SECTION 1 • COMPASS

Connecting to Local MongoDB

Establishing a connection to your local MongoDB service (mongod)

Standard Local Connection URI
mongodb://127.0.0.1:27017

Can also use mongodb://localhost:27017. 127.0.0.1 avoids Node IPv6 address resolution glitches on Windows.

URI Breakdown

  • • mongodb:// Protocol scheme for MongoDB driver
  • • 127.0.0.1 Loopback IP address of your local computer
  • • 27017 Default network port where MongoDB listens

⚡ 4-Step Connection Sequence

01
Open Compass: Launch MongoDB Compass desktop application on your PC.
02
Enter Connection String: Paste mongodb://127.0.0.1:27017 into the input bar.
03
Click [Connect]: Compass establishes a socket handshake with your local service.
04
Explore Databases: View built-in databases and create your new movieDB database.
⚠️
If connection fails: Ensure your local MongoDB service is running (in Windows Services or run net start MongoDB in admin terminal).

SECTION 2 • ATLAS

What Is MongoDB Atlas?

MongoDB's fully managed, multi-cloud database platform

☁️ Cloud vs Local Reality

When you run MongoDB locally, it only exists on your laptop. If your computer shuts down, your database goes offline. No one on the internet can reach it.

MongoDB Atlas runs MongoDB in the cloud across world-class infrastructure (AWS, Google Cloud, Azure). It provides 24/7 uptime, automated backups, and global internet connectivity for web apps.

💻 LOCAL MONGODB
Runs strictly inside your computer hard drive. Accessible ONLY by your local machine.
VS
☁️ MONGODB ATLAS (CLOUD)
Runs in AWS/GCP cloud clusters. Accessible 24/7 from anywhere by your web servers and mobile apps!
🆓 Free Tier (M0 Sandbox)

512MB free storage forever. Ideal for learning, prototypes, and student projects.

🛡️ Built-in Security

Role-based database users, IP address whitelisting, and automated SSL/TLS encryption.

🔄 Zero Maintenance

No server patching, no hard drive management, and point-in-time recovery built right in.

SECTION 2 • ATLAS

Atlas Connection String & Security

Connecting via standard URI and safeguarding production credentials

Atlas Connection String Format
mongodb+srv://admin:p@ssword123@cluster0.mongodb.net/movieDB

Component Breakdown

  • • mongodb+srv:// DNS Seedlist protocol for cloud clusters
  • • username : password Database user credentials created in Step 4
  • • cluster0.mongodb.net Cloud cluster domain hosted on Atlas
  • • /movieDB The specific target database name
.env (Keep Secret!)
ENV 
# Never commit your database credentials to GitHub!
PORT=5000
MONGO_URI=mongodb+srv://admin:secret123@cluster0.mongodb.net/movieDB
src/config/db.js
NODE.JS 
const mongoose = require('mongoose');

const connectDB = async () => {
  try {
    await mongoose.connect(process.env.MONGO_URI);
    console.log('MongoDB Atlas Connected Successfully');
  } catch (err) {
    console.error(err);
    process.exit(1);
  }
};
🚨
CRITICAL SECURITY RULE: Never hard-code database passwords into JavaScript files! Always store connection strings in .env and add .env to your .gitignore file!

GUI vs Application Code

Understanding the complementary roles in modern software development

🧭 MongoDB Compass (GUI Tool)

Built for the developer while programming and debugging.

  • 🔍 Inspecting raw data: Verify what actually got saved to MongoDB
  • 🧪 Testing queries: Try complex filters before writing code
  • ✏️ Manually tweaking fields: Fix bad test data in 2 clicks
  • 🐛 Troubleshooting: Debug missing attributes or failed writes
  • ⚡ Checking indexes: Visually review collection execution plans
💻 Application Code (Express + Mongoose)

Built for the end-users and client devices 24 hours a day.

  • 🌐 Handling client requests: React, mobile, or Postman calls
  • 🔄 Automated CRUD: Create, Read, Update, Delete at scale
  • 🛡️ Validation & Business Rules: Enforce required fields and permissions
  • 📦 API responses: Return clean JSON objects with HTTP status codes
  • 🔐 Authentication: Verify tokens and sanitize client input

SECTION 4 • MOVIE WATCHLIST API

Movie Data Model & Mongoose Schema

Defining the document shape for our movies collection

Raw MongoDB Document (JSON / BSON)
JSON 
{
  "title": "Interstellar",
  "genre": "Sci-Fi",
  "year": 2014,
  "rating": 8.7,
  "watched": false
}

Field Specifications

  • • title (String) Name of the film (required)
  • • genre (String) Category (Sci-Fi, Action, Drama)
  • • year (Number) Release year (e.g. 2014)
  • • rating (Number) Score out of 10 (e.g. 8.7)
  • • watched (Boolean) Viewing status, defaults to false
src/models/Movie.js 
const mongoose = require('mongoose');

const movieSchema = new mongoose.Schema({
  title: {
    type: String,
    required: true
  },
  genre: {
    type: String,
    required: true
  },
  year: {
    type: Number
  },
  rating: {
    type: Number,
    default: 0
  },
  watched: {
    type: Boolean,
    default: false
  }
}, { timestamps: true });

module.exports = mongoose.model('Movie', movieSchema);

Add Movie Endpoint (POST /movies)

Creating documents in MongoDB via Mongoose

Client HTTP Request
POST /movies 
// Request Body sent from client:
{
  "title": "Interstellar",
  "genre": "Sci-Fi",
  "year": 2014,
  "rating": 8.7
}

What happens behind the scenes?

1. Express parses the incoming JSON using express.json().
2. Mongoose validates the payload against movieSchema.
3. MongoDB inserts document, generates unique _id, and sets watched: false.

Express Route Handler 
// POST /movies - Add movie
app.post('/movies', async (req, res) => {
  try {
    // Insert document into MongoDB Atlas:
    const movie = await Movie.create(req.body);
    
    res.status(201).json(movie);
  } catch (err) {
    res.status(400).json({ error: err.message });
  }
});

SECTION 4 • MOVIE WATCHLIST API

Update & Delete Implementation

Modifying and removing documents by MongoDB ID

PUT /movies/:id
UPDATE 
// Update movie details or mark watched
app.put('/movies/:id', async (req, res) => {
  try {
    const movie = await Movie.findByIdAndUpdate(
      req.params.id,
      req.body,
      { new: true } // Return modified doc
    );
    if (!movie) return res.status(404).json({ error: 'Not found' });
    res.json(movie);
  } catch (err) {
    res.status(400).json({ error: err.message });
  }
});

💡 { new: true } ensures Mongoose returns the updated document instead of the original one.

DELETE /movies/:id
DELETE 
// Delete movie from collection
app.delete('/movies/:id', async (req, res) => {
  try {
    const movie = await Movie.findByIdAndDelete(
      req.params.id
    );
    if (!movie) return res.status(404).json({ error: 'Not found' });
    res.json({ message: 'Movie deleted successfully' });
  } catch (err) {
    res.status(400).json({ error: err.message });
  }
});
🗑️
Once deleted via findByIdAndDelete(), the document is gone from the database permanently!

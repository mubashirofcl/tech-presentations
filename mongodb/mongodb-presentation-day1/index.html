MongoDB Week › Database Basics › Definition
01 • Concept

What is a Database?

An organized, permanent system for storing, managing, and retrieving data efficiently.

Formal Definition for Students

A database is an organized collection of structured or semi-structured data that can be stored securely, searched rapidly, updated reliably, and retrieved efficiently.

Real-world College Example: A college needs to track and link:
  • Students: Names, roll numbers, emails, phone numbers.
  • Teachers: Staff ID, departments, qualifications.
  • Courses: Course codes, syllabus, credits.
  • Attendance & Marks: Exam grades and semester percentages.
Why Not Just Text Files?

Without a database, developers tried saving data into simple text files:

📄 students.txt
📄 students2.txt
📄 students-final.txt
📄 students-final-new(1).txt
❌ Corrupts easily, cannot search 100,000 records quickly, zero concurrent user safety, no data security!

02 • Motivation

Why Do We Need Databases?

The 7 fundamental engineering reasons why professional software relies on database management systems.

1. Organized Storage

Structured into logical databases and collections rather than scattered disk files.

2. Rapid Searching

Find 1 record out of 10 million in less than 5 milliseconds using indexing.

3. Safe Updates & Deletions

Modify specific fields without rewriting the entire file or risking corruption.

4. Data Consistency

Enforce schema rules, correct data types, and unique constraints (e.g. unique email).

5. Security & Access Control

User authentication, encrypted connections (TLS), and granular read/write permissions.

6. High Scalability

Handle gigabytes, terabytes, or petabytes of data across multiple cluster nodes.

7. Concurrency

Tens of thousands of simultaneous users reading and writing without data collision.

MongoDB Week › Database Basics › SQL vs NoSQL
03 • Categories

Types of Databases: SQL vs NoSQL

Comparing the traditional relational model with the modern document-oriented paradigm.

SQL / Relational Databases

Data is organized into rigid, tabular grids with predefined schemas:

Database → Tables → Rows → Columns
• Examples: MySQL, PostgreSQL, Oracle, SQL Server.
• Enforces strict tabular schema (every row must fit column definitions).
• Connected through complex relational JOINs.
NoSQL (Document / Non-Relational)

Data is stored as independent, flexible, JSON-like documents:

Database → Collections → Documents → Fields
• Examples: MongoDB, Redis, Cassandra, DynamoDB.
• Flexible schema (documents in the same collection can have varied fields).
• NoSQL means "Not Only SQL" — modern distributed systems.
Key Terminology Translation: An SQL Table corresponds to a MongoDB Collection. An SQL Row corresponds to a MongoDB Document. An SQL Column corresponds to a MongoDB Field.
MongoDB Week › What is MongoDB? › Definition & BSON
04 • Core Definition

What is MongoDB & What is BSON?

A document-oriented database that stores flexible, high-speed BSON data.

Core Definition

MongoDB is an open-source, NoSQL, document-oriented database management system.

Sample MongoDB Document
{
  "_id": ObjectId("6501a2b3c4d5e6f7a8b9c0d1"),
  "name": "Mubashir",
  "age": 23,
  "course": "MERN",
  "isActive": true
}
Every document contains fields (keys) and values, represented in a JSON-like format.
What is BSON? (Crucial Detail)
Do NOT say MongoDB stores JSON!
MongoDB represents data in JSON-like format to developers, but internally stores it as BSON (Binary JSON).

Why BSON over raw JSON?
• Speed: Binary encoding allows blazing-fast traversal and indexing.
• Rich Data Types: JSON only supports strings, numbers, booleans, arrays, objects, and null. BSON adds Date, ObjectId, Binary Data, and 64-bit Integers!

MongoDB Week › Why MongoDB? › Advantages
05 • Advantages

Why MongoDB? Key Characteristics

Why MongoDB is the world's most widely adopted document database for web developers.

1. Document-Oriented

Maps naturally to modern object-oriented code. A document in MongoDB looks identical to a JavaScript object in your app.

2. Flexible Schema (Polymorphism)

No strict database migrations required. You can add new fields to new documents without breaking existing records.

3. Rich & Powerful Querying

Filter deeply nested fields, search arrays, match regular expressions, and execute complex comparisons easily.

4. High Performance Indexing

Create secondary B-Tree indexes on any field, compound indexes, text indexes, and geospatial location coordinates.

5. Horizontal Scalability (Sharding)

Built from day one to scale out across clusters of servers rather than requiring one monstrously expensive mainframe.

6. The JavaScript / MERN Synergy

One language across the entire stack! JavaScript in React, JavaScript in Node/Express, and JSON/BSON in MongoDB.

MongoDB in the MERN Stack Architecture

Understanding the complete request-response cycle and why React never touches MongoDB directly.

The Full-Stack MERN Request Lifecycle
Client UI React.js Browser interface
→ HTTP Request →
Backend API Express / Node.js Server routes & logic
→ Driver Query →
Database MongoDB BSON Storage Engine
← Database Result returns to Node.js → Node.js formats JSON → React updates UI ←
Why Can't React Connect Directly to MongoDB?
  • Security Disaster: Connecting directly from the browser would expose your database credentials and secret password in public client JavaScript!
  • Zero Permission Control: Any clever user could open Chrome DevTools and run db.users.deleteMany({})!
  • Protocol Mismatch: Browsers speak HTTP/WebSocket; MongoDB speaks its own internal TCP wire protocol.
The Backend's Role as the Trusted Guardian

The Express / Node.js backend acts as the secure middleman:
1. Authenticates the incoming user request (JSON Web Tokens / Sessions).
2. Validates incoming payload data.
3. Executes authorized queries against MongoDB.
4. Returns safe, sanitized JSON responses to the React frontend.

MongoDB Week › Architecture › Core Terms
08 • Core Terminology

Database, Collection, Document & Field

Clear definitions and practical breakdowns of each architectural layer.

1. Database & 2. Collection

Database: The high-level physical container on disk that holds one or more collections. A single MongoDB server can host hundreds of independent databases.

Collection: A group of related MongoDB documents (the direct equivalent of an SQL table). Does not enforce identical schemas across documents by default.

3. Document & 4. Field

Document: An individual record stored inside a collection (equivalent to an SQL row). Written in JSON-like syntax and persisted as BSON. Maximum size: 16 MB.

Field: A key-value pair inside a document (equivalent to an SQL column). In { age: 23 }, age is the field name and 23 is the field value.

MongoDB Week › Architecture › _id & ObjectId
12 • Primary Key

The _id Field & ObjectId

How MongoDB guarantees globally unique document identification across distributed systems.

The Role of _id

Every single document in a MongoDB collection MUST have a unique _id field that acts as its primary key.

  • If you do not provide an _id when inserting, MongoDB generates one automatically.
  • The default generated type is an ObjectId.
  • Guarantees uniqueness within that collection across any cluster.
{
  "_id": ObjectId("65f1a2b3c4d5e6f7a8b9c0d1"),
  "name": "John Doe"
}
Anatomy of a 12-Byte ObjectId

An ObjectId is NOT a random string! It is a packed 12-byte binary BSON value made of:

First 4 Bytes: Unix timestamp (seconds since 1970). You can extract the exact creation date directly from the ID!
Next 5 Bytes: Random machine identifier + process ID.
Final 3 Bytes: Incrementing counter initialized to a random value.

MongoDB Week › Tools › Server vs Client
15 • Distinction

mongod vs mongosh: The Critical Distinction

Understanding the difference between the background server daemon and the foreground client.

mongod (MongoDB Daemon / Server)
• The 'd' stands for Daemon (a background process).
• It is the database server itself.
• Listens for network connections on default port 27017.
• Manages data storage, memory cache, reads, and writes to disk.
⚙️ Runs as a background service on Windows/Mac/Linux.
mongosh (MongoDB Shell / Client)
• The 'sh' stands for Shell.
• It is an interactive client tool you open in the terminal.
• Connects to the running mongod server.
• Provides an interactive Node.js REPL environment to execute database queries.
💻 This is where YOU type commands like db.students.find()!
MongoDB Week › mongosh › Starting the Shell
18 • Shell Connection

Starting mongosh & Understanding Connection Strings

Connecting your interactive command-line interface to the database instance.

Starting the Shell

Simply open your terminal (Git Bash, Command Prompt, or PowerShell) and run:

Terminal
# Connects to default local instance
mongosh

Or explicitly pass the connection URI: 

mongosh "mongodb://localhost:27017"
Connection String Anatomy
mongodb://localhost:27017
• mongodb:// → Protocol identifier (like http:// for the web).
• localhost → Host machine (the local computer you are typing on; IP 127.0.0.1).
• 27017 → Default TCP port MongoDB listens on.

Crucial Concept: Lazy Persistence!
Why does show dbs NOT show my new database?
When you run use school, MongoDB does NOT create physical files on your hard drive immediately!

MongoDB uses lazy creation:
• The database only physically exists once you insert at least one document into a collection.
• As soon as you run db.students.insertOne({ name: "John" }), MongoDB persists both the school database and the students collection!

MongoDB Week › CRUD › Create (Insert)
44 • Insert

Insert Operations: insertOne() & insertMany()

Inserting individual records and batch inserting arrays of documents.

1. insertOne(document)

Inserts a single document object into the collection: 

school> db.students.insertOne({
  name: "Mubashir",
  age: 23,
  course: "MERN"
})

{
  acknowledged: true,
  insertedId: ObjectId("65f1c4e9a8b7c6d5e4f3a2b1")
}
✓ MongoDB automatically returns the newly generated insertedId!
2. insertMany([ doc1, doc2, ... ])

Inserts an array of multiple documents in one round-trip: 

school> db.students.insertMany([
  { name: "John", age: 22, course: "MERN" },
  { name: "Sarah", age: 24, course: "Python" },
  { name: "Alex", age: 21, course: "MERN" }
])

{
  acknowledged: true,
  insertedIds: {
    '0': ObjectId("..."),
    '1': ObjectId("..."),
    '2': ObjectId("...")
  }
}
MongoDB Week › CRUD › Read (Query)
46 • Read

Read Operations: find() & findOne()

Retrieving multiple matching documents or a single document from a collection.

find(filter) → Returns All Matches

Returns a cursor to all documents that match the criteria: 

// Empty filter {} returns ALL documents
school> db.students.find()

// Filter by exact field match
school> db.students.find({ course: "MERN" })

// Filter by number
school> db.students.find({ age: 23 })
If multiple documents match, find() returns all of them.
findOne(filter) → Returns ONE Document

Returns only the first matching document object (not a cursor): 

// Finds single student by unique name or email
school> db.students.findOne({ name: "Mubashir" })

{
  "_id": ObjectId("..."),
  "name": "Mubashir",
  "age": 23,
  "course": "MERN"
}
If no match is found, findOne() returns null.
MongoDB Week › CRUD › Update
50 • Update

Update Operations: updateOne() & updateMany()

Modifying existing document fields using atomic update operators.

The 2-Argument Update Formula

Every update method requires two essential arguments: db.collection.updateOne(filter, updatePayload)

1. Filter: Which document(s)?   →   2. Operator ($set): What should change?
updateOne({ filter }, { $set: { ... } })
// Updates age of ONE student named Mubashir
school> db.students.updateOne(
  { name: "Mubashir" }, // 1. Filter
  { $set: { age: 24 } }  // 2. Update
)

{ acknowledged: true, matchedCount: 1, modifiedCount: 1 }
updateMany({ filter }, { $set: { ... } })
// Updates status of ALL MERN students
school> db.students.updateMany(
  { course: "MERN" },
  { $set: { status: "active" } }
)

{ acknowledged: true, matchedCount: 3, modifiedCount: 3 }
WARNING: Never forget the update operator! Writing db.students.updateOne({ name: "John" }, { age: 24 }) without $set will throw an error in modern MongoDB to prevent accidental document overwrite!
MongoDB Week › CRUD › Update Operators
52 • Operators

Core Update Operators: $set, $inc & $unset

Modifying, incrementing numbers, and removing specific fields atomically.

$set Modify or Add Field

Updates an existing field value, or adds the field if it doesn't exist yet: 

db.users.updateOne(
  { _id: 1 },
  {
    $set: {
      age: 25,
      city: "Calicut"
    }
  }
)
$inc Increment / Decrement

Increments a number by a positive or negative amount atomically: 

// Increase stock by 5
db.products.updateOne(
  { name: "T-Shirt" },
  { $inc: { stock: 5 } }
)

// Decrease stock by 1: use -1
{ $inc: { stock: -1 } }
$unset Remove Field Entirely

Deletes a specific field key-value pair from the document: 

// Deletes the temporaryCode field
db.users.updateOne(
  { name: "John" },
  {
    $unset: {
      temporaryCode: ""
    }
  }
)
MongoDB Week › CRUD › Delete
55 • Delete

Delete Operations: deleteOne() & deleteMany()

Removing records permanently from your MongoDB collections.

1. deleteOne(filter)

Deletes the first matching document found: 

// Deletes only one student named Alex
school> db.students.deleteOne({ name: "Alex" })

{ acknowledged: true, deletedCount: 1 }
2. deleteMany(filter)

Deletes all documents that match the criteria: 

// Deletes all students whose status is inactive
school> db.students.deleteMany({ status: "inactive" })

{ acknowledged: true, deletedCount: 4 }
CRITICAL DANGER: Accidental Total Collection Wipeout!
Running db.students.deleteMany({}) with an empty filter object will DELETE EVERY SINGLE DOCUMENT IN THE COLLECTION!
Never run deleteMany({}) in production without strict confirmation.

Introduction to MongoDB Query Operators

Using $ operator syntax to filter data beyond simple exact equality matches.

1. Comparison

Compare field values against criteria.

$eq, $ne, $gt, $gte, $lt, $lte, $in, $nin

2. Logical

Combine multiple query clauses.

MongoDB Week › Operators › Comparison
57 • Comparison

Comparison Operators: $gt, $gte, $lt, $lte, $ne

Filtering numerical ranges, dates, and inequality conditions.

Comparison Operators Syntax
OperatorMeaningExample
$eqEqual to{ age: { $eq: 23 } }
$neNot equal to{ age: { $ne: 23 } }
$gtGreater than (>){ age: { $gt: 18 } }
$gteGreater than or equal (≥){ age: { $gte: 18 } }
$ltLess than (<){ age: { $lt: 30 } }
$lteLess than or equal (≤){ age: { $lte: 30 } }
Practical Query Examples
// Students strictly older than 21
db.students.find({
  age: { $gt: 21 }
})

// Products with price <= 500
db.products.find({
  price: { $lte: 500 }
})

// Range Query: Price between 100 AND 500
db.products.find({
  price: { $gte: 100, $lte: 500 }
})
✓ Notice how range queries combine $gte and $lte inside the same field object!
MongoDB Week › Operators › $in & $nin
58 • List Matching

List Matching: $in and $nin

Matching field values against an array of multiple potential choices.

$in Matches ANY Value in the List

Matches documents where the field value matches at least one value in the array (OR logic): 

// Students whose age is 20 OR 22 OR 24
db.students.find({
  age: {
    $in: [20, 22, 24]
  }
})

// Products in Clothing OR Shoes
db.products.find({
  category: {
    $in: ["Clothing", "Shoes"]
  }
})
$nin NOT in the Given List

Matches documents where the field value does NOT match any value in the array: 

// Students NOT enrolled in Python or Java
db.students.find({
  course: {
    $nin: ["Python", "Java"]
  }
})
Documents that don't have the field at all are also matched by $nin.
MongoDB Week › Operators › Logical
60 • Logical

Logical Operators: $and, $or & $not

Combining multiple search conditions using Boolean logic.

$and ALL Conditions Must Match 
// Must be age > 18 AND course == "MERN"
db.students.find({
  $and: [
    { age: { $gt: 18 } },
    { course: "MERN" }
  ]
})
Note: In MongoDB, multiple comma-separated fields in a query already use implicit $and!
$or At Least ONE Condition Must Match 
// Matches if age == 20 OR age == 25
db.students.find({
  $or: [
    { age: 20 },
    { age: 25 }
  ]
})
Takes an array of condition objects: [ { cond1 }, { cond2 } ].
$not Negates a Condition Expression 
// Finds students whose age is NOT greater than 25 (i.e. age <= 25 or age field missing)
db.students.find({
  age: {
    $not: { $gt: 25 }
  }
})
MongoDB Week › Operators › Element & Array
62 • Element & Array

Element & Array Queries: $exists & $size

Verifying field existence and querying inside array lists.

$exists Checks Whether a Field Exists

Because MongoDB has a flexible schema, not all documents have the same fields: 

// Find users who have a phone field
db.users.find({
  phone: { $exists: true }
})

// Find users who do NOT have a phone field
db.users.find({
  phone: { $exists: false }
})
Array Query Querying Inside Arrays

If a document contains skills: ["React", "Node", "MongoDB"]: 

// Matches if "React" is ANY element in skills array
db.users.find({
  skills: "React"
})

// $size: Matches array length exact count
db.users.find({
  skills: { $size: 2 }
})
✓ MongoDB automatically unrolls and inspects array contents without needing loops!
MongoDB Week › Reference › Summary Cheat Sheet
64 • Quick Reference

Query Operators Master Reference Table

A comprehensive cheat sheet of all essential query operators for your projects and interviews.

Operator Category Meaning / Purpose Code Example
$eq Comparison Matches values that are equal to a specified value { age: { $eq: 23 } }
$ne Comparison Matches all values that are NOT equal { status: { $ne: "banned" } }
$gt / $gte Comparison Greater than (>) / Greater than or equal (≥) { price: { $gte: 100 } }
$lt / $lte Comparison Less than (<) / Less than or equal (≤) { stock: { $lt: 10 } }
$in Comparison Matches any value specified in an array list { role: { $in: ["admin", "editor"] } }
$nin Comparison Matches none of the values specified in an array list { course: { $nin: ["Java", "C++"] } }
$and Logical Joins query clauses with a logical AND (all must match) { $and: [{ a: 1 }, { b: 2 }] }
$or Logical Joins query clauses with a logical OR (any can match) { $or: [{ role: "admin" }, { age: { $gt: 30 } }] }
$not Logical Inverts the effect of a query expression { age: { $not: { $gt: 25 } } }
$exists Element Matches documents that possess the specified field { phone: { $exists: true } }
$size Array Matches any array field with the specified number of elements { skills: { $size: 3 } }

Mastering updates, deletions, and the e-commerce product query challenge.

Exercises 4 & 5: Update & Delete
// Exercise 4: Update John's age to 23
school> db.students.updateOne(
  { name: "John" },
  { $set: { age: 23 } }
)

// Update all MERN students to active
school> db.students.updateMany(
  { course: "MERN" },
  { $set: { status: "active" } }
)

// Exercise 5: Delete student Alex
school> db.students.deleteOne({ name: "Alex" })
Exercise 6: E-Commerce Product Challenge

Create products collection with T-Shirt (799, Clothing, stock 20), Jeans (1499, Clothing, stock 10), Cap (399, Accessories, stock 50): 

// 1. Products with price > 500:
db.products.find({ price: { $gt: 500 } })

// 2. Products with stock < 20:
db.products.find({ stock: { $lt: 20 } })

// 3. Price between 500 and 1500:
db.products.find({ price: { $gte: 500, $lte: 1500 } })

// 4. Category is Clothing OR Accessories:
db.products.find({ category: { $in: ["Clothing", "Accessories"] } })

// 5. Increment T-Shirt stock by 5:
db.products.updateOne({ name: "T-Shirt" }, { $inc: { stock: 5 } })

Top 10 Common Beginner Mistakes & Fixes

Avoid these critical pitfalls to write professional, bug-free database code.

# Mistake What Goes Wrong? The Correct Fix
1 Confusing Server, mongosh, Compass & Atlas Trying to type queries into mongod or thinking Compass is the database. mongod = Server daemon; mongosh = CLI client; Compass = GUI viewer; Atlas = Cloud service.
2 Thinking use school creates persistent disk files Panicking when show dbs doesn't show the new database. MongoDB uses lazy persistence: DB is created only when the first document is inserted!
3 Forgetting the $ in Operators Writing { age: { gt: 18 } } → treated as literal field search. Always prefix operators with $: { age: { $gt: 18 } }.
4 Forgetting $set in Updates Writing db.users.updateOne({ name: "John" }, { age: 25 }). Always wrap modifications in an update operator: { $set: { age: 25 } }!
5 Accidental deleteMany({}) Total Wipeout Passing empty filter wipes out every single document in the collection! Always provide a strict filter condition (e.g. { status: "archived" }).
6 Thinking MongoDB Stores Plain JSON Believing dates, ObjectIds, and binary data are saved as raw text strings. MongoDB stores BSON (Binary JSON) which supports native timestamps and ObjectIds.
7 Treating _id as a Plain String in Queries db.find({ _id: "65f..." }) returns null. Wrap the hex string in the BSON constructor: { _id: ObjectId("65f...") }.
8 Exposing Atlas Connection Strings to GitHub Cloud database passwords leaked publicly; bots compromise cluster. Never commit passwords to Git! Always use a local .env file added to .gitignore.
9 Believing React Connects Directly to MongoDB Trying to import MongoDB drivers inside client-side browser files. React → Express/Node.js → MongoDB. Only the backend touches the database!
10 Forgetting Array Brackets in insertMany Writing insertMany({ a: 1 }, { b: 2 }) throws a syntax error. Pass documents inside an array: insertMany([ { a: 1 }, { b: 2 } ]).

Comprehensive MongoDB Revision Bank

Click any question below to reveal the model answer for classroom review.

Model Answer: MongoDB is an open-source, NoSQL, document-oriented database system. Unlike plain JSON (which only supports strings, numbers, booleans, arrays, objects, and null), MongoDB internally stores documents in BSON (Binary JSON). BSON provides binary compression for lightning-fast scanning and adds native data types like Date, ObjectId, Binary data, and 64-bit Integers.
Model Answer: A Server (mongod) hosts multiple Databases. A Database is a container that holds multiple Collections (equivalent to SQL tables). A Collection contains multiple Documents (individual records up to 16MB, equivalent to SQL rows). A Document contains key-value pairs called Fields (equivalent to SQL columns).
Model Answer: mongod is the background database daemon server process that manages disk writes and listens on port 27017. mongosh is the command-line shell client where developers type interactive queries. MongoDB Compass is the official desktop graphical user interface (GUI) for visual data exploration.
Model Answer: find() returns a cursor referencing all documents that match the filter; if no documents match, it returns an empty cursor []. findOne() returns the first single document object directly; if no document matches, it returns null.
Model Answer: The $set operator tells MongoDB to update or add specific field key-value pairs without altering the rest of the document. Without $set, modern MongoDB throws an error to prevent accidentally wiping out all other fields in the record.
Model Answer: The _id field is the mandatory primary key of every document. The default generated ObjectId is a 12-byte binary BSON value composed of: (1) a 4-byte Unix timestamp, (2) a 5-byte random machine and process identifier, and (3) a 3-byte incrementing counter. It guarantees globally unique identification across distributed cloud servers.

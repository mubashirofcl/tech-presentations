Foundation

1. Introduction to CRUD

The four building blocks of every backend application, database, and API.

💡 What does CRUD stand for?

CRUD is an acronym for the four basic operations that any persistent storage system performs:

CREATE Add a new document into the database
READ Get or search for existing documents
UPDATE Modify existing document data or fields
DELETE Remove unwanted documents from storage
🎓 Student Management Example

Imagine we are building a Student Management System for a college:

  • [Create] New student enrolls → Add Rahul to the database
  • [Read] Teacher opens portal → View student profile & grades
  • [Update] Exam completed → Change Rahul's mark from 85 to 95
  • [Delete] Student graduates or cancels → Remove student record
Every web app (Instagram, Amazon, Netflix) is built on this exact cycle!

4. Student Schema and Model

The standard model we will use across all our CRUD code examples today.

src/models/Student.js 
const mongoose = require("mongoose");

// 1. Schema: Defines the structure & validation rules
const studentSchema = new mongoose.Schema({
  name: {
    type: String,
    required: true
  },
  email: {
    type: String,
    required: true,
    unique: true
  },
  age: {
    type: Number,
    required: true
  },
  course: {
    type: String,
    default: "MERN"
  },
  mark: {
    type: Number,
    default: 0
  },
  active: {
    type: Boolean,
    default: true
  }
});

// 2. Model: The constructor used to interact with MongoDB
const Student = mongoose.model("Student", studentSchema);

module.exports = Student;
🧠 Key Concept Reminder
Schema: Blueprint / structure of the student data.
Model: JavaScript class used to execute queries (CRUD).
Document: Individual student instance saved in MongoDB.
💡
Default values: If we don't provide a course, Mongoose sets it to "MERN". If we don't provide a mark, it defaults to 0.

6. CREATE — Adding Documents with create()

The simplest and most direct method to validate and store a new document.

Method 1 — Student.create() 
// 1. Call Student.create() with student details
const student = await Student.create({
  name: "Rahul",
  email: "rahul@gmail.com",
  age: 21,
  course: "MERN",
  mark: 85
});

console.log(student);
// Expected Output in Terminal: { _id: new ObjectId("66f81a7b8e3d09a12c84ef11"), name: 'Rahul', email: 'rahul@gmail.com', age: 21, course: 'MERN', mark: 85, active: true, __v: 0 }
🔍 How Student.create() Works
  1. Takes a plain JavaScript object with fields.
  2. Checks every field against studentSchema rules (e.g. required name, unique email).
  3. Applies default values (like active: true).
  4. Inserts the document into the students collection in MongoDB.
  5. Returns the newly saved Mongoose document (including generated _id).
💡
Syntax: await Model.create(documentObject)

🛡️ Why Validation Comes First

If any field fails validation (for example, missing required email or negative age), Mongoose throws an error immediately in Node.js before sending anything to MongoDB. This protects your database from bad data.

🆔 Automatic _id Generation

MongoDB automatically assigns an immutable 12-byte _id (ObjectId) to the new document. You do not need to supply an ID when creating documents.

8. CREATE — new Model() + save()

The two-step approach: instantiate in memory, then save to MongoDB.

Method 2 — new Student() + save() 
// Step 1: Create a document instance in memory (Node.js RAM)
const student = new Student({
  name: "Anjali",
  email: "anjali@gmail.com",
  age: 22,
  course: "Python",
  mark: 90
});

// (Optional: modify fields before saving)
// student.course = "Full Stack";

// Step 2: Validate and persist to MongoDB
await student.save();

console.log(student);
⚖️ create() vs new Model() + save()
FeatureStudent.create()new Student() + save()
Steps 1 step 2 steps
Execution Instantly creates & saves Creates in memory, saves when ready
Use Case Fast, direct insertion When data needs manipulation before save
⚠️
Common beginner mistake: Calling new Student({...}) without await student.save(). If you forget save(), nothing is written to MongoDB!

9. CREATE — insertMany() for Bulk Data

How to efficiently insert multiple documents in a single database operation.

Method 3 — Student.insertMany() 
// Pass an ARRAY of student objects
const students = await Student.insertMany([
  {
    name: "Arun",
    email: "arun@gmail.com",
    age: 20,
    course: "MERN",
    mark: 78
  },
  {
    name: "Sneha",
    email: "sneha@gmail.com",
    age: 23,
    course: "Java",
    mark: 88
  }
]);

console.log(students); // Returns array of inserted documents
🚀 When to use insertMany()

Instead of looping through 100 students and calling Student.create() 100 times (which makes 100 round-trip database requests), insertMany() sends all documents in one single batch command to MongoDB.

📊 Method Comparison
Student.create() → 1 document (or array)
new Student() + save() → 1 document with custom logic
Student.insertMany() → Multiple documents in bulk
READ

10. READ — Getting Documents from MongoDB

Retrieving existing data using Mongoose's query methods.

READ means querying MongoDB to fetch stored documents. Mongoose models provide three primary query methods:

find()

Fetches all documents that match the query filter. Always returns an Array (even if only 1 match or 0 matches).

Returns: [ { ... }, { ... } ] or []
findOne()

Returns the first single document that matches the filter. If no match is found, returns null.

Returns: { ... } or null
findById()

Shorthand to search for a specific document by its unique MongoDB _id. Returns the document or null.

Equivalent to: findOne({ _id: id })
💡
Rule of thumb: If you expect multiple results (e.g., student list) → use find(). If you are looking for one unique user (e.g. by email or ID) → use findOne() or findById().
READ

11. READ — find() to Get All Documents

Retrieving the entire collection when no filter condition is provided.

Student.find() — Fetch All 
// Leaving the find() argument empty retrieves all documents
const students = await Student.find();

console.log(students);
// Output: An array containing all student documents: [ { _id: ObjectId("..."), name: "Rahul", course: "MERN", mark: 85 }, { _id: ObjectId("..."), name: "Anjali", course: "Python", mark: 90 }, { _id: ObjectId("..."), name: "Arun", course: "MERN", mark: 78 } ]
🔄 MongoDB Shell Equivalent

This is the direct Mongoose equivalent of running the MongoDB shell query:

db.students.find()
📦 Return Type Note

Even if the collection contains zero students, Student.find() will not return null. It returns an empty array: [].

12. READ — find() With Filter Conditions

Filtering documents by exact values and comparison operators.

Example 1: Exact Match 
// Find all students enrolled in the "MERN" course
const mernStudents = await Student.find({
  course: "MERN"
});

console.log(mernStudents);
Filters for documents where course === "MERN"
Example 2: Comparison Operator 
// Find students whose mark is 80 or above ($gte = Greater Than or Equal)
const topStudents = await Student.find({
  mark: { $gte: 80 }
});

console.log(topStudents);
Connects Day 2 MongoDB query operators ($gte, $lte, $in) with Mongoose!
💡
How filtering works: Pass an object as the first parameter to find({ filter }). Only documents matching the filter are fetched from the database.
READ

13. READ — findOne() for a Single Match

Finding a specific document such as looking up a user by email.

Student.findOne() 
// Find the single student with this unique email address
const student = await Student.findOne({
  email: "rahul@gmail.com"
});

console.log(student);
// Output: Single document object (NOT an array): { _id: ObjectId("66f81a7b8e3d09a12c84ef11"), name: 'Rahul', email: 'rahul@gmail.com', age: 21, course: 'MERN', mark: 85, active: true }
🔍 find() vs findOne()
Aspectfind()findOne()
Matches Returns all matches Returns first match only
Format Array [ ... ] Single Object { ... }
If no match Empty array [] null
⚠️
Always check if the result is null before accessing properties (e.g. if (!student) { console.log("Not found"); }).
READ

14. READ — findById() Using Document _id

The fastest and cleanest way to fetch a document when you have its MongoDB ID.

Student.findById() 
const studentId = "66f81a7b8e3d09a12c84ef11";

// Look up document directly using its 24-character hexadecimal ID
const student = await Student.findById(studentId);

console.log(student);
💡 The Exact Equivalence

Under the hood, findById(id) is simply a convenient shorthand for:

Student.findOne({ _id: studentId })

Mongoose automatically converts the string ID into an official MongoDB ObjectId.

🚨
CastError Warning: If you pass an invalid ID string (e.g. "123" instead of 24 hex characters), Mongoose throws a CastError: Cast to ObjectId failed.
READ

15. READ — Selecting Specific Fields (.select)

Optimizing query performance by choosing exactly which properties to retrieve.

Field Selection with .select() 
// Include only name, email, and course
const students = await Student.find()
  .select("name email course");

console.log(students);
// Result: Notice that age, mark, and active are omitted: [ { _id: ObjectId("66f81a7b8e3d09a12c84ef11"), name: 'Rahul', email: 'rahul@gmail.com', course: 'MERN' } ]
⚡ Why use .select()?
  • Speed: Smaller payload transferred from MongoDB to Node.js.
  • Privacy & Security: Exclude sensitive fields (like passwords or private tokens).
  • Syntax: Pass space-separated field names (e.g. "name email") or prefix with - to exclude (e.g. "-mark").
💡
By default, MongoDB always includes _id unless explicitly excluded with select("- _id name email").

16. UPDATE — Modifying Existing Data

Understanding the two essential components of every update operation.

✏️ What is an UPDATE?

An update modifies one or more fields in an already existing document stored in MongoDB.

BEFORE
Rahul
Mark: 85
➔ UPDATE ➔
AFTER
Rahul
Mark: 95

Notice: Rahul's name, email, and ID stay identical. Only the mark field changes.

🧠 The Core Update Formula

Every update operation in Mongoose requires two vital pieces of information:

1. Filter Object
"Which document?" (e.g. { email: "rahul@gmail.com" })
2. Update Object
"What should change?" (e.g. { mark: 95 })
UPDATE

17. UPDATE — updateOne()

Modifying the first matching document without loading it into memory.

Student.updateOne() 
const result = await Student.updateOne(
  { email: "rahul@gmail.com" }, // 1. Filter: Which document?
  { mark: 95 }                  // 2. Update: What changes?
);

console.log(result);
// Result Object returned by MongoDB: { acknowledged: true, modifiedCount: 1, // Number of documents whose data changed upsertedId: null, upsertedCount: 0, matchedCount: 1 // Number of documents matching filter }
📌 Important Return Value Note

updateOne() does NOT return the updated student document!

Instead, it returns an acknowledgment object stating how many documents matched and how many were modified.

💡
If multiple students have the same course, updateOne() modifies only the first matching one it encounters.
UPDATE

18. UPDATE — The $set Operator

How MongoDB modifies specific fields while preserving the rest of the document.

Explicit $set Syntax 
await Student.updateOne(
  { email: "rahul@gmail.com" },
  {
    $set: {
      mark: 95
    }
  }
);
Explicitly tells MongoDB: "Only update the mark property."
🔍 What is $set?

$set is MongoDB's field update operator. It replaces the value of a field with the specified value without touching any other fields in the document.

✨ Mongoose Auto-$set Magic

In standard MongoDB shell commands, forgetting $set could overwrite the entire document! However, Mongoose automatically wraps top-level fields inside $set for you in updateOne() and findOneAndUpdate().

Both syntaxes work in Mongoose!
UPDATE

19. UPDATE — updateMany()

Modifying every single document that matches your query condition.

Student.updateMany() 
// Set active to true for ALL students in the "MERN" course
const result = await Student.updateMany(
  { course: "MERN" },
  { $set: { active: true } }
);

console.log(result);
// Example Output: { acknowledged: true, modifiedCount: 15, // 15 students updated! matchedCount: 15 }
⚖️ updateOne() vs updateMany()
updateOne(): Modifies ONLY the first matching document.
updateMany(): Modifies ALL documents matching the filter.
🚨
Danger of Empty Filter {}: If you pass updateMany({}, { active: false }) with an empty filter, it will modify every single document in the database collection!
UPDATE

20. UPDATE — findOneAndUpdate() & { new: true }

Finding, updating, and returning the student document in one atomic call.

Student.findOneAndUpdate() 
const student = await Student.findOneAndUpdate(
  { email: "rahul@gmail.com" }, // 1. Filter
  { mark: 98 },                  // 2. Update
  { new: true }                 // 3. Options: Return the UPDATED document!
);

console.log(student);
// Output: The newly updated document with mark: 98 { _id: ObjectId("66f81a7b8e3d09a12c84ef11"), name: 'Rahul', mark: 98, // <-- Contains the new value! course: 'MERN' }
⭐ Why { new: true } is Crucial

By default, findOneAndUpdate() returns the document BEFORE the update took place.

Without { new: true } → Returns old data (Mark: 85)
With { new: true } → Returns updated data (Mark: 98)
💡
This is the #1 method used in backend APIs when returning an updated user profile or order to a frontend client!
UPDATE

21. UPDATE — findByIdAndUpdate()

The fastest shorthand when updating a document by its unique MongoDB _id.

Student.findByIdAndUpdate() 
const studentId = "66f81a7b8e3d09a12c84ef11";

// Shorthand for findOneAndUpdate({ _id: studentId }, ...)
const student = await Student.findByIdAndUpdate(
  studentId,
  { mark: 95 },
  { new: true }
);

console.log(student);
💡 When to use findByIdAndUpdate()

In REST APIs (e.g. PUT /api/students/:id), you already receive the student's _id from the URL parameter. Using findByIdAndUpdate() is cleaner and more readable than writing { _id: id } manually.

🔄 Behind the scenes
Student.findByIdAndUpdate(id, update, opts)
↓ is shorthand for ↓
Student.findOneAndUpdate({ _id: id }, update, opts)
UPDATE

22. UPDATE — Validation with runValidators

Why update queries don't validate by default and how to enforce schema rules.

Enforcing Schema Rules on Update 
try {
  const student = await Student.findOneAndUpdate(
    { email: "rahul@gmail.com" },
    { mark: 150 }, // 🚨 Invalid mark (suppose schema max is 100)
    {
      new: true,
      runValidators: true // <-- Forces Mongoose to validate!
    }
  );
} catch (error) {
  console.error(error.message);
  // Validation failed: mark: Path `mark` (150) is more than maximum allowed value (100).
}
🚨 Critical Mongoose Gotcha!

When you use Student.create(), Mongoose always runs schema validation. But when you run update operations (findOneAndUpdate, updateOne), update validators are OFF by default!

⚡
Best Practice: Always add { runValidators: true } to your update options whenever you want your schema constraints (like required, min, max, enum) to be enforced.
DELETE

23. DELETE — Removing Documents

Permanently deleting records from your MongoDB collection.

🗑️ What is a DELETE Operation?

DELETE removes unwanted or obsolete documents permanently from MongoDB.

1. Student Document Exists in DB
↓
2. Filter Match { email: "..." }
↓
3. Permanent Delete Removed from disk

Once deleted from MongoDB, the document no longer exists and subsequent find() queries will not return it.

⚙️ The 4 Mongoose Delete Methods
deleteOne() → Deletes first match, returns stats
deleteMany() → Deletes all matches, returns stats
findOneAndDelete() → Deletes match & returns document
findByIdAndDelete() → Deletes by _id & returns document
DELETE

24. DELETE — deleteOne()

Removing the first document matching your filter criteria.

Student.deleteOne() 
// Delete the student with this specific email address
const result = await Student.deleteOne({
  email: "rahul@gmail.com"
});

console.log(result);
// Returned operation acknowledgment: { acknowledged: true, deletedCount: 1 // Exactly 1 document removed }
🔍 How deleteOne() Works
  • Scans the collection for documents matching the filter.
  • Deletes the first matching document it encounters.
  • If no matching student exists, it succeeds without error, but deletedCount will be 0.
💡
Notice: Like updateOne(), deleteOne() returns operation stats (deletedCount), not the student document itself.
DELETE

25. DELETE — deleteMany()

Removing all documents that match a query condition.

Student.deleteMany() 
// Remove all inactive students from the collection
const result = await Student.deleteMany({
  active: false
});

console.log(result);
// Example Output: { acknowledged: true, deletedCount: 8 // All 8 inactive students deleted }
⚖️ deleteOne() vs deleteMany()
deleteOne(): Deletes only the first matching document.
deleteMany(): Deletes ALL matching documents in one pass.
🚨
Critical Warning: Never run Student.deleteMany({}) in production! An empty filter {} matches every single document, wiping out your entire database collection!
DELETE

26. DELETE — findOneAndDelete()

Finding a matching document, deleting it, and returning the deleted object.

Student.findOneAndDelete() 
// Deletes the student AND returns the deleted student record
const student = await Student.findOneAndDelete({
  email: "rahul@gmail.com"
});

console.log(student);
// Output: You receive the student object before it was destroyed: { _id: ObjectId("66f81a7b8e3d09a12c84ef11"), name: 'Rahul', email: 'rahul@gmail.com', course: 'MERN' }
🔍 deleteOne() vs findOneAndDelete()
MethodReturn ValueBest For
deleteOne() { acknowledged, deletedCount } When you only care if the delete succeeded
findOneAndDelete() The actual deleted Document Object When you need to log, notify, or confirm what was deleted
💡
If no document matches the filter, findOneAndDelete() returns null.
DELETE

27. DELETE — findByIdAndDelete()

The standard shorthand for removing a document using its primary key _id.

Student.findByIdAndDelete() 
const studentId = "66f81a7b8e3d09a12c84ef11";

// Finds document by _id, removes it, and returns the deleted document
const deletedStudent = await Student.findByIdAndDelete(studentId);

console.log("Removed:", deletedStudent);
🚀 The Delete Data Flow
1. studentId string
↓
2. Locate by _id in MongoDB
↓
3. Delete document from disk
↓
4. Return deleted document to Node.js
💡
findByIdAndDelete(id) is shorthand for findOneAndDelete({ _id: id }).

28. CRUD Method Summary

A comprehensive master reference table of all Mongoose CRUD methods.

Operation Mongoose Method Returns Purpose
CREATE Student.create(data) Document Creates, validates, and saves in one step
CREATE new Student(data).save() Document Creates in-memory instance, then saves to DB
CREATE Student.insertMany([ ... ]) Array of Docs Efficiently inserts multiple documents in bulk

DELETE Student.findOneAndDelete(filter) Deleted Doc Finds, deletes, and returns deleted document

30. Complete CRUD Program (app.js)

A runnable end-to-end Node.js script demonstrating Create, Read, Update, and Delete.

src/app.js 
require("dotenv").config();

const connectDB = require("./config/db");
const Student = require("./models/Student");

const run = async () => {
  try {
    await connectDB();

    // 1. CREATE
    const student = await Student.create({
      name: "Rahul",
      email: "rahul@gmail.com",
      age: 21,
      course: "MERN",
      mark: 85
    });
    console.log("Created:", student);

    // 2. READ
    const students = await Student.find();
    console.log("Students in DB:", students);

    // 3. UPDATE
    const updatedStudent = await Student.findOneAndUpdate(
      { email: "rahul@gmail.com" },
      { mark: 95 },
      { new: true, runValidators: true }
    );
    console.log("Updated:", updatedStudent);

    // 4. DELETE
    const deletedStudent = await Student.findOneAndDelete({
      email: "rahul@gmail.com"
    });
    console.log("Deleted:", deletedStudent);

  } catch (error) {
    console.error("Error:", error.message);
  }
};

run();
🧭 Walkthrough from Top to Bottom
  1. Loads environment: Reads connection string from .env.
  2. Connects to DB: Waits for MongoDB connection to establish.
  3. Executes CRUD in sequence: Adds Rahul, lists all students, updates Rahul's mark to 95, and deletes Rahul.
  4. Handles errors: If any validation or network error occurs, the catch block captures it without crashing.
💡
This is the standard pattern for running database test scripts, seeders, and migration scripts.

32. Common Beginner Mistakes

Watch out for these 6 frequent pitfalls when working with Mongoose CRUD.

❌ 1. Forgetting await

const s = Student.find();

Without await, you receive a Mongoose Query object, NOT the student data! Always write await Student.find().
❌ 2. Wrong Field Name

Student.find({ courseName: "MERN" })

If your schema defined course, querying for courseName will find 0 results silently. Keep field names consistent!
❌ 3. Invalid _id Format

Student.findById("12345")

MongoDB IDs must be 24-character hex strings. Passing an arbitrary string causes a crash: Cast to ObjectId failed.
❌ 4. Empty Filter {} Trap

Student.updateMany({}, ...)

An empty filter {} matches every single document. Always double-check your filter before updating or deleting!
❌ 5. No runValidators

Student.findOneAndUpdate(...)

Mongoose does not validate update queries by default. You must pass { runValidators: true } to prevent invalid values.
❌ 6. Missing try / catch

await Student.create(...)

Database calls can fail (network down, duplicate email). Always wrap database operations inside try { ... } catch (err) { ... }.

The essential concepts to take home from MongoDB Day 4.

🧠 The Master CRUD Formula

Whenever you write a Mongoose query, keep these three questions in mind:

1. Filter → Which document?
Determines matching target records (e.g. { email: "rahul@gmail.com" }).
2. Update → What should change?
Specifies fields and values to modify (e.g. { mark: 95 }).
3. Options → How should the query behave?
Controls return values and validation (e.g. { new: true, runValidators: true }).

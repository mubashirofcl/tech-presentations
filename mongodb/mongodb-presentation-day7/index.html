Section 1 — Introduction

What Is Aggregation?

Aggregation is used to process multiple documents and produce useful summary results.

From Raw Data to Business Insight

Instead of simply retrieving individual documents as-is, aggregation helps us analyze and summarize data directly inside MongoDB.

💡 Key Difference:
• find() fetches documents matching a filter.
• aggregate() transforms, calculates, groups, and summarizes data across many documents.

  • ✓ Calculate averages, totals, counts, minimums, and maximums.
  • ✓ Group documents by common categories (course, product, status).
  • ✓ Restructure the final output format for reports and dashboards.

Typical Aggregation Flow

Students Collection (Raw)
↓
Filter Students ($match)
↓
Group by Course ($group)
↓
Calculate Average Marks ($avg)
↓
Sort Results ($sort)
↓
Final Course Report 🎉

Section 2 — Aggregation Pipeline

What Is an Aggregation Pipeline?

An aggregation pipeline is a sequence of stages that process documents step by step.

pipeline-example.js
const result = await Student.aggregate([ // Stage 1: Filter { $match: { course: "MERN" } }, // Stage 2: Group & Count { $group: { _id: "$course", count: { $sum: 1 } } }, // Stage 3: Order { $sort: { count: -1 } } ]);

Think of It Like an Assembly Factory

Raw materials (documents) enter the factory conveyor belt. Each workstation (stage) performs a specific transformation:

Raw Documents Enter
↓
Stage 1: Filter out unwanted items
↓
Stage 2: Group and calculate totals
↓
Stage 3: Sort the output
↓
Final Finished Report 📦
Section 2 — Aggregation Pipeline

Pipeline Stages Run in Order

Each stage receives the output of the previous stage. The order of stages matters fundamentally!

The Cascading Pipeline Flow

100 Student Documents
↓ $match: { course: "MERN" }
60 Filtered Documents
↓ $group: { _id: "$course", count: { $sum: 1 } }
5 Grouped Summary Records
↓ $sort: { count: -1 }
5 Sorted Result Documents

Three Golden Rules of Stages

  • 1 Sequential Execution: Stage 2 only sees the documents passed down by Stage 1. It never touches raw collection data directly.
  • 2 Document Reshaping: If Stage 2 groups documents into 5 groups, Stage 3 only operates on those 5 groups.
  • 3 Filter Early for Efficiency: Placing $match first reduces the document count early, dramatically accelerating subsequent stages!
Section 2 — Aggregation Pipeline

Basic Aggregation Syntax

In Mongoose, aggregation is executed by passing an array of stage objects to Model.aggregate().

general-syntax.js
// General structure Model.aggregate([ { stage1: { /* instructions */ } }, { stage2: { /* instructions */ } }, { stage3: { /* instructions */ } } ]);
concrete-example.js
const result = await Student.aggregate([ { $match: { course: "MERN" } } ]);

Key Syntax Elements

  • 1 Model.aggregate([...]) always takes an Array [] of stages.
  • 2 Each stage is an Object {} starting with a dollar sign stage name like $match or $group.
  • 3 You can have as few as 1 stage, or chain 4, 5, or more stages together.
  • 4 Aggregation is asynchronous and returns a Promise, so we use await.
Section 3 — $match

What Is $match?

The $match stage filters documents so only those matching the condition proceed to the next stage.

match-stage.js
{ $match: { course: "MERN" } }

Concept: The Pipeline Bouncer 🛡️

Think of $match as a gatekeeper. Any document that does not meet the specified condition is discarded from the pipeline right away.

$match vs. find()

The syntax inside $match is identical to the query selector in find()!

Feature Model.find() $match in aggregate()
Purpose Retrieves matching documents Filters documents for next stage
Context Stand-alone query Part of an aggregation pipeline
Operators $gte, $in, $eq, etc. Same standard query operators

$match With Query Conditions

You can use standard MongoDB comparison operators like $gte, $lte, and $in.

match-numeric-condition.js
{ $match: { mark: { $gte: 80 // Mark >= 80 } } }

{ $match: { age: { $gte: 18, // Age >= 18 $lte: 25 // Age <= 25 } } }

💡 Combines multiple operators to match students aged between 18 and 25 inclusive.

Section 3 — $match

When Should We Use $match?

Best practices on where and why $match should be placed in your aggregation pipelines.

Primary Use Cases

  • ✓ Filter Records: Select only active students, valid orders, or verified accounts.
  • ✓ Analyze Specific Categories: Restrict reports to a single department (e.g. course: "MERN").
  • ✓ Date Range Filtering: Filter transactions in the current month or quarter.
  • ✓ Status Filtering: Only process orders with status: "completed".
  • ✓ Reduce Pipeline Load: Less data in memory means faster calculations downstream.

Best Practice: Place $match Early

All Orders (10,000 docs)
↓
$match: { status: "completed" }
Discards canceled & pending orders early
↓
Completed Orders Only (3,500 docs)
↓
Subsequent Heavier Stages ($group)
Section 4 — $group

What Is $group?

$group combines documents into groups based on a specified key and performs calculations across each group.

group-stage.js
{ $group: { _id: "$course", // Grouping key totalStudents: { $sum: 1 // Accumulator (Count) } } }

Supported Calculations (Accumulators)

  • 1 $sum: Count items ($sum: 1) or add numeric fields ($sum: "$quantity").
  • 2 $avg: Calculate the mathematical average of a numeric field.
  • 3 $min: Find the lowest value in the group.
  • 4 $max: Find the highest value in the group.
Section 4 — $group

Understanding _id in $group

In the $group stage, _id represents the grouping key. It defines how documents are clustered.

What Does _id: "$course" Mean?

It tells MongoDB: "Find every document with the same course name and place them into the same group bucket."

⚠️ Notice the $ Sign:
• "$course" refers to the value of the course field in each incoming document.
• If you write _id: "course" (without $), MongoDB literally groups everything under the literal word "course"!

Visual Bucketing

MERN MERN Python Python Java
➔
Group _id: "MERN" (2 docs)
Group _id: "Python" (2 docs)
Group _id: "Java" (1 doc)
Section 4 — $group

Counting Documents With $sum

How to count the total number of documents inside each group.

group-count.js
{ $group: { _id: "$course", totalStudents: { $sum: 1 // Add 1 for every document in the group } } }

💡 How $sum: 1 works:
Whenever MongoDB encounters a document in the "MERN" group, it adds 1 to the accumulator. It's MongoDB's counter!

Example Result

_id (Course)totalStudents
MERN25
Python18
Java12

Notice how each unique course becomes a single output document with its counted total!

Section 4 — $group

$sum With Numeric Values

Summing numerical field values vs. counting documents.

sum-field-value.js
// Sample document: { product: "Laptop", quantity: 3 } { $group: { _id: "$product", totalQuantity: { $sum: "$quantity" // Adds the actual numbers in quantity! } } }

The Crucial Difference

$sum: 1

Counts how many documents exist in the group.

$sum: "$quantity"

Sums up the numerical values contained inside the quantity field across all documents.

Section 4 — $group

Calculating Averages With $avg

The $avg accumulator computes the mathematical mean of a numeric field for each group.

average-marks.js
{ $group: { _id: "$course", averageMark: { $avg: "$mark" // Computes sum(marks) / count } } }

MongoDB automatically handles null and non-numeric values by ignoring them during calculation.

Example Result

_id (Course)averageMark
MERN82.5
Python76.8
Java79.2
Section 4 — $group

Finding Extremes: $min & $max

Identify the lowest and highest values in each group simultaneously.

min-max-group.js
{ $group: { _id: "$course", averageMark: { $avg: "$mark" }, highestMark: { $max: "$mark" // Maximum mark }, lowestMark: { $min: "$mark" // Minimum mark } } }

Accumulator Reference

$min: "$field"

Returns lowest numerical or alphabetical value.

$max: "$field"

Returns highest numerical or alphabetical value.

$avg: "$field"

Computes mathematical mean.

Section 5 — $project

What Is $project?

$project controls which fields appear in the output, reshapes documents, and renames attributes.

project-basic.js
{ $project: { name: 1, // Include name email: 1, // Include email _id: 0 // Exclude _id } }

Why Use $project?

  • 1 Remove Clutter: Hide internal MongoDB fields like __v and unwanted properties.
  • 2 Rename Fields: Transform _id back into course for clean client APIs.
  • 3 Calculated Fields: Multiply quantity by price to produce a total field.
Section 5 — $project

Include and Exclude Fields

Understanding the exact rules of 1 (include) and 0 (exclude) in MongoDB projection.

default-id-behavior.js
// Example 1: _id is included by default { $project: { name: 1, mark: 1 } } // Output: { _id: ObjectId("..."), name: "Rahul", mark: 85 }
explicit-id-suppression.js
// Example 2: Explicitly suppress _id { $project: { name: 1, mark: 1, _id: 0 // Removes _id entirely } } // Output: { name: "Rahul", mark: 85 }

The Golden Projection Rule

In MongoDB projection, 1 means include and 0 means exclude.

⚠️ Cannot Mix 1 and 0 (Except _id):

You cannot specify { name: 1, age: 0 }. MongoDB does not allow mixing inclusions and exclusions in the same projection, with the only exception being _id: 0.

Section 5 — $project

Renaming Fields With $project

Use field paths like "$name" to assign existing values to brand new field names.

rename-fields.js
{ $project: { _id: 0, studentName: "$name", // Renames "name" -> "studentName" studentMark: "$mark" // Renames "mark" -> "studentMark" } }

Before & After Transformation

INPUT DOCUMENT: 
{ _id: ObjectId("..."), name: "Rahul", mark: 85 }
↓
OUTPUT DOCUMENT: 
{ studentName: "Rahul", studentMark: 85 }
Section 5 — $project

Creating Calculated Fields

$project can perform simple arithmetic calculations directly on document values.

calculated-field.js
{ $project: { _id: 0, name: 1, total: { $multiply: ["$price", "$quantity"] } } }

Computed Result

Given an order with price 30000 and quantity 2:

{ "name": "Laptop", "total": 60000 }

💡 Note for beginners: Keep arithmetic simple at first with basic expressions like $multiply. You will learn more complex expressions as you advance!

Section 6 — $sort

What Is $sort?

The $sort stage reorders documents as they pass through the aggregation pipeline.

sort-stage.js
// Descending: Highest to lowest { $sort: { mark: -1 } } // Ascending: Lowest to highest { $sort: { mark: 1 } }

Direction Values to Remember

1 → Ascending Order

Smallest to largest (0 → 100), alphabetical (A → Z), or oldest to newest date.

-1 → Descending Order

Largest to smallest (100 → 0), reverse alphabetical (Z → A), or newest to oldest date.

Section 7 — Combining Stages

Why Combine Stages?

Individual stages are simple. The true power of MongoDB aggregation emerges when you connect them together.

The Standard 4-Stage Reporting Formula

1. $match
Filter only relevant records
↓
2. $group
Group & compute mathematical summaries
↓
3. $project
Reshape fields & remove internal _id
↓
4. $sort
Order results for leaderboards & charts

Real-World Scenario

"We want a clean report showing the average mark and student count for the MERN course, sorted by highest average."

  • 1 $match discards all non-MERN students first.
  • 2 $group calculates the average mark and counts total students.
  • 3 $project renames _id to course and removes raw object metadata.
  • 4 $sort ensures top performers rank first.
Section 7 — Combining Stages

Complete Pipeline Example

Here is the full 4-stage aggregation query in Mongoose.

student-analytics-pipeline.js
const result = await Student.aggregate([ // 1. Filter: only MERN students { $match: { course: "MERN" } }, // 2. Group: calculate stats { $group: { _id: "$course", averageMark: { $avg: "$mark" }, totalStudents: { $sum: 1 } } }, // 3. Project: clean up keys { $project: { _id: 0, course: "$_id", averageMark: 1, totalStudents: 1 } }, // 4. Sort: highest avg first { $sort: { averageMark: -1 } } ]);

Returned Result Object

Mongoose sends this directly to MongoDB and returns a clean, plain JavaScript array:

[ { "course": "MERN", "averageMark": 84.5, "totalStudents": 25 } ]

Notice how clean the result is: no _id field, descriptive keys, and pre-calculated statistics ready to send directly to your frontend dashboard!

Section 9 — Aggregation with Mongoose

Aggregation With Mongoose

Using Model.aggregate() inside your Node.js and Express backend applications.

mongoose-aggregate.js
const mongoose = require("mongoose"); const Student = require("./models/Student"); async function getTopStudents() { const result = await Student.aggregate([ { $match: { mark: { $gte: 80 } } } ]); console.log(result); return result; }

How Mongoose Handles aggregate()

  • 1 Direct Pass-through: Mongoose serializes your pipeline array and transmits it directly to the MongoDB server engine.
  • 2 Returns a Promise: Always await the aggregation call or handle the Promise.
  • 3 CommonJS Standard: Use const mongoose = require("mongoose"); in standard Node backends.
Section 9 — Aggregation with Mongoose

Aggregation vs. find()

When should you use find() and when should you use aggregate()?

Model.find()

Student.find({ course: "MERN" });
  • ✓ Primary purpose: Retrieve documents matching conditions.
  • ✓ Returns hydrated Mongoose documents (with .save()).
  • ✓ Simple queries, fetching user profiles, loading item details.
  • ❌ Cannot group documents or calculate mathematical sums/averages.

Model.aggregate()

Student.aggregate([ /* pipeline */ ]);
  • ✓ Primary purpose: Complex data processing and reports.
  • ✓ Supports grouping ($group), filtering, reshaping, and sorting.
  • ✓ Calculates $avg, $sum, $min, $max.
  • ✓ Returns lightweight plain JavaScript objects (POJOs).
Section 9 — Aggregation with Mongoose

Important Aggregation Note

Aggregation results are returned as plain JavaScript objects, NOT normal Mongoose documents!

Plain JavaScript Objects (POJOs)

When you run Student.find(), Mongoose wraps every document in a rich Mongoose Document class. But with Student.aggregate(), you receive raw JSON-like JavaScript objects:

❌ Do NOT Expect Mongoose Document Methods:
result[0].save(); → TypeError: result[0].save is not a function
✅ What This Means:
• No .save(), no .validate(), and no schema virtual getters.
• Super fast, ultra lightweight, and ready for res.json(result)!

Why This Is an Advantage

  • 1 High Performance: No overhead from Mongoose hydration or tracking changes.
  • 2 Arbitrary Shapes: Aggregations often return custom shapes (e.g. { averageMark, totalStudents }) that do not match the original Student schema anyway!
  • 3 Ready for APIs: Directly serializable to JSON for Express route responses.

Section 11 — Common Mistakes

Common Beginner Mistakes

Watch out for these 5 common errors when writing aggregation pipelines in MongoDB.

1. Forgetting the $ Sign When Referencing Document Fields
❌ WRONG: _id: "course" (Groups everything under the string word "course"!)
✅ CORRECT: _id: "$course" (Reads the value of the course field)
2. Forgetting That Each Stage Receives the Previous Stage's Output
❌ WRONG: Trying to reference a field in $sort that was dropped in $project.
✅ CORRECT: Make sure any field needed downstream is preserved in earlier stages.
3. Confusing $group With In-Memory JavaScript Grouping
❌ WRONG: Expecting raw document arrays to remain intact without accumulators.
✅ CORRECT: $group transforms documents into unique key records using accumulators.
4. Using the Wrong Sort Direction
❌ WRONG: $sort: { mark: 1 } when you want top marks first.
✅ CORRECT: $sort: { mark: -1 } (-1 is descending: highest first).
5. Forgetting _id: 0 When Removing _id in $project
❌ WRONG: { $project: { name: 1 } } (MongoDB still includes _id by default!)
✅ CORRECT: { $project: { name: 1, _id: 0 } } (Explicitly excludes _id).

Q7 What is $project used for?
Selects which fields to include/exclude, renames field names, and creates calculated output fields.
Q8 What does $sort: { mark: -1 } mean?
Orders documents in descending order (highest mark to lowest mark). 1 is ascending, -1 is descending.
Q9 Why does $ appear before field names in expressions?
The $ prefix (e.g. "$mark") tells MongoDB to retrieve the *value* of that field from the current document.
Q10 Why use aggregate() instead of find()?
Use aggregate() when you need grouping, accumulators, mathematical calculations, and multi-stage transformations on the DB server.

CORE FOUNDATIONS — ENGINE INTERNALS

Execution Context & The Call Stack (LIFO)

How JavaScript manages function calls and memory frames.

EXECUTION CONTEXT

"An Execution Context is an environment created by JavaScript to store variables and run code."

An Execution Context contains a Variable Environment, Lexical Environment, and this binding. Created during creation phase (parsing/hoisting) and executed line-by-line during execution phase.

STACK OVERFLOW
If a function calls itself infinitely without a base case (e.g. function test() { test(); }), the Call Stack runs out of memory and crashes with a RangeError: Maximum call stack size exceeded!

CORE FOUNDATIONS — HOISTING

Hoisting & The Temporal Dead Zone (TDZ)

Why var returns undefined while let and const throw ReferenceError.

What is Hoisting?

During the creation phase, JavaScript allocates memory for variable and function declarations before executing code.

Temporal Dead Zone Timeline
1. Scope Entered ➔ let/const declared in memory
2. TEMPORAL DEAD ZONE (TDZ) ➔ Accessing variable throws ReferenceError!
3. let x = 10; ➔ Variable initialized & usable!

function greet() { console.log("Hello!"); }

CORE FOUNDATIONS — SCOPE

Scope, Lexical Scope & Scope Chain

How JavaScript searches for variables across nested environments.

3 Levels of Scope

• Global Scope: Accessible everywhere.
• Function Scope: Accessible only inside function (var, let, const).
• Block Scope: Accessible only inside { } block (let, const).

Scope Chain Lookup Rule

When a variable is accessed: Local Scope ➔ Outer Parent Scope ➔ Global Scope ➔ If not found ➔ ReferenceError!

CORE FOUNDATIONS — CLOSURES

Closures & Memory Retention

Functions remembering variables from their parent scope after execution.

CLOSURE DEFINITION

"A closure happens when an inner function remembers variables from its outer scope even after the outer function has finished running."

A closure is the combination of a function bundled together with references to its surrounding lexical state (the lexical environment). Closures allow data encapsulation and private variable state in JavaScript.

Closure Memory Box [Retained Environment]
let count = 0

Even though createCounter() finished running and left the Call Stack, count remains allocated in Closure memory!

closure_counter.js
function createCounter() {
  let count = 0; // Private variable

  return function increment() {
    count++;
    return count;
  };
}

const counter = createCounter();
console.log(counter()); // 1
console.log(counter()); // 2
console.log(counter()); // 3
CORE FOUNDATIONS — OBJECT REFERENCES

Objects, References & Mutation

Understanding memory references, const variable protection, and cloning.

Primitives vs Object References

Primitives copy by value. Objects copy by memory reference address! Mutating an object property via one variable affects all variables holding that reference.

Shallow Copy vs Deep Copy

• Shallow Copy: { ...obj } or Object.assign({}, obj) (Copies 1 level deep).
• Deep Copy: structuredClone(obj) or JSON.parse(JSON.stringify(obj)).

reference_mutation.js
const user1 = { name: "John" };
const user2 = user1; // Copy reference!

user2.name = "Alex";
console.log(user1.name); // Output: "Alex" (Mutated!)

// Safe Shallow Copy using Spread operator:
const user3 = { ...user1 };
user3.name = "Sarah";
console.log(user1.name); // Still "Alex" (Protected!)
CORE FOUNDATIONS — MODERN SYNTAX

Optional Chaining (?.) & Nullish Coalescing (??)

Safely navigating nested properties and handling null/undefined defaults.

Optional Chaining (?.)

Prevents TypeError: Cannot read properties of undefined when accessing nested object properties. Short-circuits to undefined if nullish. 

const city = user?.profile?.address?.city;

Nullish Coalescing (??) vs ||

• || checks for ANY falsy value (0, "", false trigger default).
• ?? checks specifically for null or undefined ONLY! 

const count = 0;
console.log(count || 10); // 10 (0 is falsy)
console.log(count ?? 10); // 0  (0 is not null/undefined)

CORE FOUNDATIONS — REVISION BANK

JavaScript Master Revision Bank

Comprehensive question bank covering Beginner, Intermediate, and Advanced topics.

Beginner

Q: Difference between var, let, and const?

var is function-scoped and redeclarable. let is block-scoped and reassignable. const is block-scoped and cannot be reassigned.

Intermediate

Q: What is the Temporal Dead Zone (TDZ)?

The period between scope entry and let/const initialization where accessing the variable throws a ReferenceError.

Advanced

Q: How do closures retain variable references in memory?

The inner function retains a reference to its parent Lexical Environment record, preventing garbage collection of outer variables.

RUNTIME COMPONENTS

The 5 Pillars of Asynchronous JavaScript

Understanding the Call Stack, Web APIs, Queues & Event Loop.

1. Call Stack

LIFO (Last In, First Out) stack executing synchronous JavaScript code one line at a time.

2. Web APIs

Browser background threads handling timers (setTimeout), DOM events, and HTTP requests.

3. Microtask Queue

High priority queue for Promise.then(), catch(), finally() & queueMicrotask() callbacks.

4. Task Queue

Standard callback queue for setTimeout() and setInterval() timer callbacks.

5. Event Loop

Monitors Call Stack. When empty, clears ALL Microtasks first, then processes ONE Task!

Microtask Queue vs Task Queue

Why Promise callbacks ALWAYS execute before setTimeout callbacks.

MYTH BUSTING

Common Event Loop Misconceptions

Clearing up 5 classic mistakes students make in technical interviews.

MYTH 1: "setTimeout(..., 0) means execute immediately"

FACT: 0ms means the timer becomes ready in Web API. The callback still waits in Task Queue until Call Stack is empty!

MYTH 2: "Promises run before synchronous code"

FACT: Synchronous code on the Call Stack ALWAYS executes first before any Promise callback.

MYTH 3: "The browser has only one callback queue"

FACT: The browser has separate Microtask Queue and Task Queue with distinct priorities.

MYTH 4: "Event Loop executes JavaScript"

FACT: V8 Call Stack executes JS; Event Loop only checks queues and pushes callbacks!

    NODE.JS MODULE — ASYNC PATTERNS

    Timers, Callbacks & Callback Hell

    Understanding Node.js asynchronous callbacks and avoiding deep nesting.

    Error-First Callback Convention

    Standard Node.js callbacks always accept (err, data) as parameters. If an error occurs, err contains the Error object; otherwise err is null.

    The Callback Hell Problem

    Nested callbacks within callbacks form a "Pyramid of Doom" that makes code unreadable and error-prone.

    callback_hell_demo.js
    // ❌ Callback Hell (Pyramid of Doom)

  if (err) return console.error(err);
  parseUser(data, (err, user) => {
    if (err) return console.error(err);
    getOrders(user.id, (err, orders) => {
      if (err) return console.error(err);
      console.log("Orders:", orders);
    });
  });
});

    NODE.JS MODULE — AUTHENTICATION

    User Authentication with JSON Web Tokens (JWT)

    Stateless authentication flow using signed cryptographic tokens.

    JWT Structure

    header.payload.signature (Encoded as Base64Url). Client sends token in HTTP header: Authorization: Bearer <token>.

    jwt_auth.js
    const jwt = require("jsonwebtoken");
const SECRET_KEY = "my_jwt_super_secret";

// 1. Issue Token on Login
const token = jwt.sign({ userId: 101, role: "admin" }, SECRET_KEY, { expiresIn: "2h" });

// 2. Auth Protection Middleware
const protect = (req, res, next) => {
  const authHeader = req.headers.authorization;
  if (!authHeader || !authHeader.startsWith("Bearer ")) {
    return res.status(401).json({ message: "Unauthorized" });
  }
  const token = authHeader.split(" ")[1];
  try {
    req.user = jwt.verify(token, SECRET_KEY);
    next();
  } catch (err) {
    res.status(403).json({ message: "Invalid token" });
  }
};

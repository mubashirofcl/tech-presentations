What Happens When We Run a Program?

The inner anatomy of Node.js execution: V8, Node APIs, libuv, and the OS

The 6-Step Execution Flow
  1. Write Code: The developer writes standard JavaScript in a .js file.
  2. Runtime Starts: Running node app.js launches the Node process.
  3. V8 Executes: V8 compiles JS to machine code and manages call stack execution.

  6. Event Loop Delivers: Callbacks execute as I/O finishes or the server keeps listening.

Synchronous vs Asynchronous I/O

Comparing blocking file operations with non-blocking event-driven execution

06 / 37
sync-demo.js (Blocking) 
import fs from "node:fs";

// readFileSync BLOCKS execution until file is fully read
const data = fs.readFileSync("message.txt", "utf8");

console.log(data);
console.log("Finished");
Terminal Output
Hello from Node.js file! Finished
⏸️ Synchronous: Steps run in strict order. The thread pauses and freezes while waiting for disk bytes.
async-demo.js (Non-Blocking) 
import fs from "node:fs";

// readFile starts reading in background and continues immediately!
fs.readFile("message.txt", "utf8", (error, data) => {
  if (error) {
    console.error(error.message);
    return;
  }
  console.log(data);
});

console.log("Finished");
Terminal Output (Notice Order!)
Finished Hello from Node.js file!
⚡ Asynchronous: "Finished" prints first! Node didn't wait; the callback runs once disk I/O completes.
💡
Why "Finished" prints first: Node offloads disk reading to the OS/libuv thread pool. The main JavaScript thread immediately executes the next line (console.log("Finished")). When the file is ready, the callback is dispatched to the event loop!

Understanding the Event Loop

How a single-threaded runtime efficiently handles thousands of concurrent operations

07 / 37
How the Loop Works
  • Single-Threaded Call Stack: JavaScript executes one function at a time (LIFO stack).
  • Asynchronous Delegation: Long operations (file reads, timers, database queries) are sent to libuv.
  • Callback Queue: When background tasks finish, their callbacks wait in a queue.
  • The Event Loop: Continually checks if the Call Stack is empty. When empty, it pushes the next callback onto the stack.

console.log("Start");

}, 0);

What Does Non-Blocking I/O Mean?

The real-world restaurant analogy and where Node.js excels

08 / 37
🍽️ The Restaurant Analogy
Blocking System (Traditional Model):
A waiter takes Table 1's order, walks into the kitchen, stands next to the chef for 20 minutes waiting for food to cook, serves Table 1, and only then talks to Table 2. Everyone in line is stuck waiting!
Non-Blocking System (Node.js Model):
The waiter takes Table 1's order, hands the ticket to the kitchen (I/O offload), immediately walks to Table 2, then Table 3. When the kitchen bell dings (event callback), the waiter delivers Table 1's dish!
Where Node.js Shines (I/O-Bound Tasks)
  • API Gateways & REST Services: Handling incoming JSON requests.
  • Database Queries: Waiting for MongoDB or PostgreSQL responses.
  • File Operations: Uploading, reading, and streaming media files.
⚠️
Crucial Caveat: Node.js does not make CPU-heavy operations non-blocking. If you run a massive synchronous loop (e.g. video rendering or complex cryptography) on the main thread, the entire event loop will freeze! Node.js is optimized for I/O, not raw CPU number-crunching.

Section 4: Modern JavaScript for Backend

Array Methods: map(), filter(), reduce()

Transforming, filtering, and accumulating dataset collections in backend pipelines

20 / 37
array-pipeline.js
const students = [
  { name: "Anu", marks: 80 },
  { name: "Rahul", marks: 45 },
  { name: "Meera", marks: 90 },
];

// 1. map() — Transform each element (extract names)
const names = students.map((s) => s.name);
console.log(names); // ["Anu", "Rahul", "Meera"]

// 2. filter() — Select matching elements (marks >= 50)
const passed = students.filter((s) => s.marks >= 50);
console.log(passed); // [{Anu: 80}, {Meera: 90}]

// 3. reduce() — Combine elements into a single accumulated result
const totalMarks = students.reduce(
  (total, s) => total + s.marks,
  0
);
console.log(totalMarks); // 215
Method Main Purpose Returns
map() Transform 1-to-1 New array of same length
filter() Select criteria matches New filtered array
reduce() Aggregate & calculate Single accumulated value
💡
Purity Guarantee: None of these three methods mutate the original array! They return brand new structures, protecting against accidental state corruption in backend logic.

Complete Program (app.js)

The complete backend script integrating dotenv, validation, map, filter, and reduce

app.js 
import "dotenv/config";

const passMark = Number(process.env.PASS_MARK);
const className = process.env.CLASS_NAME || "Unnamed Class";

const students = [
  { name: "Anu", marks: 85 },
  { name: "Rahul", marks: 42 },
  { name: "Meera", marks: 92 },
  { name: "Arjun", marks: 65 },
  { name: "Diya", marks: 35 },
];

if (!Number.isFinite(passMark)) {
  throw new Error("PASS_MARK must be a valid number in .env");
}

const studentNames = students.map((student) => student.name);

const passedStudents = students.filter(
  (student) => student.marks >= passMark
);

const totalMarks = students.reduce(
  (total, student) => total + student.marks,
  0
);

const averageMarks = totalMarks / students.length;

const topStudent = students.reduce((top, student) => {
  return student.marks > top.marks ? student : top;
});

console.log(`Class: ${className}`);
console.log("All Students:", studentNames);

console.log(
  "Passed Students:",
  passedStudents.map((student) => student.name)
);

console.log("Total Marks:", totalMarks);
console.log("Average Marks:", averageMarks.toFixed(2));

console.log(
  `Top Performer: ${topStudent.name} (${topStudent.marks} marks)`
);

console.log(
  `Pass Rate: ${((passedStudents.length / students.length) * 100).toFixed(1)}%`
);
1 & 2. dotenv & Config
Loads variables; explicitly parses passMark via Number() with fallback for class name.
3. Validation Check
Number.isFinite() ensures PASS_MARK was configured properly in .env.
4. map() for Names
Extracts an array of student names: ['Anu', 'Rahul', ...].
5. filter() for Pass List
Retains students whose marks >= passMark.
6 & 7. reduce() & Average
Sums all student marks starting from 0, then divides by count.
8. Top Student Selection
reduce() compares each student's score against current highest.
9 & 10. Pass Rate & Output
Computes percentage ratio and formats via toFixed().

Communicating with an LLM in Node.js

Understanding the 6-step backend communication lifecycle and security guidelines

36 / 37
The 6-Step LLM Backend Lifecycle
  1. Prompt Input: User enters a question or command in the web frontend.
  2. Send to Backend: The browser sends the prompt via HTTP POST to Node.js.
  3. Validate on Server: Node.js sanitizes input and checks rate limits.
  4. Request to LLM: Node.js attaches the secret API key and calls the LLM API.
  5. Model Generates: The LLM computes the response and streams tokens back.
  6. Return to Client: Node.js handles the response and sends clean JSON to React.
🔒
Core Security Best Practices:
  • Never expose private AI keys (e.g. AI_API_KEY) in client-side React code.
  • Store keys strictly in server-side .env.
  • Avoid logging confidential user passwords or sensitive documents in server logs.

🗣️ Classroom Oral Revision Questions
Question 1
What is the difference between Node.js and JavaScript?
Answer: JavaScript is the programming language. Node.js is the runtime environment built on Google's V8 engine that allows JavaScript to execute outside the browser with direct access to filesystem, networking, and OS APIs.
Question 2
What is the difference between map(), filter(), and reduce()?
Answer: map() transforms every element 1-to-1 into a new array; filter() selects elements matching a boolean condition; and reduce() accumulates array items into a single final value (such as a sum, average, or top object).
Question 3
Why should an LLM API key be kept on the backend?
Answer: Frontend React code runs publicly in the user's browser, where anyone can open DevTools and steal private keys. Storing keys on the Node.js backend inside .env prevents unauthorized access, quota theft, and unexpected billing.

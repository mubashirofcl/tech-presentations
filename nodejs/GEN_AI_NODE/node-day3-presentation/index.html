Section 2: Express Routing

Express Routing

Introduction and your first Express routes

Slide 03 / 20
🧭What Is Routing?

Routing means deciding how the server responds when a client sends a request to a particular URL and HTTP method.

Why we need it: one server must handle many different requests, such as reading, creating, updating and deleting users.

HTTP MethodEndpointPurpose
GET/usersGet all users
GET/users/:idGet one user
POST/usersCreate a user
PUT/users/:idUpdate a user
DELETE/users/:idDelete a user
📌
app.get() creates a GET route. Its callback receives the request (req) and sends a response (res).
terminal — install Express
npm init -y
npm install express
server.js
const express = require("express");

const app = express();

app.get("/", (req, res) => {
  res.send("Welcome to Express Server");
});

app.get("/users", (req, res) => {
  res.json([
    { id: 1, name: "Anu" },
    { id: 2, name: "Rahul" },
  ]);
});

app.listen(3000, () => {
  console.log("Server running on port 3000");
});
Test and Expected Response
GET http://localhost:3000/ Welcome to Express Server GET http://localhost:3000/users [ { "id": 1, "name": "Anu" }, { "id": 2, "name": "Rahul" } ]
Section 2: Express Routing

Route Parameters and Query Parameters

Two ways to receive information through a URL

Slide 04 / 20
🔑1. Route Parameters

Identify a specific resource.

/users/101

Read the value with req.params.id.

🔎2. Query Parameters

Send optional information such as search terms and filters.

/users?name=Anu&age=22

Read the values with req.query.

PropertyWhere the value comes from
req.paramsValues included in the route path
req.queryValues after ? in the URL
⚠️
Values from the URL are always strings. Notice "101" and "22" in the output.
server.js
const express = require("express");

const app = express();

// Route parameter: /users/101
app.get("/users/:id", (req, res) => {
  const userId = req.params.id;

  res.json({
    message: "User details",
    id: userId,
  });
});

// Query parameters: /search?name=Anu&age=22
app.get("/search", (req, res) => {
  const name = req.query.name;
  const age = req.query.age;

  res.json({
    name,
    age,
  });
});

app.listen(3000);
Test and Expected Response
GET http://localhost:3000/users/101 { "message": "User details", "id": "101" } GET http://localhost:3000/search?name=Anu&age=22 { "name": "Anu", "age": "22" }

Separating routes into files

🗂️Why Use a Router?

As an application grows, writing every route inside server.js becomes hard to manage. Express Router lets us keep routes in separate files.

📌
app.use("/users", userRoutes) adds the /users prefix. Inside the router, "/" means /users and "/:id" means /users/:id.

const express = require("express");

const express = require("express");

Section 3: Middleware

Middleware

Definition, request flow and a practical example

Slide 06 / 20
🧩What Is Middleware?

Middleware is a function that runs between receiving a request and sending a response. It can:

  • ▸Execute code.
  • ▸Access the request and response objects.
  • ▸Modify request data.
  • ▸Stop the request and send a response.
  • ▸Pass control on using next().
Middleware Flow
Client Request
→
Middlewarelogger
→
Routeapp.get
→
Controller
→
Response
Why we need it: shared work like logging happens once, not inside every route.
server.js
const express = require("express");

const app = express();

const logger = (req, res, next) => {
  console.log(`${req.method} ${req.url}`);

  next();
};

app.use(logger);

app.get("/", (req, res) => {
  res.send("Home Page");
});

app.listen(3000);
Terminal Output
GET http://localhost:3000/ → terminal output GET /
🔍Important Lines
  • ▸req contains request information.
  • ▸res is used to send a response.
  • ▸next() passes control to the next middleware or route handler.
⚠️
Without next() or a response, the request stays pending.
Section 3: Middleware

Types of Middleware

Application-level, router-level, built-in, third-party and error-handling

Slide 07 / 20
TypePurposeExample
Application-levelRuns across the applicationapp.use(logger)
Router-levelRuns for a particular routerrouter.use(...)
Built-inProvided by Expressexpress.json()
Third-partyInstalled using npmcors()
Error-handlingHandles application errors(err, req, res, next)
📌
Explain: application-level middleware can run for requests across the application. Router-level middleware is limited to one router.
💡
Why it matters: use application-level for work every request needs, and router-level for work only some routes need.
server.js
const express = require("express");

const app = express();
const router = express.Router();

// Application-level: runs for every request
app.use((req, res, next) => {
  console.log("Application middleware");
  next();
});

// Router-level: runs only for requests to this router
router.use((req, res, next) => {
  console.log("User router middleware");
  next();
});

router.get("/", (req, res) => {
  res.send("Users");
});

app.use("/users", router);

app.get("/", (req, res) => {
  res.send("Home");
});

app.listen(3000);
Terminal Output
GET http://localhost:3000/users → terminal output Application middleware User router middleware GET http://localhost:3000/ → terminal output Application middleware

JSON Body Parsing

Using express.json() and testing POST requests

Slide 08 / 20
📥Why Do We Need It?

When a frontend sends JSON to the backend, Express must parse it before we can read it from req.body.

app.use(express.json());
🧪Test with Postman
1Method: POST
2URL: http://localhost:3000/users
3Body → raw → JSON, then paste the JSON shown on the right.
4Click Send. Status should be 201.
⚠️
Without express.json(), JSON data is not available in req.body. Register it before the routes that use req.body.
server.js
const express = require("express");

const app = express();

app.use(express.json());

app.post("/users", (req, res) => {
  const { name, email } = req.body;

  res.status(201).json({
    message: "User created",
    name,
    email,
  });
});

app.listen(3000);
Request Body and Expected Response
POST http://localhost:3000/users (Body → raw → JSON) { "name": "Anu", "email": "anu@gmail.com" } Response — 201 Created { "message": "User created", "name": "Anu", "email": "anu@gmail.com" }
Section 3: Middleware

Error Handling

Centralized error-handling middleware

Slide 09 / 20
🚨Why Centralize Errors?

Errors can happen anywhere:

  • ▸Invalid user input.
  • ▸Database connection failures.
  • ▸Missing resources.
  • ▸Unexpected server errors.

Instead of repeating error responses in every route, one error-handling middleware handles them all.

⚠️
Important: error-handling middleware has four parameters: (err, req, res, next). Express recognizes it by these four. Register it after the routes.
🔍How It Flows
1The route catches an error.
2next(error) passes it to Express.
3Express skips normal handlers and runs the error handler.
4The handler logs the error and sends a 500 response.
server.js
const express = require("express");

const app = express();

app.get("/users", (req, res, next) => {
  try {
    throw new Error("Something went wrong");
  } catch (error) {
    next(error);
  }
});

app.use((err, req, res, next) => {
  console.error(err.message);

  res.status(500).json({
    success: false,
    message: err.message,
  });
});

app.listen(3000);
Test and Expected Response
GET http://localhost:3000/users → Status 500 { "success": false, "message": "Something went wrong" } Terminal output Something went wrong

CORS

Understanding origins and configuring CORS

Slide 10 / 20
🌐What Is CORS?

CORS (Cross-Origin Resource Sharing) is a browser security rule. It controls whether a frontend from one origin can use a backend from another origin.

Two different origins
Frontendhttp://localhost:5173
→
Backendhttp://localhost:3000
The ports are different, so these are different origins. The browser may block the request unless the backend allows the frontend origin.
🚫
CORS is enforced by browsers. It is not an authentication or authorization system.
terminal — install cors
npm install cors
server.js
const express = require("express");
const cors = require("cors");

const app = express();

app.use(cors());

app.get("/users", (req, res) => {
  res.json([{ name: "Anu" }, { name: "Rahul" }]);
});

app.listen(3000);
Allow only one frontend origin
// Allow only a specific frontend origin
app.use(cors({
  origin: "http://localhost:5173",
}));
🔍Explain
  • ▸cors() allows cross-origin requests according to its settings.
  • ▸origin says which frontend origin is allowed.
  • ▸Check the Access-Control-Allow-Origin header in the browser Network tab.

Section 4: Project Structure

Routes

Defining API endpoints

Slide 12 / 20
🛣️What Routes Do

Routes define which endpoint handles a particular HTTP request. They connect incoming requests to controller functions.

Why we need them: one file shows every endpoint of the API at a glance.

🔍Important Line
router.post("/", userController.createUser);

When a POST request reaches /users, Express calls createUser from the controller.

⚠️
Routes should not contain complex business logic. They only point to controller functions.
routes/userRoutes.js
const express = require("express");
const router = express.Router();

const userController = require("../controllers/userController");

router.post("/", userController.createUser);

router.get("/", userController.getUsers);

module.exports = router;
📌
The router is mounted at /users in server.js, so "/" here means /users.
Section 4: Project Structure

Controllers

Handling requests and responses

Slide 13 / 20
🎛️What Controllers Do

A controller receives the request, reads the data it needs, calls the service, and sends the response.

Why we need them: all request and response code stays in one place, away from business rules.

🔍How It Works
1Reads request data (req.body).
2Calls the service.
3Sends an HTTP response (201 or 200).
4Passes errors to the error-handling middleware with next(error).
controllers/userController.js
const userService = require("../services/userService");

const createUser = (req, res, next) => {
  try {
    const user = userService.createUser(req.body);

    res.status(201).json({
      message: "User created successfully",
      data: user,
    });
  } catch (error) {
    next(error);
  }
};

const getUsers = (req, res, next) => {
  try {
    const users = userService.getUsers();

    res.json({
      data: users,
    });
  } catch (error) {
    next(error);
  }
};

module.exports = {
  createUser,
  getUsers,
};

Services

Separating business logic

Slide 14 / 20
⚙️What Services Do

Services contain the actual business logic. They perform operations and apply business rules.

Why we need them: the same logic can be reused and tested without any HTTP code.

🔍How It Works

The service creates users and stores them in a temporary array. In a real application, this layer could talk to MongoDB through Mongoose.

⚠️
This example uses in-memory storage only. Data disappears when the server restarts.
services/userService.js
let users = [];

const createUser = (userData) => {
  const newUser = {
    id: users.length + 1,
    name: userData.name,
    email: userData.email,
  };

  users.push(newUser);

  return newUser;
};

const getUsers = () => {
  return users;
};

module.exports = {
  createUser,
  getUsers,
};

Introduction to Zod

Why we need validation

Slide 16 / 20
🛡️What Is Zod?

Zod is a JavaScript and TypeScript validation library. It checks whether incoming data follows the rules we define.

When a user registers, we may require:

  • ▸Name must not be empty.
  • ▸Email must be valid.
  • ▸Password must have at least 8 characters.
🚫
Why validate? Without validation, invalid data can enter our application.
✅What Zod Gives Us
  • ▸Validates incoming data.
  • ▸Checks data types.
  • ▸Supports required fields.
  • ▸Supports custom validation rules.
  • ▸Gives useful error messages.
  • ▸Can parse and return validated data.

Section 5: Zod Validation

Creating Zod Schemas

Types and validation rules

Slide 17 / 20
📐What Is a Schema?

A schema is a set of rules that describes what valid data should look like. Zod checks data against it.

ValidationMeaning
z.string()Must be a string
z.number()Must be a number
.min(3)Minimum length or value is 3
.email()Must be a valid email
.min(18)Number must be at least 18
.optional()Field is optional
user-schema.js
const { z } = require("zod");

const userSchema = z.object({
  name: z.string().min(3),

  email: z.string().email(),

  age: z.number().min(18),
});

// Valid data
const validUser = {
  name: "Anu",
  email: "anu@gmail.com",
  age: 22,
};

// Invalid data
const invalidUser = {
  name: "An",
  email: "invalid-email",
  age: 15,
};

console.log(userSchema.safeParse(validUser).success);
console.log(userSchema.safeParse(invalidUser).success);
Expected Output
$ node user-schema.js true false
📌
The valid user passes every rule. The invalid user breaks all three: the name is too short, the email is wrong and the age is under 18.
Section 5: Zod Validation

Zod Parsing

parse() vs safeParse()

Slide 18 / 20
1️⃣parse()

Validates the data. If validation fails, it throws an error, so use try/catch.

2️⃣safeParse()

Validates the data without throwing for validation failures. It returns a result with success.

On failure, result.error.issues is a list of problems. Each has a path and a message.

parse()safeParse()
Throws error when invalidReturns validation result
Use try/catchCheck success
Returns parsed dataReturns parsed data when valid
💡
For Express request validation, safeParse() is often convenient.
parse-demo.js
const { z } = require("zod");

const userSchema = z.object({
  name: z.string().min(3),
  email: z.string().email(),
  age: z.number().min(18),
});

// 1. parse() throws an error when the data is invalid
const result = userSchema.parse({
  name: "Anu",
  email: "anu@gmail.com",
  age: 22,
});

console.log(result);

try {
  userSchema.parse({ name: "An", email: "wrong-email", age: 15 });
} catch (error) {
  console.log("parse() threw:", error.name);
}

// 2. safeParse() returns a result instead of throwing
const safeResult = userSchema.safeParse({
  name: "An",
  email: "wrong-email",
  age: 15,
});

if (!safeResult.success) {
  safeResult.error.issues.forEach((issue) => {
    console.log(issue.path[0] + ": " + issue.message);
  });
} else {
  console.log(safeResult.data);
}
Expected Output
$ node parse-demo.js { name: 'Anu', email: 'anu@gmail.com', age: 22 } parse() threw: ZodError name: Too small: expected string to have >=3 characters email: Invalid email address age: Too small: expected number to be >=18
📌
Message wording can differ slightly between Zod versions. The path and message fields are always there.
Section 5: Zod Validation

Zod Validation in Express

Creating validation middleware

Slide 19 / 20
Step 1 — validators/userValidator.js
const { z } = require("zod");

const userSchema = z.object({
  name: z.string().min(3, "Name must have at least 3 characters"),

  email: z.string().email("Invalid email address"),

  age: z.number().min(18, "Age must be at least 18"),
});

const validateUser = (req, res, next) => {
  const result = userSchema.safeParse(req.body);

  if (!result.success) {
    return res.status(400).json({
      success: false,
      errors: result.error.issues,
    });
  }

  req.body = result.data;

  next();
};

module.exports = validateUser;

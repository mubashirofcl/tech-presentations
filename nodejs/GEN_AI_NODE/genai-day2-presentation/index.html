Section 1 • LLM Basics

What Is an LLM (Large Language Model)?

Plain-English Definition

A Large Language Model (LLM) is a deep learning model trained on massive amounts of text—documentation, books, articles, and source code—so it learns patterns in human language and programming.

  • How it replies It predicts the most likely next token step by step until a complete answer forms.
  • Why developers care Instead of hardcoding thousands of if/else rules, your Node.js app sends a prompt over an API and receives flexible text or structured JSON.
  • Common API tasks Chatbots, code explanation, summarization, translation, and Q&A over provided documents.
Key Mental Model: Think of an LLM as an advanced autocomplete engine scaled up to billions of learned parameters—not a lookup database of stored answers.

Section 1 • Learning Process

How Does an LLM Learn from Data?

3 Stages of Teaching an LLM
  • 1. Pre-Training (Pattern Learning) The model reads huge datasets and practices guessing the hidden next word. When it guesses wrong, training adjusts billions of internal weights.
  • 2. Instruction Tuning (SFT) Curated question-and-answer examples teach the model how to follow instructions politely and stay on topic instead of just rambling.
  • 3. Alignment (RLHF / Safety) Human reviewers rate helpful, harmless replies higher so the model learns safe boundaries and clear formatting.
Remember: As an application developer, you do not retrain GPT models from scratch on Day 2—you consume already-trained models via an API!

What Happens Inside POST /ask?

  • 2. Call OpenAI Responses API Pass model: "gpt-4.1-mini" and input: prompt asynchronously using await.

server.js (Step 1: Basic /ask) JAVASCRIPT 
require("dotenv").config();
const express = require("express");
const OpenAI = require("openai");

const app = express();
app.use(express.json());

const client = new OpenAI({
  apiKey: process.env.OPENAI_API_KEY
});

app.post("/ask", async (req, res) => {
  try {
    const { prompt } = req.body;

    if (!prompt || typeof prompt !== "string" || !prompt.trim()) {
      return res.status(400).json({ error: "A non-empty prompt is required" });
    }

    const response = await client.responses.create({
      model: "gpt-4.1-mini",
      input: prompt.trim()
    });

    res.json({
      answer: response.output_text,
      usage: response.usage
    });
  } catch (error) {
    console.error("OpenAI Error:", error.message);
    res.status(500).json({ error: "Failed to get LLM response" });
  }
});

const PORT = process.env.PORT || 3000;
app.listen(PORT, () => {
  console.log(`LLM Playground running on http://localhost:${PORT}`);
});
Section 3 • Tokens & Tokenization

What Are Tokens?

LLMs Do Not Read Characters or Whole Sentences Directly

Before an LLM can process your text, a tokenizer breaks the text into small pieces called tokens. A token can be a whole common word, part of a word (subword), punctuation, or whitespace.

  • Rule of Thumb (English) 1 token ≈ ~4 characters or roughly ¾ of an average English word.
  • Why Developers Track Tokens 1) API pricing bills per 1M input/output tokens. 2) Models have strict context limits measured in tokens. 3) More tokens = higher latency.
Important: Exact tokenization depends on the model's vocabulary! gpt-4.1-mini uses its own BPE tokenizer, so response.usage is always the real source of truth.

          Section 4 • Context Window
          
What Is a Context Window?

        


        

          

            

              
The Model's Working Memory Per Request

              

                A context window is the maximum number of tokens an LLM can see and work with in
                a single API call—including both everything you send in and the reply it generates back.
              

              
    
                
  • 
                  Total Token Budget Formula
                  System Instructions + Context/History + User Question + Generated Output ≤ Context Window
                
    • 
                
  • 
                  Model-Specific Sizes
                  Capacity varies by model (from 8K/32K on older models to 128K–1M+ tokens on modern models like the GPT-4.1 family).
                
    • 
                
  • 
                  What Happens If You Exceed It?
                  The API rejects the request with an error, or older conversation turns get dropped.
                
    • 
              

            


            

              Remember: LLMs are stateless across HTTP requests. If you want "memory" in a chat app, your Node.js backend must resend earlier messages inside the context window!

                  System Rules

                  Current Question

Why Not Paste Entire 500-Page PDFs Every Call?

                

                  Even when a model has a large context window, huge inputs cost more money, slow down responses, and can dilute the model's focus on the most relevant facts.
                

              

            

          

        

      


      
      

        

          Section 4 • Practical: Context Management
          
Practical: Manage Context & Avoid Overflow

        


        

          

            

              
3 Beginner Strategies to Protect Context

              
    
                
  • 
                  1. Keep Only Recent Turns (Sliding Window)
                  Use messages.slice(-6) so chat history stays bounded instead of growing forever.
                
    • 
                
  • 
                  2. Enforce Input Size Guards
                  Check estimated tokens or character length before calling OpenAI and return a clean 400 message if too large.
                
    • 
                
  • 
                  3. Send Only Relevant Snippets
                  Filter or summarize long text before putting it inside your prompt.
                
    • 
              

            


            

              Production Habit: Checking request budget in Express prevents surprise token bills and user-facing crashes.
            

          


          

            

              

                

                  

                    
                    
                    
                  

                  context-manager.js
                  JAVASCRIPT
                

                

                  
                

              

              

                
// Keep only the latest 6 conversation messages (sliding window)
function trimHistory(messages, maxMessages = 6) {
  if (!Array.isArray(messages)) return [];
  return messages.slice(-maxMessages);
}

app.post("/chat-window", async (req, res) => {
  try {
    const { history = [], question } = req.body;
    if (!question) {
      return res.status(400).json({ error: "Question is required" });
    }

    const recentHistory = trimHistory(history, 6);
    const formatted = recentHistory
      .map((m) => `${m.role}: ${m.text}`)
      .join("\n");

    const fullPrompt = `${formatted}\nuser: ${question}`.trim();

    // Quick approximate guard (e.g., max ~3,000 estimated input tokens)
    if (Math.ceil(fullPrompt.length / 4) > 3000) {
      return res.status(400).json({
        error: "Input exceeds Playground budget. Please shorten history."
      });
    }

    const response = await client.responses.create({
      model: "gpt-4.1-mini",
      input: fullPrompt
    });

    res.json({ answer: response.output_text, usage: response.usage });
  } catch (err) {
    res.status(500).json({ error: err.message });
  }
});

          Section 5 • Temperature
          
What Is Temperature?

        


        

          

            

              
Controlling Predictability vs Creativity

              

                For every next token, the LLM assigns probabilities to possible words.
                Temperature controls how much risk the model takes when picking from those options:
              

              
    
                
  • 
                  Low Temperature (0.0 – 0.2)
                  Picks the highest-probability words almost every time. Best for factual Q&A, JSON output, classification, and coding help.
                
    • 
                
  • 
                  Medium Temperature (0.5 – 0.7)
                  Natural balance between clarity and mild variety. Great default for general chatbots and tutors.
                
    • 
                
  • 
                  High Temperature (0.9 – 1.2+)
                  Flattens probabilities so less likely words get picked more often. Good for brainstorming ideas—higher risk of weird phrasing.
                
    • 
              

            


            

              Myth Busted: Higher temperature increases variation, NOT accuracy or intelligence! Turning temperature up on a math or policy question only makes answers less predictable.

          Section 5 • Max Output Tokens
          
What Is max_output_tokens?

        


        

          

            

              
Upper Ceiling for the Model's Reply

              

                max_output_tokens sets the maximum budget of tokens the model is
                allowed to generate in a single response. If the answer finishes sooner, the model stops naturally.
              

              
    
                
  • 
                  Not a Word Count!
                  max_output_tokens: 100 gives roughly ~75 English words, because tokens are subwords and punctuation—not whole words.
                
    • 
                
  • 
                  Why Set It in Production?
                  Prevents accidentally long answers from inflating costs, exceeding client timeouts, or breaking UI cards.
                
    • 
                
  • 
                  Risk When Set Too Low
                  The model cuts off mid-sentence or mid-JSON object when it hits the limit!
                
    • 
              

            


            

              Rule of Thumb: If you want a short answer AND clean endings, combine a prompt instruction ("Answer in 2 sentences") with a safe ceiling like max_output_tokens: 150.

          Section 6 • Hallucinations
          
What Is an LLM Hallucination?

        


        

          

            

              
Confident-Sounding Information That Is False

              

                An LLM hallucination happens when a model invents facts, wrong API method names,
                fake citations, or guessed policies while sounding 100% confident and fluent.
              

              
    
                
  • 
                  Why Does It Happen?
                  Because LLMs are trained to generate plausible-sounding next tokens, not to verify facts against your database before speaking.
                
    • 
                
  • 
                  When Risk Is Highest
                  Private company rules, niche math/dates, unseen codebases, or vague questions with no reference data.
                
    • 
              

            


            

              Developer Responsibility: Never trust ungrounded LLM output blindly for pricing, medical/legal advice, or production SQL queries!

function buildGroundedPrompt(question, context) {
  if (!context || !context.trim()) {
    return question;
  }

  return `Answer the user's question ONLY using the context below.
If the answer is not in the context, reply: "I do not know from the provided context."

Context:
${context.trim()}

Question:
${question.trim()}`;
}

              

            


            

              Honest Caveat: Grounding with manual context + low temperature reduces hallucinations, though it cannot guarantee zero mistakes—and pasting context manually here is a stepping stone toward full RAG (covered in later lessons).

          Section 6 • Knowledge Cutoff
          
Knowledge Cutoff & LLM Limitations

        


        

          

            

              
Why LLMs Need External Data & Tools

              
    
                
  • 
                  Knowledge Cutoff
                  An LLM only knows public information available up to the date its training dataset ended. Events, library releases, or prices after that date are outside its static weights.
                
    • 
                
  • 
                  No Private Data Access
                  Unless you supply it at runtime, an LLM cannot read your MySQL database, local files, or company policies.
                
    • 
                
  • 
                  Not a Calculator or Live Search Engine
                  For exact math, live weather, or up-to-date facts, modern apps pair LLMs with tools, APIs, or RAG.
                
    • 
              

            


            

              Remember Day 1? This is exactly why real GenAI architectures use RAG (retrieval + context injection) and Agents (LLM + external tools)!

          Section 7 • Transformer Architecture
          
Introduction to Transformers

        


        

          

            

              
The Architecture Behind Modern LLMs ("T" in GPT)

              

                Introduced in 2017 ("Attention Is All You Need"), the Transformer changed AI by
                processing all tokens in a sentence in parallel instead of slowly reading one word after another like older RNN models.
              

              
    
                
  • 
                  1. Embeddings + Positional Info
                  Turns token IDs into rich number vectors (meaning) plus their position in the sentence (word order).
                
    • 
                
  • 
                  2. Transformer Blocks (Repeated Layers)
                  Each block combines Self-Attention (understanding relationships) and a Feed-Forward Network (processing features).
                
    • 
                
  • 
                  3. Output Prediction
                  Produces probabilities for the next token across the vocabulary.
                
    • 
              

            

          


          

            
            

              
Diagram 10 • High-Level Transformer Pipeline


              

                

                  1. Input
                  Prompt string split into Token IDs
                

                

                  2. Embeddings
                  Convert IDs to meaning vectors + add Positional Encoding (token order)
                

                

                  3. Transformer Layer × N
                  
                    Self-Attention (tokens look at related tokens) +
                    Feed-Forward Neural Net (deep pattern processing)
                  
                

                

                  4. Output Head
                  Scores every vocabulary token → picks next token (guided by temperature!)
                

              

            

          

        

      


      
      

        

          Section 7 • Attention & Variants
          
Attention, Self-Attention, Encoder & Decoder

        


        

          

            
            

              
Diagram 11 • Self-Attention Links Related Words Across Distance

              

                How does the model know who "she" refers to in this sentence?
              


              

              

                Self-Attention lets every token weigh how important every other token in the prompt is, resolving context even across long paragraphs.

                      Architecture
                      Best At
                      Examples

  res.json({
    service: "LLM Playground API - GenAI Day 2",
    status: "running"
  });

app.post("/ask", async (req, res) => {
  try {
    const {
      question,
      temperature = 0.7,
      max_output_tokens = 150,
      context = ""
    } = req.body;

    if (!question || typeof question !== "string" || !question.trim()) {
      return res.status(400).json({ error: "A non-empty question is required" });
    }

    const safeTemp = Number(temperature);
    if (Number.isNaN(safeTemp) || safeTemp < 0 || safeTemp > 2) {
      return res.status(400).json({ error: "temperature must be between 0 and 2" });
    }

    const safeMaxTokens = Number(max_output_tokens);
    if (Number.isNaN(safeMaxTokens) || safeMaxTokens < 16 || safeMaxTokens > 2000) {
      return res.status(400).json({ error: "max_output_tokens must be between 16 and 2000" });
    }

    const hasContext = typeof context === "string" && context.trim().length > 0;
    const promptInput = hasContext
      ? `Answer the question ONLY using the provided context. If the answer is not in the context, reply: "I do not know from the provided context."\n\nContext:\n${context.trim()}\n\nQuestion:\n${question.trim()}`
      : question.trim();

    const estimatedInputTokens = estimateTokensApprox(promptInput);
    if (estimatedInputTokens > 4000) {
      return res.status(400).json({ error: "Prompt exceeds Playground token budget." });
    }

    const response = await client.responses.create({
      model: "gpt-4.1-mini",
      input: promptInput,
      temperature: safeTemp,
      max_output_tokens: safeMaxTokens
    });

    res.json({
      answer: response.output_text,
      usage: response.usage,
      estimatedInputTokensApprox: estimatedInputTokens,
      groundedWithContext: hasContext,
      status: response.status
    });
  } catch (error) {
    console.error("Playground API Error:", error.message);
    res.status(500).json({ error: "Failed to process LLM request" });
  }
});

const PORT = process.env.PORT || 3000;
app.listen(PORT, () => {
  console.log(`LLM Playground API listening on http://localhost:${PORT}`);

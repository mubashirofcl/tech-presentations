Section 1 • Model Licensing

Closed-Source vs Open-Weight Models

3 Tiers of Model Availability
  • 1. Closed-Source Models (Hosted APIs) Providers keep architecture, training datasets, and model weights private. You access them exclusively via hosted cloud APIs (e.g. OpenAI GPT-4o, Anthropic Claude, Google Gemini).
  • 2. Open-Weight Models (Downloadable Weights) Trained neural weights are published for download under provider licenses (e.g. Meta Llama 3.2, Qwen 2.5, Google Gemma). Developers can run them on their own hardware or via third-party cloud hosts.
  • 3. Open-Source AI (Fully Transparent) Traditional open-source releases full training code, weights, data recipes, and evaluation code under permissive licenses (e.g. Apache 2.0 / MIT).
Crucial Distinction: "Open-weight" does not automatically mean fully open-source! Meta releases Llama weights under the Meta Llama Community License, which permits free commercial use up to 700M monthly active users but is not an OSI-approved license.

Section 2 • Local vs Cloud

Local LLMs vs Cloud LLMs: Architectural Trade-offs

Diagram 2 • Local LLM Architecture
Local LLM Running on Your Own Machine / Infrastructure

The model weights reside in local storage, running on your computer's CPU or GPU (e.g. using Ollama).

Node.js Sends HTTP request to http://localhost:11434
Ollama Executes model on local RAM/GPU; zero external network traffic!
Pros: 100% data privacy, works offline, zero per-token API charges, complete environment control.
Cons: High RAM/VRAM requirements (8GB–64GB+), slower on modest hardware, maintenance overhead.
Diagram 3 • Cloud LLM Architecture
Cloud LLM Hosted on Provider Infrastructure

The model is hosted on large enterprise clusters (thousands of H100 GPUs) managed by OpenAI, Google, Anthropic, or Groq.

Node.js Sends secure HTTPS request to provider gateway with API key
Cloud GPU Generates tokens in milliseconds; streams back JSON answer
Pros: Instant access to massive models (GPT-4o, Claude 3.5), zero hardware setup, extreme speed, high reliability.
Cons: Requires active internet, per-token billing, prompt data travels over the wire, rate limits apply.
Section 2 • Ollama Runtime

Ollama: Run Open LLMs on Your Laptop

What Is Ollama?

Ollama is a lightweight, open-source tool and background daemon that packages model weights, configuration, and GPU acceleration into an easy local CLI and HTTP REST API.

  • 1. Local Daemon Address Runs quietly in the background on http://localhost:11434.
  • 2. Automatic Hardware Detection Automatically utilizes Apple Silicon (Metal), NVIDIA CUDA, or CPU fallback.
  • 3. Built-in Model Library Pulls and manages models like llama3.2, mistral, qwen2.5, and gemma2.
Crucial Rule: Ollama is the engine / runtime. Llama is the model family. Ollama runs Llama, but they are created by different organizations!
Ollama CLI Commands TERMINAL 
# 1. Download model weights from Ollama registry (~2.0 GB)
ollama pull llama3.2

# 2. Test chat directly in your terminal
ollama run llama3.2

# 3. View downloaded local models
ollama list

# 4. Check currently active models in memory
ollama ps

          Section 3 • Selection Triangle
          
Model Selection: Quality vs Latency vs Cost

        


        

          

            

              
The Developer's Trilemma

              

                No single model is the best for every project. Professional AI engineering is about picking
                the right trade-off across three critical dimensions:
              

              
    
                
  • 
                  1. Quality (Intelligence & Accuracy)
                  Reasoning power, coding benchmarks, complex instruction following, and factual fidelity.
                
    • 
                
  • 
                  2. Latency (Response Speed)
                  Time-to-first-token (TTFT) and throughput. Critical for voice agents, autocompletes, and live chat.
                
    • 
                
  • 
                  3. Cost (Dollars per Million Tokens)
                  Input/output token pricing, server hosting costs, and scalability under high user traffic.
                
    • 
              

            


            

              Engineering Rule: A simple customer support router should never use an expensive 400B model. Match the model to the job!

Small vs Large Models: Size and Efficiency

        


        

          

            
            

              

                Small Models
                Lightweight & Fast (1B – 8B Parameters)
              

              

                Examples: Llama 3.2 (1B/3B), Qwen 2.5 (3B/7B), Gemma 2 (2B), GPT-4.1-mini.
              

              
    
                
  • 
                  Resource Demands: Runs smoothly on standard laptop RAM (4GB–8GB) or mobile devices.
                
    • 
                
  • 
                  Speed & Cost: Ultra-fast response times and extremely cheap API costs.
                
    • 
                
  • 
                  Best For: Text classification, entity extraction, sentiment analysis, translation, drafting simple emails.
                
    • 
              

            

          


          

            
            

              

                Large Models
                High Capacity (70B – 400B+ Parameters)
              

              

                Examples: Llama 3.3 (70B), Claude 3.5 Sonnet, GPT-4o, Llama 3.1 405B.
              

              
    
                
  • 
                  Resource Demands: Requires multi-GPU server infrastructure with 140GB+ of VRAM.
                
    • 
                
  • 
                  Reasoning Power: Superior multi-step logic, edge-case handling, and complex architectural programming.
                
    • 
                
  • 
                  Best For: Complex code debugging, legal/medical review, multi-turn reasoning agents, math proofs.

const Anthropic = require("@anthropic-ai/sdk");

const client = new Anthropic({
  apiKey: process.env.ANTHROPIC_API_KEY
});

async function askClaude(prompt) {
  const response = await client.messages.create({
    model: process.env.CLAUDE_MODEL, // e.g. "claude-3-5-sonnet-latest"
    max_tokens: 300,
    messages: [{ role: "user", content: prompt }]
  });

  // Claude returns content blocks; filter and join text
  return response.content
    .filter((item) => item.type === "text")
    .map((item) => item.text)
    .join("\n");
}

          Section 4 • OpenAI-Compatible APIs
          
What Are OpenAI-Compatible APIs?

        


        

          

            

              
One SDK to Rule Many Providers

              

                Many modern cloud providers (Groq, Together AI, DeepSeek, vLLM, and even local Ollama)
                support the exact same HTTP request/response format as OpenAI's /v1/chat/completions.
              

              
    
                
  • 
                  The Magic Property: baseURL
                  Instead of installing 10 different SDKs, you can use the standard openai package and simply swap the baseURL and apiKey!
                
    • 
                
  • 
                  Why Developers Love It
                  Zero vendor lock-in! You can switch from OpenAI to Groq or local Ollama by changing two lines in your .env file.
                
    • 
              

            


            

              Keep in Mind: "OpenAI-compatible" means the API endpoint speaks the same protocol; it does not mean the model was created by OpenAI or behaves identically.

          Section 5 • Practical: Common Service
          
Practical: The Provider Adapter Pattern

        


        

          

            
            

              
Diagram 12 • The Provider Adapter Pattern

              
Why Do We Need an Adapter?

              

                Every SDK formats its reply differently. Without an adapter, your Express route would be polluted with messy if/else checks:
              

              

                

                  
                    
ProviderRaw Response Structure

                  
                  
                    
OpenAIresponse.output_text

                    
Clauderesponse.content[0].text

                    
Groqresponse.choices[0].message.content

                    
Ollamaresponse.message.content

                    
Geminiresponse.output_text

                  
                

              

              

                Adapter Pattern Goal: Wrap each provider into its own async function that returns a pure JavaScript string. Express never needs to know SDK internals!
              

            

          


          

            

              

                

                  

                    
                    
                    
                  

                  services/aiService.js (Part 1)
                  JAVASCRIPT
                

                

                  
                

              

              

                
const OpenAI = require("openai");
const Anthropic = require("@anthropic-ai/sdk");
const Groq = require("groq-sdk");

// Initialize reusable clients ONCE at file load
const openai = new OpenAI({ apiKey: process.env.OPENAI_API_KEY });
const anthropic = new Anthropic({ apiKey: process.env.ANTHROPIC_API_KEY });
const groq = new Groq({ apiKey: process.env.GROQ_API_KEY });

async function askOpenAI(question) {
  const response = await openai.responses.create({
    model: process.env.OPENAI_MODEL,
    input: question
  });
  return response.output_text;
}

async function askClaude(question) {
  const response = await anthropic.messages.create({
    model: process.env.CLAUDE_MODEL,
    max_tokens: 300,
    messages: [{ role: "user", content: question }]
  });
  return response.content
    .filter((item) => item.type === "text")
    .map((item) => item.text)
    .join("\n");
}

async function askGroq(question) {
  const response = await groq.chat.completions.create({
    model: process.env.GROQ_MODEL,
    messages: [{ role: "user", content: question }]
  });
  return response.choices[0].message.content;
}

module.exports = { askOpenAI, askClaude, askGroq };

              

            

          

        

      


      
      

        

          Section 5 • Practical: Gemini & Ollama
          
Practical: Add Gemini & Ollama (Dynamic ESM)

        


        

          

            

              
Handling ESM Packages in CommonJS

              

                Some modern packages (like @google/genai and ollama) are published
                as pure ECMAScript Modules (ESM).
              

              
    
                
  • 
                  The Solution: Dynamic import()
                  You do not need to convert your entire Node.js project to `"type": "module"`! You can asynchronously load ESM packages inside standard CommonJS functions with await import("...").
                
    • 
                
  • 
                  Local Daemon Pre-requisite
                  Ensure Ollama is running (http://localhost:11434) and ollama pull llama3.2 has finished before calling askOllama().
                
    • 
              

            


            

              All 5 Providers Ready: Exporting all 5 functions gives our application full coverage of closed, cloud-open, and local offline models!

async function askGemini(question) {
  const { GoogleGenAI } = await import("@google/genai");
  const client = new GoogleGenAI({ apiKey: process.env.GEMINI_API_KEY });

  const response = await client.interactions.create({
    model: process.env.GEMINI_MODEL,

          Section 5 • Practical: Express API
          
Practical: Build POST /ask/:provider

        


        

          

            

              

                

                  

                    
                    
                    
                  

                  server.js
                  JAVASCRIPT
                

                

                  
                

              

              

                
require("dotenv").config();
const express = require("express");
const {
  askOpenAI,
  askClaude,
  askGroq,
  askGemini,
  askOllama
} = require("./services/aiService");

const app = express();
app.use(express.json());

// Provider Lookup Dictionary
const providers = {
  openai: askOpenAI,
  claude: askClaude,
  groq: askGroq,
  gemini: askGemini,
  ollama: askOllama
};

app.post("/ask/:provider", async (req, res) => {
  try {
    const { provider } = req.params;
    const { question } = req.body;

    if (!question || typeof question !== "string") {
      return res.status(400).json({
        success: false,
        message: "Question is required"
      });
    }

    const selectedProvider = providers[provider.toLowerCase()];
    if (!selectedProvider) {
      return res.status(400).json({
        success: false,
        message: "Unsupported provider"
      });
    }

    // Call chosen adapter uniformly
    const answer = await selectedProvider(question);

    res.json({
      success: true,
      provider,
      answer
    });
  } catch (error) {
    console.error("AI Error:", error.message);
    res.status(500).json({
      success: false,
      message: "AI request failed"
    });
  }
});

const PORT = process.env.PORT || 3000;
app.listen(PORT, () => {
  console.log(`Multi-provider AI server running on port ${PORT}`);
});

          Section 6 • Decision Matrix
          
How to Choose the Right AI Provider

        


        

          

            

              
8-Point Engineering Checklist

              
    
                
  • 1. Task Capability: Does the model support your reasoning, coding, or math demands?
    • 
                
  • 2. Speed / Latency: Is it interactive (<500ms) or an asynchronous background job?
    • 
                
  • 3. Cost at Scale: Can you afford this model when handling 100,000 daily requests?
    • 
                
  • 4. Input Modality: Does your workflow require reading images, audio, or video?
    • 
                
  • 5. Data Privacy & Compliance: Can prompt data leave the country or must it stay on-premise?
    • 
                
  • 6. Context Length: Does the model support your needed document size (8K vs 1M+ tokens)?
    • 
                
  • 7. Rate Limits & Uptime: Does the provider offer enterprise SLAs?
    • 
                
  • 8. License Restrictions: Does the model license permit your commercial use-case?
    •

require("dotenv").config();
const express = require("express");
const {
  askOpenAI,
  askClaude,
  askGroq,
  askGemini,
  askOllama
} = require("./services/aiService");

const app = express();
app.use(express.json());

const providers = {
  openai: askOpenAI,
  claude: askClaude,
  groq: askGroq,
  gemini: askGemini,
  ollama: askOllama
};

app.get("/", (req, res) => {
  res.json({
    service: "Multi-Provider AI Playground API - GenAI Day 3",
    supportedProviders: Object.keys(providers),
    status: "running"
  });
});

app.post("/ask/:provider", async (req, res) => {
  const startTime = Date.now();
  try {
    const { provider } = req.params;
    const { question } = req.body;

    if (!question || typeof question !== "string" || !question.trim()) {
      return res.status(400).json({
        success: false,
        message: "Question is required"
      });
    }

    const selectedProvider = providers[provider.toLowerCase()];
    if (!selectedProvider) {
      return res.status(400).json({
        success: false,
        message: `Unsupported provider: ${provider}. Supported: ${Object.keys(providers).join(", ")}`
      });
    }

    const answer = await selectedProvider(question.trim());
    const latencyMs = Date.now() - startTime;

    res.json({
      success: true,
      provider: provider.toLowerCase(),
      latencyMs,
      answer
    });
  } catch (error) {
    console.error(`Error on provider ${req.params.provider}:`, error.message);
    res.status(500).json({
      success: false,
      provider: req.params.provider,
      message: "AI request failed",
      error: error.message
    });
  }
});

const PORT = process.env.PORT || 3000;
app.listen(PORT, () => {
  console.log(`Multi-provider AI server running on http://localhost:${PORT}`);
});

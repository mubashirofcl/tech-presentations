Database Fundamentals

What Is MySQL2?

The modern, promise-based MySQL driver for Node.js applications.

Slide 03

Why Node.js Needs MySQL2

Node.js does not have built-in support for communicating with relational databases. MySQL2 is an open-source npm library that establishes TCP socket connections to MySQL servers, sends SQL commands, and parses binary results into JavaScript objects.

Installation
# Install MySQL2 package
npm install mysql2
Promise-Based Import
// Always import the promise-based wrapper!
const mysql = require("mysql2/promise");

Why Use the Promise Version (`mysql2/promise`)?

  • ✓ Native async/await: Eliminates callback hell and deeply nested functions when chaining queries.
  • ✓ Clean Error Handling: Allows standard try / catch blocks instead of error-first callback arguments.
  • ✓ Connection Pooling: Seamlessly manages multiple concurrent connections for high-traffic Express APIs.
  • ✓ Prepared Statements: Prevents SQL injection through parameterized execute() calls.
Important: mysql2/promise is built right into the mysql2 package. You do not need to install an extra package!
Database Setup

Connecting Node.js with MySQL

Create the database, configure tables, and initialize a reusable connection pool.

Slide 04
schema.sql
-- 1. Create the database
CREATE DATABASE genai_node;

-- 2. Select database
USE genai_node;

-- 3. Create students table
CREATE TABLE students (
  id INT AUTO_INCREMENT PRIMARY KEY,
  name VARCHAR(100) NOT NULL,
  email VARCHAR(150) NOT NULL UNIQUE,
  course VARCHAR(100) NOT NULL
);
Why Connection Pools? A connection pool maintains an active pool of database connections. Instead of opening and closing a new TCP socket for every HTTP request, Express reuses existing connections.
db.js
const mysql = require("mysql2/promise");

// Create reusable connection pool
const pool = mysql.createPool({
  host: "localhost",
  user: "root",
  password: "your_password",
  database: "genai_node",
  waitForConnections: true,
  connectionLimit: 10
});

module.exports = pool;

Configuration Parameters:

  • host: MySQL server host address (e.g. localhost).
  • user & password: Credentials for database access.
  • database: The target schema (genai_node).
  • connectionLimit: Max number of simultaneous open connections.

Hands-on Implementation

Practical: CREATE & READ with Async Queries

Execute parameterized INSERT and SELECT queries using async/await and array destructuring.

Slide 06
create-read-demo.js
const mysql = require("mysql2/promise");

async function runCreateAndRead() {
  // 1. Establish database connection
  const connection = await mysql.createConnection({
    host: "localhost",
    user: "root",
    password: "your_password",
    database: "genai_node"
  });

  // 2. CREATE: Parameterized INSERT
  const [insertResult] = await connection.execute(
    "INSERT INTO students (name, email, course) VALUES (?, ?, ?)",
    ["John", "john@gmail.com", "MERN Stack"]
  );
  console.log("Inserted ID:", insertResult.insertId);

  // 3. READ: SELECT all students
  const [rows] = await connection.execute(
    "SELECT * FROM students"
  );
  console.log("Students in DB:", rows);

  await connection.end();
}

runCreateAndRead();

Hands-on Implementation

Practical: UPDATE & DELETE with Async Queries

Modify and remove records using affectedRows inspection and SQL placeholders.

Slide 07
update-delete-demo.js
// 1. UPDATE: Modify student's course
const [updateResult] = await connection.execute(
  "UPDATE students SET course = ? WHERE id = ?",
  ["GenAI Development", 1]
);

console.log("Updated rows:", updateResult.affectedRows);

// 2. DELETE: Remove student by id
const [deleteResult] = await connection.execute(
  "DELETE FROM students WHERE id = ?",
  [1]
);

console.log("Deleted rows:", deleteResult.affectedRows);

Key Rules for UPDATE & DELETE

  • • Understanding affectedRows: affectedRows informs you how many rows matched your WHERE condition and were modified/deleted. If affectedRows === 0, the record didn't exist!
  • • Always Use WHERE: Running DELETE FROM students without a WHERE clause will wipe out the entire table!
  • • SQL Injection Defense: Never concatenate user input directly into SQL strings (e.g. `WHERE id = ${req.body.id}`). Always pass parameters via the ? placeholder array!

Architectural Design

Why Reusable Database Functions?

Never write raw SQL queries directly inside Express route handlers.

Slide 08

The Anti-Pattern: SQL Inside Routes

Writing raw database connections and SQL strings inside route handlers leads to serious architectural defects:

  • × Duplicated Code: The same pool connection and query logic copied across dozens of endpoints.
  • × Maintenance Nightmare: If a table column changes, you must edit 15 different route files.
  • × Impossible to Test: Cannot write unit tests for database logic without mocking entire HTTP requests.

The Clean Solution: Model Layer

Extract database operations into separate, reusable functions inside a model layer (e.g. models/studentModel.js).

Step 1
API Route
Handles HTTP req/res
→
Step 2
Model Function
getAllStudents()
→
Step 3
MySQL Pool
Executes SQL Query

Now, your route handlers only call simple functions: const students = await getAllStudents();

Hands-on Implementation

Practical: Create Reusable Database Functions

Build config/db.js and modular CRUD functions in models/studentModel.js.

Slide 09
models/studentModel.js
const pool = require("../config/db");

// 1. Get all students
async function getAllStudents() {
  const [rows] = await pool.execute("SELECT * FROM students");
  return rows;
}

// 2. Get student by ID
async function getStudentById(id) {
  const [rows] = await pool.execute(
    "SELECT * FROM students WHERE id = ?", [id]
  );
  return rows[0];
}

// 3. Create a new student
async function createStudent(data) {
  const [result] = await pool.execute(
    "INSERT INTO students (name, email, course) VALUES (?, ?, ?)",
    [data.name, data.email, data.course]
  );
  return result.insertId;
}

module.exports = { getAllStudents, getStudentById, createStudent };

Model Design Principles

  • ✓ Single Responsibility: Each function performs exactly one database operation and returns raw data or IDs.
  • ✓ No Express Dependencies: Notice that studentModel.js does NOT import Express and does NOT touch req or res!
  • ✓ Clean CommonJS Exports: Functions are bundled and exported via module.exports = { ... } for easy importing.
Golden Rule: "Database functions return data or throw errors. Route controllers decide what HTTP response to send."
Express Integration

Using Reusable Functions in Express Routes

Import your database model into Express route handlers for clean, decoupled code.

Slide 10
routes/studentRoutes.js
const express = require("express");
const { getAllStudents, createStudent } = require("../models/studentModel");

const router = express.Router();

// GET /students — Fetch all students
router.get("/", async (req, res, next) => {
  try {
    const students = await getAllStudents();
    res.json(students);
  } catch (error) {
    res.status(500).json({ message: "Database error" });
  }
});

// POST /students — Create new student
router.post("/", async (req, res, next) => {
  try {
    const id = await createStudent(req.body);
    res.status(201).json({ message: "Student created", id });
  } catch (error) {
    res.status(500).json({ message: "Database error" });
  }
});

module.exports = router;

Why This Pattern Is Professional

  • ✓ Zero SQL in Routes: The Express route handler has no idea whether students are saved in MySQL, PostgreSQL, or SQLite. It only calls createStudent().
  • ✓ Readable Endpoints: Any new developer can open the route and instantly understand the HTTP workflow without decoding complex SQL joins.
  • ✓ Proper Status Codes: Returns 200 OK for reads, 201 Created for inserts, and 500 for database failures.

What Is Zod & Why Do We Need It?

Validate request bodies before executing database queries or invoking expensive AI models.

Slide 16
zod-demo.js
const { z } = require("zod");

// 1. Define strict schema rules
const studentSchema = z.object({
  name: z.string().min(2),
  email: z.string().email(),
  course: z.string().min(2)
});

// 2. Validate incoming payload without throwing
const result = studentSchema.safeParse({
  name: "John",
  email: "john@gmail.com",
  course: "MERN Stack"
});

if (!result.success) {
  console.log("Validation errors:", result.error.issues);
} else {
  console.log("Sanitized data:", result.data);
}

HTTP & External APIs

What Is Fetch in Node.js?

Modern Node.js (18+) includes native, built-in Fetch. No extra npm packages required.

Slide 17
fetch-demo.js
// Built-in fetch available globally in Node 18+
async function getPosts() {
  try {
    const response = await fetch(
      "https://jsonplaceholder.typicode.com/posts"
    );

    // CRITICAL: Check response.ok
    if (!response.ok) {
      throw new Error(`HTTP error! status: ${response.status}`);
    }

    const data = await response.json();
    console.log("Fetched posts count:", data.length);
  } catch (error) {
    console.error("Fetch failed:", error.message);
  }
}

getPosts();

Essential Rules for Fetch in Node.js

  • • No `node-fetch` Required: You do not need to install node-fetch or axios for standard HTTP calls in modern Node.js.
  • • The response.ok Trap: fetch() does NOT reject on HTTP 404 or 500 error responses! It only rejects on network failures. You must inspect response.ok before calling response.json().
  • • Calling External AI Endpoints: If you ever need to connect to an AI model where no official SDK exists, native fetch() handles standard REST payloads effortlessly.
GenAI Core Concepts

What Is Streaming & Why Does GenAI Need It?

Compare traditional request-response latency with continuous chunked event streams.

Slide 18

1. Traditional (Normal) Response

The server generates the entire answer in memory, waits for completion, and transmits one large payload.

Step 1 Client sends HTTP Request
↓
Wait 8-15 Seconds
User sees blank screen / spinner
↓
Step 2 Send 100% of answer at once

2. Streaming Response (Chunked)

The server establishes a continuous stream and emits partial tokens as they are generated by the model.

Step 1 Client sends Request
↓
Immediate Feedback (200ms)
Chunk 1 → Chunk 2 → Chunk 3 ...
↓
Step 2 Server closes stream ([DONE])
Why Streaming Matters for GenAI: Large Language Models generate text one token at a time. Streaming transforms a frustrating 15-second delay into an interactive, real-time typing experience.
Hands-on Implementation

Practical: Express Streaming API using SSE

Set up Server-Sent Events with res.write() and simulated asynchronous delay.

Slide 19
streamRoutes.js
// GET /stream — Server-Sent Events (SSE)
app.get("/stream", async (req, res) => {
  // 1. Set SSE Headers
  res.setHeader("Content-Type", "text/event-stream");
  res.setHeader("Cache-Control", "no-cache");
  res.setHeader("Connection", "keep-alive");

  const messages = ["Hello", "Welcome", "To GenAI Node.js"];

  // 2. Stream tokens chunk by chunk
  for (const msg of messages) {
    res.write(`data: ${msg}\n\n`);
    await new Promise(r => setTimeout(r, 1000));
  }

  // 3. End stream
  res.write("data: [DONE]\n\n");
  res.end();
});

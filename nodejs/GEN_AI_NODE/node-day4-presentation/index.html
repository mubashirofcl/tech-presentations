Section 1: Server-Sent Events (SSE)

What Is Server-Sent Events (SSE)?

Unidirectional HTTP streaming from server to client in real time

Slide 03 / 18
⚡ Core Definition

Server-Sent Events (SSE) is a web technology that enables a server to continuously push data chunks to a client over a single, persistent HTTP connection without requiring WebSockets.

🤖 Where is SSE Used in Gen-AI?
  • ▸ AI Chatbot Responses: ChatGPT, Gemini, and Claude stream tokens word-by-word as they are predicted.
  • ▸ Live Progress Updates: Tracking multi-step LLM chains and document embedding status.
  • ▸ Background Task Status: Real-time indexing of uploaded files.
📌
User Experience Advantage: Instead of waiting 15 seconds for a complete answer, the user sees the first token within 300ms, making the application feel instantaneous!
🔄 Normal API vs Streaming API
Normal API (Wait for Full Response)
Browser → [HTTP Request] → Express
Express processes for 10 seconds...
Express → [Complete 100% JSON Response] → Browser
Streaming API via SSE (Incremental Chunks)
Browser → [HTTP Request] → Express
Express → [Chunk 1: "Hello"] → Browser (0.2s)
Express → [Chunk 2: " I am"] → Browser (0.4s)
Express → [Chunk 3: " an AI"] → Browser (0.6s)
Express → [Chunk 4: " model."] → Browser (0.8s)
Section 1: Server-Sent Events (SSE)

Creating an SSE Endpoint in Express

Setting SSE headers, writing chunked events, and closing connections

Slide 04 / 18
sse-basic.js 
const express = require("express");
const app = express();

app.get("/stream", (req, res) => {
    // 1. Set required SSE headers
    res.setHeader("Content-Type", "text/event-stream");
    res.setHeader("Cache-Control", "no-cache");
    res.setHeader("Connection", "keep-alive");

    // 2. Send initial message immediately
    res.write("data: Hello from Express!\n\n");

    // 3. Send second chunk after 2s
    setTimeout(() => {
        res.write("data: Streaming response started!\n\n");
    }, 2000);

    // 4. Close connection after 5s
    setTimeout(() => {
        res.write("data: Streaming completed!\n\n");
        res.end();
    }, 5000);
});

app.listen(3000, () => console.log("Server on port 3000"));
Header Purpose
Content-Type text/event-stream tells client it is an SSE stream
Cache-Control no-cache prevents proxies and browsers from buffering
Connection keep-alive keeps the TCP socket open for more chunks
🚨 The Mandatory SSE Message Format

Every SSE message must strictly start with data: and terminate with two newline characters:

data: Hello\n\n

The \n\n indicates to the browser parser that an individual message frame has finished.

Section 1: Server-Sent Events (SSE)

Reading SSE in the Browser via ReadableStream

Using fetch(), response.body.getReader(), and TextDecoder to read incremental chunks

Slide 05 / 18
client-stream.js 
const startBtn = document.getElementById("startBtn");
const output = document.getElementById("output");

startBtn.addEventListener("click", async () => {
    output.innerHTML = "";

    // 1. Fetch SSE endpoint
    const response = await fetch("http://localhost:3000/stream");

    // 2. Acquire stream reader
    const reader = response.body.getReader();
    const decoder = new TextDecoder();

    // 3. Read chunks continuously in loop
    while (true) {
        const { done, value } = await reader.read();
        if (done) break; // stream finished

        // Decode binary Uint8Array chunk to string
        const chunk = decoder.decode(value, { stream: true });
        output.innerHTML += `<p>${chunk}</p>`;
    }
});
API Call Purpose
response.body Accesses the underlying byte stream
getReader() Locks and acquires reader on stream
reader.read() Returns { done, value } for next chunk
TextDecoder() Converts raw binary bytes into UTF-8 text
⚠️
Crucial Network Reality: A network chunk read by reader.read() does not always match one complete SSE message. Over real networks, chunks can arrive split in half. Production frontends must buffer text and split strictly on \n\n.

Building a Better SSE Streaming Example

Simulating an AI chatbot response with JSON tokens, event buffering, and [DONE] marker

Slide 06 / 18
ai-streaming-server.js 
app.get("/ai-stream", async (req, res) => {
    res.setHeader("Content-Type", "text/event-stream");
    res.setHeader("Cache-Control", "no-cache");
    res.setHeader("Connection", "keep-alive");

    const tokens = [
        "Hello!",
        " I am an AI assistant.",
        " I can answer your questions.",
        " This response is streamed."
    ];

    for (const token of tokens) {
        res.write(`data: ${JSON.stringify({ text: token })}\n\n`);
        await new Promise(r => setTimeout(r, 800));
    }

    // Standard OpenAI/LLM stream termination marker
    res.write("data: [DONE]\n\n");
    res.end();
});

Section 2: File Upload Using Multer

What Is Multer?

Handling multipart/form-data encoding for file uploads in Express

Slide 07 / 18
📦 Why Do We Need Multer?

When a browser or client uploads binary files, it uses the encoding:

Content-Type: multipart/form-data

Express's standard express.json() and express.urlencoded() body parsers cannot parse multipart streams. Multer intercepts the stream and parses the incoming files and text fields.

⚡ Installation 
npm install multer
🔄 Multipart File Upload Flow
👤 1. User Selects File Resume.pdf, Document.docx, or Data.csv
▼ FormData → multipart/form-data
⚙️ 2. Express Server + Multer Middleware Reads multipart stream, extracts metadata
▼ Populates req.file or req.files
💾 3. Destination Storage Written to disk (dest) or stored in RAM (memoryStorage)
Section 2: File Upload Using Multer

Creating a File Upload API Using Multer

Setting up destination folders, handling single files, and verifying req.file

Slide 08 / 18
multer-upload.js 
const express = require("express");
const multer = require("multer");

const app = express();

// Configure destination directory on disk
const upload = multer({ dest: "uploads/" });

// "file" is the exact field name sent by client
app.post("/upload", upload.single("file"), (req, res) => {
    if (!req.file) {
        return res.status(400).json({
            message: "Please upload a file"
        });
    }

    res.json({
        message: "File uploaded successfully",
        file: req.file
    });
});

app.listen(3000);
Multer Method Purpose
upload.single("file") Upload one file. File attached to req.file
upload.array("files", 5) Upload up to 5 files with same name to req.files
upload.fields([...]) Upload multiple files using different field names
⚠️
Field Name Must Match: The key name sent from the frontend or Postman (e.g. formData.append("file", ...)) must match exactly the string passed to upload.single("file")! Otherwise, req.file will be undefined.

async function uploadFile() {
    const file = document.getElementById("fileInput").files[0];
    if (!file) return alert("Select a file");

    const formData = new FormData();
    formData.append("file", file);

    const response = await fetch("http://localhost:3000/upload", {

Section 3: Node.js Buffers

What Is a Buffer in Node.js?

Working with raw binary data, byte sequences, and hexadecimal representations

Slide 10 / 18
0️⃣1️⃣ Definition of a Buffer

A Buffer is a built-in Node.js global object used to store, inspect, and manipulate raw binary data (sequences of bytes outside the V8 JavaScript heap).

📁 Why Gen-AI Apps Need Buffers
  • ▸ Files are bytes: PDFs, images, audio, and Word docs are binary byte streams.
  • ▸ Direct Parser Ingestion: Parsing libraries (like pdf-parse and mammoth) accept raw Buffer inputs directly.
  • ▸ Zero Disk I/O: Working in memory with Buffers is 10x faster than saving and reading from disk.
buffer-intro.js 
// Convert UTF-8 string to a Buffer
const buffer = Buffer.from("Hello Node.js");

console.log(buffer);
Node.js Terminal Output
<Buffer 48 65 6c 6c 6f 20 4e 6f 64 65 2e 6a 73>
Hexadecimal Anatomy: Each 2-character hex value represents 1 byte (8 bits):
48 = 'H', 65 = 'e', 6c = 'l', 6c = 'l', 6f = 'o'

Section 4: Document Parsing

Extracting Text from PDF Using pdf-parse

Parsing PDF buffers, reading text streams, and inspecting page counts

Slide 13 / 18
parse-pdf.js 
const express = require("express");
const multer = require("multer");
const pdfParse = require("pdf-parse"); // v1.1.1 API

const app = express();
const upload = multer({ storage: multer.memoryStorage() });

app.post("/upload-pdf", upload.single("file"), async (req, res) => {
    try {
        if (!req.file) {
            return res.status(400).json({ message: "PDF file required" });
        }

        // Pass the binary buffer directly to pdfParse
        const pdfData = await pdfParse(req.file.buffer);

        res.json({
            message: "PDF parsed successfully",
            text: pdfData.text,
            pages: pdfData.numpages
        });
    } catch (error) {
        res.status(500).json({ message: "PDF parsing failed" });
    }
});
🧪 Postman Testing Instructions
Method: POST http://localhost:3000/upload-pdf
Body: form-data | Key: file (File) | Value: sample.pdf
Expected Response

💡
Limitation: pdf-parse extracts selectable embedded text. If a PDF is a scanned flat picture from a camera, it contains no text stream and requires an OCR engine (like Tesseract).
Section 4: Document Parsing

Extracting Text from DOCX Using Mammoth

Converting Microsoft Word .docx files into clean text strings for AI models

Slide 14 / 18
parse-docx.js 
const express = require("express");
const multer = require("multer");
const mammoth = require("mammoth");

const app = express();
const upload = multer({ storage: multer.memoryStorage() });

app.post("/upload-docx", upload.single("file"), async (req, res) => {
    try {
        if (!req.file) {
            return res.status(400).json({ message: "DOCX file required" });
        }

        // extractRawText strips formatting and returns clean string
        const result = await mammoth.extractRawText({
            buffer: req.file.buffer
        });

        res.json({
            message: "DOCX parsed successfully",
            text: result.value
        });
    } catch (error) {
        res.status(500).json({ message: "DOCX parsing failed" });
    }
});
📝 Postman Testing Instructions
Method: POST http://localhost:3000/upload-docx
Body: form-data | Key: file (File) | Value: resume.docx
Expected Response
{ "message": "DOCX parsed successfully", "text": "Anu\nMERN Stack Developer\nSkills: React, Node.js, MongoDB" }
💡
extractRawText() is preferred over converting to complex HTML because LLMs process plain text with fewer tokens and less overhead.
Section 4: Document Parsing

Parsing CSV Files Using csv-parse

Converting Comma-Separated Values into typed JavaScript arrays and objects

Slide 15 / 18
parse-csv.js 
const express = require("express");
const multer = require("multer");
const { parse } = require("csv-parse/sync");

const app = express();
const upload = multer({ storage: multer.memoryStorage() });

app.post("/upload-csv", upload.single("file"), (req, res) => {
    try {
        if (!req.file) {
            return res.status(400).json({ message: "CSV file required" });
        }

        // Synchronous buffer parser into object array
        const records = parse(req.file.buffer, {
            columns: true,        // row 1 as object keys
            skip_empty_lines: true,
            trim: true
        });

        res.json({
            message: "CSV parsed successfully",
            data: records
        });
    } catch (error) {
        res.status(400).json({ message: "CSV parsing failed" });
    }
});
Sample students.csv:
name,email,course
Anu,anu@gmail.com,MERN
Rahul,rahul@gmail.com,Python
Parsed JSON Output Array
[ { "name": "Anu", "email": "anu@gmail.com", "course": "MERN" }, { "name": "Rahul", "email": "rahul@gmail.com", "course": "Python" } ]
OptionEffect
columns: trueFirst CSV row becomes property keys
skip_empty_linesPrevents creating blank records
trim: trueRemoves spaces around values

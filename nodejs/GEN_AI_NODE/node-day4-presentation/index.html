Section 1: Understanding Streaming

What Is Streaming?

Comparing normal request-response APIs with real-time streaming responses

Slide 03 / 18
⏳ 1. Normal API Response

The server processes the entire answer in the background and sends everything at once in a single package.

User asks question
    ↓
Server generates full answer... (waiting 5s)
    ↓
Browser receives entire answer at once

⚠️ Drawback: The user sees a blank screen or loading spinner until the whole response is generated.

🌊 2. Streaming Response

The server sends the answer in small pieces as soon as each word or chunk becomes available.

User asks question
    ↓
Server starts generating:
    |---- "Hello"
    |---- "I am"
    |---- "your AI"
    |---- "assistant"
    ↓
Browser displays each part immediately!
💬
Think About ChatGPT: When answers appear word by word instead of popping up after 10 seconds, that is a streaming experience!
Section 1: Understanding Streaming

What Is SSE (Server-Sent Events)?

A simple, standard way for a server to continuously send data over one HTTP connection

Slide 04 / 18
📡 Simple Definition

SSE (Server-Sent Events) allows an Express server to keep an HTTP connection open and push messages to the browser whenever new information is ready.

Unlike traditional APIs that immediately close after one response, an SSE endpoint stays alive until the server explicitly finishes the stream.

🔄 How Does It Work? 
Browser                  Express Server
   |                           |
   |------ GET /stream ------->|  (Browser starts request)
   |                           |
   |<------- Message 1 --------|  (res.write)
   |                           |
   |<------- Message 2 --------|  (res.write)
   |                           |
   |<------- Message 3 --------|  (res.write)
   |                           |
   |<------- Completed --------|  (res.end)
🎯 Where Is SSE Used?
  • 🤖 AI Chatbots: Streaming generated words in real time.
  • 🔔 Live Notifications: Pushing updates to active users.
  • 📊 Task Progress: Showing "Uploaded 20%... 50%... 100%".
  • 📈 Real-Time Feeds: Live status dashboards and stock tickers.
📌
Important Principle: SSE is a one-way street (server → browser). The browser sends a single standard HTTP GET request, and the server pushes messages back down that open pipe.
Section 1: Understanding Streaming

Creating Our First SSE Server

Writing a simple Express endpoint that sends 3 messages with a 1-second delay

Slide 05 / 18
server.js — First SSE Endpoint 
const express = require("express");
const app = express();

app.get("/stream", async (req, res) => {
    // 1. Tell the browser this is an SSE stream
    res.setHeader("Content-Type", "text/event-stream");
    res.setHeader("Cache-Control", "no-cache");

    // 2. Send first message
    res.write("data: Hello Students!\n\n");
    await new Promise(r => setTimeout(r, 1000));

    // 3. Send second message
    res.write("data: Welcome to Node.js!\n\n");
    await new Promise(r => setTimeout(r, 1000));

    // 4. Send third message
    res.write("data: Streaming completed!\n\n");

    // 5. Finish and close the stream
    res.end();
});

app.listen(3000, () => console.log("Server running on port 3000"));
🔍 Understanding the Important Methods
Method / Header Simple Meaning
text/event-stream Tells browser to expect streaming messages
res.write() Sends data without closing the connection
\n\n Two newlines mark the end of an SSE message
res.end() Closes the connection when done
Expected Stream Delivery (1s intervals)
[Second 1] data: Hello Students! [Second 2] data: Welcome to Node.js! [Second 3] data: Streaming completed!
Section 1: Understanding Streaming

How Does the Browser Read Streaming Data?

Introducing ReadableStream, reader.read(), and TextDecoder in simple terms

Slide 06 / 18
❓ The Big Question

We built a server that sends data piece by piece. But how does frontend JavaScript catch each piece as it arrives?

In the browser, the standard fetch() API provides a feature called ReadableStream!

📚 5 Key Terms to Know
  • fetch() → Connects to our Express server endpoint.
  • response.body → Contains the raw incoming data stream.
  • getReader() → Creates a reader to listen to the stream.
  • reader.read() → Reads the next available chunk.
  • TextDecoder() → Converts received binary bytes into human text.
🔄 Step-by-Step Browser Pipeline
1. fetch("/stream")
    ↓
2. response.body (the stream)
    ↓
3. getReader() (the listener)
    ↓
4. reader.read() (get next chunk)
    ↓
5. TextDecoder() (bytes → readable text)
    ↓
6. Display text on screen!
💡
Don't Panic: You do not need to memorize all five words right now. Let's see how simple they look together in real code on the next slide!
Section 1: Understanding Streaming

Practical: Display Streaming Data in Browser

A simple HTML and JavaScript webpage that receives and renders incoming stream chunks

Slide 07 / 18
frontend/script.js 
const button = document.getElementById("start");
const output = document.getElementById("output");

button.addEventListener("click", async () => {
    output.innerHTML = "";

    // 1. Connect to stream
    const response = await fetch("http://localhost:3000/stream");
    const reader = response.body.getReader();
    const decoder = new TextDecoder();

    // 2. Loop until stream is finished (done: true)
    while (true) {
        const { done, value } = await reader.read();
        if (done) break;

        // 3. Decode binary chunk into text and display
        const text = decoder.decode(value);
        output.innerHTML += `<p>${text}</p>`;
    }
});
⚡ Live Browser Streaming Demo Ready
<div id="output"> Display Box:
Click "Start Streaming" above to watch chunks appear.
⚠️
Network Reality Note: In production apps, multiple messages might arrive in one network packet, or one message may be split across packets. Production code buffers text and splits strictly on \n\n.

Section 2: File Upload Using Multer

What Is Multer?

Setting up the standard Express middleware to receive and inspect uploaded files

Slide 09 / 18
upload-intro.js 
const express = require("express");
const multer = require("multer");
const app = express();

// 1. Configure Multer destination folder
const upload = multer({ dest: "uploads/" });

// 2. upload.single("file") accepts ONE file with field name "file"
app.post("/upload", upload.single("file"), (req, res) => {
    // File details are placed in req.file
    console.log(req.file);

    res.json({
        message: "File uploaded successfully",
        fileName: req.file.originalname
    });
});

app.listen(3000);
📋 Important Multer Properties
Property What It Means
upload.single("file") Middleware that receives 1 file under the key name "file"
req.file Object containing all details of the uploaded file
req.file.originalname The original name of the file on the user's computer
req.file.mimetype File type (e.g., application/pdf)
req.file.size The size of the file in bytes
⚠️
Field Name Must Match: If your route specifies upload.single("file"), the frontend form or Postman key MUST be named file!

Section 3: Understanding Buffers

What Is a Buffer in Node.js?

A simple explanation of binary data, computer bytes, and the Buffer object

Slide 11 / 18
📦 What Is a Buffer?

A Buffer is a built-in Node.js container used to hold and manipulate raw binary data (sequences of bytes).

Simple Analogy: Computers do not store PDFs or images as English words. They store everything as bytes (numbers). A Buffer is like a tray that holds those raw bytes in RAM so our program can work with them.

buffer-demo.js
// Convert text string to a Node.js Buffer
const buffer = Buffer.from("Hello");

console.log(buffer);
// Output: <Buffer 48 65 6c 6c 6f>

// Convert Buffer back into a human-readable string
console.log(buffer.toString());
// Output: Hello

            Section 3: Understanding Buffers
            
Getting a Buffer from an Uploaded File

            
Using multer.memoryStorage() to hold uploaded documents directly in RAM

          

          Slide 12 / 18
        


        

          
          

            

              

                
memory-upload.js

                
              

              
const express = require("express");
const multer = require("multer");
const app = express();

// 1. Store file in RAM memory instead of disk
const upload = multer({
    storage: multer.memoryStorage()
});

// 2. Upload endpoint
app.post("/buffer-upload", upload.single("file"), (req, res) => {
    if (!req.file) {
        return res.status(400).json({ message: "Please upload a file" });
    }

    // Access the raw binary Buffer
    const fileBuffer = req.file.buffer;

    res.json({
        fileName: req.file.originalname,
        size: fileBuffer.length,
        isBuffer: Buffer.isBuffer(fileBuffer)
    });
});

            

          


          
          

            

              

                🔑
                Understand These 3 Properties
              

              
    
                
  • req.file.buffer → Contains the actual binary byte data of the file in RAM.
    • 
                
  • Buffer.isBuffer(fileBuffer) → Returns true, proving it is a valid Node.js Buffer.
    • 
                
  • fileBuffer.length → Gives the exact size of the file in bytes.
    • 
              

            


            

              
Postman Response

              

{
    "fileName": "sample.pdf",
    "size": 2048,
    "isBuffer": true
}

            


            

              🚀
              

                Why Memory Storage? Keeping the file as a Buffer in memory is 10x faster than saving it to hard disk, because our document parsers can read it immediately without disk I/O latency!

            Section 4: Reading Documents
            
Reading PDF Files Using pdf-parse

            
Extracting selectable text from PDF buffers with a single asynchronous call

          

          Slide 14 / 18
        


        

          
          

            

              

                
read-pdf.js

                
              

              
const pdfParse = require("pdf-parse");

app.post("/read-pdf", upload.single("file"), async (req, res) => {
    try {
        if (!req.file) {
            return res.status(400).json({ message: "Please upload a PDF" });
        }

        // The magic line: pass the Buffer to pdf-parse
        const result = await pdfParse(req.file.buffer);

        res.json({
            message: "PDF read successfully",
            text: result.text
        });

    } catch (error) {
        res.status(500).json({ message: "Unable to read PDF" });
    }
});

            

          


          
          

            

              

                🔍
                Understand the Main Line

  • req.file.buffer → provides the raw PDF bytes.

  • pdfParse() → extracts text and metadata.
    • 
                
  • result.text → contains the clean extracted text string!

Reading DOCX Files Using Mammoth

            
Extracting clean text from Microsoft Word (.docx) files using Mammoth

          

          Slide 15 / 18
        


        

          
          

            

              

                
read-docx.js

                
              

              
const mammoth = require("mammoth");

app.post("/read-docx", upload.single("file"), async (req, res) => {
    try {
        if (!req.file) {
            return res.status(400).json({ message: "Please upload a DOCX file" });
        }

        // Extract raw text directly from the Buffer
        const result = await mammoth.extractRawText({
            buffer: req.file.buffer
        });

        res.json({
            message: "DOCX read successfully",
            text: result.value
        });

    } catch (error) {
        res.status(500).json({ message: "Unable to read DOCX" });
    }
});

            

          


          
          

            

              

                📝
                What Is Mammoth?
              

              

                Mammoth is a popular library specifically created to extract plain text or HTML from .docx documents without needing Microsoft Word installed.
              

              
    
                
  • extractRawText({ buffer }) → inspects the Word file in RAM.
    • 
                
  • result.value → holds the clean extracted document text!
    •

            Section 4: Reading Documents
            
Reading CSV Files Using csv-parse

            
Converting comma-separated tabular data into clean JavaScript arrays and objects

          

          Slide 16 / 18
        


        

          
          

            

              

                
read-csv.js

                
              

              
const { parse } = require("csv-parse/sync");

app.post("/read-csv", upload.single("file"), (req, res) => {
    try {
        if (!req.file) {
            return res.status(400).json({ message: "Please upload a CSV file" });
        }

        // Parse the Buffer into an array of objects
        const records = parse(req.file.buffer, {
            columns: true,           // Use row 1 as object keys
            skip_empty_lines: true,  // Ignore blank rows
            trim: true               // Strip extra spaces
        });

        res.json({
            message: "CSV read successfully",
            data: records
        });

    } catch (error) {
        res.status(400).json({ message: "Unable to read CSV" });
    }
});

            

          


          
          

            

              
📊What Is a CSV File?

              
CSV stands for Comma-Separated Values. It represents spreadsheet tables in plain text:

              
name,email,course
Anu,anu@gmail.com,MERN
Rahul,rahul@gmail.com,Python

            


            

              
Resulting JavaScript Objects

              

{
    "message": "CSV read successfully",
    "data": [
        { "name": "Anu", "email": "anu@gmail.com", "course": "MERN" },
        { "name": "Rahul", "email": "rahul@gmail.com", "course": "Python" }
    ]
}

            


            

              Key Option: columns: true tells csv-parse to take the header row (name,email,course) and use them as keys for each object!

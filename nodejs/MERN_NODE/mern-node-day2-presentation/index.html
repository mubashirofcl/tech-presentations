Section 1: Timer Functions

Synchronous vs Asynchronous Execution

Understanding execution order and the non-blocking JavaScript thread

Slide 03 / 15
🔄 Execution Models

Synchronous execution: Statements execute sequentially one after another. Each statement must finish completely before the next statement begins.

Asynchronous execution: Certain operations allow the program to continue executing remaining statements while waiting for a scheduled callback or I/O operation.

🔍 How This Example Executes
1 console.log("1. Start") executes immediately.
2 setTimeout() schedules a callback in Node.js timer phase for ~2000ms later.
3 console.log("3. End") executes immediately without waiting for the timer!
4 After ~2 seconds, the timer callback executes when the thread is available.
📌
Teaching Point: A timer schedules future work; it does not guarantee execution at an exact millisecond if the event loop is busy.
app.js 
console.log("1. Start");

setTimeout(() => {
  console.log("2. Timer completed");
}, 2000);

console.log("3. End");

Section 1: Timer Functions

setTimeout()

Scheduling a single-execution delayed callback

Slide 04 / 15
⏱️ What is setTimeout?

setTimeout() schedules a function to run once after a specified delay measured in milliseconds (1 second = 1,000 ms).

setTimeout(callback, delay);
  • ▸ callback: The function to execute when the timer expires.
  • ▸ delay: Requested delay in milliseconds.
🌍 Real-World Uses in Backend
  • ▸ Delayed notifications: Sending a follow-up email after a delay.
  • ▸ Simulating API responses: Mocking external microservice latency during development.
  • ▸ Scheduled actions: Auto-cancelling abandoned shopping carts after 15 minutes.
⚠️
Important: setTimeout() does not pause the entire application or freeze Node.js. Other HTTP requests continue serving immediately!
delayed-order.js 
console.log("Order placed");

setTimeout(() => {
  console.log("Your order is being processed");
}, 3000);

console.log("Please wait...");
Execution Output
$ node delayed-order.js Order placed Please wait... Your order is being processed # printed after ~3 seconds
Section 1: Timer Functions

clearTimeout()

Cancelling a scheduled timeout using its unique timer handle

Slide 05 / 15
🛑 Why Cancel a Timer?

Sometimes a scheduled action should be cancelled before it executes. setTimeout() returns a unique timer handle (ID) that you pass to clearTimeout() to abort the pending callback.

💡 Practical Scenario

Imagine a user schedules a notification, auto-logout, or auto-save. If the user clicks "Cancel" or takes another action before the 3-second countdown ends:

  • ▸ We call clearTimeout(timer).
  • ▸ Node.js discards the scheduled callback from its timer queue.
  • ▸ The callback function never runs!
🔑
Important Rule: Clearing a timer only works if the callback has not already begun executing. Once the timer fires, clearTimeout() has no effect.
cancel-timer.js 
// Schedule a message for 3 seconds later
const timer = setTimeout(() => {
  console.log("This message will not appear");
}, 3000);

// Cancel the timer immediately
clearTimeout(timer);

console.log("Timer cancelled");
Expected Output
$ node cancel-timer.js Timer cancelled # Note: "This message will not appear" is never printed

Repeated execution at specified time intervals

Slide 06 / 15
🔁 What is setInterval?

setInterval() schedules a callback to run repeatedly at approximately the specified interval until stopped.

setInterval(callback, interval);

Section 2: Understanding Callbacks

What Is a Callback Function?

Functions as first-class citizens passed as arguments for subsequent invocation

Slide 08 / 15
📌 Definition

A callback is a function passed as an argument to another function so that the receiving function can invoke ("call back") it later.

Callbacks can be used in both synchronous operations (like array.map) and asynchronous operations (like timers, files, or network requests).

🔄 Step-by-Step Execution Flow
1 showMessage is passed as a function reference into greetUser("Anu", showMessage).
2 greetUser() begins executing and prints "Hello, Anu".
3 callback() is called, which invokes showMessage() and prints "Welcome to Node.js".
⚠️
Common Student Mistake: Pass showMessage (the function reference), NOT showMessage()! Adding parentheses executes the function immediately and passes its return value (undefined).
callback-basic.js 
function greetUser(name, callback) {
  console.log(`Hello, ${name}`);

  callback(); // invoke the passed callback
}

function showMessage() {
  console.log("Welcome to Node.js");
}

// Pass showMessage as a reference
greetUser("Anu", showMessage);
Execution Output
$ node callback-basic.js Hello, Anu Welcome to Node.js
Section 2: Understanding Callbacks

Callback with Parameters

Passing computed results from the host function into the callback

Slide 09 / 15
calculate-total.js (Named Callback) 
function calculateTotal(price, quantity, callback) {
  const total = price * quantity;

  callback(total); // passes total into callback
}

function displayTotal(amount) {
  console.log("Total price:", amount);
}

calculateTotal(500, 3, displayTotal);
Output 1
$ node calculate-total.js Total price: 1500
process-marks.js (Arrow Callback) 
function processMarks(marks, callback) {
  const result = marks >= 50 ? "Passed" : "Failed";

  callback(result);
}

// Using an inline anonymous arrow callback
processMarks(75, (result) => {
  console.log(result);
});
Output 2
$ node process-marks.js Passed
💡
Both named functions and inline arrow functions work identically as callbacks. Anonymous arrow callbacks are very popular in modern Node.js.
Section 2: Understanding Callbacks

Asynchronous Callbacks

Combining callbacks with delayed asynchronous operations like setTimeout

Slide 10 / 15
⚡ Asynchronous Callback Pattern

In backend Node.js applications, callbacks are frequently used with asynchronous operations (timers, file systems, databases, network requests).

🔄 Execution Sequence
1 placeOrder() is called with an arrow callback.
2 It prints "Order placed" immediately.
3 It schedules a 2-second timer to call the callback.
4 The main program continues without waiting and logs "You can continue shopping".
5 After 2 seconds, the timer expires and logs "Order completed".
🌐
Real-World Connection: This exact pattern is how traditional Node.js modules read database rows, process image uploads, or query web services.
async-order.js 
function placeOrder(callback) {
  console.log("Order placed");

  setTimeout(() => {
    callback("Order completed");
  }, 2000);
}

placeOrder((message) => {
  console.log(message);
});

console.log("You can continue shopping");
Execution Output
$ node async-order.js Order placed You can continue shopping Order completed # printed after ~2 seconds
Section 2: Understanding Callbacks

Error-First Callbacks in Node.js

The standard Node.js convention: (error, data) with early return handling

Slide 11 / 15
📂 Input File (message.txt)

Welcome to Node.js

🛡️ The Error-First Pattern

Most built-in Node.js callback APIs follow this strict signature:

callback(error, data)
  • ▸ If an error occurs: error contains an Error object; data is undefined.
  • ▸ If successful: error is null; data contains the result.
  • ▸ Early Return: Always check if (error) and return immediately to prevent executing further code!
read-file-callback.js 
import fs from "node:fs";

fs.readFile("message.txt", "utf8", (error, data) => {
  if (error) {
    console.error("Error reading file:", error.message);
    return;
  }

  console.log("File content:", data);
});
Expected Output (When file exists)
$ node read-file-callback.js File content: Welcome to Node.js
Section 3: Callback Hell

What Is Callback Hell?

The maintenance nightmare caused by deeply nested, dependent asynchronous callbacks

Slide 12 / 15
🔥 Definition of Callback Hell

Callback hell (also called the "Pyramid of Doom") occurs when multiple asynchronous operations depend on the results of previous operations, forcing callbacks to be nested inside callbacks.

⚡ Why It Becomes a Major Problem
  • ▸ Loss of Readability: Code grows horizontally rather than vertically.
  • ▸ Error Handling Nightmare: Every single nested layer requires its own error check and recovery.
  • ▸ Fragile Refactoring: Moving or reordering any step risks breaking the entire chain.
🌲 Visual Representation of Dependent Tasks
getStudent(studentId, (student) => {
getCourse(student.courseId, (course) => {
getInstructor(course.instructorId, (instructor) => {
displayDetails(student, course, instructor);
});
});
});
💡
Important Perspective: Callbacks themselves are not bad. The problem is excessive nesting, coupling, and disorganized asynchronous flow.
Section 3: Callback Hell

Callback Hell: Practical Example

A realistic 3-step order processing pipeline with nested asynchronous callbacks

Slide 13 / 15
nested-order.js 
function getOrder(callback) {
  setTimeout(() => {
    console.log("Order received");
    callback({ orderId: 101 });
  }, 500);
}

function getPayment(order, callback) {
  setTimeout(() => {
    console.log("Payment completed");
    callback({ ...order, paid: true });
  }, 500);
}

function shipOrder(order, callback) {
  setTimeout(() => {
    console.log("Order shipped");
    callback({ ...order, shipped: true });
  }, 500);
}

// Nested Callback Invocation (Callback Hell)
getOrder((order) => {
  getPayment(order, (paidOrder) => {
    shipOrder(paidOrder, (shippedOrder) => {
      console.log("Final order:", shippedOrder);
    });
  });
});

🔍 Explain the Problem
  • ▸ Each operation depends directly on the result of the previous operation.
  • ▸ Adding error handling (e.g., checking if payment fails) triples code complexity.
  • ▸ Adding more steps (send email, generate invoice) pushes the code further right.
Section 3: Callback Hell

How Can We Avoid Callback Hell?

Three progressive solutions: Named Callbacks, Promises, and async/await

Slide 14 / 15
1️⃣ Named Callback Functions

Move nested inline callbacks into standalone top-level named functions.

Benefits: Flattens code, promotes reusability, easier to unit test.
Limitation: Complex branching and shared state can still be difficult to coordinate.
2️⃣ Promises (Conceptual)

Linear .then() chaining with centralized .catch() error handling: 

getOrder()
  .then((order) => getPayment(order))
  .then((paid) => shipOrder(paid))
  .then((shipped) => {
    console.log(shipped);
  })
  .catch((error) => {
    console.error(error);
  });
* Conceptual: assumes functions return Promises.
3️⃣ async / await (Conceptual)

Reads like clean synchronous code with unified try/catch blocks: 

async function processOrder() {
  try {
    const order = await getOrder();
    const paid = await getPayment(order);
    const shipped = await shipOrder(paid);

    console.log(shipped);
  } catch (error) {
    console.error(error);
  }
}

🎓 Day 2 Core Key Takeaways
  • ▸ Non-Blocking I/O: Synchronous code never waits for delayed timer callbacks to execute.
  • ▸ Timer Suite: setTimeout/clearTimeout for single delays; setInterval/clearInterval for repeating cycles.
  • ▸ Callbacks: Functions passed as values; invoked synchronously or asynchronously.
  • ▸ Error-First Standard: (error, data) pattern protects Node.js code from uncaught exceptions.
  • ▸ The Road Ahead: Callback hell is why modern MERN backends use Promises and async/await!

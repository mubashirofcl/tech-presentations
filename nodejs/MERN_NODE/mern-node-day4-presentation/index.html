Section 1: Setup & Routing

Setting Up an Express Project

Step-by-step project initialization, installation, and launching your first server

Slide 03 / 15
🚀 What is Express.js?

Express.js is a fast, unopinionated, minimalist web framework for Node.js. It simplifies backend development by providing built-in routing, middleware support, and request/response abstraction.

🛠️ Installation Steps
1 Create Project: mkdir express-day4 && cd express-day4 && npm init -y
2 Install Express: npm install express
3 Structure: server.js, package.json, and node_modules/.
📌
app.listen(PORT, callback) binds and listens for connections on the specified port. Once running, your server stays active to receive HTTP traffic!
server.js 
const express = require("express");

const app = express();

const PORT = 3000;

// Start listening for incoming network requests
app.listen(PORT, () => {
    console.log(`Server running on port ${PORT}`);
});
Terminal Execution
$ node server.js Server running on port 3000
Section 1: Setup & Routing

Creating Your First API Route

Defining URL endpoints and sending HTTP responses to clients

Slide 04 / 15
🧭 What is a Route?

A route defines how the backend server responds to a client request at a specific endpoint.

  • ▸ HTTP Method: e.g., GET, POST.
  • ▸ URL Path: e.g., /, /about.
  • ▸ Handler Function: (req, res) => { ... }
🔍 Anatomy of a Handler
  • ▸ app.get(): Creates an endpoint that listens for HTTP GET requests.
  • ▸ req (Request): Holds incoming client headers, query, and params.
  • ▸ res (Response): Object used to send data back to the client.
  • ▸ res.send(): Sends an HTTP text or HTML response.
server.js (Add Routes) 
// Root Route
app.get("/", (req, res) => {
    res.send("Welcome to My Express API");
});

// About Route
app.get("/about", (req, res) => {
    res.send("This is my first backend application");
});

Section 2: API Architecture & HTTP Methods

What Is an API?

Application Programming Interface: The communication bridge between systems

Slide 05 / 15
🔌 Definition of an API

API stands for Application Programming Interface. It allows two independent software programs (such as a React frontend and a Node.js backend) to securely communicate and exchange data.

⛅ Real-World Example: Weather App
1User types "Tokyo" in the mobile app frontend.
2App sends an HTTP GET request to the Weather API.
3Weather server queries climate sensors/database.
4API returns JSON: { temp: "21°C", sky: "Clear" }.
5Frontend displays the weather forecast to the user.
💡
Key Takeaway: A frontend never connects directly to a MongoDB database for security reasons. The Express API acts as the secure gatekeeper!
🔄 MERN API Communication Pipeline
⚛️ React Frontend Runs in client browser (User Interface)
▼ HTTP Request (GET / POST) JSON Payload
⚡ Express API Server (Node.js) Validates requests, runs business logic
▼ Query Database / Services BSON / Driver
🍃 MongoDB Database Stores persistent collections and records
Section 2: API Architecture & HTTP Methods

API vs URL

Understanding the critical distinction between resource addresses and communication interfaces

Slide 06 / 15
📍 What is a URL?

Uniform Resource Locator: The unique address used to locate a specific resource (webpage, image, file, or endpoint) on a network or server.

https://example.com/products
⚙️ What is an API?

Application Programming Interface: Defines the complete set of rules, HTTP verbs, and data contracts that software applications use to interact with resources.

GET /api/products
POST /api/products
DELETE /api/products/101
💡
Golden Rule: An API endpoint always has a URL, but not every URL is an API! A URL can simply point to an HTML page, PDF, or image file.
Feature URL API
Primary Role Identifies the location of a resource Defines how software communicates
Who Uses It? Web browsers, human users, applications Software applications & frontend clients
What It Returns HTML webpage, static image, or endpoint Structured data (JSON), status codes, actions
Endpoints Single specific path Can expose multiple verbs on same path
Example https://site.com/about GET /api/users
🎯 Compare in Action
https://example.com/about → Returns visual HTML Webpage for humans.
https://example.com/api/users → Returns raw JSON Data for apps.
Section 2: API Architecture & HTTP Methods

Understanding HTTP Methods

Informing the backend which CRUD operation the client intends to perform

Slide 07 / 15
Method CRUD Action Backend Purpose
GET Read Retrieve existing data from server
POST Create Submit new data to create a resource
PUT Update Completely update/replace a resource
PATCH Partial Partially update specific fields
DELETE Delete Remove a resource permanently
🔑
Key Insight: The exact same URL path (/students) executes completely different backend logic based on the incoming HTTP method!
routes-by-method.js 
app.get("/students", (req, res) => {
    res.send("Get all students");

app.post("/students", (req, res) => {

});

app.patch("/students/:id", (req, res) => {
    res.send(`Partially update student ${req.params.id}`);
});

app.delete("/students/:id", (req, res) => {
    res.send(`Delete student ${req.params.id}`);
});

Section 2: API Architecture & HTTP Methods

Understanding Request and Response

The fundamental message cycle between client (req) and server (res)

Slide 08 / 15
📥 What is a Request (req)?

A message sent from client to server containing:

  • ▸ HTTP Method: (GET, POST, etc.)
  • ▸ URL & Query Params: /users?page=1
  • ▸ Headers: Authorization, Content-Type
  • ▸ Request Body: JSON data sent via POST/PUT
📤 What is a Response (res)?

A message returned from server to client containing:

  • ▸ HTTP Status Code: (200 OK, 201 Created, 404 Not Found)
  • ▸ Response Headers: Content-Type: application/json
  • ▸ Response Body: The returned data or error message
res-json-demo.js 
app.get("/profile", (req, res) => {
    // Chain status code with JSON data payload
    res.status(200).json({
        success: true,
        message: "Profile fetched successfully",
        user: {
            id: 101,
            name: "Anu"
        }
    });
});
Client Received JSON Payload (Status: 200 OK)
{ "success": true, "message": "Profile fetched successfully", "user": { "id": 101, "name": "Anu" } }
Three Crucial Express Methods:
  • res.send() → Sends general text/HTML.
  • res.json() → Sets Content-Type to JSON and formats objects automatically.
  • res.status(code) → Sets explicit HTTP status code before sending response.
Section 3: Testing with Postman

Introduction to Postman

The industry-standard development tool for building, testing, and debugging APIs

Slide 09 / 15
🚀 What is Postman?

Postman is an API client tool that allows backend engineers to construct, send, and inspect HTTP requests (GET, POST, PUT, DELETE) without writing any frontend React or HTML code!

🎯 Why Postman is Essential
  • ▸ Browser limitation: Web browser address bars can only trigger GET requests.
  • ▸ Send JSON Bodies: Easily test POST and PUT with complex JSON payloads.
  • ▸ Status Code Inspection: Verify 200, 201, 404, or 500 error responses immediately.
  • ▸ Response Time & Size: Monitor latency in milliseconds.
💡
Always thoroughly test all backend endpoints in Postman first before connecting your React or frontend application!
🖥️ 7 Core Postman UI Elements
1Method Selector: Dropdown to choose GET, POST, PUT, DELETE, etc.
2Request URL Bar: Enter endpoint (e.g. http://localhost:3000/api/students).
3Params Tab: Query strings added automatically to the URL.
4Headers Tab: Set headers like Content-Type: application/json.
5Body Tab: Select raw → JSON to send data with POST/PUT.
6Send Button: Dispatches the HTTP request to your running server.
7Response Section: Displays returned status code, response time, and payload.

Testing POST API in Postman

Parsing JSON request bodies with express.json() and creating resources

Slide 11 / 15
post-student.js 
// MUST enable JSON body parser middleware!
app.use(express.json());

let students = [];

app.post("/api/students", (req, res) => {
    const { name, course } = req.body;

    const newStudent = {
        id: students.length + 1,
        name,
        course
    };

    students.push(newStudent);

    // 201 Created indicates successful creation
    res.status(201).json({
        message: "Student created successfully",
        data: newStudent
    });
});
🚨
Critical Requirement: Without app.use(express.json()), req.body will be undefined and crash your server!
Postman Request Settings

2. Enter URL: http://localhost:3000/api/students
3. Click Body → raw → select JSON
4. Enter Payload:

  "course": "MERN Stack"
}

Section 4: Formats & Final Project

Final Practical: Student Management API

Building and testing a complete 5-endpoint REST API using Express and Postman

Slide 15 / 15
🎯 Practical Objective

Build a complete Student Management REST API in server.js with in-memory array storage and test every route in Postman.

Method Endpoint Functionality
GET /api/students Get all students (200 OK)
GET /api/students/:id Get one student by ID (200 or 404)
POST /api/students Create new student (201 Created)
PUT /api/students/:id Update student details (200 or 404)
DELETE /api/students/:id Delete student by ID (200 or 404)
Student Record Data Model: 
{
  "id": 1,
  "name": "Anu",
  "email": "anu@gmail.com",
  "course": "MERN Stack"
}
student-management-api/server.js 
const express = require("express");
const app = express();
const PORT = 3000;

app.use(express.json());

let students = [
  { id: 1, name: "Anu", email: "anu@gmail.com", course: "MERN Stack" }
];

// 1. GET ALL
app.get("/api/students", (req, res) => {
  res.status(200).json(students);
});

// 2. GET ONE BY ID
app.get("/api/students/:id", (req, res) => {
  const student = students.find(s => s.id === Number(req.params.id));
  if (!student) return res.status(404).json({ message: "Student not found" });
  res.status(200).json(student);
});

// 3. POST CREATE
app.post("/api/students", (req, res) => {
  const { name, email, course } = req.body;
  const newStudent = { id: students.length + 1, name, email, course };
  students.push(newStudent);
  res.status(201).json(newStudent);
});

// 4. PUT UPDATE
app.put("/api/students/:id", (req, res) => {
  const student = students.find(s => s.id === Number(req.params.id));
  if (!student) return res.status(404).json({ message: "Student not found" });
  student.name = req.body.name || student.name;
  student.email = req.body.email || student.email;
  student.course = req.body.course || student.course;
  res.status(200).json(student);
});

// 5. DELETE REMOVE
app.delete("/api/students/:id", (req, res) => {
  const index = students.findIndex(s => s.id === Number(req.params.id));
  if (index === -1) return res.status(404).json({ message: "Student not found" });
  const deleted = students.splice(index, 1);
  res.status(200).json(deleted[0]);
});

app.listen(PORT, () => console.log(`API running on port ${PORT}`));

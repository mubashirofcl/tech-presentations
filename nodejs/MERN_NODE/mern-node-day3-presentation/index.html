Section 1: Introduction to Promises

Why Do We Need Promises?

Connecting Day 2 callback hell to a better solution

Slide 03 / 20
🔗Recap: The Problem with Callbacks

When several asynchronous operations depend on each other, callbacks become deeply nested.

  • ▸Nested callbacks grow into a pyramid.
  • ▸Difficult error handling — every level needs its own check.
  • ▸Difficult maintenance — hard to read, hard to change.
  • ▸Complex workflows — more steps means more nesting.
🔍How This Example Runs
1getUser() waits 1 second, then calls its callback with the user.
2Inside it, getOrders() waits another second and calls its callback.
3Only the innermost function can use both user and orders.
✅
Solution: Promises provide a structured way to handle asynchronous operations.
callbacks-problem.js
function getUser(callback) {
  setTimeout(() => {
    callback({ id: 1, name: "Anu" });
  }, 1000);
}

function getOrders(userId, callback) {
  setTimeout(() => {
    callback(["Order 101", "Order 102"]);
  }, 1000);
}

getUser((user) => {
  getOrders(user.id, (orders) => {
    console.log(user);
    console.log(orders);
  });
});
Expected Output (after ~2 seconds)
$ node callbacks-problem.js { id: 1, name: 'Anu' } [ 'Order 101', 'Order 102' ]
Section 2: Understanding Promises

What Is a Promise?

An object that represents the eventual result of an asynchronous operation

Slide 04 / 20
📖Definition

A Promise is a JavaScript object that represents the eventual completion or failure of an asynchronous operation.

  • ▸A successful result, or
  • ▸An error (a rejection).

Why it is useful: one object carries the result, so the code stays flat and errors have one place to go.

🍔Real-World Example: Ordering Food
1You place an order.
2The restaurant accepts the order.
3The restaurant prepares the food.
4The order is completed or cancelled.

A Promise represents the pending result of that operation.

order.js
const order = new Promise((resolve, reject) => {
  const success = true;

  if (success) {
    resolve("Order completed");
  } else {
    reject(new Error("Order failed"));
  }
});

console.log(order);
Expected Output
$ node order.js Promise { 'Order completed' }
📌
Execution flow: the executor function runs immediately. Calling resolve() or reject() decides whether the Promise is pending, fulfilled, or rejected.

Section 2: Understanding Promises

Creating a Promise Using resolve()

Simulating a user that loads after two seconds

Slide 06 / 20
✅What resolve() Does

resolve(value) marks the Promise as fulfilled and passes value to .then().

const promise = new Promise((resolve, reject) => { resolve("Success"); });

Why it is useful: a function can hand back a result that is not ready yet.

🔍Execution Flow
1getUser() returns a Promise.
2setTimeout() simulates an asynchronous operation.
3resolve() returns the successful result.
4.then() receives the result.
user-loading.js
function getUser() {
  return new Promise((resolve) => {
    setTimeout(() => {
      resolve({
        id: 1,
        name: "Anu",
        role: "Student",
      });
    }, 2000);
  });
}

getUser().then((user) => {
  console.log("User loaded:", user);
});
Expected Output
$ node user-loading.js User loaded: { id: 1, name: 'Anu', role: 'Student' } # printed after ~2 seconds
Section 2: Understanding Promises

Creating a Promise Using reject()

A Promise can represent failure as well as success

Slide 07 / 20
❌What reject() Does

reject(error) marks the Promise as rejected. The error goes to .catch().

Why it is useful: failures travel through the same object as successes, so they can be handled in one place.

🔍Execution Flow
  • ▸Valid amount → resolve().
  • ▸Invalid amount → reject().
  • ▸.catch() handles the rejection.
  • ▸Here the amount is -500, so the Promise rejects.
💡
Reject with new Error(...), not a plain string. An Error carries a message.
payment.js
function processPayment(amount) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (amount > 0) {
        resolve("Payment successful");
      } else {
        reject(new Error("Invalid payment amount"));
      }
    }, 1000);
  });
}

processPayment(-500)
  .then((result) => {
    console.log(result);
  })
  .catch((error) => {
    console.log(error.message);
  });
Expected Output
$ node payment.js Invalid payment amount # printed after ~1 second
Section 3: Handling Promises

Understanding then()

Handling the successful result of a Promise

Slide 08 / 20
✅What then() Does

.then() runs a function when the Promise is fulfilled. The function receives the resolved value.

promise.then((result) => { console.log(result); });

Why it is useful: your code runs exactly when the data is ready, with no polling.

🔍Execution Flow
1getProduct() returns a pending Promise.
2After 1 second, resolve() fulfills it with the product object.
3.then() receives that object as product.
product.js
function getProduct() {
  return new Promise((resolve) => {
    setTimeout(() => {
      resolve({
        name: "Laptop",
        price: 50000,
      });
    }, 1000);
  });
}

getProduct().then((product) => {
  console.log("Product:", product.name);
  console.log("Price:", product.price);
});
Expected Output
$ node product.js Product: Laptop Price: 50000
Section 3: Handling Promises

Understanding catch()

Handling Promise rejections

Slide 09 / 20
🛡️What catch() Does

.catch() runs when the Promise is rejected, or when an earlier handler in the chain throws an error.

Why it is useful: one .catch() at the end can protect a whole chain.

🔍Execution Flow
1checkAge(16) runs. 16 is less than 18.
2The Promise is rejected with an Error.
3.then() is skipped.
4.catch() prints the error message.
check-age.js
function checkAge(age) {
  return new Promise((resolve, reject) => {
    if (age >= 18) {
      resolve("Access granted");
    } else {
      reject(new Error("Access denied"));
    }
  });
}

checkAge(16)
  .then((message) => {
    console.log(message);
  })
  .catch((error) => {
    console.log("Error:", error.message);
  });
Expected Output
$ node check-age.js Error: Access denied
Section 3: Handling Promises

Understanding finally()

Running cleanup code after a Promise settles

Slide 10 / 20
🏁What finally() Does

.finally() runs after the Promise settles, whether it was fulfilled or rejected.

  • ▸.then() handles success.
  • ▸.catch() handles failure.
  • ▸.finally() handles cleanup or completion tasks.
🌍Why It Is Useful

Hiding a loading indicator after an API request finishes, whether the request worked or not.

📌
Flow: the Promise fulfills after 2 seconds → .then() prints the data → .catch() is skipped → .finally() always runs last.
loading-status.js
function fetchData() {
  return new Promise((resolve) => {
    setTimeout(() => {
      resolve("Data loaded successfully");
    }, 2000);
  });
}

fetchData()
  .then((result) => {
    console.log(result);
  })
  .catch((error) => {
    console.log(error.message);
  })
  .finally(() => {
    console.log("Operation completed");
  });
Expected Output
$ node loading-status.js Data loaded successfully # after ~2 seconds Operation completed
Section 3: Handling Promises

Promise Chaining

Running asynchronous steps in sequence without nesting

Slide 11 / 20
🔗What Chaining Does

Promise chaining runs several asynchronous operations one after another, in a flat list instead of a nested pyramid.

🔍Execution Flow
1getUser() returns a Promise.
2The first .then() receives the user.
3It returns another Promise from getCourses().
4The next .then() receives the courses.
5.catch() handles errors from anywhere in the chain.
⚠️
Always return the next Promise. Each .then() must return the next asynchronous operation. Without return, the next step does not wait for it.
student-info.js
function getUser() {
  return new Promise((resolve) => {
    setTimeout(() => {
      resolve({ id: 1, name: "Anu" });
    }, 1000);
  });
}

function getCourses(userId) {
  return new Promise((resolve) => {
    setTimeout(() => {
      resolve(["React", "Node.js", "MongoDB"]);
    }, 1000);
  });
}

getUser()
  .then((user) => {
    console.log("User:", user.name);

    return getCourses(user.id);
  })
  .then((courses) => {
    console.log("Courses:", courses);
  })
  .catch((error) => {
    console.log("Error:", error.message);
  });
Expected Output (1 second between lines)
$ node student-info.js User: Anu Courses: [ 'React', 'Node.js', 'MongoDB' ]
Section 4: Understanding async/await

What Is async/await?

Modern syntax that makes Promise-based code easier to read

Slide 12 / 20
✨The Two Keywords
  • ▸async declares an asynchronous function.
  • ▸An async function always returns a Promise.
  • ▸await waits for a Promise to settle before continuing inside that async function.
⚡
Non-blocking: await does not block the entire Node.js runtime. Other work keeps running while the function waits.
🌍Why It Is Useful

Asynchronous code reads from top to bottom like normal, step-by-step code.

syntax.js (pattern only)
async function getData() {
  const result = await somePromise();

  console.log(result);
}
📌
somePromise() stands for any function that returns a Promise. This slide shows the pattern; the next slides run real code.
Section 4: Understanding async/await

Understanding async

An async function always returns a Promise

Slide 13 / 20
📦What async Does

Adding async in front of a function makes it return a Promise automatically.

Even though greet() returns a normal string, JavaScript wraps it in a fulfilled Promise.

🔍Execution Flow
1greet() is called and returns a Promise, not a string.
2console.log(greet()) prints that Promise.
3.then() receives the string inside it.
async-basics.js
async function greet() {
  return "Hello from Node.js";
}

console.log(greet());

greet().then((message) => {
  console.log(message);
});
Expected Output
$ node async-basics.js Promise { 'Hello from Node.js' } Hello from Node.js
Section 4: Understanding async/await

Understanding await

Waiting for a Promise and using its value

Slide 14 / 20
⏳What await Does

await waits for a Promise to settle. It gives back the fulfilled value, or throws the rejection reason.

Why it is useful: no .then() needed. The result goes straight into a variable.

🔍Execution Flow
1main() starts and prints Loading user....
2await waits for getUser() to fulfill (2 seconds).
3The user object is assigned to user.
4Execution continues with the next statement.
await-user.js
function getUser() {
  return new Promise((resolve) => {
    setTimeout(() => {
      resolve({
        name: "Anu",
        role: "Student",
      });
    }, 2000);
  });
}

async function main() {
  console.log("Loading user...");

  const user = await getUser();

  console.log("User:", user);
  console.log("Completed");
}

main();
Expected Output
$ node await-user.js Loading user... User: { name: 'Anu', role: 'Student' } # after ~2 seconds Completed

Section 5: Error Handling with async/await

try/catch with async/await

Catching rejected Promises with familiar syntax

Slide 16 / 20
🛡️How It Works

When an awaited Promise rejects, the rejection is thrown as an error. A try/catch block can catch it.

Why it is useful: the same try/catch you already know handles asynchronous errors.

🔍Execution Flow
1try contains the asynchronous operation.
2await receives the Promise result.
3If the Promise rejects, execution moves to catch.
4The error is handled without crashing the workflow.
try-catch.js
function getUser() {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      reject(new Error("Unable to load user"));
    }, 1000);
  });
}

async function main() {
  try {
    const user = await getUser();

    console.log(user);
  } catch (error) {
    console.log("Error:", error.message);
  }
}

main();
Expected Output
$ node try-catch.js Error: Unable to load user # after ~1 second

Practical Login Workflow

A simulated login using Promises, async/await, and try/catch

Slide 17 / 20
🚫
Demonstration only. This is a simulated login workflow. It is not real authentication and must never be used to store or verify real passwords.
🔍Execution Flow
1login() prints Checking credentials....
2await loginUser(...) waits 1.5 seconds.
3Correct credentials → the Promise resolves and the welcome lines print.
4Wrong credentials → the Promise rejects and catch prints the failure.
🧪Try It: Wrong Password

Change "12345" in the loginUser(...) call to "wrong" and run it again:

Output with a wrong password
$ node login.js Checking credentials... Login failed: Invalid username or password
login.js
function loginUser(username, password) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (username === "admin" && password === "12345") {
        resolve({
          id: 1,
          username: "admin",
          message: "Login successful",
        });
      } else {
        reject(new Error("Invalid username or password"));
      }
    }, 1500);
  });
}

async function login() {
  try {
    console.log("Checking credentials...");

    const user = await loginUser("admin", "12345");

    console.log(user.message);
    console.log("Welcome:", user.username);
  } catch (error) {
    console.log("Login failed:", error.message);
  }
}

login();
Expected Output (after ~1.5 seconds)
$ node login.js Checking credentials... Login successful Welcome: admin

Section 6: Final Practical Implementation

Complete Practical Project

Student Enrollment System — explained section by section

Slide 19 / 20
app.js
function registerStudent(name, email) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (!name || !email) {
        reject(new Error("Name and email are required"));
        return;
      }

      resolve({
        id: 101,
        name,
        email,
      });
    }, 1000);
  });
}

function enrollCourse(studentId, course) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (!course) {
        reject(new Error("Course is required"));
        return;
      }

      resolve({
        studentId,
        course,
        status: "Enrolled",
      });
    }, 1000);
  });
}

async function main() {
  try {
    console.log("Student registration started...");

    const student = await registerStudent("Anu", "anu@example.com");

    console.log("Student registered:", student.name);

    const enrollment = await enrollCourse(student.id, "MERN Stack");

    console.log("Enrollment completed:", enrollment);
  } catch (error) {
    console.error("Process failed:", error.message);
  } finally {
    console.log("Enrollment process finished");
  }
}

main();
🧩Code Walkthrough
1registerStudent() returns a Promise. It rejects if the name or email is missing; otherwise it resolves with the student after 1 second.
2enrollCourse() returns a Promise. It rejects if the course is missing; otherwise it resolves with the enrollment record.
3async main() connects both functions. Each await pauses main() until its Promise settles.
4try/catch catches a rejection from either Promise.
5finally always runs last, on success or failure.
Expected Output (about 2 seconds total)
$ node app.js Student registration started... Student registered: Anu Enrollment completed: { studentId: 101, course: 'MERN Stack', status: 'Enrolled' } Enrollment process finished

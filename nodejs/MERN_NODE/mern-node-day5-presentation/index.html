Section 1: Query Parameters

What Are Query Parameters?

Passing optional key-value pairs to Express routes using req.query

Slide 04 / 18
📖 Theory & Purpose

Query parameters are key-value pairs appended to the end of a URL after the ? symbol. They are used to send optional instructions to the server without changing the route endpoint.

  • 🔍 Searching: /students?search=anu
  • 🎯 Filtering: /students?course=MERN
  • 📊 Sorting: /products?category=electronics&sort=price
  • 📄 Pagination: /students?page=2&limit=10
⚠️
Important Behavior: Query parameter values are always received as strings (e.g., "22" instead of 22). Always convert them using Number() when performing numeric comparisons!
server.js — Accessing req.query 
const express = require("express");
const app = express();

// GET /students?course=MERN&age=22
app.get("/students", (req, res) => {
    const course = req.query.course;
    const age = req.query.age;

    res.json({
        message: "Query parameters received",
        course,
        age
    });
});

app.listen(3000);
Postman / Browser Request & Response
GET http://localhost:3000/students?course=MERN&age=22 { "message": "Query parameters received", "course": "MERN", "age": "22" }

Practical: Filtering Students Using Query Parameters

Dynamically filtering an in-memory array based on user-provided course values

Slide 05 / 18
filter-students.js 
const students = [
    { id: 1, name: "Anu", course: "MERN" },
    { id: 2, name: "Rahul", course: "Python" },
    { id: 3, name: "Neha", course: "MERN" },
    { id: 4, name: "Arun", course: "React" }
];

app.get("/students", (req, res) => {
    const course = req.query.course;
    let filteredStudents = students;

    // Only filter if a course query was provided
    if (course) {
        filteredStudents = students.filter(
            (student) => student.course.toLowerCase() === course.toLowerCase()
        );
    }

    res.json({
        count: filteredStudents.length,
        data: filteredStudents
    });
});

Section 1: Query Parameters

Multiple Query Parameters: Search, Filter & Pagination

Combining queries to build professional, production-ready search and pagination features

Slide 06 / 18
search-paginate.js 
app.get("/students", (req, res) => {
    const { course, search, page = "1", limit = "5" } = req.query;

    let result = [...students];

    // 1. Filter by course
    if (course) {
        result = result.filter(
            s => s.course.toLowerCase() === course.toLowerCase()
        );
    }

    // 2. Search by student name
    if (search) {
        result = result.filter(
            s => s.name.toLowerCase().includes(search.toLowerCase())
        );
    }

    // 3. Calculate Pagination indices
    const pageNumber = Math.max(1, Number(page) || 1);
    const pageSize = Math.max(1, Number(limit) || 5);
    const startIndex = (pageNumber - 1) * pageSize;

    const paginatedData = result.slice(
        startIndex,
        startIndex + pageSize
    );

    res.json({
        total: result.length,
        page: pageNumber,
        limit: pageSize,
        data: paginatedData
    });
});
📐 The Pagination Formula
const startIndex = (page - 1) * limit;
Page 1 (limit 5) → Items 0 to 4
Page 2 (limit 5) → Items 5 to 9

            Section 2: Route Parameters
            
What Are Route Parameters?

            
Capturing dynamic path values inside the Express route using req.params

          

          Slide 07 / 18
        


        

          
          

            

              

                🎯
                Theory & Definition
              

              

                Route parameters are named URL segments used to capture dynamic values at specific positions in the URL path.
              

              

                In Express, a route parameter is defined by prefixing a path segment with a colon (:).
              

              

                app.get("/students/:id", (req, res) => { ... });
              

            


            

              

                📌
                Resource Identification Examples
              

              
    
                
  • /api/students/101 → Parameter id is "101"
    • 
                
  • /api/students/102 → Parameter id is "102"
    • 
                
  • /api/products/501 → Parameter id is "501"
    • 
              

              

                Unlike query parameters which filter a collection, route parameters target a distinct individual resource.
              

            

          


          
          

            

              

                

                  
                  route-param-intro.js
                

                
              

              
// Defining a dynamic route parameter with :id
app.get("/students/:id", (req, res) => {

    // req.params contains all defined route parameters
    const studentId = req.params.id;

    res.json({
        message: "Student details",
        id: studentId
    });

});

            


            

              

                
                Postman Test: GET /students/101
              

              

GET http://localhost:3000/students/101

{
    "message": "Student details",
    "id": "101"
}

            


            

              ⚠️
              

                String Type Warning: Notice that id is returned as a string: "101"! To compare it against numeric array IDs, we must cast it with Number(req.params.id).

const students = [
    { id: 1, name: "Anu", course: "MERN" },
    { id: 2, name: "Rahul", course: "Python" },
    { id: 3, name: "Neha", course: "React" }
];

app.get("/students/:id", (req, res) => {
    // 1. Convert string parameter to a Number
    const id = Number(req.params.id);

    // 2. Search student in array
    const student = students.find(
        (student) => student.id === id
    );

    // 3. Handle non-existent student (404)
    if (!student) {
        return res.status(404).json({
            message: "Student not found"
        });
    }

    // 4. Return matching student (200)
    res.status(200).json({
        data: student
    });
});

            Section 2: Route Parameters
            
Query Parameters vs Route Parameters

            
Clear architectural distinction and how to seamlessly combine both in a single endpoint

          

          Slide 09 / 18
        


        

          
          

            

              
                

                  Feature
                  Query Parameters (req.query)
                  Route Parameters (req.params)
                

              
              
                

                  Position in URL
                  Appended at the end after the ? mark
                  Embedded directly within the URL path segments
                

                

                  Express Access
                  req.query.paramName
                  req.params.paramName
                

                

                  Primary Purpose
                  Filtering, searching, sorting, and pagination
                  Identifying a specific, distinct resource
                

                

                  Necessity
                  Almost always optional
                  Usually required by the route pattern
                

                

                  Multiple Values
                  Separated by ampersands: ?course=MERN&page=1
                  Separated by path slashes: /students/:id/grades/:sem
                

                

                  Example URL
                  GET /students?course=MERN
                  GET /students/101
                

              
            

          


          
          

            

              

                🤝
                Can We Use Both Together? Yes!
              

              

                A real-world API often targets a specific entity via route params while requesting optional related fields via query params:
              

              

                GET /students/101?include=course
              

              

                Route param → req.params.id = "101"
                Query param → req.query.include = "course"
              

            


            

              

                

                  
                  combined-params.js
                

                
              

              
app.get("/students/:id", (req, res) => {
    const id = Number(req.params.id);
    const include = req.query.include;

    res.json({
        studentId: id,
        include
    });
});

            

          

        

      


      
      

        

          

            Section 3: CRUD API Implementation
            
What Is CRUD?

            
The four foundational operations of data management and their REST HTTP method mappings

          

          Slide 10 / 18
        


        

          
          

            

              POST
              CREATE
              
Add a new record to the data store. Receives data from the client request body.

              
Status: 201 Created

            


            

              GET
              READ
              
Retrieve existing records. Fetch all items or a single item by its ID parameter.

              
Status: 200 OK

            


            

              PUT / PATCH
              UPDATE
              
Modify existing records. PUT replaces the full entity; PATCH updates specific fields.

              
Status: 200 OK

            


            

              DELETE
              DELETE
              
Remove an existing record by its ID. Spliced from the array or deleted from DB.

              
Status: 200 OK

            

          


          
          

            

              

                🎓
                Real-World Student Management Example
              

              
    
                
  • Create: Register a new student enrollment (POST /students).
    • 
                
  • Read: View the student roster or view a single profile (GET /students or GET /students/:id).
    • 
                
  • Update: Edit phone, email, or change selected course (PUT or PATCH /students/:id).
    • 
                
  • Delete: Withdraw or graduate a student (DELETE /students/:id).
    • 
              

            


            

              

                🔄
                REST Architecture Insight
              

              

                CRUD is a general conceptual model used in all database and software engineering.
              

              

                In web applications, HTTP Methods (POST, GET, PUT, PATCH, DELETE) provide the standard communication protocol to execute CRUD operations across the network.

            Section 3: CRUD API Implementation
            
CREATE — Adding a New Student

            
Implementing POST /students with body validation, ID generation, and 201 Created

                  create-student.js (POST /students)
                

                
              

              
app.post("/students", (req, res) => {
    const { name, email, course } = req.body;

    // 1. Validate required fields (400 Bad Request)
    if (!name || !email || !course) {
        return res.status(400).json({
            message: "All fields are required"
        });
    }

    // 2. Auto-increment dynamic ID
    const newStudent = {
        id: students.length
            ? Math.max(...students.map(s => s.id)) + 1
            : 1,
        name,
        email,
        course
    };

    // 3. Append to state
    students.push(newStudent);

    // 4. Respond with HTTP 201 Created
    res.status(201).json({
        message: "Student created successfully",
        data: newStudent
    });
});

UPDATE — Updating Student Details Using PUT

            
Replacing complete resource representations with PUT /students/:id

          

          Slide 14 / 18
        


        

          
          

            

              

                

                  
                  update-put.js (PUT /students/:id)
                

                
              

              
app.put("/students/:id", (req, res) => {
    const id = Number(req.params.id);

    // 1. Locate student by ID
    const student = students.find(
        (student) => student.id === id
    );

    if (!student) {
        return res.status(404).json({
            message: "Student not found"
        });
    }

    const { name, email, course } = req.body;

    // 2. PUT requires complete representation
    if (!name || !email || !course) {
        return res.status(400).json({
            message: "All fields are required"
        });
    }

    // 3. Replace fields
    student.name = name;
    student.email = email;
    student.course = course;

    res.status(200).json({
        message: "Student updated successfully",
        data: student
    });
});

            

          


          
          

            

              

                PUT
                The Nature of HTTP PUT
              

              

                In REST conventions, PUT implies replacing the complete record. The client must supply all required fields (name, email, and course).

PATCH — Updating Specific Fields

            
Performing partial updates with PATCH /students/:id, field whitelisting & Object.assign

                  update-patch.js (PATCH /students/:id)
                

                
              

              
app.patch("/students/:id", (req, res) => {
    const id = Number(req.params.id);

    const student = students.find(s => s.id === id);
    if (!student) {
        return res.status(404).json({ message: "Student not found" });
    }

    // 1. Whitelist allowed fields for security
    const allowedFields = ["name", "email", "course"];
    const updates = Object.keys(req.body);

    // 2. Reject empty updates or illegal keys
    if (updates.length === 0 || updates.some(f => !allowedFields.includes(f))) {
        return res.status(400).json({
            message: "Provide valid fields to update"
        });
    }

    // 3. Merge only provided fields
    Object.assign(student, req.body);

    res.status(200).json({
        message: "Student partially updated",
        data: student
    });
});

DELETE — Removing a Student

            
Finding record index, splicing from array, and confirming deletion

          

          Slide 16 / 18
        


        

          
          

            

              

                

                  
                  delete-student.js (DELETE /students/:id)
                

                
              

              
app.delete("/students/:id", (req, res) => {
    const id = Number(req.params.id);

    // 1. Locate index of target student
    const studentIndex = students.findIndex(
        (student) => student.id === id
    );

    // 2. If findIndex returns -1, student does not exist
    if (studentIndex === -1) {
        return res.status(404).json({
            message: "Student not found"
        });
    }

    // 3. Remove 1 item at studentIndex
    const deletedStudent = students.splice(studentIndex, 1)[0];

    // 4. Return confirmed deleted payload
    res.status(200).json({
        message: "Student deleted successfully",
        data: deletedStudent
    });
});

                Key JavaScript Mechanics

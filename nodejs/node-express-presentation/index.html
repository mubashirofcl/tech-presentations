DAY 1 — DEFINITION

What is Node.js?

Understanding JavaScript outside the web browser environment.

Simple Definition

Node.js is an open-source, cross-platform JavaScript runtime environment built on Google Chrome's V8 Engine.

REMEMBER
Node.js does NOT make JavaScript a new language. It provides an environment where JavaScript can run on servers!
  • Created in 2009: Created by Ryan Dahl to solve the slowness of traditional web servers (like Apache PHP).
  • Full-Stack JS: Developers can now use JavaScript for BOTH Frontend (React/Vue) and Backend (Node.js).

DAY 1 — CORE ENGINE

The V8 JavaScript Engine

How high-level JavaScript code is compiled into ultra-fast machine code.

What is V8?

V8 is Google's open-source high-performance JavaScript engine written in C++. It parses JavaScript and compiles it directly into native machine code (0s and 1s) using Just-In-Time (JIT) compilation.

WHY V8 IS FAST
Instead of interpreting code line-by-line slowly, V8 compiles JavaScript straight to machine bytecode before executing!

DAY 1 — NON-BLOCKING I/O

Event-Driven Architecture & Non-Blocking I/O

Why Node.js handles thousands of requests without crashing or blocking.

Blocking I/O (Traditional Servers)

In traditional servers (like Apache PHP), reading a file from disk blocks the thread. The thread sits idle waiting for the hard drive to respond.

Result: High CPU/RAM usage, slow user response times.

Non-Blocking I/O (Node.js)

Node.js requests the OS to read the file in the background and immediately moves to serve the next request! When the file is ready, an Event is fired.

Result: Extremely fast, lightweight, handles 10k+ concurrent users.

Real-World Analogy: Restaurant Waiter

Blocking Waiter: Takes customer 1 order ➔ Waits inside kitchen 15 mins for food ➔ Serves customer 1 ➔ Only then takes customer 2 order. (Terrible!)
Non-Blocking Waiter (Node.js): Takes customer 1 order ➔ Hands ticket to kitchen ➔ Immediately takes customer 2 & 3 orders ➔ Serves customer 1 when kitchen bell rings! (Super Efficient!)

DAY 1 — THREAD MODEL

Single-Threaded Model & Concurrency

How a single thread handles thousands of users simultaneously.

Single-Threaded Event Loop

JavaScript execution in Node.js runs on one single thread. This eliminates complex multi-thread locking bugs and thread switching overhead.

COMMON QUESTION
"If Node.js is single-threaded, how does it handle 10,000 users at once?"
Answer: Node.js delegates expensive I/O operations to libuv (which uses background worker threads) so the main JS thread never stops!
Thread Model Comparison
Multi-Threaded Server (Java/PHP) Node.js (Single-Threaded)
1 User = 1 Thread 1 Thread for ALL User Requests
10,000 Users = 10,000 Threads (High RAM!) 10,000 Users = 1 Thread + Asynchronous I/O
Threads spend time waiting for disk/DB Thread never waits; delegates disk/DB to OS
DAY 1 — BACKGROUND SYSTEM

What is libuv?

The C library behind Node.js asynchronous magic.

Definition of libuv

libuv is a multi-platform C library that provides Node.js with support for asynchronous I/O based on Event Loops and Thread Pools.

  • Event Loop: Monitors pending callbacks and pushes ready tasks to the call stack.
  • Thread Pool (4 default threads): Handles expensive tasks like file reading (fs) and crypto operations.

DAY 1 — WORKLOAD CHOICE

CPU-Intensive vs I/O-Intensive Tasks

When to use Node.js and when NOT to use Node.js.

Ideal: I/O-Intensive Applications

Applications that spend most time reading/writing data over disk or network.

  • RESTful APIs & Microservices
  • Real-time Chat Apps (WebSockets)
  • Streaming Apps (Netflix/Spotify)
  • E-commerce Backend Systems

Avoid: Heavy CPU-Intensive Tasks

Applications that require massive CPU mathematical calculations.

  • Heavy 4K Video Encoding / Rendering

Timer Functions in Node.js

Core Timer APIs

  console.log("Running every 1 second...");
}, 1000);

  clearInterval(intervalId);

DAY 2 — TIMING MYTH

The Myth of setTimeout(fn, 0)

Why 0ms delay does NOT mean immediate execution.

IMPORTANT CONCEPT
setTimeout(fn, 0) does NOT execute immediately. It registers the callback in the timer queue and waits until the synchronous Call Stack is completely empty!

Why Timers Get Delayed

If synchronous code takes 5 seconds to run, a setTimeout(fn, 100) will be delayed and run AFTER the 5 seconds finish!

DAY 2 — ASYNC PATTERNS

Callbacks & Error-First Callback Pattern

Passing functions as arguments and handling asynchronous results.

What is a Callback?

A callback is a function passed into another function as an argument, which is executed when an asynchronous operation completes.

Node.js Error-First Pattern
Node.js standardizes callback parameters as (error, data).
• If operation fails: error contains an Error object, data is undefined.
• If operation succeeds: error is null, data contains the result.
callback_pattern.js 
function getUser(id, callback) {
  setTimeout(() => {
    if (id === 101) {
      callback(null, { id: 101, name: "John" }); // Success
    } else {
      callback("User not found!", null); // Error
    }
  }, 1000);
}

getUser(101, (err, user) => {
  if (err) return console.error("Error:", err);
  console.log("User Name:", user.name);
});

DAY 2 — JAVASCRIPT CONTEXT

Controlling Context: call(), apply(), bind()

Explicitly binding the 'this' keyword to objects.

Method How it works Arguments Format Execution Time
call() Invokes function immediately with explicit this context Passed individually: arg1, arg2, arg3 Executes Immediately
apply() Invokes function immediately with explicit this context Passed as an Array: [arg1, arg2, arg3] Executes Immediately
bind() Returns a NEW bound function with this context locked Passed individually: arg1, arg2 Executes Later when invoked
call_apply_bind.js 
const person = { name: "John" };

function greet(city, country) {
  console.log(`Hello ${this.name} from ${city}, ${country}`);
}

greet.call(person, "Kochi", "India");      // Output: Hello John from Kochi, India
greet.apply(person, ["Kochi", "India"]);   // Output: Hello John from Kochi, India

const boundGreet = greet.bind(person, "Kochi", "India");
boundGreet(); // Executes later when invoked!

DAY 3 — PROMISE STATES

Why Promises Exist & The 3 States

A Promise is an object representing future completion of an async job.

1. Pending

Initial state. Async task is ongoing, neither resolved nor rejected yet.

2. Fulfilled

Task completed successfully! resolve(value) was called.

3. Rejected

Task failed! reject(error) was called.

create_promise.js 
const myPromise = new Promise((resolve, reject) => {
  setTimeout(() => {
    const success = true;
    if (success) {
      resolve("Data received successfully!");
    } else {
      reject("Network Error!");
    }
  }, 1000);
});

myPromise
  .then(data => console.log("Success:", data))
  .catch(err => console.error("Failed:", err))
  .finally(() => console.log("Finished operation."));

DAY 3 — CONCURRENCY METHODS

Promise Combinators & Utilities

Executing multiple Promises in parallel efficiently.

Promise.all([p1, p2])

Waits for ALL promises to fulfill. Rejects IMMEDIATELY if ANY single promise fails.

Promise.allSettled([p1, p2])

Waits for ALL promises to complete, returning status and value/reason for each. Never rejects early!

Promise.race([p1, p2])

Returns as soon as the FIRST promise settles (whether resolved or rejected).

Promise.any([p1, p2])

Returns as soon as the FIRST promise fulfills successfully. Ignores rejections unless ALL fail.

SESSION — EVENT LOOP PHASES

Interactive Phase Explorer

Understand the 6 distinct phases of the libuv event loop in Node.js.

Phase 1

TIMERS

Executes callbacks scheduled by setTimeout() and setInterval() whose threshold time has elapsed.

Phase 2

PENDING CALLBACKS

Executes I/O callbacks deferred to the next loop iteration (e.g. certain TCP errors like ECONNREFUSED).

Phase 3

IDLE, PREPARE

Used internally by Node.js and libuv for housekeeping prior to the Poll phase.

Phase 4

POLL

Retrieves new I/O events (file disk read, incoming HTTP sockets) and executes I/O-related callbacks. Node can block here waiting for I/O!

Phase 5

CHECK

Executes callbacks scheduled by setImmediate(). Runs immediately after the Poll phase completes.

Phase 6

CLOSE CALLBACKS

Executes close handlers when sockets or handles close abruptly (e.g., socket.on('close', ...)).

SESSION — LIBUV ARCHITECTURE

libuv & The Thread Pool

How Node.js offloads synchronous OS tasks without blocking JavaScript.

What is libuv?

libuv is an open-source C library built for Node.js. It provides the event loop engine, asynchronous I/O primitives, and a default 4-thread Worker Pool (configurable via UV_THREADPOOL_SIZE).

What Uses the Thread Pool?

  • File System (fs): fs.readFile(), fs.writeFile()
  • Cryptography (crypto): crypto.pbkdf2(), crypto.randomBytes()
  • DNS Lookups: dns.lookup()
  • Compression (zlib): zlib.gzip()
Network I/O vs Thread Pool
🌐 Network Sockets (http/https/net)
Handled directly by OS Async Kernel (epoll / kqueue / IOCP) — No Thread Pool needed!
vs
📁 File System & CPU Crypto Tasks
Offloaded to libuv Worker Thread Pool (Threads #1 to #4)
SESSION — PRIORITY QUEUES

process.nextTick() vs Promises (Microtasks)

Node.js high-priority queues that run before event-loop phase transitions.

process.nextTick()

• Node.js specific priority queue.
• Processed IMMEDIATELY after current operation finishes, before moving to ANY event loop phase or microtask queue!
• ⚠️ Recursively calling nextTick() will starve the Event Loop!

Promise Microtasks

• Standard V8 Microtask queue.
• Processed right after the nextTick queue is completely drained.
• Used by Promise.then(), await, and queueMicrotask().

SESSION — CONTEXT MATTERS

setTimeout(0) vs setImmediate() in I/O

Why execution order is guaranteed inside I/O callbacks.

In Main Module Context

The execution order of setTimeout(0) vs setImmediate() in the main script is non-deterministic and depends on process startup performance.

Inside an I/O Callback (fs.readFile)

Inside an I/O callback, setImmediate ALWAYS executes before setTimeout(0)! Because the I/O callback executes during the POLL phase, and POLL always moves to CHECK phase (setImmediate) next!

io_context_demo.js 
const fs = require("fs");

fs.readFile(__filename, () => {
  setTimeout(() => {
    console.log("timeout");
  }, 0);

  setImmediate(() => {
    console.log("immediate");
  });
});
Console Output in I/O Context
immediate ← POLL phase moves to CHECK phase first!
timeout ← Timers phase reached on next loop turn
SESSION — PERFORMANCE HAZARD

Why Blocking the Event Loop is Dangerous

What happens when synchronous CPU work hogs the JavaScript main thread.

THE DANGER OF BLOCKING
Node.js runs JavaScript on ONE main thread. If a request executes a heavy synchronous loop or CPU calculation, the Call Stack stays full, freezing ALL other incoming HTTP requests!

How to Avoid Blocking

  • Use asynchronous non-blocking APIs (fs.readFile instead of fs.readFileSync).
  • Offload heavy CPU math to Worker Threads (worker_threads module).
blocking_server.js 
app.get("/block", (req, res) => {
  console.log("Start heavy CPU calculation...");
  
  // ⚠️ SYNCHRONOUS CPU BLOCKING LOOP!
  for (let i = 0; i < 1e9; i++) {
    // Hogs thread for 3-5 seconds
  }
  
  res.send("Finished!");
});
Thread Saturation Effect
Request A ➔ [ HOGGING MAIN CALL STACK ]
Request B ➔ ⏳ WAITING (TIMEOUT ERROR)
Request C ➔ ⏳ WAITING (TIMEOUT ERROR)

Common Node.js Event Loop Misconceptions

Clearing up the top 7 myths taught in traditional tutorials.

Myth 1: Node.js is completely single-threaded
Truth

JS execution is single-threaded, but libuv uses background threads and kernel async APIs.

Myth 2: Every async operation uses the thread pool
Truth

Network sockets (HTTP/TCP) use non-blocking OS kernel polling directly.

Myth 3: setTimeout(fn, 0) executes in exactly 0ms
Truth

0ms is a minimum delay threshold. It must wait for Call Stack and phase queues.

Myth 4: process.nextTick() is an event loop phase
Truth

nextTick is a Node priority queue processed immediately after current operation.

DAY 5 — COMPARISON

Route Parameters vs Query Parameters

When to use req.params versus req.query in web APIs.

Feature Route Parameters (req.params) Query Parameters (req.query)
URL Format /users/:id ➔ /users/101 /products?category=shoes&page=2
Primary Purpose Identify a specific, unique resource item Filter, search, sort, or paginate data lists
Express Property req.params.id req.query.category, req.query.page
Mandatory? Required part of the route URL path Optional parameters after ?
route_params.js 
app.get("/users/:id", (req, res) => {
  const userId = req.params.id; // "101"
  res.json({ id: userId, name: "John Doe" });
});
query_params.js 
app.get("/products", (req, res) => {
  const { category, page } = req.query;
  res.send(`Category: ${category}, Page: ${page}`);
});

DAY 6 — CODE IMPLEMENTATION

Complete User CRUD API Implementation

Full working Express in-memory CRUD server.

crud_api.js 
const express = require("express");
const app = express();

app.use(express.json()); // Body parser middleware for req.body!

let users = [
  { id: 1, name: "Alice", email: "alice@example.com" },
  { id: 2, name: "Bob", email: "bob@example.com" }
];

// GET All Users (READ)
app.get("/api/users", (req, res) => res.status(200).json(users));

// POST Create User (CREATE)
app.post("/api/users", (req, res) => {
  const newUser = { id: Date.now(), name: req.body.name, email: req.body.email };
  users.push(newUser);
  res.status(201).json(newUser); // 201 Created
});

// DELETE User (DELETE)
app.delete("/api/users/:id", (req, res) => {
  users = users.filter(u => u.id !== parseInt(req.params.id));
  res.status(200).json({ message: "User deleted successfully" });
});

app.listen(3000, () => console.log("CRUD Server running on port 3000"));

200 OK (Success) • 201 Created (POST) • 400 Bad Request (Invalid data) • 404 Not Found (Resource missing) • 500 Error

DAY 8 — AUTH ARCHITECTURE

Session & Cookie Authentication Flow

How servers maintain logged-in state over stateless HTTP.

Session Concept

When a user logs in, the server creates a Session object in memory/DB and sends a unique Session ID back to the browser inside a Cookie header.

Cookie Security Flags
• HttpOnly: Prevents XSS scripts from reading session cookies.
• Secure: Transmits cookie over HTTPS only.
• SameSite=Strict: Protects against Cross-Site Request Forgery (CSRF).
1. User sends POST /login (email, password)
↓
2. Server verifies credentials & creates Session
↓
3. Server sets Header: Set-Cookie: connect.sid=ABC123
↓
4. Browser automatically sends Cookie on future requests!

DAY 9 — CODE WALKTHROUGH

Multer Single File Upload Example

Configuring storage destination and route middleware.

Why Multer?

Standard express.json() cannot parse raw binary files. Multer handles incoming multipart/form-data requests.

Accessing Uploaded Files
• Single Upload: req.file contains file object.
• Multiple Uploads: req.files contains array of files.
multer_config.js 
const multer = require("multer");

const storage = multer.diskStorage({
  destination: (req, file, cb) => cb(null, "uploads/"),
  filename: (req, file, cb) => cb(null, Date.now() + "-" + file.originalname)
});

const upload = multer({ 
  storage: storage, 
  limits: { fileSize: 2 * 1024 * 1024 } // 2MB limit
});

app.post("/upload", upload.single("image"), (req, res) => {
  res.json({ message: "File uploaded!", file: req.file });
});

DAY 10 — BINARY DATA

What is Buffer & How It Works

Raw memory chunks allocated outside the V8 JavaScript heap.

Buffer Definition

A Buffer represents a fixed-size sequence of raw bytes. It is used in Node.js when reading files, processing network streams, or handling images.

  • Buffer.from("Hello"): Converts string to UTF-8 byte array.
  • buf.toString("hex"): Encodes bytes into hexadecimal format.
  • buf.toString("base64"): Encodes bytes into Base64 format.
buffer_demo.js 
const buf = Buffer.from("Node.js", "utf8");

console.log(buf); 
// Output: <Buffer 4e 6f 64 65 2e 6a 73> (Hex bytes)

console.log(buf.length); // Output: 7

console.log(buf.toString("hex")); // 4e6f64652e6a73
console.log(buf.toString("base64")); // Tm9kZS5qcw==

  console.error("Error Stack:", err.stack);

  });
});
